# Decision 0025 — the task-context packet gains a `cochange` slot mined from local history

Date: 2026-09-02. Status: accepted. Authority: repository owner, verbatim instructions "research
the first two" (graph retrieval over code dependency graphs; evolutionary coupling from version
history) and "add co-change as a slot in the context packet" (2026-09-02), given after the
utilisation-gap reading of the development rerun.

## What was measured

A probe over the 34-task unseen set (`tools/cw-trial/testdata/unseen-corvint-v1`), history strictly
before each task's base commit, top 20, gold = the other files the same commit changed (177 paths):

| retriever | tasks with any gold | gold paths found |
|---|---|---|
| syntax packet (decision 0024 slots) | 27 | 63 |
| co-change alone, commits over 50 paths ignored | 20 | 74 |
| union of the two top-20 lists | 28 | 95 |
| packet with a `cochange` slot capped at 3 | 28 | 69 |
| packet with a `cochange` slot capped at 5 | 28 | 75 |

Commit-size cap sweep for co-change alone (tasks with any gold): 8 → 9, 20 → 18, 50 → 20, none →
21, with 19, 9, 9, and 0 subjects respectively left without any usable prior commit; this
repository has 157 non-merge commits, median 4 paths, p90 16, max 1,633. Minimum support 2 halves
recall here (46 gold paths against 74). Nine subjects have no prior history at all, which is
where the slot is blind.

Cap against history length, gold paths in the slot's top five: tasks with under 50 commits of
history (15) find 1 at cap 6 and 4 at every cap from 8 up; tasks with 100 to 200 commits (15)
find 3 at cap 6, 9 at cap 8, and 31 to 33 at every cap from 12 to unbounded. The age rule below
(50 paths up to 50 commits, 8 at 200, linear between) scores 38 paths and 16 tasks, the same as a
fixed 50 on this set; a fixed 8 scores 14. The rule's tight end is therefore untested here: this
repository's commits are large (p90 16 paths), and the variable the sweep actually separates on
is commit size, not commit count. When this repository reaches 200 commits the cap of 8 would,
on today's commit sizes, drop the slot to about a quarter of its hits.

A read-only literature charter (evolutionary coupling; summary in `docs/BUILD-LOG.md`) reports:
the commit-size cap is the dominant knob and the systematic sweep (Moonen et al., ASE 2016) puts
the best caps at 6 to 8 on mature open-source histories (the charter's reading of the paper; not independently opened here); confidence and support rank as well as
any of 39 interestingness measures; history goes stale with age, not with length, so no decay;
historical co-change reaches recall 0.87 against 0.42 for call/use/define relations on the same
systems (Hassan and Holt 2004), and the two candidate sets overlap little; test/source
co-evolution is often phased, so naming pairs stay primary. No published work uses co-change as a
retrieval signal for agent context.

## What is decided

1. The packet gains a `cochange` slot after `reverse-import` and before `sibling`: tracked paths
   that changed in the same commits as the subject among the last 200 non-merge commits behind
   the revision, commits over 50 paths ignored, more shared commits first, `git-history`
   authority, high confidence when shared more than once and medium otherwise, each row's reason
   naming the count and the cap. Minimum support stays 1 because this young repository loses half
   its recall at support 2.
4. The commit-size cap depends on repository age, measured as the number of non-merge commits in
   the 200-commit window: 50 paths for a history of at most 50 commits, the literature's 8 for a
   history filling the window, linear between. The young end is the measured value here; the
   mature end is the literature's and is not measured by any Corvint set yet.
2. The slot is capped at five, not three: the fourth and fifth rows still carried gold (75 against
   69 paths) with no task lost.
3. Determinism now covers the recent history the slot reads (TCP-V0-007).

## Amendment (2026-09-02, first history-backed reading)

`benchmarks/results/cw-trial-unseen-corvint-v1-run-3.json`, the first agent run whose copies
carried history (CWT-V0-005 `--history`): the slot put 31 gold rows in 34 packets and the agent
claimed 19 of them, lifting true claims from 50 to 59 at precision 0.81; two of the three wrong
`certain` claims cited co-change rows rated `high` ("4 of 4", "3 of 4" shared commits) that the
commit did not touch. Every co-change row is now `medium`: history is a reason to read a file,
never proof that it changes with this edit (AGENTS.md invariant 3), and the trial's prologue
bounds a medium row to `likely`. The requirement text for the slot, which the two earlier edits
had silently failed to insert, is now in TCP-V0-004.

## What is not decided

Whether the cap should follow the repository's own commit-size distribution (for example its 90th
percentile, floored at 8) instead of, or as well as, its age; the sweep above points that way and
it is the first thing to measure when a mature-repository set exists. Multi-file queries
(TARMAQ-shaped), confidence-pruned re-ranking of the syntax slots by history,
and any change to the public held-out reading, whose snapshots carry no history and where this
slot is therefore empty. The unseen set's gold is co-change by construction, so the numbers above
favour history in a way a review-comment task would not; the paired trial on that set is the
reading that counts.
