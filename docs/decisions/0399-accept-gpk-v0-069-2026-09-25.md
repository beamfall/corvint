# Decision 0399 — accept `GPK-V0-069`

Date: 2026-09-25. Status: accepted. Authority: repository owner instruction "accept GPK-V0-069"
(2026-09-25). Finding: pre-1.0 panel review blocker B3. Ticket: V1-0283.

`corvint impact` on a TypeScript workspace reported complete reverse-import coverage while
missing importers that reach the changed file through a workspace package name. Rule (c) of
`GPK-V0-027` resolves relative and alias specifiers only
(`internal/contextindex/reverseimports.go`), and the coverage gap was counted only for a suffix
with no rule (`internal/contextindex/receipt.go`).

`GPK-V0-069` is accepted as written (`docs/specs/go-production-kernel-migration-v0.md`; PR #224).
When a changed web path sits in a nested package whose `package.json` name some indexed specifier
names, or whose name cannot be read, the `impact` packet adds a counted
`reverse-import results for N changed paths importable by workspace package name are unresolved`
line to `coverage.uncertainty`. The clause discloses the gap and resolves no importer. The
analyzer schema moves one version, so existing indexes rebuild.

The acceptance evidence is the panel B3 BUILD-LOG entry and
`TestImpactDisclosesWorkspacePackageImporters`, which fails on the base and passes with the change.
Resolving workspace names, `exports`, `tsconfig` `paths` and barrel re-exports stays future work.
The matching `affected` gap (panel D8) is a separate defect under decision 0398.

Rollback: remove `webWorkspaceImportGap` from `setCoverage`, restore the previous analyzer schema,
and restore the proposed status of `GPK-V0-069`.
