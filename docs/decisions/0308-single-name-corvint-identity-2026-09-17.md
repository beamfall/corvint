# Decision 0308 — Corvint carries one name everywhere; the transition alias layer is retired

Date: 2026-09-17. Status: accepted. Authority: repository owner, who directed that the previous
product name be removed from every remaining reference before publication and that the result be
the first commit on the public repository.

## Decision

Every runtime setting, exported symbol, configuration key, executable name, flag, MCP metadata
pair and publication destination has exactly one Corvint name. The compatibility layer that
decision 0295 and `docs/specs/corvint-rebrand-v0.md` admitted for the prerelease transition
(absent-only fallback, equal-alias acceptance and alias-conflict refusal) no longer exists,
because there is no second name for it to compare against. Concretely:

- `internal/runtimeenv` resolves `CORVINT_<suffix>` and cannot fail; the
  `conflicting-runtime-environment` degradation and the pre-command environment validation are
  removed as unreachable.
- Shell helpers resolve one release setting; the JavaScript hosts read one `CORVINT_*` name; the
  VS Code extension reads the single `corvint.*` namespace and admits the `corvint` CLI kind
  and the `corvint-mcp` server pair only.
- `corvint-companion-release` accepts `-source-root` and `-tasks-root` only.
- Publication receipts accept only `https://github.com/Beamfall/corvint/releases/tag/<tag>` with
  `corvint_*` archive names. `GPK-V0-015`'s install-name prohibition is retired; `GPK-V0-023` still
  gates promotion of the candidate to the production executable.
- The `pi` host gains a row in the shared harness golden fixture for the five events it emits
  (session-start, user-prompt, post-tool, stop, session-end), which is the narrow successor to
  decision 0188's cross-host-identical goldens and satisfies `AHI-011`'s one-golden-per-host rule.
- Companion inventory cases that only existed to reject the pre-rename identities are dropped;
  the pre-rename Go archive names remain rejected.
- Frozen receipts, digests and goldens whose bytes carried the old name are re-pinned from the
  rebuilt commands: the shader compiled-CLI receipts, the structured-data source digests, the
  context-index analyzer schema (`corvint-analyzer/67`, then `corvint-analyzer/68` under layer C) and its default-recipe golden, the
  `AHI-016` disclosure counts and the release-artifact legal-file digests. Host package versions
  advance with the changed shipped content (`CRB-V0-012`).
- Identity strings inside frozen evidence carry the name too, so their dependent digests are
  re-pinned from the rebuilt output, never edited by hand: the analyzer candidate profile
  (`corvint-analyzer-candidate/experimental`) and evidence domain
  (`corvint-analyzer-candidate-evidence/experimental`) with every analyzer golden, including the
  1024-row corpus; the native-bridge request profile (`corvint-analyzer-native-bridge/v0`); the
  dashboard digest domains, local-trace profile and `.context-corvint/traces` location with the
  registry digest and conformance fixtures; the work-queue `adapter:corvint:*` and
  `capacity:corvint:*` identifiers with the frontier, pulse, LRF, TCQ, doc-compiler, doc-view and
  proof-abstraction digests; the native-hook-observer embedded activity schema digest; and the
  member name inside the PR-tests frozen export archive (header checksum recomputed, bytes
  otherwise identical); the `pulse-snapshot-v0` conformance corpus (per-case, case-set and file
  digests, regenerated by the corpus's own canonical encoder); and the committed
  `.corvint/work-queue-policy.json` identity, rederived from its renamed body.
- `conformance/lrf-v0` `failure.bound`: the `output-bytes.at-limit` and `plus-one` bounds move from
  594/593 to 596/595 bytes, exactly the two bytes `.corvint/change.cem.json` gained over
  `.atlas/change.cem.json` in the bounded output; the manifest entry and registration digest are
  re-derived. No other bound moves.
- The `cem status` canonical golden (`cmd/corvint/testdata/cem-status-canonical.golden`) is
  re-recorded from the rebuilt fixture: its `targetRevision` is the fixture commit whose tree now
  holds `.corvint/change.cem.json`. Every other member of the envelope is byte-identical. The
  OCM link fixtures select the subtest claim by selector rather than ordinal, and the
  local-authority release fixtures list `corvint` in sorted position, because claim ids sort by
  digest and release paths sort by name; neither changes what the tests assert.
- The VS Code extension's Python `atlas` CLI kind is retired, so both admitted kinds use the Go
  argv (`query --limit 1`, `impact --limit 20`); the configuration-conflict and unreachable
  refusal branches are removed, the request-echo validator checks one shape, and MCP presentation
  drift is classified `toolset-mismatch`.
- `ACP-009`: the JavaScript/TypeScript candidate ceiling is raised from 92,039 to 92,045 bytes,
  exactly the +6 bytes the two identity strings gained. This is the operator adjudication the
  ceiling test names, not a routine repair; no other ceiling moves.
- `conformance/cli-parity-v0` no longer rejects the historic `corvint-context` module path (the
  detector clause and its fixture case are dropped; the current-module and product-path rejections
  remain). The `lrfrepo` anchor fixture selects its top-level claim explicitly, because claim ids
  sort by digest and the extractor name changed.
- The context-index agent-tooling term and anchor sets (`internal/contextindex`) and the
  `CORVINT_CONTEXT_TERMS` override carry the single name; the retired name is no longer a tooling
  term.
- `conformance/cli-parity-v0`'s frozen oracle inputs are evidence bytes and keep their frozen
  forms: the fixture builder identity and format (`atlas-cli-parity-fixture/0`), the twenty-three
  fixture files, every per-case argv, setup and path in `manifest.json`, the `oracleCommand`
  provenance and the argv pins in `manifest.go`. Only the manifest profile, the candidate command
  and the `CORVINT_CACHE_DIR` environment key are renamed. The genesis inventory digest domains
  (`atlas-genesis-inventory/0.1-experimental`) are preserved for the same reason. Against those
  inputs the renamed candidate diverges in two ways, both recorded as `DR-0038`: the ten harness
  receipts differ only by the event profile name and carry a pinned `identityRenameDivergence`;
  twenty-nine cases whose frozen argv, fixture or expectation address `.atlas/`,
  `.context-atlas/traces` or the product-name tooling term (`cem` 16 of 37, `eval` 1 of 3,
  `migrate-traces` 2 of 5, `ocm` 5 of 9, `query` 4 of 27, `record` 1 of 3) carry a pinned `retired`
  declaration, are neither executed nor scored, and are reported `RETIRED`, never `PASS`. Two
  refusal items are retired the same way: `lrf-ocm-python-claim-refusal` (argv names the `.atlas/`
  maps) and `query-present-trace-store-refusal` (setup creates `.context-atlas/traces`); the typed
  refusals they certified remain in the candidate. The `SUMMARY` counts range over the 104
  executed cases and the one executed refusal, and the seven affected commands carry inventory
  status `PARTIAL` (`GPK-V0-026`). The alternative of keeping the `.atlas/` state paths and the
  `atlas` tooling term to retain full oracle parity was rejected by the one-name rule.

- The Go candidate directory and binary are `cmd/corvint` and `corvint` (owner directive,
  2026-09-17: the tree has no non-Go runtime, so the `-go` migration-candidate suffix named
  nothing). `GPK-V0-023` is amended in place: packaging the binary as `corvint` no longer waits on
  the complete CLI matrix, and the matrix stays reported as measured (`full-gpk-v0-005=PARTIAL`,
  `DR-0038`); this is a naming decision, never a parity claim. Names in which `go` means the Go
  language stay (`corvint-go-test-provider`, `corvint-go-toolchain-receipt`,
  `corvint-go-toolchain-tree`, `corvint-go-build-cache`, the `corvint-go-live-*` protocol profiles
  and the `corvint-go-format*` / `corvint-go-archive-*` / `corvint-go-release` gate scratch names),
  as do the internal `corvintGo` identifiers that name the Go arm of the two-runtime trial tools.
  `CORVINT_GO_HELPER_PROCESS` becomes `CORVINT_HELPER_PROCESS`, the bare `CORVINT_GO` planner
  override becomes `CORVINT_PLANNER`, the benchmark result keys `corvint_go_path` and
  `corvint_go_sha256` become `corvint_path` and `corvint_sha256`, `corvint-go-witness-v0.md` and
  decision 0163 are renamed to `corvint-witness…`, and the VS Code extension admits one `corvint`
  CLI kind. The release-artifact v1 and v2 schemas name the same `corvint_*` archive set; the
  retired `corvint-go` archive, binary and companion component names remain rejected. Frozen
  receipts, digests and goldens whose bytes carried the candidate name are re-pinned from the
  rebuilt output: `internal/contextindex` production bytes changed (`range_impact.go` profile and
  hash-domain strings), so `analyzerSchemaID` moves to `corvint-analyzer/68` and the
  `IDX-SNAP-V0-017` audit digest is re-recorded; the two `AHI-016` boundary cases whose prompt
  segment names `cmd/corvint/...` lose three bytes each, so their pinned disclosure counts move
  from 2968/109 to 2965/106 (`over-bound-prompt-anchor-query`) and from 2842/32 to 2839/29
  (`over-bound-prompt-trims-next-line`) in `common-logical-interaction.json` and
  `prompt_bound_test.go`; the `GPK-V0-023` amendment shifts one decision 0093 citation and the
  `context_lookup.go` comment shifts two `falsifiable-packet-v0` citations, all re-pinned to the
  same bytes; `gofmt` realigns two map literals whose keys shortened. The shipped hooks, skills
  and prompt-bound twins changed, so the host package versions advance again (claude-code and
  codex `0.2.2`, gemini-cli and opencode `0.2.4`, `CRB-V0-012`). The installed core proof then
  surfaced one pin the earlier layer had left behind: `script/seed-planning-store-data.json` pins
  the roadmap's source digest, and the roadmap carried the retired name, so the seed script refused
  with `source-digest mismatch`. The pin is refined to the renamed roadmap's digest
  (`3cffe17a…` to `a13c1e46…`; the roadmap diff is the name alone), verified by
  `seed-planning-store_test.sh` and the `core-planning-proof` replay. No bound, ceiling or
  threshold moves under this layer.

Sealed benchmark partitions under `benchmarks/blind-v4/` and their manifest are excluded from the
rename and unchanged, as are the bytes of `benchmarks/blind-v3-manifest.json`, the registered
corpora and case files, and the split rule `atlas-eval-split-v0` in `internal/evalrepo` and
`benchmarks/eval-split-v0.json` (renaming the rule would reassign rows). Retrieval thresholds,
candidate inventory and release acceptance criteria are untouched.

## Requirements

- **CRB-DEC-002:** One name per identity. A future compatibility alias requires its own accepted
  amendment to `corvint-rebrand-v0`; none is admitted by default.

## Consequences

`corvint-rebrand-v0` requirements CRB-V0-010, 011, 013, 015, 016 and 018 are amended in place and
their traceability rows name the surviving tests. The `atm` executable name of the Tasks tool is
that tool's own identity and is unchanged. Historical decisions keep their wording.
