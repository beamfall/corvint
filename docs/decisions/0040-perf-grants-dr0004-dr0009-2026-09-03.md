# Decision 0040 — perf grants for DR-0004 and DR-0009 on the Beamfall impact invocation

Date: 2026-09-03. Status: accepted. Authority: repository owner, verbatim instruction "ratify the
grants for DR-0004 and DR-0009" (2026-09-03).

## What is ratified

`conformance/perf-v0` may measure task `beamfall-impact-path`, argv
`impact internal/graph/graph.go --limit 10`, across the recorded output differences of `DR-0004`
and `DR-0009`. Each grant relaxes `unequal-stdout` and nothing else. Decision 0007 item D9's grant
for the corvint `impact-path` is unchanged and is not widened.

## The evidence the grants rest on

The grants were written after the divergence was reproduced against the pinned corpus and diffed
member by member, not from the register's summaries. On Beamfall at `fa3b1e7f`, oracle versus a
candidate built from this branch, the two receipts differ in exactly 22 nodes and no others:

- `coverage.requested_results` 10 versus 205, `coverage.omitted_results` 0 versus 195, one extra
  candidate `uncertainty` line, and `coverage.packet_bytes` 12,682 versus 12,730 as their
  consequence. That is `DR-0009`, adjudicated `python-defect`: the oracle denominates coverage in
  its own truncated output, so its `omitted_results` is structurally zero. The candidate is right.
- Test-marker evidence rows permuted within `results[4]` and `results[6]` — the same rows, the same
  lines, a different order. That is `DR-0004`, adjudicated `python-defect` under `GPK-V0-027` as
  amended.
- The ranked result ids are identical in both runtimes, which is what makes this a pair of recorded
  disagreements rather than a retrieval difference.

Both entries are `LANDED` / known-divergent with the oracle at fault and frozen, so no repair to
either runtime can close them and the timing comparison is between two runtimes doing the same work.

## What the mechanism had to grow, and what it did not

`ratifiedAcceptedDivergences` held one grant per entry and `taskSpec` named one entry per task.
Both are now plural: an entry maps to the invocations it has been ratified for, and a task may name
several entries, because one invocation genuinely carries two adjudicated disagreements and
absorbing one while the other still invalidated would report a diagnosis nobody made.

The properties that make this a grant rather than an escape hatch are unchanged and still tested. A
grant is matched by entry *and* task id *and* exact argv, so it never travels to another invocation
— `TestAGrantDoesNotTravelToAnotherInvocation` shows `DR-0009` absorbing nothing on the corvint task.
Every grant relaxes `unequal-stdout` alone; a timeout, an exit-status difference, a changed corpus,
a sample failure or an unstable oracle is never a diagnosed disagreement and still invalidates.
The set lives in Go source, not manifest data, so a manifest edit can never widen it, and
`TestOnlyRatifiedGrantsAreInTheSet` enumerates every grant so an unratified addition fails there
first. Each absorbed task still discloses both runtimes' stdout digests, and every criterion
measured across a relaxation says so in its observed text.

## What this record does not do

It does not grant `beamfall-impact-path-snapshot-present`. That task carried `sample-failure`,
`timeout`, `unequal-exit-status` and `unstable-oracle-stdout` alongside `unequal-stdout` in the
2026-09-03 run: the oracle exceeded the 30-second sample timeout and its own output varied between
samples. None of that is a diagnosed disagreement, no grant may relax it, and the task stays
invalid until the timeout is understood. It does not grant any other task. It does not repair
`src/`, and it does not assert that the run now qualifies packet-5 — the next full run decides that,
and it is the first under this grant set.

## Rollback

Remove the `beamfall-impact-path` grants from `ratifiedAcceptedDivergences` and the
`acceptedDivergences` key from that task in the manifest. The plural shape may stay; with an empty
list it behaves exactly as the singular one did.
