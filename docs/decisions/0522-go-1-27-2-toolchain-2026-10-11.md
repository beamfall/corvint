# Decision 0522 — The pinned toolchain moves from go1.27.1 to go1.27.2

Date: 2026-10-11. Status: accepted (owner, "we should make sure the go version is tagged
everywhere as using 1.27.2", 2026-10-11). Authority: repository owner. Supersedes the exact pin
of decision 0293; 0293 stays the record of the 1.27.0 to 1.27.1 move.

## Context

Homebrew upgraded the host's default `go` to 1.27.2 and removed the 1.27.1 keg, while `go 1.27.1`
remained the exact pin in `go.mod`, the Makefile and `AGENTS.md` verify lines, every CI workflow,
the release, companion, readiness and conformance identity checks, and the spec sentences that
state the pin. Under the upgraded host each exact identity check refuses, as 0293 recorded for the
previous patch release.

## Decision

The exact pin becomes `go1.27.2` everywhere a live check or instruction names the current
toolchain: the root and `tools/local-authority` `go.mod` directives; the Makefile and `AGENTS.md`
verify lines; `.github/workflows/{ci,release-gates,pr-tests-qualification,intake-containment}.yml`
(setup-go versions, `GOVERSION` asserts and the generated `cishards`/`testconfine` module
directives); the `protocol/postmerge-host` workflow templates; `script/public-release-check`,
`script/corvint-companion-release-gate` and their tests; `cmd/corvint-public-release-check`;
`conformance/release-artifact-v0` (code, manifest, report schemas, README) and
`conformance/go-live-test-v0`; `internal/companionrelease`, `internal/liveverify/provider`,
`internal/opencodequalification`, `internal/releasecandidate`; `tools/compat-trial` and
`tools/corvint-pr-tests`; the keg paths in the analyzer-go compiled-CLI test and the VS Code
installed-host harness; current README, runbook, example and integration prerequisites; and the
normative spec sentences (`GPK-V0-018`, `AFP-V0-014` and its native-execution note,
`compat-trial-v0` build identity, `go-live-test-provider-v0` tuple, `public-release-v0` checker,
`ARTIFACT-GO-V0-001` and its trust-boundary note, `stable-readiness-record-v1`, the external
evidence provider prerequisites and the VS Code harness note). Requirement IDs are unchanged.
Every check stays exact: nothing accepts a range or skips identity validation. This decision is
the new conformance tuple that `go-live-test-provider-v0` requires for a later Go release.

Left as they were (invariant 1: evidence stays pinned to what actually ran): `docs/build-log/**`,
`https://github.com/beamfall/corvint-history/blob/1c4d8793cf71cbb01b8509b68a6cb1502a40a13e/docs/BUILD-LOG.md`, existing decision bodies, published release-note sections, frozen benchmark
runs and qualification freezes, retained `.agent-evidence`, `.corvint/` records, spec
evidence/measurement paragraphs, and fixtures that only carry an arbitrary `go` directive. Also
left, each needing its own measurement or qualification rather than a relabel:

- the frozen, digest-pinned `protocol/cem-1.0` S0E packet (`FULL-RESULT-CASES.json`,
  `LOGICAL-LEDGERS.json`, the inherited envelope cells), which records `go1.27.1` and is never
  rewritten;
- the proposed `aggregate-local-outcome-v0` frozen admission commands and the delivered
  `CRB-V0-008` foundation acceptance.

The CEM structural-proof runtime tuple is re-qualified rather than relabelled (`CEM-V1-050`).
`go1.27.2` joins `go1.27.1` as an admitted tuple in `internal/cem/verify/stable.go` and
`interop/cem01-go` (`cem.go`, `stable_repository.go`); every other release still refuses with
`unsupported-structural-runtime`. The admission rests on the sealed packet
`protocol/cem-1.0/structural-tuples/go1.27.2/` (`TUPLE.json` plus `manifest.json`). It binds the S0E
packet manifest and the two result files by SHA-256 and declares a single substitution,
`expectedResult.runtime.goVersion` from `go1.27.1` to `go1.27.2`. It records the evidence: the
go/ast, go/format, go/parser, go/printer, go/scanner, go/token, go/build/constraint and cmd/gofmt
sources are byte-identical between the two toolchains. A 3745-file repository corpus with the
structural fixture matrix, plus the native and interop S0E results, produced byte-identical output
under both toolchains. The tests that skipped as NOT_RUN on go1.27.2 now run through that binding.
Qualification stays `EXPERIMENTAL_TUPLE_PENDING_FULL_CORPUS`.

The CI shard cost table and test-slice provenance checkers (`.github/cishards`, `AFP-V0-022`,
`AFP-V0-041` (3)) admit `go1.27.2` beside `go1.27.1`. So `tools/ci-shard-costs refresh` and
`tools/ci-test-slices generate` work on the pinned toolchain and record it, and the retained
go1.27.1 tables stay valid. The tables themselves are not regenerated, because their inputs are
hosted CI run logs that are not available locally. The first go1.27.2 CI refresh replaces them.

## Consequences

- A host without go1.27.2 as `GOTOOLCHAIN=local` refuses, as before with 1.27.1.
- CI installs 1.27.2 through `actions/setup-go`; the pinned action SHA is unchanged.
- Rollback: revert this commit and install go1.27.1 alongside (official archive) as the
  `GOTOOLCHAIN=local` toolchain; the previous pin then applies unchanged. The structural tuple
  admission rolls back on its own by removing `go1.27.2` from the two `structuralTuples` maps and
  deleting `protocol/cem-1.0/structural-tuples/go1.27.2/`; go1.27.2 then refuses structural proof
  and its S0E checks return to NOT_RUN.
