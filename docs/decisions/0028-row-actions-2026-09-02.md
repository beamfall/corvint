# Decision 0028 — every task-context row says what to do with the file

Date: 2026-09-02. Status: accepted. Authority: repository owner, verbatim instruction "make the
rows say what to do with the file" (2026-09-02), given on the corroborated-rank reading.

## What was measured

Across the history-backed unseen runs and the corroborated-rank rerun (decision 0027), the
agent claimed gold rows by what their relation said, not by rank or count: "test counterpart"
rows 25 to 26 of 27 and "changed with" rows 19 to 21 of 31 were claimed; "same directory as"
rows 3 of 8 and "defines `X`" rows 0 of 3 were not, at any rank, before and after the ranking
change. The packet told the agent how a file was found and left it to infer what to do.

## What is decided

1. Each result row carries `action`, one imperative sentence fixed per relation
   (TCP-V0-003): update the test counterpart; read the source counterpart; open a file the
   task names; reconcile a named definition; check an importer; expect to touch a co-changed
   file; scan a sibling for the task's identifiers; read a term match only if the terms are
   load-bearing. Each sentence claims what the relation establishes and no more (AGENTS.md
   invariant 2): the co-change and sibling actions say "expect" and "scan", not "change".
2. The trial's corvint prologue tells the agent to act on `action`. Nothing else in the packet,
   slots, ranking, or confidence changes.
3. The readings are the corvint-only reruns on both sets over their reused baselines.

## What is not decided

Task-specific actions (naming the identifier a sibling should be scanned for, or the exported
symbol an importer depends on) need the packet to carry the task's identifiers per row, and wait
on this reading.
