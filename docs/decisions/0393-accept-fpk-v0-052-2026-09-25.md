# Decision 0393 — accept `FPK-V0-052`

Date: 2026-09-25. Status: accepted. Authority: repository owner instruction "accept FPK-V0-052 and
keep merging as CI goes green" (2026-09-25).

`FPK-V0-052` was proposed on 2026-09-25 for pre-1.0 panel blocker B2 (PR #218). It is accepted as
written in `docs/specs/falsifiable-packet-v0.md`:

- Every Git process that `cmd/corvint` starts is built by one helper, `hermeticGitCommand`. This
  covers the Git processes for `prove`, `affected`, bundle export and replay, checkpoint reads, and
  compaction-pin reads.
- The helper passes the `-c` set from `internal/contextindex`, plus `core.hooksPath=/dev/null` and
  `--no-optional-locks`.
- It drops global and system configuration and sets `GIT_NO_LAZY_FETCH=1` and
  `GIT_NO_REPLACE_OBJECTS=1`.
- It sets `GIT_CEILING_DIRECTORIES` to the root's parent only when the root holds its own `.git`
  entry.
- As a result, a `core.fsmonitor` or hook program configured by the repository never runs. A
  `refs/replace` entry cannot change a changed path, a hunk span, a cited blob byte, or an object
  id (invariant 1).
- A root inside a worktree, such as a `CLAUDE_PROJECT_DIR` subdirectory, keeps discovery up to its
  enclosing worktree, so the PostCompact pin check still verifies from a subdirectory.
- The wire is unchanged.

Evidence, all in `cmd/corvint/prove_git_hardening_test.go`:

- `TestProveGitReadsNeverRunRepositoryFSMonitor`. Its control run shows that plain `git status` runs
  the program. The test failed before the fix.
- `TestProveGitReadsIgnoreReplaceObjects`. Before the fix, the replace ref moved the spans from
  {3 5} to {4 8}.
- `TestAffectedBaseRangeIgnoresReplaceObjects`. This is a regression guard.
- `TestCompactionPinVerifiesFromSubdirectoryRoot`. It failed under the first cut, which set the
  ceiling unconditionally.

Rollback: restore the environment-only `scrubbedGitEnvironment` at each call site, then return
`FPK-V0-052` to proposed or delete it. No stored state changes.
