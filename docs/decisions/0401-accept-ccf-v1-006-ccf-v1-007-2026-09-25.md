# Decision 0401 — accept the `CCF-V1-006` and `CCF-V1-007` amendments

Date: 2026-09-25. Status: accepted. Authority: repository owner instruction "accept AHI-031,
LCP-V0-008, CCF-V1-006 and CCF-V1-007" (2026-09-25). Finding: pre-1.0 panel review blocker B6.
Ticket: V1-0285.

`CCF-V1-007` named 0.7.0 as N-1 on the premise that nothing under `cmd/corvint` or `internal` had
changed since. Tags `v0.8.0` and `v0.8.1` shipped the contract after that premise stopped holding,
and commit 2f3bfe6 (V1-0186) added `instruction-routed` to `context`'s frozen
`coverage.unexamined[].relation` list. The enumeration rule named no enumerations, so no test
could apply it.

The amendments are accepted as written (`docs/specs/core-compatibility-freeze-v1.md`; PR #226):

1. `CCF-V1-007`: N-1 is the newest release tag on `main`, currently 0.8.1. Its clause (d) is a
   register of the frozen enumerations, keyed by member and `tool`, each row `closed` or `open`
   with a cited source. `relation` and `abstention.reason` are `open`.
2. `CCF-V1-006`: adding a value is breaking only in a `closed` register row; removing or renaming
   any registered value is always breaking.
3. The contract's claim, Agent digest, `INDEX.json` claim and README row read "0.8.1 to 1.0".

The rest of the contract stays proposed pending V1-0001. The acceptance evidence is the panel B6
BUILD-LOG entry and `TestCoreVerbsEmitTheFrozenProfiles`, which reads the register from the spec,
passes on this tree and on a `v0.8.1` checkout, and fails on an added relation, on the 0.7.0
relation set, and on a row no frozen mode reaches. A release gate that replays the N-1 tag and
registers for nested enumerations remain NOT_PRODUCED.

Rollback: restore the proposed status of both amendments, and the 0.7.0 N-1 text with a recorded
divergence for `instruction-routed`.
