# Decision 0396 — accept `GPK-V0-068`

Date: 2026-09-25. Status: accepted. Authority: repository owner instruction "accept GPK-V0-068"
(2026-09-25). Finding: pre-1.0 panel review must-fix M2.

`query --limit 1` returned `READY` when the limit cut a competing record. Before this change,
`evalQuery` asked for widening only when the top two record scores tied exactly
(`internal/contextindex/eval_query.go`).

`GPK-V0-068` is accepted as written (`docs/specs/go-production-kernel-migration-v0.md`; PR #223).
When the result limit omits a competitive record that rests on a query word no emitted result
rests on, the packet carries `state` `NEEDS_WIDENING` and an active abstention with reason
`omitted-competing-record`, and keeps its emitted results. A limit that admits every such record
leaves the packet unchanged. The analyzer schema moves from `corvint-analyzer/84` to
`corvint-analyzer/85`, so existing indexes rebuild.

The acceptance evidence is the panel M2 BUILD-LOG entry and
`TestEvalQueryLimitOmittingCompetingRecordNeedsWidening`, which fails on the base and passes with
the change. The Beamfall goldens and the retrieval benchmarks are unchanged. The Beamfall M2 query
and `ambiguous-reveal-navigation` at limit 1 now answer `NEEDS_WIDENING`. Beamfall's frozen golden
is not amended here, because Beamfall owns it.

Rollback: remove the `evalOmitsCompetingRecord` check in `evalQuery`, restore the analyzer schema
to `corvint-analyzer/84`, and restore the proposed status of `GPK-V0-068`.
