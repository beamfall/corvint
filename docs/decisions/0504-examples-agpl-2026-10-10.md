# Decision 0504 — Examples move to AGPL-3.0-or-later; protocol stays Apache-2.0

Date: 2026-10-10. Status: accepted by the owner. Authority: owner decision in chat, 2026-10-10.
The owner said "I just don't want people using it in closed source projects", and, asked which
Apache-2.0 islands to keep, chose "Examples AGPL, protocol Apache".

## Context

Decision 0002 put `examples/**` inside the Apache-2.0 interoperability layer, and `LICENSING.md`
listed it. The tree disagreed with itself: five files under `examples/evidence-provider/v0/` already
carried `AGPL-3.0-or-later` headers and their README called them AGPL, while PR #751 (V1-0135,
V1-0128) added `Apache-2.0` headers to the eight headerless example files. Every commit under
`examples/**` was authored by the owner.

## Decision

1. `examples/**` leaves the Apache-2.0 layer and joins the AGPL-3.0-or-later product layer.
   `LICENSING.md` no longer lists it, and decision 0002 gains a dated amendment that records the
   change.
2. Every non-Markdown file under `examples/**` carries `SPDX-License-Identifier: AGPL-3.0-or-later`.
   No file under `examples/**` carries an Apache-2.0 notice.
3. `protocol/**` stays Apache-2.0 and remains the only place a new Apache-2.0 file may enter.
4. Copies of `examples/**` already published under Apache-2.0 keep those terms. The change applies
   from the commit that records this decision forward; it withdraws no right already granted.

This decision changes no other path. `conformance/**`, `interop/**`, the `docs/` schema and protocol
files that `LICENSING.md` lists, and the three frontier files of decision 0422 keep their terms.

## Enforcement

`script/check-license-headers.sh` (`make license-headers-check`, a `make gate` step scoped to
`examples/` in `tools/gate-ledger`) fails when a tracked file under `examples/` carries an SPDX
expression naming Apache anywhere or the "Licensed under the Apache License" line, or when a
non-Markdown file there lacks exactly `SPDX-License-Identifier: AGPL-3.0-or-later` in its first five
lines. `script/check-license-headers_test.sh`
(`make license-headers-test`) covers a clean tree, both Apache notice forms, compound SPDX
expressions, a missing header, and an Apache file under `protocol/` that the check leaves alone. The check is lane tooling delivered under
this decision; the owner decided the licensing, not the check's shape.

The release-artifact manifest pins `LICENSING.md` and `PROVENANCE.md` by digest (`GPK-V0-020`), so
both pins in `conformance/release-artifact-v0/manifest.json` move to the amended bytes. As with
decision 0422, this is an owner licensing decision, not part of the Go migration.

## Consequences

- `docs/CEM-CI.md` tells adopters to copy `examples/cem/verify-pr.sh` and
  `examples/cem/github-actions.yml` into their repositories. Those copies are now AGPL-3.0-or-later.
  The `interop/cem01-go` portable verifier stays Apache-2.0.
- `GPK-V0-020` in `docs/specs/go-production-kernel-migration-v0.md` now names `examples/**` as
  AGPL-3.0-or-later; `README.md`, `PROVENANCE.md`, `ROADMAP.md` and the recipes README match.
- Decision 0064's P4 note, that a CI wrapper under `examples/**` preserves the Apache-2.0
  boundary, is superseded for `examples/**`: only a wrapper under `protocol/**` would be Apache-2.0.
- Historical evidence that quotes the old boundary, such as the 2026-08-29 GPK-V0-020 notices
  assessment and earlier build-log entries, is left unchanged.

## Rollback

Revert this decision, the 2026-10-10 amendment of decision 0002, the `LICENSING.md`, `README.md`,
`PROVENANCE.md`, `ROADMAP.md`, `docs/CEM-CI.md` and `GPK-V0-020` text, the `examples/**` SPDX
headers, the manifest digests, and the header check with its Makefile and gate-ledger entries,
together. Rights already granted under AGPL-3.0-or-later for the intervening commits stay granted.
