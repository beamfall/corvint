# Decision 0584 — Remove the CEM size wall; only learning stays bounded

Date: 2026-10-27. Status: experimental under the standing lane auto-accept (V1-2883). It amends
`DCW-V0-039`, `DCW-V0-040` and `DCW-V0-032`, adds `DCW-V0-373..376` and `ALO-V0-027`.

## Context

A change of more than about 256 evidence records, or more than 200 changed paths, could not be
bound, checked and sealed as one change. The daily loop refused it with `git-budget-exceeded`
(a fixed 1,024-operation verifier budget) or `admitted-path-limit` (the 200-path learning
recorder), and the `fix:` lines told users to split the work into separately sealed lanes and run
`dogfood batch-check`. Replaying the 583-path, 1,687-hunk range `98b780811..ed70f3efb` with the
previous binary refused at stage 2: `cem prepare` needed 1,477 operations. The full map needed
3,225 candidate and 5,123 stable operations. The legacy recorder counted 573 admitted paths,
over both the 200 learning limit and the aggregate's former 512.

## Decision

1. The Git operation budget of the candidate verification `cem prepare` and `cem cite` run scales
   with the map: 1,024 plus 4 per hunk and evidence record (`DCW-V0-373`). The stable verifier
   keeps the `cem/1.0` protocol's fixed 1,024 operations: `CEM-V1-260`, the sealed public S0E
   cases (`ledger-337-evidence` must refuse with `unsupported-resource-limit`) and
   `interop/cem01-go` pin it, so a default change would break conformance. Instead
   `cem status --scaled-operations` opts into the same scaled bound, and the dogfood flows rerun
   `cem status` with it once, only after the protocol budget's refusal; the OCM stable admission
   of a prepared CEM reruns the same way. The first run keeps the
   protocol argv, so a verifier that predates the flag sees an unchanged argv on every change
   within 1,024 operations, as with `--max-deferred-intents`. `dogfood check` requires its base and
   tree verifiers to agree on the rerun too, so a large change whose base verifier lacks the flag
   fails closed until the flag is on the base. The `cem/1.0` caps (2,048 hunks, 4,096 evidence
   records, 4 MiB) bound every scaled budget at 25,600, so every operation, total and
   per-operation deadline, and every output bound still holds and still fails closed.
2. A local outcome over 200 paths records the complete nonlearning aggregate
   (`aggregate-local-outcome-v0.md`) instead of refusing (`DCW-V0-374`). `dogfood check`
   reacquires it (`DCW-V0-375`). The aggregate now admits up to its 4,096 candidate bound
   (`ALO-V0-027`). The trace store, the index and every learning step still admit at most 200
   paths and never read an aggregate, so product invariants 4 and 5 hold.
3. The 16-scope intent bound is kept (`DCW-V0-376`). It is the aggregate OCM map's scope bound
   under its 256-obligation total, and the aggregate fit search enumerates subsets of the scopes,
   so it cannot scale with a change. It is not a change size wall: scopes past the ones that
   govern the change are recorded as deferred intents (`DCW-V0-371`). An over-count manifest now
   refuses with its own code, `intent-scope-limit`, instead of `missing-intent-scope`.
4. The `fix:` lines no longer tell users to split a change that can now bind. Splitting and
   `batch-check` remain the route only for the bounds that still hold: the map caps, the
   aggregate's 4,096 paths and 4 MiB, and the intent scope bound.

The aggregate fallback is opt-in through `dogfood-record --aggregate-over-limit`, which only
`dogfood change` passes. Local completion keeps its enrolled aggregate path, which relies on the
legacy refusal row. The receipt that `dogfood change` writes is not an enrollment marker while
its plain change report binds the receipt's digest, so the same change can be rerun.

## Rejected alternatives

- Raising the 200-path learning limit: learning inputs must stay bounded and evaluation-gated.
- An unbounded verifier budget: a hung or looping verifier must still fail closed.
- Scaling the stable verifier by default: it changes the frozen `cem/1.0` stable result of the
  public `ledger-337-evidence` case and diverges from `interop/cem01-go`.
- Raising the 16-scope bound: the OCM obligation total and the subset search both grow with it,
  and deferred intents already remove it as a size limit.

## Rollback

Revert the change. The candidate budget returns to a fixed 1,024 operations, `--scaled-operations`
and the status reruns disappear (the stable default never changed), the local outcome refuses
`admitted-path-limit` again, and the aggregate admitted bound returns to 512. No stored state
changes shape: an aggregate receipt written by this change is the existing ALO-V0 profile.
