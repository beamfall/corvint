# Decision 0384: the 0.9 candidate ships as 1.0.0-rc.1

Date: 2026-09-24. Status: accepted (owner answer 2026-09-24: "you can rename 0.9 to
v1.0.0-rc.1"). Tickets: V1-0018, V1-0020. Amends decision 0381 critical-path steps 7 and 9.

## Decision

1. No 0.9.0 is published. The candidate that decision 0381 step 7 freezes is version `1.0.0-rc.1`,
   tag `v1.0.0-rc.1`, a GitHub pre-release. A fix after the candidate is sealed restarts step 7 as
   `1.0.0-rc.2`, and so on. The stable release is `1.0.0`.
2. The version uses the SemVer pre-release form the owner named, not the PEP 440 form of the alpha
   tags (`v0.5.0a1` to `v0.5.0a4`). `script/release-checklist` already accepts it: the version is
   `[0-9A-Za-z.+-]` and the expected tag is `v$VERSION`.
3. The store keeps release id `v0-9`, because release ids are immutable. `release update` sets its
   version to `1-0-0-rc-1` and its title to `Corvint 1.0.0-rc.1 release candidate`. Predecessors,
   tickets, criteria and gates are unchanged. V1-0018 is retitled `Freeze and qualify the 1.0.0-rc.1
   release candidate`.

## Follow-up inside V1-0018

`corvint-release-candidate` and `corvint-release-install` (Core, `PUB-V0-022..026`) admitted only
`MAJOR.MINOR.PATCHaN` when this decision was taken, so neither `1.0.0-rc.1` nor `1.0.0` assembled.
V1-0018 widens that grammar (`internal/releasecandidate/candidate.go:24@3051c034`, used again at
`internal/releasecandidate/install.go:109@0a2f615a`), with its spec text and tests, before the
candidate is frozen.

## Rollback

Revert this change and run the inverse `release update` on `v0-9` (version `0-9`, title `Corvint
0.9 release candidate`) and the inverse `ticket refine` on V1-0018. Nothing is published by this
decision, so no tag or archive needs retracting.
