# Decision 0330 — verified local-workflow scope for 0.6

Date: 2026-09-22 (UTC). Status: accepted scope; delivery unqualified.
Authority: the owner requested “Get to version 0.6.0”, selected the roadmap's verified-workflow
milestone, requested latest Corvint use in Codex and Claude, and explicitly accepted the concrete
local-workflow scope proposal in this task. The proposal separated installed local use from formal
FULL authority and selected the three new governed identities below. This is not publication approval.

## Decision

The 0.6 milestone qualifies the one-binary local change-evidence workflow: task orientation,
change consequence, and evidence-carrying completion. Its governing contract is
`docs/specs/daily-change-evidence-workflow-v0.md`. Add `UC-TASK-ORIENTATION`,
`UC-CHANGE-CONSEQUENCE`, and `UC-EVIDENCE-CARRYING-COMPLETION` without changing the nineteen
existing jobs or their claims. Version the closed ledger as `/1`, preserve historical `/0` admission
and archived bytes, and keep all six evidence classes and real Corvint/Beamfall dogfood mandatory.
The `/1` compatibility mechanism implements the selected identities; it is not a new promotion gate.

Core contracts cover init, adopt, index, query, context, impact, affected, prove, CEM, OCM,
frontier and dogfood's retained local outcome. Optional profiles and language families inherit no
qualification. Native Darwin/Linux targets require their own retained evidence; cross-builds are
not native qualification and Windows is outside this milestone.

Codex and Claude must use the current qualified binary and installed skills/hooks, exercised on
exact host versions. Formal FULL/Frontier authority remains a separate nonblocking objective for
0.6. This supersedes only conflicting Public Release V0 prerequisites requiring optional companions
or unavailable formal host authority for the 0.6 Core workflow; historical contracts and claims stay
visible. Local completion does not become host authority.

Console, Tasks, MCP, editor, test-provider and automatic-documentation surfaces, other hosts and
protected authority remain optional companions or experimental profiles. Other shipped profiles
remain experimental unless separately qualified; deferred surfaces remain deferred. No unrelated
proposed specification is accepted by this decision.

The three jobs still need preregistered sealed correctness/cost evidence, a fixed adequate baseline,
zero treatment-only critical misses, zero false complete-evidence verdicts, independent review and
all required candidate-bound gates. Missing dimensions remain NOT_OBSERVED. No cost-reduction claim
is accepted here. Freeze the version/build and source before candidate-specific evidence. Tagging,
pushing, publication and formal promotion await approval of the exact qualified packet.

## Rollback

Before qualification retain `specified`/`UNPROVEN` rows and the prior published release. If a
compatibility or evidence gate fails, preserve the failing result and withhold promotion. Historical
`/0` ledgers remain readable; never relabel a failed run, move a public tag or rewrite archived proof.
