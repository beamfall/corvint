# Decision 0033 — the packet's lexical and sibling slots read a term table built with the index

Date: 2026-09-02. Status: accepted. Authority: repository owner, verbatim instruction "build the
term table, gate it with the probes" (2026-09-02), given on the slot timing that showed the two
slots scanning every source body once per task term (`docs/BUILD-LOG.md`, same date), and on the
owner's goal, "I want this to destroy the other tools in speed".

## What is decided

1. `Index` carries a `TermTable` (`internal/contextindex/termtable.go`): every readable source's
   lowercased camel-split tokens with occurrence counts, its identifier words as written, and its
   path's tokens, each inverted into flat sorted postings. `Build` and `BuildContext` build it with
   the other tables; the snapshot carries it; an index compiled without one builds it on first use.
2. The `lexical` slot counts a task term once for a source whose body holds it as a whole token
   and once for a path holding it, and its occurrences from the table, in the same order as before
   (distinct, occurrences, path). The `sibling` slot's identifier evidence is the weight of the
   task's identifiers present as whole words. Both are amendments to TCP-V0-004: a term matched
   any substring before and matches a token now. A term is a maximal ASCII alphanumeric run split
   where a lowercase letter meets an uppercase one, lowercased, at least two bytes; a word is a
   maximal ASCII word run of at least three bytes. The tokeniser is tested against the regex
   definition on synthetic texts and every Go file of the package.
3. The postings travel through gob as one fixed-width little-endian byte string
   (`termPostings.MarshalBinary`): gob's element-wise integer decoding of the 3.6 million
   postings of the Beamfall tree cost about 250 ms; the bulk copy is under 10 ms.

## What was measured

Offline gold placement (the real binary, each base commit checked out, limit 20), previous
binary against this one: beamfall-apple 68 to 70 gold rows in the top 20 (31 to 33 tasks with
any gold), corvint v2 242 to 244 (59 to 59), beamfall 95 to 98 (52 to 54). No set lost a row; the
gate the owner set is met. On the Beamfall checkout (3,233 files, 2,630 sources), unloaded, a
145-term review comment against `internal/plugin/plugin.go`: `context` with a snapshot 968 to
1,092 ms before, 111 to 122 ms after (ripgrep 43 to 53 ms on the same run); without a snapshot
1,287 to 1,366 ms before, 797 to 826 ms after; `index` 456 to 473 ms before, 873 to 1,018 ms after
(the table's inversion is single-threaded); the snapshot 44.3 MB before, 52.9 MB after. In-package
on that hit: `siblingRows` 545 ms to 5 ms, `lexicalRows` 360 ms to 1 ms, the packet 27 ms with
the co-change wait, the Git observation 30 ms, the decode 40 ms. The same twenty rows come back
in a different order.

## What is not decided

Whether the source bodies should stay in the snapshot's eager decode now that the two slots that
read every body no longer do (the flat memory-mapped encoding under the invariant 7 format gate
would make the 40 ms decode lazy); a parallel inversion for `index`; the model trial for this
change, which the offline probes gate but do not replace.

## Amendment 2026-09-14: symbol-window postings

`TermTable` also carries `SymbolWindows` (`internal/contextindex/symbolwindows.go`): the terms of
every non-test symbol's context window, inverted into ascending symbol positions as LEB128
deltas, so `evalRankSymbols` reads a symbol's context terms by walking the query's postings
instead of tokenising every window per query. Receipts are byte-identical by parity test; the
snapshot grows 2.6% (Corvint) to 6.8% (caddy). Measurements and the predeclared acceptance:
`docs/plans/symbol-window-table-2026-09-14.md`.
