# Decision 0585 — Verify a pinned CEM once per run; surface the obligation bound first

Date: 2026-10-27. Status: experimental under the standing lane auto-accept (V1-2894, V1-2893).
It adds `OCM-V0-027`, `OCM-V0-028` and `DCW-V0-377`, which amends `DCW-V0-025`.

## Context

Replaying the 583-path range `98b780811..ed70f3efb` after decision 0584 reached the OCM steps
and showed three problems.

1. Every OCM `prepare`, `status` and aggregate scope reran the full stable CEM verification of
   the same pinned map, about 51 s each. A 16-intent change spent about 28 minutes in the
   per-intent steps and 14 more in the aggregate, all verifying identical bytes.
2. Only after those 42 minutes did the aggregate refuse `too-many-obligations` (1,192 against the
   fixed 256-obligation bound, `OCM-V0-021`). The bound could have been computed from the intent
   blobs alone at the start.
3. `coordination-time-impact` was `NOT_PRODUCED` `context-abstention-invalid`. `corvint impact`
   correctly refused, but the `IDX-SNAP-V0-102` snapshot-miss notice put a second line before the
   refusal envelope, and the abstention validator required exactly one stderr line. The check
   rerun also compared stderr byte for byte, and the notice's millisecond value varies.

## Decision

1. **Run-scoped stable reuse (`OCM-V0-027`).** Within one `dogfood change` or `dogfood check`
   run, an accepted stable verdict is reused for the same exact CEM bytes, expected base, target,
   repository root and verifier executable digest. The run owns a private 0700 directory inside
   its temporary directory and passes it to its children through `CORVINT_OCM_STABLE_REUSE_DIR`,
   replacing any inherited value. The aggregate reuses verdicts in memory. Only ACCEPT verdicts
   are stored. Each reuse re-reads every declared artifact and requires the stored checks,
   because the artifact root is a mutable worktree. The verifier digest comes from the running
   image on Linux; elsewhere an executable file changed since the process started, as an
   install's rename onto it does, yields no digest and disables reuse. The OCM patch
   re-derivation still runs on every read. A changed digest, or any other key difference, triggers a full verification.
   `cem status` and the stable verifier itself are unchanged.
2. **Up-front obligation refusal (`OCM-V0-028`).** The 256-obligation aggregate bound stays fixed
   (`OCM-V0-023`: a refusal never widens a bound). `dogfood change` counts each listed intent's
   derived obligations from its blob at `HEAD` before any step runs, and before the previous
   evidence is cleared. Over the bound, it refuses with the same code, the per-scope shares and
   the `DCW-V0-346` fitting subset as its `fix:` line. The existing steps stay authoritative for
   everything the precheck cannot read.
3. **Snapshot notice in the impact abstention (`DCW-V0-377`).** Exactly one leading
   snapshot-miss notice line is admitted before the envelope. The check rerun compares stderr
   with that one line removed from both sides; every other byte stays exact.

## Rejected alternatives

- Scaling the obligation bound with the change, even opt-in. The aggregate map, its obligation
  rows and the subset search all grow with it, and `OCM-V0-023` and `docs/DOGFOOD.md` §5 fix the
  bounds. Surfacing the refusal in seconds with the exact narrowing removes the 40-minute wall
  without widening anything.
- Persisting verdicts across runs, or reusing them in `cem status`. Cross-run reuse needs its own
  invalidation and storage contract. `cem status` is the independent check of the map.
- Suppressing the snapshot notice for dogfood children. It is the operator's index hint, and the
  check must also accept evidence recorded by binaries that print it.

## Rollback

Revert the change. Every OCM read verifies in full again, the aggregate refuses
`too-many-obligations` only after the OCM steps, and the impact abstention needs one stderr line.
No stored state changes shape: the reuse directory is removed with each run.
