## User job and current boundary

An agent developing Corvint should use the applicable existing retrieval, impact, evidence, review,
verification and learning features rather than relying only on automatic prompt context. The
simpler baseline remains the existing dogfood workflow with task-specific manual CLI selection.
This slice makes that selection discoverable; it does not create another planner or require every
command on every task. Generic host skills use the shared guide only for Corvint or explicit local
adoption; unrelated repositories keep their own workflow.

The qualified prior source `7d1297bae60081c3023571683c2a4fe4dbcc29ab` already supplies native local
completion, CEM/OCM binding and the feature families. Help lacked feature/eval topics despite their
production dispatchers, and prove prose contradicted its separate committed-range mode. The
current change repairs discovery and records actual route use, without adding language/platform,
profile, execution or closing-authority semantics. Compatibility remains FALLBACK.

## Non-goals and trust boundary

No feature-count target, universal runner, strict LCP schema change, new ledger/database, service,
protected principal, signing key or automatic command fanout. No sealed evaluation input, transcript
collection, silent trace migration, fabricated provider attachment, authority promotion or guaranteed
future model adoption. Existing root/key, full-frame/privacy, optional execution and cleanup contracts
remain controlling. Feature routes preserve failed, unknown, withheld and unavailable observations.
The lane procedure (`ASD-V0-013..020`, `ASD-V0-024..026`, `ASD-V0-028..032`) is operator guidance and helper scripts: the tested-tree identity is a printed label, not a signed or retained record, the background rule is a heuristic shell scan rather than a shell parser, and neither replaces the installed out-of-repository hook or the live lane wrapper; it adds no Tasks
store state, no daemon, no automatic lane stop and no product command, and its scripts are never
inputs to ranking, evidence or authority.
`ASD-V0-033..036` extend that procedure on the same terms: they edit no `.github/` file and install no Git hook. `ASD-V0-040..044` extend it on the same terms; `ASD-V0-042` reuses the existing gate ledger and adds none. `ASD-V0-050..053` extend it on the same terms; `ASD-V0-050` and `ASD-V0-051` only narrow what a based run executes, the batch's CI still runs every test, and a run without a base is unchanged.

## Failure and rollback

A missing guide in an unrelated repository is not an error. Unsupported command admission retains
its typed gap and uses original source/repository tools; it never calls a legacy runtime to invent
success. A valid open frontier is advisory, while malformed input remains a failure. Missing local
completion evidence blocks that enrolled gate under its existing policy, not under a new rule here.

Lane procedure failures are refusals, never silent success: `heavy.sh` refuses an invalid slot,
parallelism or retry value and an unusable lock directory (exit 2), and an unavailable offload runs
locally with a stderr line and a fallback-log entry, never silently; a remote without `timeout(1)` is
unavailable rather than unbounded, a remote whose reproduced tree differs from the local tree (different excludes or Git configuration) is unavailable (exit 97) and the command runs locally, never on a different tree; a failed remote temporary-directory setup is unavailable too; the subagent background rule fails closed on an unterminated quote and on arithmetic `&` (`$((a & b))`), and a `<<WORD` inside a quoted string can hide later lines from it (a known limit); and a remote command whose wrapper was killed runs on until
`HEAVY_REMOTE_TIMEOUT` (a known limit, not a cleanup); `dogfood-finish.sh` refuses missing or
unusable inputs before building; `lane-idle-check.sh` refuses a missing path and reports a lane with
no readable activity as `UNKNOWN` (flagged); `lane-clean.sh` refuses an unavailable reference ref
and keeps any checkout it cannot read, with the reason. A stale shared repository makes merged
checkouts look unmerged (kept), never the reverse. `go-cache-trim.sh` refuses invalid arguments
(exit 2), never touches a directory without Go's cache marker, and keeps every work directory when
the process list is unreadable; a trimmed entry is only a later cache miss. `scratch-sweep.sh` keeps
anything it cannot inspect or archive, with the reason, and never removes unfinished Git work
without an archive.

`batch-regen.sh` refuses tracked changes (exit 2) and stops at the first failing step with nothing committed. `batch-precheck.sh` fails, never skips, a `doc-gates` command it cannot run, a drift package that runs no test, and a mechanical repin that changes a committed file; a run that is not clean and unmoved writes no receipt, and the push guard refuses a missing, malformed or stale receipt.
