## User job and current boundary

An agent developing Corvint should use the applicable existing retrieval, impact, evidence, review,
verification and learning features rather than relying only on automatic prompt context. The
simpler baseline remains the existing dogfood workflow with task-specific manual CLI selection.
This slice makes that selection discoverable; it does not create another planner or require every
command on every task. Generic host skills use the shared guide only for Corvint or explicit local
adoption; unrelated repositories keep their own workflow.

The qualified prior source `7d1297bae60081c3023571683c2a4fe4dbcc29ab` already supplies native local
completion, CEM/OCM binding and the feature families. Help lacked feature/eval topics despite their
production dispatchers, and prove prose contradicted its separate committed-range mode. The
current change repairs discovery and records actual route use, without adding language/platform,
profile, execution or closing-authority semantics. Compatibility remains FALLBACK.

- `ASD-V0-021`: (accepted under the owner's standing auto-accept (2026-10-11); V1-0360) `script/go-cache-trim.sh` (`make go-cache-trim`) bounds Go build caches and removes stale `go-build*` work directories, as a dry run unless `--apply` is given. It trims only directories that hold Go's cache README marker (by default `go env GOCACHE`, `/tmp/corvint-go-build-cache` and `/tmp/corvint-work-queue-gocache-<uid>`), deleting entry files in the two-hex-digit subdirectories oldest first, never one younger than `--min-age-hours` (default 2), until the entry bytes are at most `--max-gib` (default 20). It removes a `go-build*` directory directly under a temp root (default `$TMPDIR` and `/tmp`) only when it is older than `--work-age-hours` (default 24) and no running process names it; an unreadable process list keeps them all. Work directories are read NUL-delimited and a name holding a newline is kept; a cache entry name holding a newline is never listed. Under `--apply` the process list is re-read immediately before each removal; a process that starts after that check is not seen (a stated limit, not a closed race). Every candidate is reported (`KEEP`, `WOULD-TRIM`/`TRIMMED`, `WOULD-REMOVE`/`REMOVED`) with a `SUMMARY` of bytes, counts and free disk before and after.

A checkout with uncommitted, untracked, stashed or unpushed work is kept unless `--archive DIR` is given, in which case `status.txt`, `staged.patch` (index against `HEAD`), `worktree.patch` (working tree against the index), `untracked.list`, `untracked.tgz` and a `repo.bundle` of the commits not on a remote are written first and any failed step keeps it. The archive directory is created only under `--apply`. Under `--apply` the in-use, recency and Git-state checks are repeated immediately before archiving and before removal, and a change keeps the candidate (`changed`); a process that starts after that last check is not seen (a stated limit, not a closed race). Status reads take no optional locks. It reports each decision and a `SUMMARY` of counts and free disk before and after.
- `ASD-V0-023`: (accepted under the owner's standing auto-accept (2026-10-11); V1-1725) `script/pre-push-windows-vet.sh` is an installable Git pre-push hook. For each pushed ref that is not a deletion it diffs `<remote sha>..<local sha>` (or the merge base with `origin/main` for a new ref or a remote sha the clone lacks; no base counts as a Go change) over `*.go`, `go.mod` and `go.sum`; when any ref changed Go it runs `make windows-vet` once and refuses the push (`windows-vet-failed`) when it fails. Because the vet reads the working tree, it refuses (`windows-vet-not-run`) a Go-changing ref whose commit (an annotated tag is peeled) is not the checked-out `HEAD`, a tree with uncommitted Go changes, or untracked (including ignored) Go files. A push that changes no Go input runs nothing. Installing the hook is the operator's step (`docs/LANE-ORCHESTRATION.md` section 3).
- `ASD-V0-024`: (accepted under the owner's standing auto-accept (2026-10-11); V1-1953) `script/lane-guard.sh` is an installable Claude Code PreToolUse(Bash) hook that denies foreground polling loops (`until`/`while` with `sleep`, `for` over `seq`/`jot` with `sleep`, `tail -f | grep -m`) and `go test` not wrapped by a `heavy.sh` semaphore, while never matching heredoc bodies (`<<WORD`, `<<-WORD`, quoted or not; `<<<` stays a command), since they are file content. `LANE_GUARD_ROOTS` optionally scopes it to cwd prefixes and `LANE_GUARD_HEAVY` names the wrapper in the deny message; unparseable input is allowed and the hook always exits 0.
- `ASD-V0-025`: (accepted under the owner's standing auto-accept (2026-10-11); V1-1979) `script/install-local-bin.sh [--keep N] SOURCE DEST` installs a locally built executable by a sibling temporary copy renamed over `DEST` (never an in-place overwrite), keeps the replaced binary as `DEST.corvint-prev-<n>`, prunes all but the newest `N` (default 1) such backups, and `--rollback DEST` swaps the newest backup back in. It never prunes files outside that exact name pattern and refuses (exit 2) a missing source, a missing backup, a non-regular `DEST` or `--keep` below 1.

## Non-goals and trust boundary

No feature-count target, universal runner, strict LCP schema change, new ledger/database, service,
protected principal, signing key or automatic command fanout. No sealed evaluation input, transcript
collection, silent trace migration, fabricated provider attachment, authority promotion or guaranteed
future model adoption. Existing root/key, full-frame/privacy, optional execution and cleanup contracts
remain controlling. Feature routes preserve failed, unknown, withheld and unavailable observations.
The lane procedure (`ASD-V0-013..020`, `ASD-V0-024..025`) is operator guidance and helper scripts: it adds no Tasks
store state, no daemon, no automatic lane stop and no product command, and its scripts are never
inputs to ranking, evidence or authority.

## Failure and rollback

A missing guide in an unrelated repository is not an error. Unsupported command admission retains
its typed gap and uses original source/repository tools; it never calls a legacy runtime to invent
success. A valid open frontier is advisory, while malformed input remains a failure. Missing local
completion evidence blocks that enrolled gate under its existing policy, not under a new rule here.

Lane procedure failures are refusals, never silent success: `heavy.sh` refuses an invalid slot or
parallelism value and an unusable lock directory (exit 2); `dogfood-finish.sh` refuses missing or
unusable inputs before building; `lane-idle-check.sh` refuses a missing path and reports a lane with
no readable activity as `UNKNOWN` (flagged); `lane-clean.sh` refuses an unavailable reference ref
and keeps any checkout it cannot read, with the reason. A stale shared repository makes merged
checkouts look unmerged (kept), never the reverse. `go-cache-trim.sh` refuses invalid arguments
(exit 2), never touches a directory without Go's cache marker, and keeps every work directory when
the process list is unreadable; a trimmed entry is only a later cache miss. `scratch-sweep.sh` keeps
anything it cannot inspect or archive, with the reason, and never removes unfinished Git work
without an archive.

Roll back `ASD-V0-013..025` by reverting `docs/LANE-ORCHESTRATION.md`, the three lane scripts, the
`DOGFOOD_BASE` Makefile refusal, the GOOS filename check, `script/go-cache-trim.sh`, `script/scratch-sweep.sh`, `script/pre-push-windows-vet.sh`, `script/lane-guard.sh`, `script/install-local-bin.sh`, the
`dogfood-finish` input refusal and `lane-scripts-test` together; lanes then return to charter-only
procedure. Rollback the guide, links, skill routing and help fixes together; retain existing local completion,
old outcomes and failed evidence. Future feature changes update their guide route and relevant
witness in the same change. Delivery may become implemented only after the in-scope checks, real
task evidence and independent review pass. Usefulness, token savings, formal FULL and protected
runner acceptance have separate gates and are not claimed by this status.
