## Requirements

- `ASD-V0-566`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4175; refines `ASD-V0-997`) The flow-guide check MUST read a shell `refuse "..."` message to its closing double quote under shell quoting: a backslash escapes the next character, and a `$( ... )` command substitution or a backquoted command inside the message opens a new quoting context, so `refuse "code $(git -C "$dir" status) (fix: ...)"` yields the whole message, with its hint, rather than stopping at the inner quote. An unterminated message yields no site.
- `ASD-V0-567`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4114, V1-3477) `make dogfood-closeout` MUST run its five steps (the spec capacity and README checks, the repin of `ASD-V0-568`, the pre-flight, the lane-closeout batch-precheck and dogfood-finish) through `closeout_step`, which prints `dogfood-closeout: step N/5 NAME ok after Ss` for a passing step and, for a failing one, `dogfood-closeout: FAILED step N/5 NAME rc=RC after Ss` followed by `resume: make dogfood-closeout CLOSEOUT_FROM=N` with the same BASE, SEAL (a `SEAL=0` run keeps `SEAL=0` after BASE, as `DTL-V0-004` requires of every rerun hint; another given value is kept quoted), CITATIONS, INTENTS, VERIFY and OUTCOME, then exits with the step's status. The resume line MUST be printed as one literal string (`printf '%s\n'` with the whole command single-quoted as one argument), so the shell neither ends it at a double quote in a value nor runs a backtick in one. `CLOSEOUT_FROM=N` MUST skip the steps before N, printing one `skipped` line each, so a closeout cut by a foreground time limit resumes at the step that stopped. The sealed-head batch-precheck stays its own command, `make dogfood-closeout-precheck` (DCW-V0-923), which the closeout names last.
- `ASD-V0-568`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4101) The closeout's repin step (`script/dogfood-closeout-repin.sh BASE CITATIONS`) MUST run the repin command `make` passes as `DOGFOOD_CLOSEOUT_REGEN` (default `script/batch-regen.sh --mechanical`; unset or empty skips the step, so the script itself names no batch script) before the pre-flight and batch-precheck on a clean tracked tree, so the pre-flight's line-citation and use-case receipt checks see current pins and check the refreshed plan (review, 2026-11-06); when the repin is enabled, the step first runs the wrapper's missing-input refusal alone (`DOGFOOD_STATIC_PRECHECK=0`), so a closeout missing an input refuses before any repin or commit; when the repin changes tracked files it MUST commit exactly those files as `chore(repin): mechanical repin before the closeout (V1-4101)` and refresh CITATIONS with `corvint dogfood propose-citations --refresh CITATIONS BASE`, keeping the replaced plan as `CITATIONS.pre-repin`, so batch-precheck's own repin is a no-op and the bind sees rows for the repin's hunks. A failed repin MUST exit 1 with its output tail and a `fix:` line and commit nothing. Because the default repinner stages what it rewrites, the failure path MUST reset HEAD and the index to the starting commit and then check the tracked tree out of that index. A restore that fails MUST exit 1, naming that commit and its recovery; a tree with uncommitted tracked changes skips the step, so batch-precheck still names them. A non-mechanical citation failure keeps failing in `line-citations-check` with its own recovery.
- `ASD-V0-569`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3319) `make shell-test-register TEST=script/NAME_test.sh` (`script/register-shell-test.sh`) MUST register a shell test in the `Makefile` in one command: add the `NAME-test` rule and its `.PHONY` line when no recipe runs the file, and insert the target at its sorted place in `GATE_STEPS` (after the fixed first five) and in the `shell-test` prerequisites; a second run changes nothing, and it prints the unbounded-readers record (`docs/SHELL-TEST-REGISTRATION.md` item 3) as the next step. `make dogfood-inputs-check` MUST first print `hint: unregistered-shell-test FILE` naming the command and the doc for each `script/*_test.sh` added since BASE that no recipe runs or that either list omits.
- `ASD-V0-570`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3513) `go run ./tools/run-measure [--] COMMAND [ARG...]` MUST run one command with the caller's stdin, stdout, stderr and environment and then print one stderr line `run-measure: wall=S.SSSs peak_rss_kib=N rc=RC cmd=...`, where `peak_rss_kib` is the child's maximum resident set size from getrusage normalized to KiB on Linux and macOS (macOS reports bytes) or `unknown` where the platform reports none. It MUST exit with the command's code (128+N for a signal), 127 when the command cannot start and 2 for a usage error, so a lane host without `/usr/bin/time` or `bc` can still measure a run.
- `ASD-V0-571`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4167) `script/merge-drivers.sh` MUST list each custom merge driver `.gitattributes` names (`merge=NAME`, other than Git's built-in text, binary and union, and not in a comment) and exit 1 when the checkout's Git config lacks `merge.NAME.driver`, naming the fix, since an unset driver silently falls back to a text merge. `--install` MUST set each unset driver whose `script/merge-NAME.sh` exists to `script/merge-NAME.sh %O %A %B %L` in the local config, never overwriting a set driver; `script/lane-setup.sh` MUST run it for every new lane and refuse the lane when it fails. Exit 2 outside a checkout or on an unknown flag.
- `ASD-V0-573`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3461) `.corvint/agent-grep-exclude` MUST list, one Git glob per line, the generated and data paths kept out of agent searches (CEMs, ticket records, test corpora and results among them), and `script/agent-grep.sh` MUST run `git grep` with the caller's arguments and pathspec (default `.`) plus each glob excluded; `docs/AGENT-ROUTES.md` names both. `make long-lines-check` (`script/long-lines-check.sh`, in `doc-gates`) MUST fail, naming each file and its fix, when a tracked text file holds a line over 4096 bytes and is neither under an excluded glob nor listed by exact path in `.corvint/long-line-allow`. A scan that does not finish (the tracked-file list, a file read or the allow-list read fails) MUST exit 2 with the error and a `fix:` line, never print `ok`; a scan that finds no long line is not a failure.
- `ASD-V0-574`: (experimental under the standing lane auto-accept, 2026-11-01; V1-2178) `make py-signal-lint` (`tools/py-signal-lint`, in `doc-gates`) MUST fail, naming the file, line and handler, when a tracked `*.py` file's signal handler raises `InterruptedError`: a handler is a function named as the second argument of `signal.signal(...)`, whose indented body is read, or a lambda written there. Each `signal.signal(` call is read as one logical call through its matching closing parenthesis, so a registration split across lines counts; parentheses in strings and comments do not. String literal contents (triple-quoted docstrings among them) and comments are blanked before the registration, the handler's `def` and its `raise` are read (review, 2026-11-07), so a handler that only names `InterruptedError` in a string passes. Comments, unregistered functions and handlers that raise `SystemExit` or `KeyboardInterrupt` pass.
- `ASD-V0-575`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4139) `make mcp-tools-list-goldens` MUST rewrite every `internal/mcp/cli/testdata/tools-list-*.golden.jsonl` from the server's own `tools/list` response, by running the golden tests with `CORVINT_UPDATE_TOOLS_LIST_GOLDENS=1`, and then print `git status` for that directory. Without that variable the same tests MUST compare each golden byte for byte, name the target in a mismatch, and fail when a golden on disk is one they neither regenerate nor compare.
- `ASD-V0-576`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3390) `make changed-checks BASE=FULL_SHA` (`script/changed-checks.sh`) MUST run `line-citations-check` only when a changed path is Markdown or is cited as `` `PATH: `` in a tracked Markdown file, `unbounded-readers-check` whenever a changed path is not Markdown or a path was added or deleted (the ratchet rebuilds the affected graph from code in every indexed language and from the `.corvint` read declarations, so a Go test edit, a Go source edit or a read-scope declaration change can move it), and `test-read-scopes-check` only when a changed path is a Go test, that check's own inputs, or an added or deleted path; every check no changed path reaches MUST print a `skip` line naming it. It MUST exit 1 naming each failed check and 2 on a usage error. The `AGENTS.md` Verify section MUST declare it as a conditional check so `corvint affected` lists it.
- `ASD-V0-577`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3503) `make dogfood-inputs-check` MUST report, before any bind attempt, each citation-plan row whose cited span the candidate head no longer holds, as when a merge of main removes a cited requirement, naming the plan row, its path and its span as `cite-span-not-stable`, and MUST bind nothing. The DCW-V0-379 cite probe already does this for a span the change deletes; this requirement pins the removed-span case.
- `ASD-V0-578`: (experimental under the standing lane auto-accept, 2026-11-01; V1-4128; refines DCW-V0-353) When a code edit moves lines that unrelated specs cite, the `line-citations-check` fix line MUST name `make repin` first, as the one command for every mechanical repin (DCG-V0-801), and `script/check-line-citations.sh --repin` as the citation-only alternative, both of which stage what they rewrite. A citation whose cited text changed stays a failure for a reader to resolve.
- `ASD-V0-579`: (experimental under the standing lane auto-accept, 2026-11-01; V1-3489) `DOC_GATE_TARGETS` MUST include `no-python-runtime-dependency-test` and `qualify-tasks-basic-test`, so that every pull request's `make doc-gates` runs both script self-tests whatever the Go selection, and a Python interpreter call added to a script fails pull-request CI. The fixture in `script/check-bash32_test.sh` MUST spell its interpreter name so the no-Python check does not flag it. Non-goal: a macOS CI lane, which needs a `.github` change this lane cannot make.

## Boundaries and rollback

Only lane tooling scripts, their fixtures, Makefile targets and this contract change; no product
behavior or completion authority changes. Rollback reverts the scripts, tools, targets and fixtures
together and removes this spec's generated rows.
