# Design: `mcp-tool-table`

## Decisions

- Table location. The table is Go data in `internal/capcatalog` (extending `MCPTools()`), because
  both servers and the capability catalogue already import it. Each row holds: `name`, `server`,
  `inputSchema` (a path to the JSON schema under `protocol/` or the package that defines it),
  `outputProfile`, `errors` (closed list of typed codes), `availability`, `cliEquivalent` (the command
  that returns the same content, for PROD-DOCS-010 and PROD-TEST-009), and an optional `replaces`
  list of old names.
- "No MCP tool" rows. A row with `server: none` names a CLI answer that is deliberately not served,
  with a reason. Initial rows: every `corvint-tasks` command (R17). Rows for the feature map, review,
  the context brief and `how` are not decided (Open).
- Generated document. `docs/MCP-SERVER.md` is generated by a Make target from the table and checked
  for staleness in `doc-gates`, in the same way as `REQUIREMENTS.tsv`.
- Drift check. A Go test starts each server in-process, lists its registered tools and schemas, and
  fails if the list differs from the table rows for that server, in either direction.
- Server split.
  - `corvint mcp`: `impact`, `status`, `affected`, `test_evidence`, `test_validity`, the six flow
    report tools and `help`. The `docs` and `corpus` profiles are removed from
    `internal/mcp/cli/main.go`. A client that asks for them gets a typed refusal naming
    `corvint-docs mcp`.
  - `corvint-docs mcp`: the 20 `docs_*` corpus tools, `docs_draft`, `docs_consume` and `help`, served
    from `cmd/corvint-docs` through the same `internal/mcp` transport code.
- Naming. One convention: `corvint.<area>_<verb>` with underscores after the single dot, matching the
  majority of today's names. The six `corvint.flows.<x>` tools become `corvint.flows_<x>`. Whether
  the old names stay as aliases for one release is not decided (Open); if kept, they appear in
  `replaces` and are listed by the server as deprecated.
- `CORVINT_SELECTION` (R13). The `affected` tool reads the same variable and grammar as the CLI. An
  unknown value selects all tests and returns the reason `SELECTION_UNKNOWN_VALUE_FULL` (name to be
  aligned with the CLI code of PROD-TEST-013) instead of exiting 2, because an MCP call cannot
  return a process exit code to the user.
- Binaries. `corvint-mcp` and `corvint-test-validity-mcp` leave `binaries.json` in the removal batch
  that retires them (R14). Keeping `corvint-docs-mcp` as an alias for one release is not decided
  (Open).

## Failure modes

- A tool registered in code but missing from the table: the drift test fails.
- A table row with no registered tool: the drift test fails.
- A schema file edited without regenerating the document: the staleness check fails.
- A client configured for the old docs profile: it gets a typed refusal naming the new server, not an
  empty tool list.
- The two servers expose the same name: the table refuses duplicate names across servers.

## Acceptance evidence

- The drift test and the document staleness check passing.
- For each row with a `cliEquivalent`, a parity test that the tool and the command return the same
  records on one fixture (PROD-DOCS-010, PROD-TEST-009).
- `corvint mcp` tool list without any `docs_*` tool; `corvint-docs mcp` tool list with them.
- No tool whose name begins with `tasks` or `corvint.tasks` on either server.

## Rollback

- Restore the `docs` and `corpus` profiles in `internal/mcp/cli/main.go`; the table and generated
  document stay valid with those rows moved back to `corvint mcp`.
- Restore the `corvint.flows.<x>` names through `replaces` aliases.
- Restore removed binaries to `binaries.json` in a revert of the removal batch.
