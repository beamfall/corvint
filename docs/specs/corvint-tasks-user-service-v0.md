## Human intent and scope

The owner reports that killed long-running steward/helper loops stayed dead and a reboot would stop the program silently. The request is install/status/uninstall of per-user launchd/systemd units that keep the supervisor/dispatcher and optional registered helper loops alive, honor stop-file/drain semantics, preserve adopted workers across controller restart, and expose liveness in dispatch status. The reported two-minute keepalive workaround is context, not an installation target or specification of its undisclosed script/file paths.

The requirement IDs below, SERVICE500-001..011, retain the original proposal IDs. Independent plan review closed its restart-debt/legacy-control concerns and the lifetime-lock inversion; repaired pure models also passed independent review. Those are technical review results, not proof of integrated service behavior or platform testing.

The owner accepted this #500 intent as drafted on 2026-10-04. The acceptance holds within these limits:

- the service is an optional, operator-installed deployment profile;
- the default local product keeps no permanent daemon (agent contract invariant 7);
- deliveries are slices: the pure foundation first, then the local runtime slice recorded in Traceability;
- every real OS installation and platform qualification stays NOT_RUN and unclaimed until disposable Darwin/Linux evidence exists.

No test, installation or human signoff beyond that acceptance is invented here.

On 2026-10-04 the owner also deferred #500 platform qualification. The runtime slice ships with real launchd and systemd qualification NOT_RUN, and native ticket V1-0697 stays open until a disposable Darwin/Linux target exists. The deferral does not accept any SERVICE500-004, -005 or -010 platform witness.

This is an explicitly optional `taskman-user-service/0` deployment profile: the separately accepted profile that agent contract invariant 7 requires before anything outside the default boundary, here a manager-kept-alive process, may exist. It cannot silently broaden the local path. The default native-Go binary, foreground dispatch and ordinary installation remain daemon-free, and nothing enables the profile implicitly. The profile adds no index transport, encoding, database, network or hosted service, so the transport-neutral immutable index contract in [deployment-neutral index platform](deployment-neutral-index-platform-v0.md) is unchanged; a future profile that serves or synchronizes index data would need that contract's own descendant profile. Private deployment state is local derived/control evidence with no ticket authority and is not another Tasks queue. Managed main remains foreground and invokes the existing dispatcher in-process. It does not recursively spawn a second dispatcher. A helper cannot concurrently control the same program. Existing optional Codex supervision is not automatically enabled.

### Non-goals

No root/system service, elevation, network/account/database, enable-linger or login-policy mutation, host-wide logging changes, automatic existing-script migration, arbitrary shell/unit directives, restart of interactive agents, native ticket retry refund/unpark/reopen, physical-lane cleanup, hostile-process containment, or guarantee that processes survive reboot/logout. No persistent installation on an owner's active program is authorized by this profile's acceptance. Disposable same-user manager campaigns need their own exact resources and admission. Site-specific workaround compatibility requires its actual configured path/foreground semantics and qualification.

## Lock and wait graph

U is managed main/helper wrapper lifetime ownership; L is existing dispatcher lifetime ownership from OpenControlled to Close; F is the short shared control/launch fence; S is short record/ledger synchronization; O is management operation serialization. Allowed edges are U-main→L→F→S, U-helper→F→S and O→F→S. Controls never acquire U/L, Close/join, manager/helper completion or native reconciliation while F/S is held. Runtime outcome/join publication does not require O. Helpers never acquire L; no S→F or F→L/U/O edge. Main single-writer accounting releases S before admission enters F. Never hold F for a lifetime/tick or release it between final control read, checked intent, spawn and owned result publication. U-helper is the nonblocking per-helper `helper-<H>.lock`: a helper wrapper holds F from its final control read through the SPAWNING intent, spawn, descendant verification and the RUNNING acknowledgement, and releases F before any retirement wait; it takes F again only to record an outcome. Install/replace (O→F) saves STOPPED under F, releases it, and only then waits for helper trees to settle.

OpenControlled takes existing nonblocking L before F; suppression/unknown/pending refuses or idles without another dispatcher. Stop/drain publish under F/S, release before waiting, then reacquire and revalidate operation/revision/intent identities. Strong ACK means durable suppression and earlier intents committed/proved no-effect, not observed lifetime close; close status remains pending until actually observed. Drain CAS publishes STOPPED then joins/closes outside F. Resume records unfinished reconciliation as launch HOLD, releases F for owned retirement/intent observation, then revalidates CAS/pins/legacy and publishes only remaining resets/RUNNING. Completed replay does not reopen/reset later debt. Replacement/uninstall/rollback likewise suppress, release F before manager/shutdown/quiescence waits and reacquire for CAS journal steps. Runtime finalizers retain U/L until retirement-required transients join, with F only for bounded final records; workers retain adoption semantics.

A cmd.Start-success/identity-lookup-failure retains captured owned handle/session facts and Wait channel despite error; zero PID/nil channel or one signal is not no-effect/retirement. Post-spawn ledger/outcome save failure retains ambiguous intent and owned facts, preventing replacement/ACK until reconciled. Never signal identities reconstructed from a log. Timeout returns PENDING/UNKNOWN rather than successful stop/clean unlock. Concurrency fixtures must prove bounded successful progress, not merely both sides timing out.

## Traceability

The first delivery was the pure foundation in `internal/tasks/service` (profile.go, render.go). The runtime slice adds store.go (private registry under `$HOME/.local/state/corvint-tasks/service/<program>`: manifest, control, pulse, `operations/` journal capped at 256 records with the last 8 reserved for uninstall, a control request ledger of the most recent 256 request ids, flock), observe.go (descriptor-anchored no-follow file observation, owner/mode/ancestor checks), manager.go (`Manager` interface; `ExecManager` runs only `/bin/launchctl` or `/usr/bin/systemctl` with a minimal environment, 30s timeout and 64KiB output), lifecycle.go (install/replace/uninstall/stop/resume/status), run.go (managed main) and the CLI route in `internal/tasks/cli/service.go`. Witnesses inject a fake launchd/systemd manager and a temp HOME; no test runs launchctl or systemctl. Runtime limits of this slice:

- stop and drain are fenced. Every control write (stop, drain, resume, install bind, rollback restore, legacy latch, drain settlement) and every new worker launch or pool-sweep start of the managed main's dispatcher (`dispatch.OpenControlled`, which refuses a nil `LaunchControl`) takes F, `fence.lock` (flock, bounded 5s wait, LOCK_TIMEOUT). Admission (`LaunchControl.Admit`) requires a bound RUNNING control, an ABSENT legacy stop file and no unresolved launch intent, then saves the durable intent `launch-intent.json` (the effect's worker or sweep request id and the admitting dispatcher's random token, file and directory fsync) before the effect starts. An admitted launch holds F from that final control read through spawn and the saved worker record; the intent is removed before F is released only when the outcome is durable (in a ledger save whose rename and directory fsync both succeeded, or a launch failure proven before spawn). A save or directory-sync failure after spawn leaves it UNRESOLVED. A launch that started but whose start identity could not be read is uncertain, not failed: the group is killed, the dispatcher keeps its pid and wait channel, the intent stays UNRESOLVED and that dispatcher reports no recorded or settled boundary again, so a later successful save cannot resolve it. A cancel that arrives while F is awaited starts nothing. A retained STARTING or UNKNOWN pool sweep (native admission unproved) is replayed only under an admission; a PENDING one replays unfenced. So a stop that saves STOPPED or DRAINING orders after every admitted launch, and no later launch or sweep start is admitted. Stop answers ACKNOWLEDGED when suppression is durable, no launch intent is UNRESOLVED or UNKNOWN under the same F (the model's IntentStates), and the dispatcher owner is NOT_RUNNING or the fenced managed main (the owner lock's PID equals a fresh bound pulse's PID); otherwise PENDING. Its `close` field is OBSERVED only once STOPPED, no owner and no RUNNING pulse are observed, and PENDING otherwise. The main still re-reads control under F after `Open` takes dispatcher ownership and before `Run`;
- drain (`stop --drain`) applies only from RUNNING; otherwise it is RESOURCE_COLLISION. The managed main keeps the dispatcher open to supervise, heal and account while the fence refuses launches. Settlement is the dispatcher's tick boundary (`LaunchControl.Boundary`), never a poll of the saved ledger: only after an uncancelled tick has completed its accounting and its final ledger save, with no recorded worker, no pending or in-flight pool sweep and no unresolved launch intent, does it CAS-move DRAINING R to STOPPED R+1 under F, keeping the drain request. The dispatcher then ends with `ErrSettled` and the main closes it without a hold. A recorded boundary also resolves the same dispatcher's own unresolved intent. A main restarted during a drain reopens to supervise. Resume from DRAINING wins; resume from STOPPED needs no dispatcher owner. No deadline ends a drain;
- `legacyStopFile` is observed as SERVICE500-003 states (owned regular file PRESENT, verified ENOENT ABSENT, symlink, other owner, error or parent drift UNKNOWN) and `service status` reports it. Only the main latches RUNNING R to DRAINING R+1, with request `legacy-stop-r<R+1>`, at its poll or under the same F when an admission observes PRESENT, so removing the file before the next poll cannot lose the stop. Removing the file keeps the latch; UNKNOWN holds new opens and refuses admission; resume refuses PRESENT (RESOURCE_COLLISION) and UNKNOWN (UNCERTAIN_EFFECT);
- launch intent: `service status` reports `launchIntent` ABSENT, UNRESOLVED or UNKNOWN. When the main next opens a dispatcher (holding L, under F) it removes an intent left by an earlier dispatcher only if the saved ledger records that worker or sweep request id. Any other left intent stays UNRESOLVED: admission refuses, stop answers PENDING and a drain does not settle. Automatic reconciliation of an unrecorded intent (proving no orphan process) is not delivered; an operator verifies that no unrecorded worker tree or sweep remains and removes `launch-intent.json` from the service state root; this includes a post-start identity failure, whose descendants may have left the killed group. Pins are rechecked once per poll, not per launch. Legacy latch ids are not written to the control request ledger. An immediate stop or interrupt between the dispatcher's progress save and its accounting can still lose that tick's accounting (pre-existing dispatcher behavior); it cannot settle a drain;
- stop and resume replay through the control request ledger: a delayed retry of an older request answers `replayed: true` with the current control and never reapplies over a later change (a superseded stop answers SUPERSEDED). An id bound to any other request or journaled operation is REQUEST_ID_CONFLICT. Replay detection spans the most recent 256 control requests; an older id is treated as new;
- a NO_CHANGE install takes no journal slot; its id is kept in the request ledger. Installs refuse LIMIT_EXCEEDED at 248 journal records so uninstall always has headroom; finished records are never pruned, so a program past that cap needs a new program name;
- helpers (SERVICE500-007) run only on Linux; elsewhere install refuses a profile with helpers UNSUPPORTED, and `service run-helper` refuses UNSUPPORTED off Linux or for a manifest not bound to this program and helper. Each helper has its own unit (`<label>.helper-<H>`) whose command is `service run-helper --program P --manifest ABS --helper H`; argv and env come only from the bound manifest, and env is the helper's explicit env plus HOME, LANG, LC_ALL, LOGNAME, PATH, TZ, USER and XDG_RUNTIME_DIR from the wrapper. The nonblocking per-helper lock `helper-<H>.lock` admits one wrapper and a second refuses. The wrapper is a child subreaper (verified after setting) and refuses to spawn while it has any child. Under F it reads control, spawns only when RUNNING and eligible, writes the durable intent `helper-<H>.intent.json` SPAWNING, starts the helper in its own process group, verifies the leader's start identity and parentage, and only then acknowledges RUNNING in the intent and the record `helper-<H>.json` (8KiB bound). A start or verification failure retires the tree with no acknowledgement, and an interruption that arrives while the wrapper waits for F starts nothing. Stop treats an acknowledged RUNNING helper intent as a committed effect, but a SPAWNING or unreadable one seen under F as an unresolved launch, so it answers PENDING instead of ACKNOWLEDGED;
- helper retirement runs on DRAINING or STOPPED, on helper exit, on wrapper termination and on verification failure, always outside F. It stops the helper's process group through the #464 group owner (only Released proves the group), kills and reaps every reparented descendant, including one that left the group or session, and accepts only wait4 reporting ECHILD within 10s as proof that the tree is gone. Only then is the intent removed. An unproved retirement records HOLD and keeps the intent: no wrapper spawns that helper, a stop's close stays PENDING, resume and uninstall refuse UNCERTAIN_EFFECT, and install/replace rolls back (RESTORED) when a helper tree is not proved retired after STOPPED is saved. A wrapper that finds an existing intent at start, for example after its own SIGKILL, cannot prove the earlier tree retired and holds; an operator verifies that no process of that tree remains and removes the intent file. systemd `KillMode=control-group` covers a helper unit whose wrapper is killed. The wrapper starts no other children;
- helper restart debt is charged at runtime (SERVICE500-006): every helper exit, including exit 0, and every start or verification failure charges ChargeFailure on the helper record under F, keyed by spawn generation so a replay changes nothing. A settlement retry after its record was written only removes the intent and never rewrites the record, which a reconciled resume may own once the intent is gone; a settlement whose intent vanished before its record was written holds UNCERTAIN_EFFECT instead of writing. A stop racing an exit may over-charge one failure, never under-charge. Failures 1..5 back off 30/60/120/240/300s from the observed termination, measured by boot id plus boot-relative seconds; failure 6 records SERVICE_RESTART_HOLD; an unknown boot clock HOLDs without spawning. Helper debt has no health-based reset in this slice: only a reconciled `service resume` with every helper tree settled resets it, prunes its fences, raises its floor and reports `helperDebtReset`. Before any reset, resume durably writes `resume-operation.json` under F. It binds the request and its hash, the digest of the observed control, and the per-helper record digests before and after the reset, and it is removed after the control and ledger writes. A retry of the same request reconciles each record at its Before or After digest. A record at neither digest, or a changed control, refuses the retry with RESOURCE_COLLISION and keeps the newer debt. A different resume that finds an unfinished journal first records its request in the control ledger under a superseded marker hash, so a later retry of it is REQUEST_ID_CONFLICT and erases nothing. While a journal is unfinished, its request id is reserved for every service verb: stop, install and uninstall reusing it are REQUEST_ID_CONFLICT. Main-controller runtime restart debt remains NOT_OBSERVED and not charged;
- service logging is always on. The managed main's stderr diagnostics and each helper's stdout and stderr go to `logs/<unit>/<stream>.log` (mode 0600), which rotates to `<stream>.log.1`, so a stream retains at most two 8MiB files. Writers never block: each stream has a 64KiB pending buffer drained by one writer goroutine; bytes that do not fit are dropped and counted; a write error latches `LOG_IO_ERROR: ...` and its bytes are dropped and counted. Streams close concurrently; each waits at most 2s and counts pending and in-flight bytes as dropped, and a write that completes later changes no counter. One publisher goroutine writes the counters to `logs/<unit>/status.json` (4096B bound), so a stalled filesystem never blocks the supervision loop; close waits at most 2s for the final counters. Only the wrapper holding a helper's lock opens and publishes that helper's logs, and it keeps the lock until every log writer and the publisher have actually exited, so a successor never shares the files with late I/O. Each unit's `logs/<unit>` directory is created and pinned without following any symlink, and appends, rotation and status go through that pinned directory; log files are opened no-follow and nonblocking and must be private regular files, so a planted symlink or FIFO neither redirects nor blocks a writer or status. Before the final counters, the wrapper waits at most 2s for its pipe readers to forward what a retired tree wrote, then closes any pipe still held open (its unread bytes are not counted). Status reports written, dropped and ioError per stream and the byte count of a sanitized tail excerpt (4KiB bound); the excerpt text itself is withheld because log text is unscreened user output. Unit stdout and stderr stay /dev/null, and logging failure never blocks supervision;
- the managed main idles (STOPPED) or holds (pin/config drift, open failure with a 30s retry) instead of exiting, so the manager keepalive never becomes a restart loop;
- reinstall after uninstall keeps the retained STOPPED control until `service resume`;
- the install request hash binds the service profile bytes; a changed dispatch config under the same request id replays the original operation;
- every ROLLED_BACK install answers RESTORED (first attempt, the call completing a held rollback, and a replay), keeping the cause as the diagnostic. Rollback also restores the previous manifest, or removes a fresh install's manifest, when a commit renamed before its readback failed;
- systemd drop-ins are observed for the unit under the user root and `/etc`, `/run`, `/usr/local/lib` and `/usr/lib` `systemd/user`; type-wide drop-ins (such as `service.d`) and generator output are not observed;
- an install with an invalid profile is refused before the registry is created.

## Failure modes and dependencies

Missing/corrupt journal/control/source or observation outage produces UNKNOWN/HOLD, never absence/zero debt. Disk-full, file/directory fsync failure or response loss preserves exact original identity/publication uncertainty. Manager timeout/foreign registration/drop-in drift cannot authorize delete or guessed success. Pinned config/executable changes cannot silently adopt new bytes. Incomplete launch identity/descendant retirement prevents replacement/ACK; helper uncertainty never justifies killing preserved workers. Missing pulse/tick continuity cannot clear service HOLD. Log failure is visible and bounded; required accounting failure suppresses admission.

Concrete blockers are serialized shared dispatcher/CLI paths; actual #464 transient/helper cancellation/ownership proof; disposable Darwin/Linux manager/login/boot access for corresponding claims; shared terminal availability. The site's unspecified legacy file/script is a compatibility limit only, not a blocker for an explicit configured adapter. No older private aggregate lineage, imagined generic #464 interface or pure VERIFIED flag satisfies a dependency. Current public main must be refreshed before each later source integration.

## Rollback

Disable optional new launches by checked STOPPED suppression; release F before required owned helper/transient join/manager waits. Unregister only exact owned optional labels, verify absence, remove only unchanged generated unit/current-manifest bytes, and retain durable operation/control/debt/log/worker ledgers. Restore previous owned installation only under the same operation lineage and fresh safe target/domain facts, preserving suppression/debt. Unknown removal/restoration stays REMOVING/ROLLBACK_REQUIRED. Never recursively delete state, erase failure evidence, kill preserved workers, or promise host rollback/worker immortality. Default foreground dispatch remains available when ownership and pins agree. The first delivery added intent, catalog and an unreferenced pure package only. Reverting the runtime slice removes the `service` route and the `dispatch status` hook; it cannot unregister an installed unit, so an operator runs `service uninstall` before reverting, and retained registry state under `$HOME/.local/state/corvint-tasks/service/` is inert without the route. Reverting the fence, drain and legacy slice restores observed-boundary stop and the UNSUPPORTED refusals for drain and `legacyStopFile`. `fence.lock` and any `launch-intent.json` are then inert; an operator resolves an UNRESOLVED intent before reverting. The prior runtime idles on a retained DRAINING control, so an operator resumes or stops the program before reverting. Reverting the helper and logging slice restores the UNSUPPORTED helper refusal and removes `run-helper`; an operator first uninstalls (or replaces without helpers) any program with helpers so every helper tree is retired and no `helper-<H>.intent.json` remains. Retained `helper-*` files and `logs/` are then inert.
