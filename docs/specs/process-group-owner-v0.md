## Requirements

- `PGO-V0-001`: Own a process group through its unreaped leader; send at most one real group signal before reaping begins (a caller that sets `Primitives.RepeatKillWhileLive`, which the callers named in `PGO-V0-017` do, repeats it on each pre-reap observation of a live member, still while the leader is held unreaped) and never send a real numeric group signal after reaping begins. Scans and signal-0 probes confer no signal authority.
- `PGO-V0-002`: Preserve Darwin signal-0 quiet-first retirement. The Linux platform default is also quiet-first, with the PGO-V0-006 proof; ReapAfterSuccessfulSignal remains available only when a caller selects it explicitly. Preserve Linux signal failures, including ESRCH and EPERM, as failure evidence.
- `PGO-V0-003`: Check the original retirement allowance before new primitives and before accepting absence; intersect it with the fixed two-second post-reap cap. Retain terminal HOLD for unproved cleanup and late asynchronous reap completion. A post-reap HOLD reports the newest probe that completed inside the window (`PostReap`, `PostReapObserved`), even when the cap is noticed before the next check, and never a probe that completed after the cap (V1-2679).
- `PGO-V0-004`: Serialize concurrent Finish and Stop so signalling and reaping occur once. Refuse invalid modes and unsupported platforms before process creation.
- `PGO-V0-005`: Preserve existing Wait/Run and callers. Only RELEASED proves cleanup; HOLD must remain explicit and must not trigger a weaker fallback or success claim.
- `PGO-V0-006`: On Linux, where signal 0 succeeds for a group whose only members are zombies (including the owner's unreaped leader), the pre-reap quiet observation reads /proc instead of signalling. It runs only after the exit observation and the single group signal, while the leader is unreaped. It first identifies the leader as this process's exited child leading its own group, then reports quiet only when every process whose group is the leader is a zombie or dead with a status Threads count of one (task/ is not walked, because its ordinal enumeration can skip a surviving thread) and the scan saw the leader, and re-checks the leader identity. Each scan is bounded by a fixed entry count and stat and status sizes, and the retirement allowance is checked before and after it. It sends no signal and grants no signal authority. An unavailable or unreadable /proc, an identity mismatch, a malformed entry or an exceeded bound is a probe failure and HOLD; a live member keeps the owner polling until the allowance HOLDs. Release still requires post-reap signal-0 absence.
- `PGO-V0-007`: Proposed (V1-0608). `RunContained` runs a command as a group leader like `Run` and also retires owned descendants that escaped the group (for example a browser started with setsid). Ownership is structural only: members of the leader's group plus their descendants by parent link whose start time is not earlier than their parent's, read from the kernel process table (Darwin `kern.proc.all`, Linux `/proc/<pid>/stat`) while the exited leader is unreaped. The group is stopped; an escaped descendant is stopped or killed individually only while its parent is an owned process observed stopped, and one that leads its own session is killed with one group signal for that session-led group. A stopped parent does not hold its child's PID when it auto-reaps (SIGCHLD ignored or `SA_NOCLDWAIT`), so every individual signal is also pinned to the target's PID and start time: on Linux through a pidfd opened before the start time is rechecked (a session-group signal counts only if the pinned leader still exists afterwards, and a kernel without pidfds fails closed); on Darwin, which has no pidfd, by a fresh `kern.proc.pid` read just before the signal, leaving a residual window between that read and the signal. A changed start time is never signalled. On Linux a process counts as stopped only when every live task in `/proc/<pid>/task` is in a group stop (`T`); a tracing stop (`t`) or a partly stopped thread group is running, and a zombie leader with live threads takes its threads' state. Bounded run-time samples (every 200 ms, at most 4096 identities) record escaped identities while their ownership is structural; one that lost its owned parent before the sweep (a runner tearing down its worker, say) is SIGKILLed, deepest first, only while a fresh table and the pinned signal show the same PID and start time. That identity step runs before the leader is reaped, so an orphan holding inherited output cannot block the reap, and on Darwin it keeps the same residual window between the identity read and the signal. A new identity beyond the sample bound makes containment incomplete. After the group SIGKILL and reap, a signal-free observation bounded at two seconds checks retired and sampled identities by PID and start time. Containment is complete only with no error and no survivor; an unavailable table, a descendant that does not stop within two seconds, a signal failure or an unavailable leader exit observation is incomplete. `Run`, `Wait` and the Owner are unchanged.
- `PGO-V0-008`: Proposed (V1-0373, V1-0652). Where waitid is available (Darwin and Linux), no legacy helper or runner sends a numeric group signal after the leader may have been reaped. `Wait`, `Run` and `Drain` signal the group only while the exited leader is held unreaped; an exit observation that is a stop or continue report (Darwin `waitid` returns those for `WEXITED|WNOWAIT`, golang/go#19314) is not an exit. A failed exit observation (for example ECHILD after a foreign reaper) reaps without any group signal, so cleanup is then not proved; `RunContained` already reports that as incomplete. Early stops (`Contain`'s context cancellation and `Stop`) SIGKILL only the leader through `os.Process`, which refuses a leader it has reaped; the leader's exit then triggers the pre-reap sweep. `Drain` owns a command's non-file output pipes so the sweep follows the drain: a group member still holding a pipe past the delay is reported as `exec.ErrWaitDelay` (incomplete capture) and killed while the leader is unreaped, and context cancellation stops the leader at once and sweeps the group once its exit is observed. `WaitResidue` is `Wait` that also reports residue: whether a member other than the exited leader may still be live, decided by the owner's quiet proof (PGO-V0-006 on Linux; on Darwin signal 0, whose EPERM is accepted as quiet only when the process table shows a zombie-only group) while the leader is held unreaped and before the group signal; a failed proof or exit observation reports residue. Pre-reap signal errors stay non-fatal, so no previously working command is refused. Limits: platforms without waitid (not 1.0 platforms) keep the legacy post-reap signal; on Darwin `os.Process` has no pidfd, so a leader-only kill that races the reap keeps the same single-PID window as the standard library's default cancellation.
- `PGO-V0-009`: (accepted, decision 0492; V1-1036, V1-1047, V1-1050, V1-1056) Where waitid is available, no product code path sends a real numeric process-group signal to a group once its leader may have been reaped. A group signal is sent only while the exited leader is held unreaped, or as an early stop that signals the leader through `os.Process`. Specifically: (a) the task-store lease gate, `RunBatchCommand` and preflight kill their group in the pre-reap reap step and keep no group ID once `execute` has reaped; (b) the dashboard's Linux wait decides residue, cleanup and group quiescence before it allows the reap with the `PGO-V0-006` /proc proof itself (`groupreap.ProcGroupLive`: leader identity, status Threads counts, bounded reads, any failure reported as live), and its Darwin stop loop re-checks that the leader is still pinned before every signal-0 probe and every signal, so a failed exit observation ends all signalling; (c) the tasks doctor plugin and the work version probe run through `groupreap.Contain` and `groupreap.Run`, so their timeouts signal the leader only and the group is killed before the reap; (d) `groupreap.Run`, `RunRetiring`, `RunContained` and the work adapter runner start through the `AHI-048` live registry, so a group the command leads is recorded for the exit kill until the pre-reap release, and a start after `KillLive` is refused with `ErrExiting`. Retained post-reap observations are signal 0 only and fail closed: a reused group ID can only make the group look present, which refuses the command or reports cleanup unproved, never accepts it. They are the task-store pool's `CAL-V0-188` absence check, the release gate's `processGroupGone`, and the Owner's post-reap absence check (`PGO-V0-001`, `PGO-V0-003`). The supervisor's group check targets a recorded identity this process did not start and is outside this requirement. This requirement does not convert the retained observations to an ownership proof; that needs a `CAL-V0-188` amendment. Limits: `internal/liveverify/gorunner` `cleanupCommand` still sends a post-reap group SIGKILL and signal-0 poll under the go-live-test-provider contract and is a known gap; platforms without waitid keep the legacy post-reap signal (`PGO-V0-008`).

- `PGO-V0-010`: (accepted, decision 0507) POSIX descendant snapshots retain at most 4 MiB stdout and 16 KiB stderr per command; excess stderr is drained and discarded, with overflow retained as an error and no parsed identities returned, including when the command also fails. Command cancellation and the existing 100 ms pipe wait delay must still join the command and output-copy goroutines before return. Production ps argv, environment, PID/start representation, structural ownership and retirement semantics remain unchanged. A finite noisy-stderr fixture must demonstrate the boundary through the real command path, separately from V1-0689 cumulative identity-cap evidence.

Each case releases with exactly one group signal, sent before the reap, and no signal after it; anything unproved HOLDs. Darwin signal-0 EPERM cases (`TestWaitResidueDarwinDeniedLiveMemberIsResidue`) stay Darwin-only; their Linux counterpart is `TestLinuxOwnerHoldsWhileLiveMemberRemains`.
- `PGO-V0-012`: (accepted under the owner's standing auto-accept (2026-10-11); cem1-producer-harness-cleanup-20261001) The CEM stable verifier's owned Git subprocesses retire with bounded, ownership-safe cleanup on the paths that replaced the private stable-producer proof harness (`prove_historical.py`, 2026-10-01): the Core stable runner in `internal/cem/gitrun` through the Owner (`StartWith`, `Stop`, `FinishBounded`), and the portable verifier in `interop/cem01-go` through its own two-step `stableRetire`. No group signal follows the reap that ends identity ownership, and no wait is unbounded. A failed exit observation sends no group signal and no reap; a failed pre-reap quiet or identity proof sends no second signal and no reap. Both report HOLD (`ProcessContainment` in Core, `unsupported-process-containment` in the portable verifier), never a released or retired outcome, and the held runner starts no later operation. The new tests observe descendants with signal 0 only. Limits: on Darwin, signal-0 EPERM counts as quiet in both the Owner and the portable verifier, so a live member this process may not signal is reaped past and then reported as HOLD by the post-reap probe (which never sees ESRCH); the portable verifier has no kill/reap recording seam, so its signal-before-reap order is pinned by the code structure and the Core ledger test, not by a portable ordering test. - `PGO-V0-016`: (accepted under the owner's standing auto-accept (2026-10-11); V1-1244). In the `PGO-V0-006` /proc quiet proof, a zombie or dead group member whose status reports `Threads:` 0 has no remaining thread and counts like a member whose status vanished: it does not keep the group live and is not a probe failure. Linux prints a count of 0 when the task was released (reaped by its parent) between opening its status and reading its signal state, so the count says the member is gone, not that the read failed. A missing, malformed or negative count, an oversized status and every other `PGO-V0-006` failure stay probe failures, and a count above one stays live. The leader identity re-check and post-reap signal-0 absence are unchanged, so a released member's reused PID cannot prove quiet: a new process reports a count of at least one or a non-zombie state.

A test-injected host keeps the opt-in. Each opted-in caller has a fake-host test whose first pre-reap quiet proof is live and whose later proof is quiet only after a repeated signal and otherwise fails, so the test HOLDs and fails with the opt-in removed. Limits: a member that keeps forking faster than the repeats can still reach the bound and HOLD; the portable `interop/cem01-go` `stableRetire` is not an Owner caller and keeps its single signal; Linux runs of the new tests come from PR CI only.

## Non-goals and baseline

No lease/heartbeat implementation, dispatcher event changes, aggregate positive
event delivery, CEM promotion, legacy Wait/Run repair, escaped-session containment inside the Owner,
account-wide process management or release qualification. The /proc proof does
not reap or release zombie members that a non-reaping init or subreaper keeps
after the leader reap: post-reap absence is unobserved and the owner HOLDs. A
member hidden by a /proc hidepid mount cannot cause release either, because
release still needs post-reap ESRCH. The quiet proof, like Darwin signal 0, is
an observation of the group's members: a same-session process from outside the
group that joins it with setpgid after the single signal, or after the scan read
its entry, is not covered by it and can be followed by the reap; it is never
signalled, and the post-reap absence check HOLDs while it remains a member. PGO-V0-007 does not
retire an escaped descendant that was never sampled (one that escapes and is orphaned within one
sample interval), does not
cover processes whose start time is not monotonic with their parent's, does not close the Darwin
window between the identity read and the signal (no pidfd), and is not run on Linux by this host's
evidence. The simpler baseline is
the existing helper; it is retained but does not provide the new Owner contract.

## Trust boundary and failures

Only the owned live handle grants signal authority. Disk records, saved PIDs and
producer assertions grant none. Signal, observation, probe and reap failures keep
cleanup unproved. Expiration cannot be extended by retry or late success. An
unsupported platform refuses before spawn. The private test controller must own,
join and clean up its children even when interrupted; scans are observations only.
