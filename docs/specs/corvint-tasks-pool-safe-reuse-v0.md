## Requirements

- `PSR-V0-001`: Optional `memberConfig[MEMBER].safeReuse` adds operator-owned reset argv, verify argv/expected exit/literal stdout predicate, timeoutSeconds, maxAttempts and env settings to existing string-member pools. Existing policy without it is byte-identical and has no automated confirmation authority. Occupied member definitions remain immutable. No implicit shell invocation; operator may explicitly declare an interpreter argv.

- `PSR-V0-002`: `pool sweep [--member M] --request-id ID` is an OWNER/OPERATOR foreground mutation. It selects only currently QUARANTINED configured members in deterministic pool/member order; no ALLOCATED, PREPARING, CLEANING or unconfigured member executes a command. Selected allocations/definition digests are fixed before command ownership. No live store/environment runs during fixture qualification.

- `PSR-V0-003`: The writer durably records exclusive command ownership bound to original allocation, definition digest, canonical sweep request, phase/attempt, actor, source revision/tree and runner identity before executing outside the writer lock. Cleanup/reset/verify and all retries retain one durable sweep owner bound to canonical original request. Each phase receipt advances an expected predecessor-observation digest without clearing owner or exposing manual admission. Ordinary cleanup/manual confirm-safe and second sweeps refuse while owned; delegated confirmation consumes exact owner plus final successful predecessor, allocation and definition. Terminal failure/cancellation or explicit proved-orphan recovery releases owner only into quarantine. Pending replay never launches again; concurrent sweeps never both run reset. No unconditional free transition, successor allocation removal or replacement ownership.

- `PSR-V0-004`: Bounds: 1..900 seconds per member attempt, shared reset+verify deadline; maxAttempts 1..2 includes initial try. Optional existing cleanup executes first within the same deadline. A foreground invocation requires explicit `--timeout-seconds` 1..1800 total execution budget; bounded final group cleanup/receipt recording uses the existing writer timeout plus at most5 seconds group/pipe cleanup allowance, recorded separately; when exhausted, no new member/attempt launches and remaining members stay quarantined. Retry starts a new reset only after failed attempt evidence is durably recorded and owned descendants are proved gone. Cancellation/unknown cleanup/fencing are terminal, not retried. A failure does not reset ticket retry debt.

- `PSR-V0-005`: Verification: reset requires exit0 and proved group cleanup; then verify must exit `expectExit` (0..255) and stdout must contain the exact declared nonempty UTF-8 literal, with no regex/prose inference; stderr cannot satisfy stdout. Empty/overflow/incomplete output or source/config change cannot pass. Output bound is 64KiB total per phase; parser bounds for argv/env remain existing policy limits. Literal stdout contains is the requested predicate; no regex/equality alternative.

- `PSR-V0-006`: Preserve existing allowlisted environment names; optional `env:"file:PATH"` names an explicit operator-owned private regular file, relative to command repository or absolute outside it. This execution input is not project authority. Read once before durable sweep preparation (max64KiB, at most64 declared NAME=VALUE lines), using the existing bounded regular-file/symlink refusal and opened-descriptor identity check (`intent.ReadFile`), plus regular nonsymlink parent-chain checks and pre/post-read identity/size/modtime checks; do not follow path aliases or traversal components. Require private access (no group/other permission bits); this is a local safety constraint, not authenticated operator identity. Parser accepts literal NAME=VALUE split at first equals, UTF-8/no NUL, no interpolation/export/quoting execution; reject duplicates, undeclared names or missing required configured file. Capture ambient allowlisted values once, then overlay file values deterministically (file wins). Filter captured merged map separately for each phase's declared keys, including existing cleanup's subset; no phase inherits undeclared names. Snapshot bytes once and record SHA256 only; use that captured map for cleanup/reset/verify and retries, never reload it. Concurrent input change during read refuses SNAPSHOT_MOVED; later file replacement does not change this run's snapshot and cannot substitute values. Structured environment values are never policy, journal, status or request preimage bytes; operator commands may echo values into private captured logs, which are not claimed secret-free; exact in-memory environment digest plus file-snapshot digest binds execution. Missing-env behavior otherwise retains existing gateEnvironment semantics. No secrets are required in Git.

- `PSR-V0-007`: Retain each phase's exit code or explicit unknown/signal class, stdout/stderr digests, attempt index, times, match result, deadline/cancellation, group-clean result and predecessor-observation digest. Each canonical phase observation stays <=4096 bytes and binds sweep/request/allocation/definition/source/environment/file snapshot. Capture stdout/stderr separately under one combined64KiB cap; pack both byte streams in one canonical length-delimited binary log blob (32-bit big-endian stdout length, stdout bytes, then stderr bytes; max65540 bytes). Each phase records pool-state + observation evidence + log evidence + request, receipt and head; large pool state may add one afterimage blob: exactly6 artifacts for inline pool state, at most7 with pool blob, two gate/evidence POST paths, at most1 EVIDENCE afterimage. Existing StageLease limits are11 artifacts/2658 descriptor bytes and <=3 afterimage EVIDENCE slots; gate/evidence POST count<=2, no reservation/ticket posts, so no global cap increase. Logs use existing private native evidence publication, with creation mode0600 and no inline receipt/status/source/PR upload; observations retain only digest references. Existing archive export includes evidence when explicitly requested and must document that boundary. No automatic publication, new redaction framework or invented secret-screening guarantee. If private retention/encoding/publication fails, confirmation refuses and quarantine remains.

- `PSR-V0-008`: Only after reset+verify pass, evidence is durable and descendants are proved retired may the writer apply delegated confirm-safe against the exact original allocation/definition and successful observation. Operator's optional definition is prospective delegated attestation, so it explicitly amends CAL-V0-030. If existing cleanup is configured, run and record it first, require exit0/clean descendants, then reset and verify; no implicit substitution. Its command limit stays1..300 seconds and all phases share the member deadline. A failed cleanup prevents reset/verify and remains quarantined. On failure, interruption, unknown facts or stale identity, retain QUARANTINED and recorded reason/evidence; no FREE result claimed until queue readback agrees.

- `PSR-V0-009`: Canonical caller request identity includes member selector and explicit total budget, not mutable execution observations. Original-request replay lookup occurs before reading current source, member configuration, environment or env file, then precedes fresh eligibility. Same request returns original receipt/evidence even after successful freeing and successor allocation; changed meaningful request with same id conflicts. Child mutation IDs derive canonically from original request + original allocation + retry index + phase, never ambient time. A timed-out confirmation response is resolved by receipt lookup/readback before any retry; replay never frees a successor or reruns reset. Host death while command pending requires existing explicit orphan recover with runner identity check; sweep does not assume killed host cleaned physical resources.

- `PSR-V0-010`: Foreground CLI handler installs INT/TERM cancellation using signal.NotifyContext(writerContext(), os.Interrupt, syscall.SIGTERM), matching existing lease.go signal ownership, and defers stop so notification watcher retires. Runner execution uses absolute deadline, absolute helper executable /bin/ps and bounded subprocess probes: every PID/start/group observation gets remaining execution/cleanup budget, blocked probe becomes UNKNOWN. Cancellation joins watchers, kills/reaps owned process group and drains bounded pipes before absolute cleanup deadline and terminal evidence. Verify descendant retirement on normal return, timeout, INT and TERM. Unknown group state remains quarantined; detached/escaped processes and external services are explicit unqualified limits. New status only exposes evidence identities/reasons, and read commands remain probe-free. Dispatcher auto-sweep is separate opt-in glue after this contract is proven; no daemon/service lifecycle work here.

## Acceptance evidence

Initial fixture must initialize and canonically roundtrip policy/pool state, claim/release exact allocation and show QUARANTINED before fault injection. Positive reset+verify and optional cleanup-first produce bounded observation/log evidence, delegated confirmation and FREE readback; subsequent claim has fresh allocation. Exact replay after env deletion/current config change/successor allocation returns original evidence without execution. Barrier tests afterreset/beforeconfirm refuse competing sweep, ordinary cleanup and manual confirmation. Retry max2, combined deadline, total budget, exit/stdout/stderr predicates, overflow/source drift/private env syntax/permissions/symlinks/races, receipt publication failure and request conflict controls retain quarantine. Blocked identity/group probes are bounded. Actual foreground subprocess INT/TERM retirement observes PID/start identities and descendant absence; killed-host explicit recovery refuses live/unknown runner and retains quarantine. Large pool projection, descriptor/count maxima, duplicated evidence digest and archive evidence retention must be checked. All tests/runtimes currently NOT_RUN; Linux and physical external cleanup remain NOT_OBSERVED.
