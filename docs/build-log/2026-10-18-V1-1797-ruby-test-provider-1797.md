## Design

- The new `internal/rubytestprovider` package and the `corvint-ruby-test-provider rspec` command
  follow the JavaScript provider. One run prints one closed document, and `--retain` writes those
  same bytes through `testevidence.Retain` (`LPCV-V0-055`). `testvaliditydoc` recomputes every
  axis from the document's observations and never trusts a carried verdict.
- Git is observed on the host with `jstestprovider.ObserveTestRepositoryAtStart`, both before and
  after the run, and never through `--exec-prefix`. This is how a worktree whose `.git` file names
  a host path keeps its identity when RSpec runs in a container (#1130 acceptance 4). The test
  exercises this with a real `git worktree add` checkout and a prefix whose `git` exits 97.
- Freshness is bound to Git blob IDs of each example's spec file and of the conventional helper
  files (`spec/spec_helper.rb`, `spec/rails_helper.rb`, `spec/support/**`). The files are
  snapshotted before and after the run, so an edit during the run unbinds the example instead of
  binding stale bytes. The helper set is the files present on disk, not the files RSpec actually
  loaded. The document records this as `helperBasis: conventional-paths`, so a later slice that
  observes loading can change the basis without silently changing what the field means.
- Hygiene is `UNSUPPORTED` (`ruby-hygiene-not-produced`) and strength is `NOT_MEASURED`. Hygiene
  and strength belong to a later lane, which is why the PR uses `Refs`, not `Closes`.
- `.corvint/.gitignore` containing `*` is created by a small private function with `O_EXCL`, so an
  existing file is never overwritten. It runs before the report directory is used and before
  retention. Without it, the first retained run makes every later run start `dirty`. A mutation
  check confirmed the guard is needed: with the function disabled, the CLI test failed with
  `?? .corvint/test-evidence/...`. The JavaScript provider is unchanged, and a separate lane owns
  the shared helper.

## Evidence

- Focused tests pass for `internal/rubytestprovider`, `internal/testvaliditydoc`,
  `cmd/corvint-ruby-test-provider` and `conformance/mcp-test-validity-v0`. They use a fake `rspec`
  shell script that emits canned JSON. Ruby is not installed and is not required.
- `NOT_RUN`: a real RSpec run, a real `docker compose` prefix, and a non-root container writing
  `.corvint/rspec`.

## Residual limits

- JUnit output is retained as a digest only and is not parsed.
- Application source, `Gemfile.lock` and the Ruby runtime tuple are not freshness inputs.
- `ProjectBound` (the test plan path) reports Ruby freshness as `UNKNOWN`,
  `retained-blob-identity-not-compared`.
- The exec prefix must run in a working directory equal to `--dir`.
