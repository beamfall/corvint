  - Checker gap, recorded under AC2: check-line-citations scans docs only. It does not parse
    `file:N` citations in Go comments, so this form of drift is still uncaught.

  the hook deadline. Past that bound the hook abstains and leaves the build to the background
  refresh.
- **V1-3042 (FPK-V0-920).** Each suspected cause was tested separately:
  - Staged file in the caller's tree: ruled out. A regression test stages a file in the caller tree,
    and the verb still reads its own worktree.
  - Git deadline under load: inferred, not reproduced, because the host load of 127-198 could not be
    induced safely. The fix covers it anyway. A status read that outlasts its Git deadline now
    refuses with the typed `repository-probe-timeout` instead of the generic "cannot read the
    worktree status". A test pins this with an expired deadline.
- **V1-2683 (PRS-V1-920).** Every listed caller maps `testvaliditydoc.ErrPlatformUnsupported` to a
  typed platform-unsupported reason, and each caller has a test.
- **V1-2735 (AHI-921).** AC option 2 was chosen.
  - AHI-921 defines the user-prompt `packet_bytes` as the byte length of the compiled query receipt,
    and a test pins that definition.
  - Why the value itself was not changed: the frozen cli-parity-v0 python-oracle manifest pins it.
    TestGPKV0002ManifestReplay checks the harness-user-prompt stdoutSha256, so changing the value
    would break that frozen oracle.
- **V1-2741 (WQO-V0-920).** The adapter capture drain now counts only awake time.
  - Analysis: the old drain used a fixed wall-time timer after the reap. A host stall can deliver
    that timer's expiry in the same scheduling slice as the pipe EOF, which falsely reports
    `incomplete pipe capture`.
  - How the new drain works:
    - It samples a 25 ms ticker. Only gaps of at most 2 ticks count as awake time.
    - An open pipe is reported incomplete after 1 s of awake time.
    - A one-minute wall-time hang detector still applies.
    - Cancellation closes the pipes without an error.
  - A fake-clock unit suite pins each of those paths.
  - Bound change: the WQO-V0-034 escaped-holder test bound is now 3 s. That is still inside its 4 s
    guardian and well short of the 8 s holder.
  - Evidence: at a 250 ms idle budget, one loaded batch failed once, with the process awake. That
    suggests a real transient holder, probably a concurrently forked child that holds an inherited
    pipe write end until its exec closes CLOEXEC fds. This is an inference: an lsof-instrumented
    run of 14 passes never caught the holder. At 1 s, three loaded batches each passed 7 of 7, for
    21 of 21:
    - Command: `-count=7 -cpu=1 -run 'TestWorkFinalCheckCaptureBinding|TestWorkRunnerEscapedPipeHolder'`
    - Host load: 8-19.
    - Logs are kept in the lane scratchpad (v1-2741-loaded-{a,b,c}.log).
