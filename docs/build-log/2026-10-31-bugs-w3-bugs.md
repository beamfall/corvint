## V1-2615: a recorded anyOf branch, not a replaced node

Fork: rewrite `/$defs/criterionBinding` to the plain form, overlay a definition in the verifier,
or add the plain form as a second alternative. Decision: a second alternative (`CEM-V1-881`),
added by a new `cem-stable-regen --any-of --record` mode (`CEM-V1-880`). The sealed Tasks form stays
byte-identical as the first alternative, so every frozen case, cell and expectation stays valid;
the schema only admits more. The record names the predecessor node digest, so a branch added to a
node that moved since the record was written is refused, as are a repeated branch, an `anyOf`
beside another keyword, and a pointer that is not an object-schema member.

The run: packet manifest base `c3b7a8e6db645267b71f24e16a18f7f109e6050199f5591cf62d45efb5542d6f`;
record `tools/cem-stable-regen/testdata/v1-2615-any-of-record.json` (sha256
`d5abcdf74034dcf9bde6d9eeb5bf4d9cf00705d60e0a029051cd93247601e3b2`); node
`328958d8cce0eabc535794f407421543f7c954f4f3bcb2ab6f49b7f09a017e06` ->
`60a7761c4555bb7c17e8b56828fd81e78d77bcba20d85d34d80be5c2adee0a45`. Both schema copies are
identical; the structural tuples were re-pinned. `TestCEMV1622OpaqueReceiptResultValidates` now
validates the native plain-map result against both copies. Rollback is a Git revert of a41d3a601.
