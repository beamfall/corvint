# Affected plan spec split at the OCM obligation limit — V1-3429

Problem: the Requirements section of `docs/specs/affected-plan-v0.md` held 263 requirement
definitions, over the OCM bound of 256 (`maxObligations` in `internal/lrfrepo/ocm.go`). Every
change that named the spec as a dogfood intent refused at ocm-prepare with `too-many-obligations`,
and `corvint cem defer --intent docs/specs/affected-plan-v0.md` refused with "is not an intent
document". Lanes adding AFP-V0 requirements could not seal.

Decision: follow the owner's 2026-10-17 rule (recorded on the completed CAL-V0-073 re-home ticket)
to re-home requirements into a companion spec rather than raise the bound. One coherent domain
moved unchanged into `docs/specs/affected-plan-python-playwright-v0.md`, the non-Go frontiers of
the plan:

- Python adapter (experimental): AFP-V0-181 to AFP-V0-189, AFP-V0-680 to AFP-V0-682, with the
  inline Python non-goals and failure-mode paragraphs.
- Playwright environment inputs and TypeScript alias and config frontiers, Playwright dotenv inputs
  and grep-omission verification, Playwright frontier sites and tag-closure precision:
  AFP-V0-382 to AFP-V0-389, AFP-V0-404 to AFP-V0-414, AFP-V0-417 to AFP-V0-419,
  AFP-V0-423 to AFP-V0-426.
- Playwright declaration closure and the declaration path: AFP-V0-442, AFP-V0-443.
- Advisory pytest command: AFP-V0-472 to AFP-V0-477.
- The Playwright non-goals and failure-mode paragraphs for AFP-V0-382 to AFP-V0-389 and
  AFP-V0-404 to AFP-V0-413, and the 46 traceability rows.

Each moved heading stays in the parent with a prose stub pointing to the companion. The block under
the old Python heading that is not Python (AFP-V0-230 to AFP-V0-232, AFP-V0-201, AFP-V0-380,
AFP-V0-381, AFP-V0-400 to AFP-V0-403: base prefixes, directory paths, plugin path evidence) stays
in the parent under a new heading, "Range prefixes, directory paths and plugin path evidence".

IDs: the moved requirements keep their `AFP-V0` IDs; the companion declares
`Requirement prefix: AFP-V0`. Unlike the documentation-corpus split, which renamed prefixes and
tests, keeping IDs changes no test name, ticket, CEM, receipt or code comment.
`script/gen-spec-requirements.sh` maps each ID to whichever file defines it, its SRG-V0-547 check
still refuses an ID defined in two files, and the line-citations check resolves IDs through
`REQUIREMENTS.tsv`. New AFP-V0 IDs go in whichever of the two specs owns the domain.

Measured with `corvint cem defer` on a scratch clone whose map base held the change (the same
counter OCM uses): before, the parent refused with `too-many-obligations`, and the shell count of
definition lines in its Requirements section was 263. After, the parent reports
`obligationCount` 217 and the companion reports 46.

Rollback: move the sections, paragraphs and rows back to the stubs, delete the companion and run
`make spec-requirements`. No ID changed, so nothing else needs to change.
