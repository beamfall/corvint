# V1-1676: e2e-safe ceilings for large suites (issue 1079)

Ticket V1-1676, GitHub issue 1079. Requirements AFU-V1-065 and AFU-V1-066 in
[application-flow-understanding-v1](../specs/application-flow-understanding-v1.md), accepted under
the owner's standing auto-accept of lane requirements (2026-10-11). This is not a new owner
decision; it applies that standing acceptance to this lane's requirements.

## Decisions

- **Fixed ceilings, not configuration.** The issue allowed either raised bounds or a configurable
  bound under a ceiling. A fixed ceiling has one tested refusal and no new option, so the bounds
  become 16,384 tests, 65,536 paths per list and 131,072 coverage paths in total. Above them the
  closed `e2e-bound-exceeded` refusal is unchanged. The 5 MiB document bound still applies first.
- **Profile version `/0` to `/1`.** At the old shape every reviewed-links omission repeated its
  flow's link list, and every omission repeated the changed paths, so output grew with tests times
  links. `/1` states each distinct proof once in `proofs`, names it from each omission by digest
  (`sha256:` over the canonical JSON), and hoists `disjoint_from` to the top level. Selection
  itself is unchanged.
- **Linear evaluation.** Per-test link lookups, the dirty set, closure membership, the evidence
  diff per coverage commit and the reviewer's anchor facts are computed once and reused, so
  planning time no longer grows with tests times links.

## Review round

One independent Codex round on PR 1084 (head `6adc15a5d`) found four issues. All four were valid
and are fixed with tests that fail on the reviewed code (each was checked by reverting the fix):

1. **P1, proof digest covered `"digest":""`.** `addProof` hashed the struct encoding with an empty
   digest member, in struct field order, and the test repeated it. The digest is now over the
   canonical JSON of the proof with the member absent, keys sorted at every level (AFU-V1-066 now
   states the form). `runE2ESelection` recomputes every stated digest from the emitted `proofs`
   JSON alone, and `TestAFUV1066ProofDigestOmitsDigestMember` pins the canonical bytes.
2. **P1, unbounded evidence cache.** Each distinct coverage evidence commit kept its changed paths,
   set and unit map for the whole selection. The changed paths cached across evidence commits are
   now bounded at 131,072 (`MaxSelectionEvidencePaths`, specified in AFU-V1-065). The read that
   would pass it drops the cache and the selection refuses with `e2e-bound-exceeded` on
   `evidence-paths`; memoized reach answers stop caching at the same count. The per-commit
   changed-path slice is no longer kept. `TestAFUV1065EvidenceCacheBounded` (exactly 131,072 cached,
   then refusal) and `TestAFUV1065ReachMemoBounded`.
3. **P2, no per-list coverage ceiling.** One coverage tier's path list is now bounded at 65,536 on
   its own (`coverage-tier-paths`). `TestAFUV1065CoverageTierListCeiling`: 65,536 plans, 65,537
   refuses.
4. **P2, quadratic global matching.** `global` scanned every `global_paths` prefix per changed path.
   It now looks up the path and each prefix before one of its slashes in a set, which is exactly
   `under`'s semantics. The closure and evidence reach checks use the changed-path sets instead of
   `reach`'s linear membership scan. `TestAFUV1065GlobalPathMatchingScales`: 65,536 changed against
   65,536 global paths, brute-force semantics on planted edge cases, under 2 s (the reverted code
   took 59.6 s).
