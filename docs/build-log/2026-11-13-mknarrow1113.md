## What changed

- `affected.AttributeMakeEdit` (NCM-V1-011, NCM-V1-012) parses the make file at the base and at the
  head with the driver's own parser (`parseDriverMake`, AZU-V0-001). It adds no second parser. The
  parser gained three things: a flag for a rule that sits inside a conditional, a flag for a `::`
  rule, and the remainder positions of plain top-level assignments. The planner reads none of
  them. A changed line is attributable in two cases. It can lie inside an explicit rule's text,
  which selects that rule. Or it can be a plain assignment whose variable is used only in explicit
  rules' text or in other plain assignments; that variable is then followed to every rule that
  uses it. Every other remainder line is compared as text, so any change to one refuses with its
  kind (include, conditional, define, export, override, vpath, special target, default goal,
  computed target). Other edits also refuse, each with its named reason: a removed rule; a changed
  pattern, `::` or conditional rule; a global, built-in or exported variable; a variable that is
  unused or used outside every rule; a changed assignment that has effects; and any variable change
  in a file that names a variable by a computed reference.
- `affected.ReachMakeTargets` (NCM-V1-013, NCM-V1-014) follows the driver units forward from the
  changed targets through prerequisites and recipe make calls. It collects what the reached units
  run or read, and the workflows whose jobs invoke a changed target directly.
- `gateselect.makeEditAttribution` (`makeedit.go`) reads the head file from the root and the base
  blob with the hermetic `baseGit` (`ls-tree` and `cat-file`). It passes them to `Decide` as
  `Input.MakeEdit`. When the edit is attributable, the selector prints
  `noncode make-targets <path> -> <targets>`. It adds `make <pkg> <- <path>` for the packages the
  reach names, and `make-ci <pkg> <- <workflow>` for the readers of each such workflow. The make
  file's own rule (c), declared and unresolved readers stay as they are. Otherwise the verdict is
  `FALLBACK never-narrowed-path <path>: make edit: <why>`. `SelectQualified` now keeps `noncode`
  lines in its audit, so the CI selector and `corvint test` print the targets too.
- Only `Makefile`, `makefile` and `GNUmakefile` are attributed, at any depth. An included `*.mk`
  file stays never narrowed. `tools/gate-ledger`'s frozen selector fixture stubs `makeedit.go`, as
  it already stubs `recordadditions.go`.

### One design call: what "cannot be bounded" means for the reach

The charter asks for the units the changed rules "can run", and for everything when that cannot be
bounded. The driver marks a unit `driver:computed-invocation` in two different situations. In the
first, its commands or make goals did not resolve: the builder's `computed`, for example a command
word taken from a shell variable. In the second, its evaluated commands all resolved, but one of
them reads files the graph does not bound: an evaluated, uncertified site. A whole-tree read
(`PathGlobs /*`) is also a statement about reads.

Only the first situation leaves the run set unknown. The reach therefore refuses for unresolved
units, for unparsable files and for missing imports. It stays bounded for the read-only cases. To
avoid reading the diagnostic-only `reasons` map (AFP-V0-9620), `driverUnitsObserved` exposes the
builder's `computed` flag as its own output (`unresolved`). This is not a loosened charter rule.
The first cut refused every frontier unit, which turned out to be stricter than the charter asks,
and it moved no change.

Soundness for the Go product shard does not rest on the reach. CI runs `go test` directly, not
through make, so a Go test can depend on the Makefile only by reading it or by running `make`. The
tests in this repository that run `make` against the real Makefile all name it: `perf-budget`,
`test-commands-check`, `merge-drivers` and `ci-reuse-plan` are rule (c) readers, and the selector
keeps every rule (c) reader. `tools/str-parity` runs `make` only inside its own testdata clones.
The reach only adds packages, and `SelectQualified` may drop those again with an exclusion
certificate (AFP-V0-9500).

## Round 2: word lists, pattern instances and environment prefixes (NCM-V1-015 to NCM-V1-017)

Round 2 adds three rules. Each one is fail-closed, and no rule of round 1 was loosened.

- **NCM-V1-015, `makeWordListUse`.** It covers a changed plain variable whose value is a literal
  word list at the base and at the head: one `=`, `:=` or `::=` assignment, no `$` or backslash,
  the only assignment of the name. If every use of the variable is something make evaluates on
  the words alone, the variable selects its changed words. Two uses qualify:
  - a prerequisite-list reference in an explicit rule that is not a pattern, `::` or conditional
    rule, and that reads no `$^`, `$+`, `$<`, `$?` or `$|`;
  - a computed target line with literal prerequisites and no recipe.

  Each reference must be `$(V)` or `${V}`, or the last argument of an `addprefix`, `addsuffix` or
  `patsubst` call whose other arguments are literal. Every use must come after the assignment, and
  the file must not enable `.SECONDEXPANSION`. The edit also selects the computed line's literal
  prerequisites, because the changed words now run them. The owning rules (`gate`) go into
  `MakeEdit.Touched`: the reach does not follow them, but a workflow that invokes one counts for
  NCM-V1-014. Any other use leaves the variable to round 1's rules, and those refuse on the
  computed line. That includes a recipe, another variable's value, a conditional, `.PHONY`, an
  unevaluated function, a reordering that changes no word, and a non-literal or `$(shell)` value.
- **NCM-V1-016, `driverMakeFile.instance`.** A changed target that no explicit rule names
  (`ledger/hlq-local-test`) is followed in the reach through the one pattern rule that matches it,
  with `$@` and `$*` bound. The rule must have no prerequisites, must not be a `::` rule, and must
  pass the slash rule. Before this, `ledger/%`'s own unit expanded `$*` as unknown and imported
  every target of the file. The instance runs `tools/gate-ledger` and target `<word>`. Instances
  exist only when the reach asks for them (`driverRegistry.instances`), so the planner's units do
  not change: `TestReachMakeEditInstance_NCMV1016` asserts this.
- **NCM-V1-017, `driverInertPrefix`.** It covers a POSIX `NAME=value` directly in front of the
  command word, with no wrapper between them. Such an assignment no longer opens the reach's run
  set when two conditions hold:
  - the value is literal: no command substitution, backticks, parameter expansion, or make value
    the graph does not know, which includes a `$(shell)` result;
  - the name neither chooses nor loads the program: not `PATH`, `BASH_ENV`, `HOME`, `LD_*`, `GO*`,
    `GIT_*`, `NODE_*`, interpreter options and the like (`driverRunNames`, `driverRunPrefixes`).

  This lives in the existing scanner: `driverScan.envPrefix` sets `computed` without the new
  `runOpen`, and `driverUnitBuilder.runOpen` feeds the reach's `unresolved` map. `computed`, the
  frontier and AFP-V0-3128 do not change for the planner; `TestDriverEnvPrefix_NCMV1017` checks
  that the site keeps its frontier.

The driver's `makeUnits` loop body became the `build` closure, so a pattern instance reuses the same
unit construction. Merging a scan or the shared reasons now copies the reasons without calling
`markComputed`, which would set `runOpen`. `computed` is unchanged. The whole
`internal/liveverify/affected` package passes, and so does
`internal/liveverify/affected/liverepo`, which reads the real repository's driver units.

## Round 4: the followed-command rule is closed

The round 3 fix review (`~/lanes/mknarrow1113.review.md`, CHANGES_REQUIRED) found two more P1s in
`driverFollowed`. Both belong to one open-ended class: the reach certified arbitrary programs
together with their options.

1. `go -C . generate ./gen` took `.`, the first word without a dash, as the subcommand. That
   bypassed the generate refusal.
2. Every pure or bounded program passed whatever its options were. For example,
   `sort -S 1 --compress-program=script/check.sh data/lines.txt` runs a script.

The orchestrator directed that the class be closed, not the two cases patched. `driverFollowed`
(`internal/liveverify/affected/driver_shell.go`) now uses no program allowlist. It follows only:

- `go` whose first argument is `test`, `vet`, `build` or `list`, with no `-exec`, `-toolexec` or
  `-vettool` word (with one dash or two).
- `echo`, `printf`, `true`, `false`, `:`, `test`, `[`, `cd`, `exit`, and `set` with only `-e`, `-u`,
  `-x` and `-o pipefail`.

Everything else is open, including `sh -c`, `find`, every wrapper (`env`, `nice`, `timeout`,

orchestrator allowed. The driver's pure and bounded tables still drive read certification for the
