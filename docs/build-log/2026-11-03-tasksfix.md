# tasksfix: delivery-phase progress citations, per-commit reconcile runs, lane-host ticket reads

Base: `6f12f4704235dc8f9bea19fc12995bfb68c746c3` (`origin/main`). Tickets: V1-4448, V1-4449,
V1-4440 (with V1-4226). Requirements: `TCD-V0-2400`, `TCD-V0-2401` in
`docs/specs/corvint-tasks-closeout-debt-v0.md`; `ASD-V0-2420`, `ASD-V0-2421` in
`docs/specs/corvint-self-development-v0.md`. All are experimental under the standing lane
auto-accept.

## Decisions

- **Progress-head citation (V1-4448, TCD-V0-2400).** `ticket closeout-debt` cited a ticket's
  effective progress head at any phase, so a lane's dispatch base (`IN_PROGRESS`) read as delivery
  as soon as it was on the integration ref. Only the delivery phases (`DELIVERED_ON_BRANCH` and
  later) now cite. An `IN_PROGRESS` or `BLOCKED` head is reported in `excludedCandidates` with the
  reason `PROGRESS_IN_PROGRESS` or `PROGRESS_BLOCKED` and its commit. A message or PR citation of
  the same ticket still lists it. batch-delivered/batch-close `progressDelivery` already delivered
  no `IN_PROGRESS`/`BLOCKED` entry, so it is unchanged.
- **Reconcile runs export (V1-4449, TCD-V0-2401).** `script/tasks-reconcile.sh` exported the
  latest `RECONCILE_PRS*4` runs, so an older merge's green run fell out of the window and
  batch-close refused it. The export is now `gh run list --commit SHA` for each proposal's merge
  commit and PR head, merged with `jq -cs 'add | unique_by(.databaseId)'` into the retained
  `runs.json`. A failed per-commit export exits 2 and never leaves an empty file. A merge with no
  green run is still refused by batch-close.
- **Lane-host ticket reads (V1-4440, V1-4226; ASD-V0-2420, ASD-V0-2421).** Options considered: a
  new bundle verb that exports a per-lane ticket set, or reusing the existing verified queue
  snapshot (`CTS-V0-680`, `CORVINT_TASKS_SNAPSHOT`). Chose the snapshot: it already serves
  `ticket show/search/export/similar/digest`, verifies its tree digest and names its age, and needs
  no new wire format. `script/lane-dispatch.sh inputs` now stages `queue-snapshot.json` beside the
  ticket bodies (refusing `queue-snapshot-failed` on a failed or empty export). Its brief header
  names the read route (`Read any ticket: ...`) and the all-lane screen
  (`delivery-screen ... --lane-refs`, `--unaudited` without a journal). A journal-absent
  `ticket show` miss names the newest snapshot staged under `$HOME/lane-inputs` with its age and the
  exact retry, or the `script/lane-stage-inputs.sh` staging command when none is staged. The
  unaudited all-lane screen was observed to run in a journal-less clone; the audited form refuses
  there and names `--unaudited`. Out of scope: an ssh alias for one lane host that does not
  resolve on another (host configuration).
