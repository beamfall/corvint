## Delivered

- **V1-3844, V1-3595, V1-3673** (DCW-V0-840): every printed cite row, drafted or carried by
  `--refresh`, is judged by the `cem cite` span rule; a row cem cite would refuse, or one overlapping
  BASE lines a hunk removes, is printed unknown with the refusal named.
- **V1-3778** (DCW-V0-841): a new file is drafted from its BASE sibling (the file a test tests, then
  the same name in a sibling directory). Decisions: siblings never include a file the change
  modifies; the change-wide path-line admission covers only untouched files. Replay of the cmdcem-r
  lane: 51 to 27 unknown rows of 97.
- **V1-3814, V1-3791** (DCW-V0-842): `--refresh` across a new BASE re-pins carried rows without
  stale marks. Decision: a range re-key matches only within the same base.
- **V1-3502** (DCW-V0-843): `propose-citations --from-cem` seeds a reseal draft; the CEM's base is
  the prior base for re-pinning.
- **V1-3680** (DCW-V0-849): `dogfood change` and `propose-citations` refuse a BASE that is not an
  ancestor of HEAD. Decision: the ancestry check runs before `requireFreshWorktree`, so the refusal
  names the real cause.
- **V1-3836** (DCW-V0-848): `inputs-check` binds nothing and no longer requires `OUTCOME`. Decision
  kept: the preflight receipt key still includes the outcome, so an inputs-check without one is not
  reused by a later closeout.
- **V1-3613, V1-3671, V1-3672** (DCG-V0-840..842): `--repin` reports the citations it rewrote across
  every pass; the plain check reads HEAD's diff, so a surviving twin of deleted lines gets the
  restore-or-`--hash` hint and never a `--repin` suggestion; `--repin` prints each unresolved
  citation and exits 1. Callers affected by the exit code: `script/repin.sh` and the
  `citations`/`changed_citations` steps of `script/batch-regen.sh` now fail while citations remain.
- **V1-3511, V1-3694, V1-3833** (DCW-V0-847): a test or data hunk's requirement ID anchors only
  when the change's non-test edits or the tested BASE file name it; no test-file line is an anchor;
  a path line carrying requirement IDs must carry one the hunk names, which sets aside a
  neighbouring traceability row; the change-wide path admission no longer covers a line carrying
  another requirement's IDs. Set-aside candidates are named in the draft notes. The shared
  `check_tiers.go` call site changed only for the third return value; that path uses basenames
  and is unaffected.

## Friction

- The corvint MCP server failed with CONNECTION_CLOSED; the CLI was used instead.
- `corvint impact` builds the whole in-memory index for a small question.
- `self-binary-stale` needs a replay build before a lane can draft with its own changes.
- A frozen status header refuses a requirement edit with no hint that only the body may change.
- `propose-citations --base X` fails with a confusing invalid-local-completion-option; BASE is
  positional.
- WSL umask 0002 leaves `$TMPDIR` group-writable, which fails TestWorkMappingReproducedSelfDogfood
  until `chmod 755`.
- `heavy.sh` refuses a whole-package run without `HEAVY_WHOLE_REASON`, with no hint in the usage.
- Lane ticket JSON keys tickets as `ticket:corvint:main:V1-xxxx`; a lookup by the bare ID misses.
