## V1-2353: affected, init and overview swallowed Git's dubious-ownership refusal

- Problem: under a Git that refuses the repository for dubious ownership, `corvint affected`
  reported `unsupported-affected-revision` (no resolvable HEAD), `init` printed an `INVALID`
  inventory with an `invalid-repository` gap, and `overview` reported
  `unsupported-repository-guidance: invalid-repository`, instead of `GPK-V0-071`'s
  `repository-ownership-refused`.
- Root cause: `GPK-V0-071` classifies in `emitError`, which only sees Git's stderr when the error
  carries it. `affectedRevision` discarded the `rev-parse` stderr; the genesis repository reader
  collapses every Git failure to the bare code `invalid-repository`.
- Fix (`GPK-V0-089`): `affectedRevision` classifies its `exec.ExitError` stderr
  (`gitExitOwnershipRefusal`, `cmd/corvint/repository_ownership.go`); `init`/`adopt` on an `INVALID` inventory and the guidance verbs on
  any failure probe once with a hermetic `git rev-parse --git-dir` (`repositoryOwnershipRefusal`).
  The probe runs on the failure path only; the genesis receipt contract is unchanged.
- Evidence: `TestGPKV0071DubiousOwnershipIsOneCodedRefusal` subtests `affected`, `init`, `overview`
  FAIL with the three source files reverted and PASS with them (`-count=5`); the cmd/corvint
  `Init|Adopt|Activation|Guidance|Overview|Features|Review|Affected|Genesis|Ownership` subset passes.
- Rollback: remove the two helper calls; the helpers are unused otherwise.

## V1-2361: pool entry reasons could push pools.json past 1 MiB

- Problem: a `pool recover` reason of up to 4,096 bytes is copied into the QUARANTINED entry
  reason, so about 200 such entries fill the 1 MiB pools.json bound and every later pool write is
  refused `LIMIT_EXCEEDED`.
- Root cause: the only bound on entry reasons was the 4,096-byte prose bound shared with other
  verbs; nothing tied entry count x reason length to `MaxPoolStateBytes`.
- Fix (`PSR-V0-202`): `MaxPoolRecoverReasonBytes = 512`, enforced by the lease codec
  (`LIMIT_EXCEEDED` before planning). The longest composed entry reason is then 580 bytes.
- Evidence: `TestPSRV0202_FullSizePoolLongestReasonsStayBounded` (256 members, 254 QUARANTINED at
  the longest reason the codec admits, 1,280 receipts trimmed to 512, maximum identifier lengths)
  writes 730,154 of 1,048,576 bytes and still admits recovery, acquire and release; it and
  `TestPSRV0202_OverlongRecoverReasonRefusedTyped` FAIL with `lease.go` reverted. Whole
  `internal/tasks/transaction` passes.
- Rollback: restore the 4,096-byte recover bound; no recorded reason is rewritten.
