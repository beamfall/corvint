# Stock OpenCode integration qualification

The owner requested FULL OpenCode integration and rejected maintaining a fork. AHI-032 separates
native integration qualification from execution authority; legacy receipts and protected profiles
keep their existing meaning. The independent plan review approved this boundary with all latency,
recall and functional gates retained. No upstream OpenCode source was modified.

The earliest native proof on unmodified OpenCode 2.0.18 showed that its awaited prompt hook supplies
the current task’s receipt to the model. The host persists that augmented prompt normally; the
adapter writes no prompt files. A previous native completion probe queued one continuation but the
CLI exited before it completed, so enforced continuation remains unavailable.

Native iteration evidence passed query, exact source expansion, edit/evidence/verification/outcome,
advisory stop, real compaction and following-request recovery, direct installation/uninstallation,
environment filtering and interruption of an active child. The interruption exited 143 with no
live descendants. The final frozen campaign remains required before promotion.

The first implementation review found missing pre-run identity binding, cwd-sensitive binary
resolution, concurrent message deduplication, context-call cancellation, incomplete latency scope,
and detached-process cleanup gaps. Repairs bind identities before and after the campaign, resolve
binaries from the invocation root, reserve pending message identities, cancel session-owned context,
measure real native callbacks, and register/reap owned process groups. An already observed advisory
stop is allowed its existing two-second bound at normal shutdown; cancelling it immediately loses
the only completion observation the stock CLI exposes.

The declared recall task is narrowly “locate Add in add.go”: one critical declaration at a pinned
path/line. It compares bounded injected bytes against reading the complete named source file.
It does not measure task-solving quality or token savings. Provider usage is synthetic pressure
used to trigger actual host compaction and is never reported as measured token consumption.

Repository-wide make gate is NOT_RUN under the owner's scoped-issue preference. The affected plan's
broader unresolved scope stays visible in the retained scratch report; focused adapter/spec checks,
the native campaign and independent review are the selected completion evidence.

A final captured run failed the 250ms non-query limit at 361ms. The collector was timing its own
Python capture process in addition to the shipped adapter. Functional capture is retained, while a
separate real-host campaign now measures callbacks using the real Corvint executable directly.
The first direct campaign measured query p95 226ms and lifecycle p95 135ms. These are fixture
measurements, not a claim that load variability has been removed. The targeted review required
successful receipt-linked prompt delivery and zero adapter fault notices for those samples, so a
fast fail-open path cannot satisfy the performance gate. Executable paths are resolved identically
for both campaigns. Final promotion still depends on the frozen campaign's actual result.
