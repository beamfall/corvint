## Problem

Eighteen pre-1.0 CI tickets. After the in-flight screen, five had open work: a `ci:batched`
constituent showed a red required `go-product` (V1-2265); `interop/cem01-go` tests and vet ran
twice per run (V1-1103); release gates installed `ripgrep` from apt instead of the checksum-pinned
release that `ci.yml` uses (V1-1104); `doc-gates` in CI ran fewer checks than the lane charter's
local list (V1-0389); the VS Code extension had no CI job (V1-0437); and batch pull requests were
pushed once per constituent, cancelling CI runs (V1-2253).

## Decisions

- V1-2265, AFP-V0-027 amended: `go-product` passes with a `::notice::` and a step-summary line when
  the `pull_request` payload carries `ci:batched`, both `go-product-shard` and `go-static` were
  skipped and `doc-gates` passed. Every other skip, failure or cancellation still fails. The merge
  guard is the `main` ruleset's `merge_queue` rule (ruleset 23699808 read 2026-10-22: MERGE,
  ALLGREEN, build 3, merge 4): the `merge_group` run ignores the label and, with no AFP-V0-170 tree
  record for a skipped constituent, runs FULL. If the queue rule is removed, revert the amendment.
- V1-1103, AFP-V0-380: the module's `go test` and `go vet` run once, in `go-static` (which
  `go-product` needs); `go-interop` keeps `gofmt -l` and the Windows build, and its name stays in
  `static-reuse` (AFP-V0-080).
- V1-1104: release-gates Linux provisioning downloads ripgrep 15.2.0 musl with the SHA-256 that
  `ci.yml` pins, checks it with `sha256sum --check --strict`, and verifies the resolved path and
  version. macOS keeps Homebrew.
- V1-0389: CI `doc-gates` adds `traceability-tests-test`, `test-read-scopes-check` and
  `test-commands-check`, so it matches the charter's local list.
- V1-0437, VSC-V0-080: new path-filtered `.github/workflows/vscode-extension.yml` (not required),
  with read-only permissions, `persist-credentials: false` and SHA-pinned checkout and
  setup-node v7.0.0 (820762786026740c76f36085b0efc47a31fe5020). It runs `npm ci --ignore-scripts`,
  lint, typecheck and `npm test` when the extension, its spec, its conformance corpus or the
  query/impact, MCP or live test-provider sources change. The unit tests use fake executables, so
  a Go-side wire change is caught only where fixtures pin it.
- V1-2253, ASD-V0-027: `docs/LANE-ORCHESTRATION.md` section 8 sets one push after all merges and
  one per failure round, and gives the `gh run list` count of cancelled runs per batch.
