# Lane ghci2: port of lane ghci (V1-5098, V1-5099), V1-5258, V1-5349 and the V1-5097 proposal

Base: `b55635262788687c3eea9a08a94378e4ab8856a4` (origin/main, 2026-11-11). Every requirement
here (CIN-V0-8720 to CIN-V0-8723) is proposed, delivery experimental; nothing is accepted.
The five `2026-11-08-*` entries of lane ghci are carried over unchanged as history; this entry
records what the port changed.

## Port of lane ghci (CIN-V0-8720, CIN-V0-8721)

Lane ghci's change (branch `claude/ghci`, merge base `6339f980e`) was re-applied by hand on the
base, without its `.corvint/`, `docs/evidence/` or binding commits (decision 0594). Differences:

- The known-flake authorizer `known-flakes.py` is now read from the event base too, and run from a
  copy outside the tested tree. Lane ghci read the list from the event base (so criterion 1 held
  for the list) but ran the candidate's `known-flakes.py`, which the change under test could edit.
  The ported test commits a fixture list and authorizer, puts a permissive list and an
  always-forgiving authorizer in the worktree, and requires that neither counts; a base without
  the authorizer forgives nothing.
- The requirement headers say "proposed" instead of lane ghci's "owner-approved"; the charter
  gave no owner acceptance.
- `go-product.needs` was re-done on main's current list (no `host-adapters`, decision 0594).
- The pull request range may not mix `.github/` commits with others (ASD-V0-706), so the change
  lands in two halves, the code half first. Every new assertion that pins new workflow text lives
  in the Python tests under `.github/forward-rows/` (`.github` half). Lane ghci's Go additions
  that pinned new workflow text (`TestCINV08721IntegrityBeforeEarlyReturns`, the two new lines in
  `TestAFPV0441WorkflowBindings`, the exact new needs list) would fail on the intermediate tree, so
  they moved: the result matrix is now `test_CINV08721_result_matrix_before_every_early_return`,
  the authorization order is in `test_CINV08720_workflow_trust_and_registration`, and the exact
  needs list is in `test_CINV08721_workflow_dependencies_and_bindings`. The Go side only adds a
  successful `INTEGRITY_RESULT` to the go-product fixtures and accepts the needs list with or
  without the two new needs (`wantGoProductNeeds`), the same before-and-after idiom main uses for
  `cutJobs`; the old form should be dropped after the `.github` half lands.
- `TestCINV08423GuardClassifiesEveryInput_CINV08423` requires every `.github/forward-rows` file to
  be a named global input or mapped. The new files have no Go test consumer and `known-flakes.*`
  decide a shard's status, so they are global (`guardUnmappedInputs`); `github-guard.sh` is
  unchanged (an unlisted file is already global).
- Seed: `known-flakes.tsv` keeps lane ghci's two V1-4549 rows and expiry 2026-11-15 unchanged.
  Found while porting: `internal/tasks/cli` no longer exists on main, so the rows forgive no real
  test, and from 2026-11-15 the expired rows make `exceptions()` refuse the whole list, so no
  rerun is forgiven at all. Either way a fail-then-pass shard fails; renewal or replacement is the
  owner's decision.

## V1-5258 (CIN-V0-8722): `--accept-stale-binary`, not `-buildvcs=false`

`-buildvcs=false` would leave the planner without a Git stamp, which AFP-V0-846 does not judge, so
the plan would carry no degradation and the narrowing decision and its proof would not show that
`main`'s planner, not the tested tree's, chose the tests. The step keeps the stamp, passes
`--accept-stale-binary`, admits only `degradations` absent, empty or exactly `self-binary-stale`,
names it in the summary and writes `degraded` into the retained proof; anything else falls back.
Local probe (no index, so no line selection): `main`'s stamped `corvint` on a commit that edits
`internal/gateselect/select.go` exits 2 `self-binary-stale` without the flag and exits 0 with
`"degradations":["self-binary-stale"]` with it. The hosted run of criterion 4 is NOT_RUN.

## V1-5349 (CIN-V0-8723)

`main-miss.yml` gains `concurrency: main-miss-<failed head sha>` with `cancel-in-progress: false`
and `defaults.run.shell: bash`. `mainmiss-confirm.sh` (POSIX `sh`) reads packages one per line
from a file; the unconfirmed-package line follows the unchanged count line, so the existing
assertion on that line holds.
