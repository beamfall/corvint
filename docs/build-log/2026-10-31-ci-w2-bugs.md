## V1-3093: stale event base — ALREADY-DELIVERED (hosted NARROWED observation pending the bar)

Evidence on the base:

- AFP-V0-800..802 in `docs/specs/affected-plan-v0.md` (owner-accepted 2026-10-28) govern the
  fix. `effectivePRBase` in `tools/corvint-pr-tests/main.go` admits an event base older than the
  tested merge's parent 0 only when the merge has two parents, parent 1 is the event head, and
  the event base is an ancestor of parent 0. Each refusal is named (`pr-base-invalid-oid`,
  `-parents-unreadable`, `-parent-count`, `-head-mismatch`, `-not-ancestor`). `plan` then plans
  against parent 0 and records `EventBase` (AFP-V0-801).
- `.github/forward-rows/pr-base.sh` applies the same proof for the CI shadow step of
  `ci.yml`. That step is `continue-on-error`, so a refusal leaves the row incomplete, never
  narrowed. `.github/forward-rows/narrow.sh` takes the effective base from the driver selection
  only when `Reason` is empty and `EventBase`, `Head` and `Target` match the event. It uses that
  base for the shadow dry-run and for the no-renames `.github/` diff. A main-only `.github/`
  commit between the event base and parent 0 is therefore not attributed to the PR.
  `collect.sh` re-proves the parent and ownership through the API (AFP-V0-802).
- Tests pass at the base, run through `script/heavy.sh`:
  `go test -count=1 -run TestAFPV0800 ./tools/corvint-pr-tests/` ok (10.7 s), and
  `go test -count=1 -run 'TestAFPV0800ShadowBase|TestAFPV0098SupersetGuardSidecar|TestAFPV0047CollectorNamesRows|TestCINV000' ./tools/ci-forward-row/`
  ok (30.1 s). Between them they cover the stale base, main-only `.github/` commits and every
  named refusal (acceptance items 1 to 3).
- Hosted: in every 1.0-repository PR run inspected, the shadow plans against the tested merge's
  parent 0. Example: run 41119599587 (PR #11), with `PR_BASE`, shadow `base` and parent 0 of
  `eea518993` all equal to `fd51f53a2`, scope `NARROWED`. No inspected run had an event base that
  was a strict ancestor of parent 0. PR #14 opened before main moved, and its run 41152816353
  received `base.sha` `e00e20d2c`, already the new main. So the stale-base path has not been
  exercised by a hosted run of this repository.

Acceptance item 4 ("a real PR opened before main moved reports NARROWED") cannot be observed
