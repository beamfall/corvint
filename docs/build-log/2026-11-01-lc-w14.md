# Lane lc-w14: derived delivery lifecycle

Lane lc-w14 (WSL, git 2.53.0, Go 1.27.3, umask 0002), base origin/main
`e9a5d6c803cb0a1cce3d4eebf74ab1da84dcd4e1`, branch `claude/lane-lc-w14-1101`. The spec
[corvint-tasks-delivery-lifecycle-v0](../specs/corvint-tasks-delivery-lifecycle-v0.md)
(`TLC-V0-001` to `TLC-V0-012`, a new prefix) landed in its own commit before the code.

## Delivered

- **V1-3945**: `ticket show`, `ticket search`, `roadmap` and `release readiness` report a
  `lifecycle` object derived at read time (`internal/tasks/lifecycle`). It carries the state, a named
  reason, what it was derived from, and its evidence: status, hold IDs, the live attempt, the
  effective progress and the Git observation. `ticket search --lifecycle STATE` filters, and
  `facets.byLifecycle` counts every state. `release readiness` reports
  `memberCounts.byLifecycle`, and with `--lifecycle STATE` also `lifecycleMembers`. Delivery is
  recorded with the existing `ticket progress DELIVERED_ON_BRANCH`. The lifecycle checks it against
  Git: `AWAITING_INTEGRATION` while the head sits only on its branch, `AWAITING_CLOSEOUT` once the
  integration ref reaches it, and OPEN with `REF_DELETED`, `HEAD_NOT_ON_REF` or `COMMIT_MISSING`
  when Git does not confirm it.
- **V1-3856**, the overlap only: a delivered lane head is now visible before its batch lands, as
  `AWAITING_INTEGRATION` with the branch ref and commit, in show, search, roadmap and release
  readiness. Once integrated, closeout-debt lists it as a `progress-head` row
  (`TestTLCV0012_DeliveredThenIntegratedIsCloseoutDebt`).

## Not delivered

## Decisions

1. **Derived, not stored.** No new status and no record bytes. The value comes from the summary
   status, the record's holds and effective progress, the live attempts (`liveAttemptsByTicket`
   over one plan input) and one Git observation. Admission, planning, gates and completion never
   read it.
2. **A live attempt outranks progress.** Attempt receipts are runtime evidence; a progress mark is
   a principal's claim. Git checks a mark only for OPEN tickets with no live attempt, so the Git
   query set stays small.
3. **A journal-absent store reads UNKNOWN with `ATTEMPTS_NOT_OBSERVED`, never OPEN.** The one
   exception is a delivery that Git confirms. It stands because it does not depend on the receipts.
4. **Git is observed in batches, with a fixed process count:**
   - one `for-each-ref`;
   - one `cat-file --batch-check`;
   - one `rev-list --stdin` over the heads plus `^integration`;
   - one `log --source --stdin` over the distinct branch refs of the heads that are not integrated;
   - at most 16 `merge-base --is-ancestor` fallbacks, used only when a walk exceeds its 16 MiB
     output budget.

   Heads are restricted to hexadecimal, so stdin never carries a revision expression.
   `TestTLCV0006_ObservationIsBatched` covers 200 heads on 10 branches with at most 4 processes.
5. **Integration ref:** `refs/remotes/origin/<intentBranch>`, else `refs/heads/<intentBranch>`.
   Branch resolution, in order:
   - `refs/heads/B`;
   - `refs/remotes/origin/B`;
   - the only other remote-tracking `B`.

   No read fetches.
6. **Facets wire amendment.** The `CAL-V0-206` summary is a closed object in
   `internal/tasks/wire/facets.go`, so `byLifecycle` first decoded as MALFORMED. The decoder now
   admits it as the one optional member, closed over `wire.FacetLifecycles` and summing to
   `total`. `TestTLCV0001_Vocabulary` keeps that list equal to `lifecycle.States`. The amendment
   is recorded in `TLC-V0-009`, not in the leases spec, which is at its obligation limit.
7. **Release readiness reads the store twice.** `releaseRead` loads intent without the journal,
   so the lifecycle makes one more `withInventoryStore` read with `lazyClosed`. If that read fails,
   every member counts as UNKNOWN, with a warning; the readiness outcome does not change.

## Measurement

The measurement used the read-only WSL clone store: 2,463 ticket files, 713 OPEN, journal absent.
Each command ran five times, alternating the base binary and the lane binary, at host load 11 to
15. The medians are within noise:

| Command | Base | Lane |
| --- | --- | --- |
| `roadmap --limit 50` | 242 ms | 240 ms |
| `ticket search --status OPEN --count` | 244 ms | 252 ms |

That store has no journal and no delivered progress marks, so every row reads UNKNOWN with
`ATTEMPTS_NOT_OBSERVED` and no Git observation runs. The Git path's cost is covered by the
process-count test, not by this timing. Its timing on a store with a journal stays `NOT_OBSERVED`.

## Friction

- The corvint MCP plugin failed to connect (CONNECTION_CLOSED) for the whole session.
- `make dogfood-change` printed receipt instructions instead of writing the receipts; the lane
  ran the query and impact receipts by hand.
- `releaseRead` loads intent without the journal, so a readiness member that needs attempt
  receipts costs a second store read (decision 7).
- The 160-character limit on an Agent digest Claim shows up only when `make spec-requirements` runs.
  No authoring check or template states it.
- The closed facets decoder in `internal/tasks/wire` is not named in the `CAL-V0-206` route. Adding
  a facet member failed only at envelope decode in the CLI tests.
- `make spec-requirements` refuses unstaged specs, which adds an extra round after every spec edit.
- `heavy.sh` refuses a whole-package `go test` when affected reports UNKNOWN (here
  LANGUAGE_FRONTIER=78). The focused regression set had to be built by hand from test names.
- Commands nested in `ssh` quoting are fragile. An apostrophe inside a single-quoted remote command
  broke one patch halfway, so the patches moved to piped scripts.
- `TestCAPV0046HelpJSONIsTheTree` names the regeneration target, but a help-text edit gives no
  earlier sign that the catalog tree is now stale.
