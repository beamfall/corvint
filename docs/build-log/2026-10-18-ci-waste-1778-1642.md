## What changes

- AFP-V0-079: the two control-plane status jobs skip a cancelled `CI` run and share one
  concurrency group per event and head commit. `forward-rows` is unchanged.
- AFP-V0-080: a `static-reuse` job on a `main` push finds a passed merge-queue run of the same
  commit whose go-static, artifact-integrity and go-interop jobs all passed, and the push skips
  those three jobs. `go-product` accepts the skipped go-static only on that push.
- AFP-V0-081: a `ci:batched` constituent also skips go-interop, artifact-integrity,
  ci-shard-cost-drift and intake containment. doc-gates, docs-plan and the go-product failure
  stay.
- AFP-V0-082 (V1-0728): a push run is grouped by its commit, so the next merge no longer cancels
  it. Pull-request runs still cancel superseded runs.

Expected saving: about 13 runner-minutes per merge (push), about 12.5 per constituent push
(median; 15.9 mean), and about one control-plane runner slot in six. Push runs are no longer
cancelled; each now costs about 6 to 7 runner-minutes, most of it job start-up.

## Decisions

- **No ci:batched skip in `ci-control-plane.yml`.** `ci-control-plane` is a required status
  context, and the `workflow_run` payload has no labels, so no job-level condition can read the
  label. A skip inside the step would save the few seconds of the step and would add a timing
  dependency on the label. The job is kept, as the request allows when a status depends on it.
- **The merge queue still tests the exact tree in full.** Only the push, whose commit is the queue
  commit, takes the result. Pull-request and merge-queue runs never run the decision.
- **Fail closed.** The step is `continue-on-error`, and anything short of three passed latest jobs
  on the exact commit, in a successful run on a `gh-readonly-queue/main/` branch of this
  repository, leaves the jobs in full.
- **intake-containment push concurrency** has the same pattern as V1-0728 but costs one 27 s job.
  It is left unchanged and reported.
