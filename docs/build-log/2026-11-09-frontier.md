## What was wrong

Every plan on this tree was `UNKNOWN` with about 60 `LANGUAGE_FRONTIER` entries, 57 of them
TypeScript, whatever the dirty set. Measured with the lane build at `32140bb3b` for the Go-only
path `internal/sessiontest/balanced_test.go`: scope UNKNOWN, selected 198, unknown 59. Three
causes, each visible in `plan.frontierBearers`:

1. **Declared runtime callers made TypeScript take part on every plan.** `inboundRuntimeCallers`
   (AZU-V0-8902) seeded the three fixture Playwright suites of `.corvint/runtime-edges.json` with a
   `FRONTIER_SITE` witness on every code-bearing change and traversed their dependents, so they were
   followed, non-terminal selections; `participants` then counted TypeScript as taking part and
   AFP-V0-511 (3) raised all 57 plugin-wide entries as `PARTICIPATING_PLUGIN`. The 2026-11-05 entry
   (`2026-11-05-affected-unknown-frontier.md`) measured LANGUAGE_FRONTIER=1 to 3 on comparable
   plans; the cascade returned with the 2026-11-07 inbound-caller change.
2. **`release-gates.yml` was unparsable.** It reuses six setup steps through YAML anchors and
   aliases, which the driver's YAML subset rejected, so its fallback unit carried
   `driver:unparsable-file` and `driverSites` reached it on every plan with an unproven dirty path.
3. **The conformance e2e site had no declaration.** `typescript:e2e-runtime-dependency:conformance/
   interactive-alpha/fixture/e2e.spec.js` bore as a `CROSS_LANGUAGE_ENTRY` on every code change.

Once TypeScript does take part (a dirty TypeScript source), the plugin-wide frontier still bore in
full: 65 to 69 entries, 35 of them sites inside `testdata` fixture repositories no runner executes.
AZU-V0-003 (outbound site closure) and AZU-V0-008 (package-runnable fallback) were specified but not
implemented.

## The fix

- **AZU-V0-210** (`inbound_runtime.go`, `terminalWitness`): a declared runtime caller is selected
  for its tests alone, as a terminal `FRONTIER_SITE` selection; its dependents are not traversed and
  it does not make its plugin take part. Soundness is AFP-V0-560 (4): the declaration says what the
  caller's tests run, so none of the caller's own code changes. The plugin-wide TypeScript frontier
  now appears in `plan.frontierExcluded` (the non-scope diagnostic V1-4999 asks for).
- **AZU-V0-214** (`driver_workflow.go`): the driver YAML subset accepts `&name` on a sequence item
  or mapping value and `*name` in either position; an alias stands for the anchored node. Unknown
  or redefined anchors, aliases with trailing text, anchored aliases, merge keys and tags stay
  outside the subset. `release-gates.yml` parses into three jobs with their steps.
- **Declarations**: `.corvint/runtime-edges.json` declares `conformance/interactive-alpha/fixture/
  e2e.spec.js` runs `typescript:conformance/interactive-alpha/fixture/app/server.js` (the counter
  page it drives); `.corvint/shell-foreign-callers.json` declares the callers of the three scripts
  that read workflow YAML (`script/check-ci-least-privilege.sh`, `script/github-split-check.sh`,
  `.github/gate-reuse/find.sh`), with the caller and mention sets computed by the plugin's own
  completeness rule (`TestRepositoryShellForeignCallersComplete_TSP_V0_005`).
- **AZU-V0-212** (`frontier_closure.go`, `FrontierDirection`, `Result.FrontierSites`): a plugin
  classifies its reasons `OUTBOUND`, `DISCOVERY`, `INBOUND` or `PACKAGE_RUNNABLE` and records every
  located site so `reason:+N` entries are locatable (graph cache carries the record; the digest does
  not). When an `OUTBOUND` or `DISCOVERY` entry bears through participation or reach, the plan
  selects each site unit (`FRONTIER_SITE`), traverses its dependents, test users, command users,
  embedders and the readers of its files, and drops the entry at the fixed point. A `DISCOVERY`
  (executable configuration) entry stays when its file or a plugin path below its directory is
  dirty, which keeps `TestMochaConfigsAlwaysRetainDiscoveryFrontier` true. Unlocated sites, bare
  entries and `+N` entries without a record stay unknown. A plan with a path no plugin owns stays
  UNKNOWN whatever the frontier says, so the closure does nothing on it.
- **AZU-V0-211**: a participating plugin's entry whose sites lie in a hosted `testdata` fixture the
  change neither touches nor reaches (fixture root = the directory below `testdata`) is closed by the
  fixture's Go host: outright for source-bound and fixture-closed reasons, and for path-open reasons
  by selecting the host for its tests alone; reported in `frontierExcluded` under
  `HostedFixtureExclusionReason`. A dirty resolution input the plugin does not own turns the rule
  off (`steeredBy`; the previous `readsResolutionInput` treated every TypeScript source as an input).
- **AZU-V0-213**: `PACKAGE_RUNNABLE` entries select their runnable site unit (`RunnableUnit`) or stay
  unknown with the `NO_RUNNER` hint.
- **TJAA-V0-1161**: TypeScript declares `relative-import-unresolved`, `bare-import-undeclared`,
  `dynamic-import` OUTBOUND; `executable-config-unresolved` DISCOVERY; `runtime-flags-unresolved`,
  `test-runner-unknown` PACKAGE_RUNNABLE; `path-alias-unresolved` stays INBOUND because its site may
  be the resolution table (TJAA-V0-059). A configuration name needs a loadable extension, so
  `playwright.config.js.txt` fixture copies raise nothing (two sites gone). An alias a `paths`
  pattern claims but cannot map records its substituted targets as path tokens of the importer, so a
  dirty JSON imported through the alias selects the importer (V1-4683).
- **V1-5124** (`tools/affected-zero-unknown-replay`): the report and the per-merge line carry
  `unknownByCategory` (reason, or `LANGUAGE_FRONTIER <plugin>:<category>`).

## V1-5124

Delivered: per-category unknown counts in the replay report and per-merge line (criterion 3). Not
delivered: a safety producer. The checker (`safety`) accepts a receipt only with complete parent
and merge suite inventories and changed-line mutants whose killers it can compare, which requires a
full-suite run of this repository at each of 56 merge trees plus one per mutant; the lane rules forbid
whole-repository runs and the budget does not hold it. A producer that runs only the selected tests
cannot find a miss, so it would prove nothing. The report therefore still records `NOT_PRODUCED`
per merge, and AZU-V0-009 stays `NOT_ACCEPTED`.
