# V1-0632 S5b: Core stable bundle export

Date: 2026-10-11. Native work: V1-0632 slice S5b, migration row C10. Spec:
`docs/specs/cem-stable-v1.md`, section "Core stable bundle export (V1-0632 S5b)",
`CEM-V1-060..064` (proposed).

## Finding

Before this slice, `cem export` refused every `cem/1.0` map: its 0.x reader cannot parse one. The
0.x bundle (`corvint-receipt-bundle/0`) carries gate receipts, not the six role artifacts a stable
map binds, so a bundle cannot be verified offline anywhere else.

## Decisions

- The route is selected by `wire.DeclaresStable` over the map bytes, which is the same exact-spec
  selection S1 to S3 use. Every other map keeps the 0.x export path unchanged.
- Export verifies the source first and publishes only an ACCEPT. The bundle must then reproduce
  the source's complete verifier result from its own `artifacts/` directory, or it is removed. A
  refusal can therefore never become a published bundle.
- The bundle layout is `cem.json` (the exact map), `artifacts/<declared path>` and a canonical
  `manifest.json`. That layout is exactly what `cem verify-stable --map --artifacts` reads, so a
  moved bundle verifies through the existing hidden command and no import verb is needed. Adding
  a cem action would change `cemActionOrder` and the 0.x invalid-choice message bytes.
- Closure checks (missing, unused, escaping, digest, manifest, revision) are in the Go API
  `CollectStable` / `WriteStable` / `ReadStable` / `VerifyStable`. Later C11, C12 and C19 consumers
  can use that API instead of a second format.
- The caller root is admitted byte for byte as in `CEM-V1-017`: a relative root refuses at stage
  `arguments`. No repository is opened until the verifier has accepted; `gitauth.Open` is used
  afterwards only to apply the 0.x out-of-worktree output rule.
- `internal/cem/cli/cli.go` (C03 registration) gains only `--artifacts` in the export flag list and
  passes `callerRoot` to the `Export` hook. The edit is line-count neutral so line citations into
  that file stay valid.

## Evidence

- `corvint affected --base a8c05c4f4` (1.0.0-rc.3, build 407): empty plan at base, scope UNKNOWN.
  `corvint context "C10 stable cem/1.0 bundle export receiptbundle"`: exit 0, 20 of 23 candidates,
  no specific-term answerability. Both outputs were kept in lane notes.
- Positive: the public S0e sealed map exports with ACCEPT/EXACT on host go1.27.2. After
  `os.Rename` to another parent, `VerifyStable` and `cem verify-stable` over the moved bundle
  return results equal to the source (all 21 fields, exit 0). The bundled map and all six role
  artifacts, including the snapshot-head receipt, are byte-identical to the source.
- Controls: a stale base and a tampered artifact give REJECT with exit 1. An omitted artifact gives
  UNSUPPORTED with exit 2. In each case nothing is written. A tampered byte, an omitted file, an
  extra file or directory, a symlink, an inexact manifest and another target are all refused by the
  bundle reader with their own code.
- Focused tests: `internal/receiptbundle` ok; `internal/cem/...` ok; `cmd/corvint -run
  'CEM|Cem|Bundle|Export|Help'` ok; `go vet` clean on those packages.
- Review repair (Codex round 1, three P2 and one P3 on b08dce919):
  - `WriteStable` trusted the in-memory artifact paths and wrote through the output's parent root,
    so an altered `../../leaked` path left bytes beside the removed bundle. It now checks the exact
    map closure before creating anything and writes through a root opened on the new directory.
  - Entry opens used a blocking `root.Open` after `Lstat`, so a FIFO swapped in could hang the
    reader. They now use `O_NOFOLLOW|O_NONBLOCK` (the verifier's own precedent) and require the
    opened file to be the same regular file. Non-unix hosts fail closed.
  - `fs.WalkDir` read each directory whole before the entry bound applied. The walk now reads
    directories in batches of 64 and refuses once the bound is passed.
  - Refusal tests now compare the export's result with `verify.Stable` over the same inputs, and
    a CLI caller-root matrix compares `cem export` with `cem verify-stable` for each spelling.
- Review repair (Codex round 2, one P2 and one P3 on a6a70bc8b):
  - Go 1.27.2 `Root.OpenFile` resolves an in-root symlink even with `O_NOFOLLOW`, so an entry
    swapped for a symlink to an undeclared sibling after the walk could be read and admitted.
    Each read now re-checks that the name is still the same regular file, and `ReadStable` walks
    the tree again after all reads and refuses any difference. A nil-in-production test hook makes
    the swap deterministic.
  - The escaping-path write control also changed the artifact count, which masked the path check.
    The control is now split into escaping, duplicated and added cases.

## Limits

- Closure checks over a received bundle are API-only. `cem verify-stable` checks every declared
  artifact but does not refuse unused entries, and there is no CLI import verb.
- Witness, dogfood and gate receipts are not carried in a stable bundle (`--witness` refuses).
- The ACCEPT case needs an admitted structural tuple (go1.27.1 or go1.27.2). On any other runtime
  the positive tests skip as NOT_RUN, and export returns the verifier's runtime refusal with
  nothing written.
- Help is unchanged and the route stays hidden, as for the S1 read.
