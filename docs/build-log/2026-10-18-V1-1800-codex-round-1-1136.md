# 2026-10-18 V1-1800, V1-1801: Codex round 1 fixes on PR #1136

A single read-only Codex review of PR #1136 reported six findings. All six are fixed in this change,
each with a regression test. The amended requirement text stays under the owner's standing
auto-accept of lane requirements (2026-10-11). No requirement ID was added and there is no CAL-V0
change.

| Finding | Fix | Regression test |
|---|---|---|
| P1: a blocked tee sink (for example a stopped `--runner-output -` reader) held the drain goroutines past `Run`, and the shared lock held the other stream. | `internal/procgroup` gives the capture the bytes first, then queues a copy (at most 64 drain reads) for a per-stream forwarder. A sink that accepts nothing for one second ends that tee. `Run` waits at most two seconds for the forwarders after the drains. A sink that implements `procgroup.IncompleteTee` is told, and the CLI then prints `runner-output-incomplete`. The `jstestprovider` lock now blocks only forwarders. | `TestPWPV0028BlockedTeeSinkDoesNotHoldDrains`, `TestPWPV0028RunnerOutputReportsEarlyEnd` |
| P1: `--runner-output` followed a symlink and could truncate an unrelated file. A FIFO blocked the open. | On darwin and linux, PATH is opened `O_NOFOLLOW` and `O_NONBLOCK`, `fstat` requires a regular file, then `fchmod` and `ftruncate` run. Elsewhere, an `Lstat` and `Stat` check comes first. | `TestPWPV0028RunnerOutputRefusesSymlink`, `TestPWPV0028RunnerOutputRefusesFIFO` |
| P2: an existing log kept its `0644` mode. | `fchmod 0600` runs before the truncate. | `TestPWPV0028RunnerOutputExistingFileBecomes0600` |
| P2: an exit observed during the send dropped the stop signal that caused it. | The recorder reads `leaderGone` before the send. | `TestPWPV0029StopSignalSurvivesExitDuringSend` (deterministic: the fake send marks the exit) |
| P2: a directory or symlink `.gitignore` counted as protection. | A non-regular entry fails the retention. | `TestLPCVV0084NonRegularIgnoreIsRefused` |
| P2: a failed write left an empty `.gitignore` that later runs accepted. | A file the retention created but could not write is removed. An existing empty regular file is repaired. | `TestLPCVV0084FailedIgnoreWriteIsRemovedAndEmptyIsRepaired` |

`testevidence.IgnoreRetained(worktree, evidence *os.Root, createdCorvint bool) error` keeps its
signature, because the Ruby provider (#1135, V1-1811) converges on it.

The fix changes one behaviour: the two streams reach a shared sink in forwarding order, not in the
child's order. `TestPWPV0028ExternalConsoleOverBoundTruncatesAndTees` now checks containment, not
a suffix, and PWP-V0-028 states this.

Residual risks:

- A forwarder that stays blocked on a sink outlives `Run` until the sink returns. Its tee is marked
  incomplete, so later writes to the CLI sink return at once. At most one stuck forwarder per stream
  remains per process.
- `O_NOFOLLOW` covers only the final path component.
- The non-unix open checks the path and opens it in two separate steps.

Live Playwright qualification remains `NOT_RUN`.
