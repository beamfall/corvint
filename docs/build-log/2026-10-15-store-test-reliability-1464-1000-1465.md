# 2026-10-15 Tasks store/cli test reliability (V1-1464, V1-1000, V1-1465)

Base `a0b4c4108e4ce3a1ccc51127b06741e9315a1108`. Darwin/arm64, 12 CPUs, go1.27.2, shared with other
agent lanes. No CPU burners were used: "load" is the host's own load average (1/5/15 min) recorded
before and after each run, and it stayed between 51 and 88 for the whole lane. Every run used a
`-race` test binary and `-run` on the named tests only. Test-only change: no production code, product
bound, spec or requirement changed, and no requirement ID was added.

## V1-1464: data race in TestPSRForegroundSignals' failure path

- Location: `internal/tasks/cli/pool_sweep_test.go`. The ticket names `internal/tasks/store`, but
  the test and the race are in the cli package.
- Root cause: the helper's combined output was a `bytes.Buffer`. os/exec's copier goroutine writes
  to it until `Wait` returns, and the "injected signal path not reached" failure read it before then.
- Fix: the output is a mutex-guarded writer, so every read and write holds the lock.
- Reproduction: a binary that forces the failure path by reading a marker that never appears.
  - BASE: 3/3 runs reported 3 `WARNING: DATA RACE` each, a `bytes.Buffer.String` read against the
    copier's write (load 53-58).
  - Fixed: 0/3 runs raced. The output was read both while the helper was still running and after
    it returned (load 59-60).
- Mutation: restoring the plain `bytes.Buffer` races 3/3 (this is the BASE row).

## V1-1000: TestPSRForegroundSignals and TestPSRDispatchNativeAdapter under load

**Test margins (fixed)**
- TestPSRForegroundSignals waited a fixed 4s for the helper to reach the injected path. Under load
  the marker appeared after 7.8-11.4s.
- TestPSRDispatchNativeAdapter (bounded-native-writer-join) waited a fixed 10s for the sweep's reset
  fixture, which appeared after 9.6-9.9s.
- Each wait now ends on an event:
  - the fixture appears; or
  - the operation running the fixture returns, which fails at once with its result. The signals
    helper is observed through its `done` channel. The dispatch sweep is observed through a
    `PoolSweepQueue` wrapper that forwards to the real native adapter and reports its return.
- A backstop of the operation's own declared bound plus 30s remains only to detect a hang. The
  helper sweep's `--timeout-seconds` is 30, and the dispatch sweep uses `PoolSweep.TimeoutSeconds`.
- Counts:
  - BASE (3 runs, load 51.6-58.6): signals subtests 0/6 passed, all "injected signal path not
    reached"; dispatch passed 2/3.
  - Fixed (17 runs, load 56-88): signals subtests 24/34 passed and dispatch 4/5. No failure was a
    test-margin failure (see residuals).
- Mutation: forcing the marker absent and making the dispatch reset `sleep 60` fails both tests
  promptly with the new messages, about 26s and 30s, at load 69-71. Neither hangs.

**Residual: product fixed bounds the cli tests cannot lift**
- Every remaining fixed-run failure is a fixed product bound in `internal/tasks/store`.
  - The sweep Git observation's 2s bound (`sweep git: bounded observation failed: TIMEOUT`):
    - before the owner commit, the helper returns ERROR (4 runs);
    - after it, the helper returns OK with the member QUARANTINED `TIMEOUT; safe reuse failed`
      and the marker never written (3 runs).
  - The runner-identity probe's 1s bound (`QUIESCENCE_UNPROVED: sweep: runner identity
    unavailable`, 1 run).
  - After the signal, the cleanup proof's 1s WaitDelay and 5s allowance. The member's reason was
    `UNKNOWN; safe reuse failed` rather than INTERRUPTED (2 runs).
- The store tests lift the first two bounds through the package-private context key
  `PSRTestLiftObservationBounds` (V1-1324). The cli tests cannot use it: they run in another package
  and through a re-exec'd CLI, and no production seam exists. The cleanup proof bounds are
  deliberately never lifted.
- Recorded as V1-0849 evidence and an owner decision, choosing one of:
  1. scale the sweep observation bound from the invocation's `--timeout-seconds`;
  2. add an exported or environment test seam (a production change);
  3. accept as a ticketed load limit.

## V1-1465: classification

**TestTOLV0027_PreflightDeepStatusPastTheGateTimeoutFails** (`internal/tasks/cli`): load-sensitive
fixture margin, fixed.
- Cause: the gate's `timeoutSeconds` was 2, and it also bounds the post-gate check. That check is
  two Git resolves plus the status up to the clean filter, and at load 60-68 it took 5-8s. The check
  was therefore killed before the filter ran, so the fixture never exercised its subject. The test
  fails at "the clean filter never ran".
- Fix: the timeout is 20s, well below the filter's 600s sleep. The elapsed bound becomes that
  timeout plus 60s for worktree creation and removal. A product that waited for the filter would
  still take its full ten minutes and fail. Measured elapsed was 29-33s.
- Counts:
  - BASE 6/6 FAIL (load 51.7-64.5), plus 1 diagnostic FAIL at load 67.
  - Fixed 5/5 PASS (load 62-79).
- Mutation: `preflightWorktreeChange` reports the late status as "unreadable" (Changed) instead of
  Unchecked. It fails at the findings assertion with "changed the worktree (its status is
  unreadable)" (load 79).

**TestCALV0078 sweep and pool-command tests and TestPSRV0012PinnedSweep** (`internal/tasks/store`):
load-sensitive, fixed with the V1-1324 pattern.
- Failures and their causes:
  - "WaitDelay expired before I/O complete" and "signal: killed": the runner-identity probe's
    250ms WaitDelay and 1s bound in `PoolCommand`.
  - "runner identity unavailable" and "sweep git: bounded observation failed: TIMEOUT": the sweep's
    probe bounds.
  - Once lifted, the pinned sweep's reuse phase spent its 60s member deadline (`TIMEOUT; safe reuse
    failed`) in 1 of 2 runs.
- None of these tests is about those bounds; their subjects are retry classification and pinned
  worktrees.
- Fix:
  - Each test's sweeps and pool commands run under `psrLoaded`.
  - The sweep tests use `psrLoadTolerant` and `psrLoadedSweepSeconds`.
  - The pinned sweep's member deadline is 120s.
  - Cleanup proof bounds are unchanged.
- Counts on this subset (`TestCALV0078_Sweep.*`, `PoolCommandReportsExecution`,
  `PreparedPoolCommandIsNotRetryable`, `TestPSRV0012PinnedSweep`):
  - BASE (4 runs, load 62-82):
    - sweep tests 0/12;
    - PoolCommandReportsExecution 2/4;
    - PreparedPoolCommand 3/4;
    - PinnedSweep 2/4.
  - Final fix: all 6 tests pass 3/3 (load 67-77). The intermediate run with the 60s member deadline
    passed 2/2 except PinnedSweep/pinned 1/2.
- Mutation: a fresh sweep's committed failure left retryable (`swept.Unretryable = false`). Both
  not-retryable sweep tests fail with the injected LOCK_TIMEOUT, and the retryable control passes
  (load 71-80).

**Program-workflow CALV0078 tests** (`Supervised*`, `IntegratorFailure*`): load-sensitive, not fixed
here.
- One BASE run of all CALV0078 tests took 17 minutes at load 67-82:
  - `SupervisedRunAfterCommitIsNotRetryable` failed 4 of 5 subtests (264-512s each);
  - `IntegratorFailureBeforeLeavingSelectionIsRetryable` failed 1 of 5.
- Both failed with `implement: ... context canceled` in phase WAITING, or "fault point role-finished
  reached 0 times".
- The cancel comes from the stage watcher in `workflow.go`, after a failed heartbeat transition or a
  program-record read failing for `watchReadTolerance`. The ticket reported them passing alone at
  load 44.8.
- Recorded for V1-0849, not fixed. The bound is a product supervision tolerance, not a test margin.

**TestCloneTrustEncodingAndLifetime** (`tools/corvint-pr-tests`): load-sensitive, fixed.
- Cause: the test's own read of the written config (`git config --get-all safe.directory`) had a 1s
  bound. At load 69-75, `/usr/bin/git` start-up alone took 1.6-2.9s, so the test failed with
  `unsafe encoding: -1 context deadline exceeded`.
- Fix: the bound is one minute. It only detects a hung Git, and the asserted output is unchanged.
- Counts: BASE 5/5 FAIL (load 68-75); fixed 5/5 PASS (load 66-73).
- Mutation: dropping backslash escaping from the trust config's quoting fails with `bad config
  line 2`.
- Not met: the acceptance asks for a run below load 10, which was not achievable on this shared
  host. It stays a residual.
