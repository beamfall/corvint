# V1-4719: preserve N-1 exceptions during nested fixture replay

The independent review found that the CCF-V1-9800 fixture regression nests the
CCF-V1-002 core-profile test. Its enclosing test name changes, but the CCF-V1-007
N-1 exception maps use canonical core-profile case names. Looking up those maps
through `t.Name()` therefore executes intentionally excluded modes against 0.8.1
and sends unsupported `--full` arguments to its affected command.

Decision: derive the canonical logical case key from the frozen case table and
pass it explicitly to `replayCoreModeN1`. Both existing exception maps use that
key. Their entries, skip reasons, frozen assertions and artifacts remain intact.
`TestFixtureGitIdentityIsHermeticWithN1Replay` requires the opt-in
`CORVINT_CORE_N1_BINARY` and runs the entire fixture regression under another
nesting level, covering both excluded CEM/OCM modes and the two affected full
modes with the actual N-1 reader. An absent baseline is an explicit test skip.
The owning spec's evidence table names this regression; no requirement or
product contract changes.

Acceptance is the new nested regression and existing fixture/core-freeze tests
against the supported `v0.8.1` baseline, plus the same frozen tests without N-1
replay. Rollback is to revert the explicit-key change and its new regression
together. No product state or wire format changes or migrations are involved.

The existing pre-change capture and selected feature route are reused. This
round uses affected selection and CEM binding/checking; retrieval, learning,
ranking, live providers and release gates are outside this test-only repair.
Independent review remains orchestrator-owned. No publication, Tasks write,
model-backed reviewer or seal is authorized.

Raw evidence is outside the repository at
`/home/russell/lanes/fixtureident-evidence/` with prefix `reviewfix-`.

failed against `v0.8.1` (commit
