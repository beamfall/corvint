# 2026-09-28 CAL-V0-026: verified audit reuse and bounded lease lock holds

The owner asked to meet CAL-V0-026 after S8 retained its cache and latency clauses as NOT_MET. The default product remains local native Go; this change adds neither a persistent service nor a serialized cache format.

Lease writers prepare the complete physical inventory, journal proof, request replay, scope facts and pure transaction model before locking. A one-entry process-local cache retains only a successful audit, keyed by the head receipt digest and intent tree digest and additionally matched against all physical content digests and observed path membership. Matching head and intent are insufficient by themselves because private projections can be corrupted without changing them. Request history retains only audited path/digest metadata; replay reads one bounded request projection under the same guard. A fresh process takes one full audit. Stable-head replay/refusal can reuse the verified result. No cross-process reuse is claimed.

A command-scoped native change monitor is installed before reads. Darwin watches every file and directory with kqueue; Linux uses inotify. Ancestors protect path replacement; directory registration precedes enumeration. Any mutation, invalid monitor, overflow or registration failure invalidates the prepared result. Under the store lock the writer rechecks the exact head, branch, guards and monitor, then uses the existing receipt-first writer. Full inventory/model work and monitor teardown happen outside the lock. Monitor descriptors are closed at command completion; there is no background watcher.

Recovery keeps the same receipt authority. Orphan slot cleanup is bounded under lock. A pending receipt is audited outside the lock, and only the guarded consistent PRE_OR_POST result authorizes redo of the bounded posts and head. Gate execution settles through that same path before running its command.

Gate A independently challenged watcher coverage, cache trust, hidden lock work and recovery. The revised plan passed. Early concurrency tests found that wrapping a single error in errors.Join hid SNAPSHOT_MOVED from the wire code classifier, and that Go preemption can interrupt nonblocking kqueue reads. Cleanup now preserves original errors when successful, and event reads retry EINTR within a bound. The race regressions passed after these changes.

The early frozen 3,000-ticket run at `2f12901c3fb5e7286594c0d905c61cfb7d74e5b3` (full source ID retained in the raw host receipt) measured claim p95 lock hold 175.014 ms and renew 126.666 ms, with 20 samples per verb. Separate cold CLI processes took claim 2,807 ms, renew 2,500 ms and release 2,604 ms versus S8 baseline 3,778 / 3,449 / 3,435 ms. These one-sample cold comparisons show useful complete-command improvement, not a general speed guarantee. Load ranged from 15.77 to 348.22 on 12 CPUs, so this run cannot qualify the load condition. A final low-load attempt at `677e469f0e26d059a565d61e6f249527bffff716` waited 15 minutes without a stable qualifying interval and did not start the measurement.
