# 2026-10-22 runners-oc-1022: sk- path screen, killed-producer Git groups, sqllogictest statement errors

Lane `runners-oc-1022`, base `14dc0e985bab1c296a7e79d04f40f6e2eabffc83`. Tickets V1-2418, V1-2291
and V1-2341 delivered; V1-2395 and V1-1545 were already fixed on the base. Requirements

lane requirements (2026-10-11). V1-2291 follows decision 0552.

## Problem and root cause

- V1-2418: the writer screen's `\bsk-[a-z0-9_-]{20,}` branch counted hyphens toward the 20
  characters, so the build-log path `2026-10-22-sk-1022p-site-knowledge-setup.md` was a "key" and
  dogfood `local-outcome` failed with `secret-shaped-path`.
- V1-2291: worksource starts each Git child as its own group leader (`groupreap.Contain`). A
  SIGKILL of the producer's group therefore leaves the Git child running inside the producer's
  acquisition scratch, racing `run.Close`'s `RemoveAll`.
- V1-2341: sqllogictest.c prints `<file>:<line>: statement error` on stderr when a `statement ok`
  record is rejected and also when a `statement error` record succeeds. The parser did not read
  that line, so a rejected statement became a complete FAILED suite.

## Fix

- `LTA-V0-017`: the writer `sk-` branch (`writerSKAlt` in `internal/secretscreen/prefilter.go`)
  now needs 20 consecutive `[a-z0-9_]` characters inside the run and still redacts the whole run.
  `StoredV1Pattern` is unchanged. The writer digest was repinned. The analyzer input digest was
  repinned too, and the output digest is unchanged, so `corvint-analyzer/146` is kept.
- `WQO-V0-052` (as repaired, below): every scratch-owning Git run gets a locked record named for a
  random token before Git exists, and Git carries `-c corvint.worksourcerun=<token>`.
  `workMaterialization.Close` retires each run whose record is still locked and keeps the run root
  when it cannot confirm release.
- `TRE-V0-119`: that `statement error` line now records `SQL_STATEMENT_UNRESOLVED`, so the
  observation is incomplete. The two directions cannot be separated from the streams.
- V1-2395: already fixed by 41e673557 (#1534). Every staged exec goes through `startProcess`,
  which retries ETXTBSY with a bounded backoff.
- V1-1545: already fixed by 49eca8f62. The timeouts expire at sampled readiness, not at a wall
  clock.

## Repair round 1 (independent review of V1-2291)

- Producer death before PID publication: the first version wrote the group ID after `Drain`
  started Git, so a SIGKILL in between left a locked, empty record. The record is now complete
  before fork. It is named for a random token, and Git's arguments carry that token. Retirement
  finds the group leader by its argument (`groupreap.GroupLeadersWithArgument`). Arguments stay
  readable for platform binaries, but the environment does not: a groupreap token in the
  environment was tried first and is invisible on macOS for `/bin/sh` and `/bin/sleep`.
- Cleanup despite failure: `Close` now returns an error and keeps the run root when the lock is not
  released within the bound, a record is unreadable, or a lock call fails. `corvint work` writes
  that error to stderr.
- Group ID reuse: no recorded number is signalled. `groupreap.StopKillGroup` stops the marked
  leader's group through `signalPinned` (pidfd on Linux, fresh identity read on Darwin, the
  PGO-V0-007 window), then kills it. The stopped leader cannot be released in between.
- `Close` coverage: `TestWorkCloseRetiresKilledProducerGit` SIGKILLs a real producer helper during
  a fixture Git read in the run's scratch, confirms the Git processes survived, then calls
  `run.Close`. `TestWorkCloseKeepsScratchWhenRetirementIsUnconfirmed` covers the fail-closed path.

Evidence (each test fails without its fix):

  seam added): the record is "still alive" at the 60 s bound.
- `TestRetireGitGroupsNeverSignalsAnUnpinnedGroup` fails on the first version, which signalled
  the recorded group.
- Without the marker argument, both killed-producer tests fail.
- `TestWorkCloseRetiresKilledProducerGit` fails without the `Close` retirement ("outlived

- `TestWorkCloseKeepsScratchWhenRetirementIsUnconfirmed` fails when `Close` removes the root

- Stress: worksource group tests passed 30/30, and the package passes under `-race`.
  `TestWorkClose*` passed 10/10 at load 12 to 17. `TestWork|TestObserveWork` passes, and so do the
  `internal/groupreap` and `internal/worksource` packages.
