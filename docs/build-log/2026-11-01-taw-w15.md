## Delivered

- **V1-3975**: `corvint-tasks work start|deliver|block` run offline. They validate each ticket ID and
  state against the local store copy and print `Corvint-Ticket` trailers for the lane commit. They
  write no store state.
- `work close-merged` (operator and owner hosts) reads the trailers reachable from the integration
  ref and completes each delivered ticket through `complete-manual` with the reason code
  `INTEGRATED`. Re-ingestion is idempotent, because the request IDs are deterministic and the
  current ticket state is checked first. A trailer that is no longer reachable after a rebase or a
  dropped commit leaves the ticket `AWAITING_INTEGRATION`.
- `work finding` runs the similar-ticket check first and attaches to a match unless
  `--new-despite` is passed. `--ingest` dedupes a batch within itself and against the store, and
  `--supersede ID --by ID` archives the old ticket with `supersededBy` set.
- `work release-sync` adds missing OPEN milestone members to the release and reports members from
  outside the milestone. A second run changes nothing.
- The `CORVINT_TASKS_ROLE` class: under `AGENT`, `complete-manual` and `archive` need a fixed
  reason code (`--reason-code`), and hand edits of status are refused. `OPERATOR`, `OWNER` and an
  unset role keep today's behaviour.
- `corvint-mcp --profile tasks [--tasks-role AGENT|OPERATOR|OWNER]` exposes the verbs as
  `tasks_work_*` tools over stdio, each call running the installed `corvint-tasks` as a child
  process (see the fix-up below). AGENT lists the four lane tools, and OPERATOR and
  OWNER also list `close_merged` and `release_sync`.
- Docs: `docs/TASKS-EXTERNAL-AGENTS.md` gains "Report lane work with commit trailers", and the
  lane charter template in `docs/LANE-ORCHESTRATION.md` (Roles) now tells lanes to emit trailers
  instead of writing the store.

## Decisions

- The wire outcome codes stay closed. Refusals reuse existing codes and name the cause with a
  `TAW_*` tag in the message (`TAW_ROLE_UNKNOWN`, `TAW_ROLE_NOT_PERMITTED`, `TAW_TICKET_UNKNOWN`,
  `TAW_TICKET_CLOSED`, `TAW_REASON_CODE_REQUIRED`, `TAW_REASON_CODE_UNKNOWN`, and the trailer tags
  `TAW_TICKET_ID`, `TAW_STATE`, `TAW_REASON_REQUIRED`, `TAW_REASON`, `TAW_LANE`,
  `TAW_TRAILER_MALFORMED`). A new wire code would have broken every consumer that switches on it.
- The role guard sits at the entry of `submitMutationContext`, so every mutating verb passes it.
  Release membership writes take a separate path and bypass it. That is acceptable only because
  `release-sync` is host-only (OPERATOR or OWNER); see friction 5.
- The close-merged cursor lives under `<git-common-dir>/taskman-work/`. It is an optimisation;
  correctness comes from the ticket state plus the deterministic request IDs, so a lost cursor only
  costs a longer scan.
- REFINE gains a `supersededBy` field so supersede is one atomic mutation. It refuses a ticket that
  names itself.
- Batch dedupe ranks candidates within the store corpus, so a batch and its store neighbours share
  one IDF.
- MCP: no daemon. Each call runs the `corvint-tasks` binary as a child process with the session's
  class in `CORVINT_TASKS_ROLE` (the first cut ran `cli.Run` in process; see the fix-up below). The
  class defaults to `AGENT` and is fixed at startup by `--tasks-role`; a tool call cannot change it.
- `.corvint/test-read-scopes.json` declares `internal/mcp/tasksbridge`. After the fix-up its tests
  build `cmd/corvint-tasks` from the module (`cmd/corvint-tasks/`, `go.mod`, `go.sum`,
  `internal/`), and `internal/mcp/cli` adds `cmd/corvint-tasks/` for the same build. That file is a
  test-selection input, so `make selection-baseline-check` runs after each change to it.
- The `corvint-mcp` serverInfo description still says the server is read-only. The usage text names
  the tasks group as the exception. The description was left alone so the protocol goldens do not
  churn (friction 12).

## Fix-up: process boundary for the MCP tasks group

The first seal attempt (dogfood commits `1e2aff452` and `6de283dd4`, kept in history) failed
batch-precheck `batch-drift`: `TestImportDirection` refused `internal/mcp/tasksbridge` importing
`internal/tasks/cli` (and its test importing `internal/tasks/fixture`), "Core imports only the Tasks
wire package". `cmd/corvint` imports `internal/mcp/cli`, which imports the bridge, so the corvint
binary would have linked Tasks mutation code, against decision 0397.

Decision (orchestrator): keep the process boundary and add no `importViolation` exception, which
would need an owner-accepted 0397 addendum. The bridge now:

- runs the `corvint-tasks` binary as a child process in the root, with the argv the verb takes, the
  payload on stdin and `CORVINT_TASKS_ROLE` set to the session class. An inherited value is
  replaced, so the caller's environment cannot widen the class;
- resolves the binary as `cmd/corvint-console` resolves companions: beside the running executable
  after symlinks, then on PATH (`tasksbridge.Locate`);
- answers the tool error `TASKS_BINARY_UNAVAILABLE` when the binary is absent or cannot be started,
  and never falls back to running the verb in process;
- imports only `internal/tasks/wire`, which now holds `RoleEnv` and the three class names
  (`internal/tasks/wire/roles.go`). `internal/tasks/cli` aliases them, so its API is unchanged.

The tool names, schemas and envelopes are unchanged. `TAW-V0-015` now says "child process" instead
of "in process", and the new `TAW-V0-025` records the boundary, the resolution and the absent-binary
error. The bridge tests no longer import Tasks. `TestTAWV0025_ChildProcessContract` re-executes the
test binary as a fake `corvint-tasks` to check the argv, cwd, stdin, class override, nonzero exit
and unreadable envelope. `TestTAWV0015_CallsEachTool` builds `cmd/corvint-tasks` into a temporary
directory and runs every tool end to end over a fixture store. The queue and policy bytes are
inlined, because `internal/tasks/fixture` is out of bounds. `TestTAWV0015TasksGroupProfile` checks
`TASKS_BINARY_UNAVAILABLE` with only git on PATH, and the built binary found on PATH.

## Adversarial refusal cases

Each case is covered by a focused test.

- Guard (`TestTAWV0001_RoleUnknown`, `TestTAWV0013_AgentGuard`): an unknown role value on a lane
  verb, a host verb and an ordinary mutation; an AGENT `complete-manual` or `archive` with no reason
  code or with an unknown code; an AGENT status hand edit; an AGENT host verb; the OWNER class
  unchanged.
- Trailer parser (`TestTAWV0002_TrailerRoundTrip`): an unknown state, `blocked` with no reason, a
  malformed ticket ID, two states in one block, a state with no ticket, and unrelated trailers
  ignored.
- Lane verbs (`TestTAWV0003_LaneVerbs`): a malformed ID, an unknown ticket, a multi-line reason,
  `--allow-unknown` downgraded to a warning, a root with no store (`STORE_NOT_PRESENT` warning), and
  no store write.
- Integration (`TestTAWV0007_RebasedAndDropped`): a rebased commit and a dropped commit.
- MCP arguments (`TestTAWV0015_*`): an unlisted tool name, an extra property, empty arguments,
  `close_merged` under AGENT, a repeated, unpaired or invalid `--tasks-role`, and a root with no
  store.
- Not covered by a test: `TAW_TICKET_CLOSED` on a lane verb.

## Friction

1. `dogfood-prechange` refuses a lane branched from another lane's head.
2. As a result, `dogfood-change` reports the prechange query and impact as `NOT_OBSERVED`.
3. The corvint MCP plugin server closes with `CONNECTION_CLOSED`.
4. The spec template does not document the 160-character limit on the spec-requirements digest.
5. Release membership writes bypass `submitMutationContext`, so a single guard point cannot cover
   them.
6. The state-dir audit refuses any extra directory and breaks every read. No location for private
   files is documented.
7. `wire.Parse` silently requires a trailing newline.
8. `ticket show` does not display the archive reason.
9. heavy.sh refuses a whole-package run of a small new package without a selection manifest. Then
   `corvint test` selects 233 packages whole (wide or UNKNOWN), so building the manifest is a
   ritual.
10. `corvint affected` reports `self-binary-stale` DEGRADED. The untracked
    `.corvint/change.cem.json` left by `dogfood-change` also widens the selection

12. The `corvint-mcp` serverInfo description is hard-coded as read-only across the goldens.
13. `go vet` under `go test` misses "append with no values". Only the `make windows-vet` run before
