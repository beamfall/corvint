# Lane mk1114: the make edit reach fails closed on a recipe shell, cd options and missing selectors

Date: 2026-11-13. Branch `claude/mk1114`, based on origin/main `ee2dd4e34`. Tickets V1-5551 and
V1-5552 (P1), both from a static review of the NCM-V1-010 to NCM-V1-019 delivery
(`docs/build-log/2026-11-13-mknarrow1113.md`). Requirements amended: NCM-V1-019 and NCM-V1-013 in
`docs/specs/non-code-map-v1.md`; no new ID.

## Reproduction

Each defect was reproduced first with the selector test that now pins it, run against the unfixed
code:

- V1-5551: `SHELL = ./tools/test-shell` (unchanged; the wrapper runs `go test ./tool`) and a changed
  `echo` recipe line narrowed to the Makefile's reader alone (`run <module>/mkread`). The driver
  only marked the file's targets uncertified (`make:recipe-shell-uncertified`), which the reach
  reads as bounded (NCM-V1-013), so the run set stayed closed.
- V1-5552: `cd -- tool && go test ./b` recorded `--/b`; `runPackages` dropped that directory without
  a word, so `<module>/tool/b` was not selected (`run <module>/mkread`).

## What changed

- The driver opens every target's run set of a make file whose recipe shell it does not certify,
  with the existing reason `make:recipe-shell-uncertified` (NCM-V1-019). The planner's site is
  unchanged: the mark lives only in the reach.
- `cd` is followed only with `-L`/`-P` (alone or combined) and an optional `--` before exactly one
  operand that is not `-`; the scanner resolves that operand as the directory. Any other form (other
  option, no operand, `-`, a second operand) is `shell:unfollowed-command:cd` in the reach and
  leaves the directory unknown, uncertified `shell:cd-unresolved`, in the planner, whose go
  selectors then keep the whole tree. pushd takes only `--` and never a rotation; the closed rule
  still never follows it.
- Each scanned text now carries its go package selectors, one set per scan directory (the make
  file's own and, for a nested make file, the root), as `MakeReach.Selectors`. The selector refuses
  an edit whose reached selectors name no indexed package in every scan directory, instead of
  dropping them in `runPackages` (NCM-V1-013). The per-directory sets matter: a nested make file's
  `go test ./x` names `sub/x` from its own directory and `x` from the root, and only one of them
  exists. The whole-tree pattern is no selector.

## Not changed

- `driverVariants` still records every operand both against the working directory and as written
  from the root, so `cd tool && go test ./b` also adds a root `b` package when one exists. That is a
  conservative superset, kept.
- A `CDPATH` in the recipe's environment can send `cd tool` elsewhere; the scan does not model the
  environment. Reported to the orchestrator.
