## V1-0402: PreToolUse Read/Grep (AHI-805)

- Decision (review fix, replacing an earlier `permissionDecision: "defer"` answer): `pre-tool`
  never carries `permissionDecision`, `permissionDecisionReason`, `updatedInput` or a blocking
  member. The hooks reference says `defer` ends a `-p` turn and is ignored interactively, and that
  `additionalContext` is ignored under it, so `defer` was not permission-neutral. The hook adds
  `additionalContext` only for a Read `file_path` or Grep `path` that is inside the project,
  compiled as a project-relative path, and otherwise returns `{}`.
- Decision (invariant 4): recording unplanned reads from the hook is NOT admitted. Rows still need
  the operator marker `.corvint/unplanned-reads.enabled` (SOL-V0-010), so a hook gains no new
  ledger writer.
- Measured on WSL with a fresh-snapshot clone, n=30:

  | Tool | p50 (ms) | p95 (ms) | max (ms) |
  |---|---|---|---|
  | Read | 756 | 813 | |
  | Grep | 765 | 843 | 1200 |

  A stale snapshot degrades in about 81 to 105 ms. Every run stayed under the 2 s hook timeout.
- Not verified live: the pre-tool `additionalContext` on a released host.

## V1-2240: untracked cache and fsmonitor (measured, rejected)

Setup: git 2.53.0, 32 cores, load about 9 to 10. A clone with 1,500 untracked files, measured with
`git --no-optional-locks status --porcelain=v1 -z --untracked-files=all`, n=31, two rounds.

| UNTR extension | core.untrackedCache | p50 (ms) | p95 (ms) |
|---|---|---|---|
| absent | false | 31-32 | 36-37 |
| absent | true | 31 | 39-40 |
| present | false | 31-32 | 37 |
| present | true | 30-31 | 34 |

- Decision: REJECT the untracked cache. The gain cannot be measured, the adapter's cost is not the
  untracked walk, and a read-only status run cannot persist the UNTR extension.
- Decision: REJECT fsmonitor. Linux Git has no built-in daemon. A hook or watchman daemon would
  break invariant 7. Isolated status forces `core.fsmonitor=false` for safety.
- Limit: the load-40-to-80 condition in the ticket was not reproduced. The UNTR extension was
  removed afterwards.

## V1-2838: per-edit test spike (recommendation)

- Recommendation: do not implement per-edit test runs. A per-edit run cannot fit the 2 s hook
  deadline (`cmd/corvint` alone takes about 591 s). The V1-2806 `-run` source slices exist only as
  TSP-V0-006, which is experimental.
- The smallest viable path is an opt-in extension of the AHI-191 Stop done-list. It would run once
  per turn, not per edit, executing tier-1 sliced units under a time budget and abstaining when the
  selection is UNKNOWN or wide.
- Proposed criterion (not in a spec): "A Stop done-list with tests enabled runs only tier-1
  selected slices within a declared budget, and reports NOT_RUN with the selection's unknowns
  otherwise."
- OpenCode parity and an offline replay come later. A paid paired trial needs an owner yes.
