## V1-2262: struct fields index as field definers (TCP-V0-162)

- Problem: a task that named a Go struct field, such as `ExpectedTests` (V1-1015), did not get
  `internal/testrunner/types.go` as a definition. TCP-V0-152(c) only reported the anchor as
  unresolved.
- Root cause: `goSymbols` recorded only top-level func, type and var/const names. Fields were
  never extracted.
- Fix:
  - `goSymbols` now also returns the named fields of top-level struct types, in a separate
    `Index.Fields` table.
  - Every encoding persists that table: gob event and wire, sectioned `fields` section, a pack gob
    section, blob facts, snapshot reuse, and the `necessity` reduction.
  - The `definition` slot uses a field only when no declaration defines the name. A declared name
    keeps its definer set and rarity.
  - Other `Symbols` consumers do not read fields.
  - The analyzer schema moves to corvint-analyzer/147 via `script/analyzer-schema.sh bump`.
  - The `index write` core-freeze golden grows by 12 bytes.
- Evidence:
  - On this repository, the V1-1015 task now ranks `definition internal/testrunner/types.go:32` at
    #5. Before, the file was lexical #18 and `ExpectedTests` was an unresolved anchor.
  - The new tests fail when `goStructFieldNames` returns nothing.
  - The full `./internal/contextindex` package passes.
- Frozen bench: `tools/retrieval-bench --arms context` on v2_code2test, all 106 samples:

  | metric | base | lane |
  | --- | --- | --- |
  | recall@20 | 0.5022 | 0.5022 |
  | recall@10 | 0.4013 | 0.4013 |
  | recall@5 | 0.3160 | 0.3160 |
  | MRR | 0.2149 | 0.2117 |

  - The base row reproduces the recorded baseline.
  - 4 of 106 rankings changed, all in Go repositories.
  - In two of them the first gold result moved from rank 2 to rank 3.
  - The comment2context, edit2ripple and trace2code subsets were NOT_RUN.
- Rollback: revert the commit. The schema bump makes old packs miss.
