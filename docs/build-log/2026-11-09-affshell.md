## V1-5119: absolute executables (AFP-V0-9131)

Wrong: an absolute command word fell through to certification by base name on origin/main. On
this branch every head holding `/` already went through `driverOperandRecorded`, which refuses
rooted paths, so `/work/project/tools/cat` was uncertified (the fallback stayed) but recorded no
edge, and so was `/bin/cat`. Fix: `repositoryExecutable` maps an absolute head below the
source's disk root to its repository-relative path before certification and path recording, so
`<root>/tools/cat` records the `tools/cat` edge and stays uncertified, and `<root>/script/x_test.sh`
certifies exactly as `script/x_test.sh` does. Every other absolute head (`/bin/cat`,
`/usr/bin/cat`, `/opt/tools/cat`) is certified for nothing and records no edge.
Test: `TestDriverAbsoluteExecutable_AFP_V0_9131`.

## V1-5169: line continuations and function shadows (AFP-V0-9130)

Wrong: `script` replaced every backslash-newline blindly and revoked all narrowing of the step
(`shell:line-continuation`), so any step with a continued `$(...)` or command stayed computed.
Fix: `driverJoinContinuations` removes a backslash-newline exactly where bash does (outside
single quotes and comments, inside double quotes or not, not itself escaped, through nested
`$(`, `${` and parentheses) and declines, falling back to the old join plus revoke, for a
backtick, `$'`/`$"` outside single quotes, a here-document operator or an unclosed quote or
substitution. After an exact join a line ending in a backslash is complete (escaped backslash,
comment or single-quoted text), not continued. A function defined by `name()` or `function name`
whose name is a command the scanner models now marks `shell:function-shadow`; `alias` was already
computed. The scanner was not misparsing the substitution as a prefix assignment on this branch;
the revoke was the whole effect.
Tests: `TestDriverLineContinuations_AFP_V0_9130`, `TestDriverJoinContinuations_AFP_V0_9130`,
`TestDriverFunctionShadowing_AFP_V0_9130`.

## V1-5171: step outputs as run-time values (AFP-V0-9132)

Wrong: `${{ steps.x.outputs.y }}/run` rendered as `\x01/run`, which `driverComputedWord` admits
as a root-like `$X/` word, so a step whose output came from `echo "y=$(cmd)" >> "$GITHUB_OUTPUT"`
chose the executable at run time with no frontier. Fix: `driverLiteralOutputSteps` lists the
steps whose every `run` line is blank, a comment or a literal `echo "NAME=VALUE" >> "$GITHUB_OUTPUT"`
(no `uses`, no expression); `driverOutputExpressions` renders an expression that reads any
other step's output as `driverRuntimeComputed` (two markers, never root-like) before
`driverExpressions` runs, for workflow jobs and composite actions alike. A command word built
from it marks `shell:computed-command-word`.
Test: `TestDriverStepOutputCommandWord_AFP_V0_9132` (computed, action, mixed, `||` and
expression-bearing producers stay computed; literal producers and `github.workspace` do not).
Census: CI computed sites 37 before and after; no corvint workflow builds a command word from a
step output.
