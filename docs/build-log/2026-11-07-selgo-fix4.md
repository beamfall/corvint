# Selection: every admitted deletion stays unowned for other plugins (review fix round 4)

Date: 2026-11-07
Lane: selgo (branch `claude/sel-go`, PR #128), review fix round 4 after `2026-11-07-selgo-fix3`.
Ticket: V1-4931. Requirement: AFP-V0-2749 (new) in `docs/specs/affected-plan-selection-v0.md`;
AFP-V0-2740's rollback text now names the shared predicate.
Owner goal: never fewer tests than needed.

## Finding

The PR review (Greptile, P1) flagged `deletedGoSource` (`internal/liveverify/affected/deletedtests.go`,
AFP-V0-2610): it drops `UNINDEXED_SOURCE_PATH` for a deleted Go file of a surviving package, but
`participants` (`select.go`) still treated the path as Go-owned. An otherwise unreached test in
another language that reads the file by a computed name, such as a Ruby spec with a path-open
`implicit-test-dependency` entry, lost that entry. Before AFP-V0-2610 the fallback forced FULL.

Checked against the code: confirmed. Round 3 (AFP-V0-2740) had re-listed only deleted fixtures as
unowned in `participants`. The other two admitted deletions in `seed` had the same gap:

- `deletedGoSource` (AFP-V0-620, AFP-V0-2610), a deleted source or `_test.go` file of a surviving
  package, is new on this branch.
- `deletedGoPackage` (AFP-V0-821), a file of a wholly deleted package, is already on `origin/main`.
  Its comment said the path "still stays unowned, so frontierUnknowns treats it as any other
  unowned path", but `claimantsOf` names Go for any `.go` path, so it never did.

No other `seed` branch admits a claimed path without an entry. `goReadData` paths are claimed by
no plugin, so they are already unowned. A driver seed is attributed to the driver's targets
instead.

## Decisions

- **One predicate, `admittedDeletion`**, is the union of `deletedGoSource`, `deletedGoPackage` and
  `deletedFixture`. `seed` and `participants` both call it, so a path cannot be admitted by one and
  left Go-owned by the other. In `participants` it is asked for every claimed dirty path that no
  unit declares. The test for an unknown entry is unchanged.
- The claimant still takes part as the owner of a dirty path. Every other plugin applies the
  ordinary AFP-V0-511 rules to the path: a path-open entry bears and names the deleted path in its
  hint, and a source-bound entry does not bear. An edit to a file that a unit still declares stays
  owned, so ordinary edits gain no entry.
- `goPackageDirectories` is computed once per plan, lazily. Each claimed undeclared path costs one
  `Lstat`.

## Tests and fault injection

- `TestDeletedGoSourceStaysUnownedForOtherPlugins_AFPV2749` (`deletedsources_test.go`):
  - Setup: Go units `go:pkg`, `go:user` (imports `go:pkg`) and `go:other`, plus the Ruby-shaped
    `rb` plugin with a path-open `implicit-test-dependency` entry and a source-bound
    `relative-load` entry.
  - Cases: a deleted `pkg/gone.go`, a deleted `pkg/gone_test.go`, a deleted package
    `removed/removed.go`, and, as a control, an edited declared `pkg/pkg.go`.
  - For each deletion: no entry for the path itself; the implicit entry bears through
    `UNOWNED_DIRTY_PATH` with the hint quoting the path; the source-bound entry does not bear; the
    scope is `UNKNOWN`. Selection is unchanged: `go:pkg` plus its importer `go:user` for a source,
    `go:pkg` alone for a test file, and never `go:other`.
  - For the control: no entry bears and the plan stays narrowed.
- `TestAdmittedDeletionsStayUnownedInParticipants_AFPV2749`: `participants` lists exactly the paths
  `admittedDeletion` admits, one per rule. The kept twins (a present undeclared `.go` file, a
  present fixture, declared sources) are not listed. A sparse checkout admits only the Go source,
  and a graph with no disk root admits nothing. `seed` raises no entry for any admitted path.
- **Fault injection:** with `participants` calling `deletedFixture` alone (the round-3 form), both
  tests fail. The first fails for all three deletion cases (`frontier [], bearers []`). The second
  fails with `pkg/gone.go listed = false`. With the fix restored, both pass.
