## V1-3724: reverse impact for Swift, Kotlin and C#

Delivered. Screening found no V1-3724 commit or mention on origin/main.

Decision: the `GPK-V0-027` reverse-import rules come from a frozen oracle, so `ImpactRuleNamed`
stays false for `.swift`, `.kt` and `.cs`. The capability listing, the historical packet budget and
the `corvint graph` rule-unavailable unknown all keep their current answers. Instead, path
`impact` runs a separate module-membership reading (`internal/contextindex/module_impact.go`) for
these suffixes under every language profile. It follows the Ruby autoload precedent: a per-request
`moduleMapped` view withholds the profile-gap line for resolved paths, and each language's fixed
coverage line names its precision limits.

How each language resolves:
- Swift reuses the affected Swift model's SwiftPM target parse. Importers of a target's module are
  `reverse-import` rows at high confidence. A file that no target claims keeps the gap.
- Kotlin and C# rules read package/namespace and import/using syntax over code-only text. The
  index admits no `.csproj`, `.sln`, Groovy `build.gradle` or `project.pbxproj`, so no build-unit
  graph exists for them.
  - An explicit, static or alias import of a declared name is a high-confidence importer.
  - A wildcard or namespace import is medium confidence, and only when the importer also names a
    declaration.
  - A same-package or enclosing-namespace file that names a declaration is a `reference` row.
- `.kts` and `.csproj` are marked NOT_SUPPORTED in help.

Requirement IDs added: `NGI-V0-980` to `NGI-V0-987` in `docs/specs/non-go-impact-v0.md`. All are
experimental under the standing lane auto-accept, and each is traced to a test.

Kept out of scope as non-goals: range impact, `corvint graph`, Xcode, Gradle and .NET project
graphs, and transitive dependents.

## Repair: the corvint-tasks source archive closure (NGI-V0-988)

The seal's batch precheck failed `TestCurrentTasksSourceArchiveBuildsOffline` in
`internal/companionrelease`, and the failure was introduced by this lane. `module_impact.go` had made
`internal/contextindex` import `internal/liveverify/affected` and `affected/swift`.
`internal/tasks/scopes` and `internal/tasks/similar` import `contextindex`, so the offline
corvint-tasks rebuild from the `tasksExportPrefixes` subset could not find the planner.

Decision: invert the dependency. The archive manifest stays as it is.
- `contextindex` declares a `SwiftPMReader` interface (`swiftpm_reader.go`) and keeps no
  planner import.
- The new package `internal/swiftimpact` implements the interface over the affected Swift model
  and registers it from `init`. It lives outside the `internal/contextindex/` export prefix.
- Each of the nine binaries that already linked the Swift model (`corvint`, `corvint-mcp`,
  `corvint-lsp`, `corvint-corpus-mcp`, `corvint-docs-mcp`, `corvint-test`,
  `corvint-test-validity-mcp`, `corvint-web-flows`, `corvint-postmerge-workflow`) blank-imports it
  from a new `swift_impact.go`. None of their link closures change, so their Swift answers stay the
  same.

Widening was rejected. The Swift model's parent package is the whole test-selection planner, about
14k lines plus every language plugin under one prefix. corvint-tasks never serves path impact,
so that code does not belong in the Tasks closure, and `PUB-V0-012` and `PUB-V0-013` need no
change.

Two alternatives were also rejected:
- Moving the SwiftPM parser into a leaf package would refactor about 600 lines of planner code.
- Re-implementing it would fork `NGI-V0-980`'s "as the affected Swift model parses".

What the inversion costs: a binary that serves impact without the registration reports the gap.
It shows no rows and keeps the profile gap, and the receipt says so with a fixed line, so it never
claims an empty closure (product invariant 2).
`TestNGIV0988TasksClosureExcludesPlannerAndImpactBinariesLinkReader` keeps the Tasks closure free
of the planner and checks that the nine binaries link the reader.
