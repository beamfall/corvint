## V1-3724: reverse impact for Swift, Kotlin and C#

Delivered. Screening found no V1-3724 commit or mention on origin/main.

Decision: the `GPK-V0-027` reverse-import rules come from a frozen oracle, so `ImpactRuleNamed`
stays false for `.swift`, `.kt` and `.cs`. The capability listing, the historical packet budget and
the `corvint graph` rule-unavailable unknown all keep their current answers. Instead, path
`impact` runs a separate module-membership reading (`internal/contextindex/module_impact.go`) for
these suffixes under every language profile. It follows the Ruby autoload precedent: a per-request
`moduleMapped` view withholds the profile-gap line for resolved paths, and each language's fixed
coverage line names its precision limits.

How each language resolves:
- Swift reuses the affected Swift model's SwiftPM target parse. Importers of a target's module are
  `reverse-import` rows at high confidence. A file that no target claims keeps the gap.
- Kotlin and C# rules read package/namespace and import/using syntax over code-only text. The
  index admits no `.csproj`, `.sln`, Groovy `build.gradle` or `project.pbxproj`, so no build-unit
  graph exists for them.
  - An explicit, static or alias import of a declared name is a high-confidence importer.
  - A wildcard or namespace import is medium confidence, and only when the importer also names a
    declaration.
  - A same-package or enclosing-namespace file that names a declaration is a `reference` row.
- `.kts` and `.csproj` are marked NOT_SUPPORTED in help.

Requirement IDs added: `NGI-V0-980` to `NGI-V0-987` in `docs/specs/non-go-impact-v0.md`. All are
experimental under the standing lane auto-accept, and each is traced to a test.

Kept out of scope as non-goals: range impact, `corvint graph`, Xcode, Gradle and .NET project
graphs, and transitive dependents.
