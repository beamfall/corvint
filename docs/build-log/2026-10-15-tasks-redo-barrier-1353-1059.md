## Finding

V1-1352 (CAL-V0-222) fixed the lease commands. Each of them ran one `snapshot.Probe`, only to learn
the queue, and returned its retryable `REDO_PENDING` before reaching a store writer that settles a
validated pending receipt under the lock. That writer path is `redoPending` / `redoPendingFor` for
`Barrier`, `PolicyUpdate` and `Import`, and `administrativeWrite` for cutover and escalation.
`settleLease` covers the attempt-run lease writes. The same pre-write probe pattern remained in
these commands:
- `pause` and `unpause` (`barrier.go`)
- `policy update`
- `import`
- `cutover`, with or without `--execution`
- `ticket escalate` and `ticket answer` (`escalationWriter`)
- `parseAttemptRun`, the initial probe of `attempt run`

So a receipt that an interrupted writer left pending refused every one of them until some other
writer settled it. `health` and `pool cleanup` already reached `settleLease` through
`store.PoolCommand`, but discarded its result, so they never reported the redo.

`attempt run --attach` reads with patience. It is a read and stays one: it never settles a receipt.

## Change

- One shared pre-write probe, `writerProbe` (`internal/tasks/cli/writer_probe.go`). It accepts
  `REDO_PENDING` when the head is readable and passes any other error through. The lease command
  now uses it too, with the same CAL-V0-222 condition.
- `policy update` skips its CAL-V0-124 fence preview over a pending receipt and reports it
  `NOT_OBSERVED (REDO_PENDING)`. Without the skip the preview is a read that waits out the 2 s
  production read patience and then reports the same thing. The writer does not need that wait.
- `attempt run` records whether its pre-launch heartbeat or renew settled a redo. It reports the
  completed-redo warning in the run envelope, including detached runs, which reach the same `run`.
- `store.PoolCommand` sets `Report.Redone` when its `settleLease` settled a receipt. The CLI's
  `mutateResult` already turns that into the warning.
- Each command in CAL-V0-260/261 gets a `redoPending` entry in its verbose help (CAL-V0-262).

## Review

One Codex round (static, read-only) reviewed `883caa3d2..b40dec205`. Both findings were confirmed
and fixed in this change, and CAL-V0-260's wording now names both cases. That wording is this
lane's own unmerged requirement, so no accepted requirement was amended.
1. P2: an `import` retry could complete the redo silently. The last batch of an interrupted
   import is held pending, then the same export is rerun. The retry settles the receipt, plans
   zero records and returns no batch, so the warning carried on `Batches[0]` was lost.
   `ImportReport.Redone` now carries it independently of batches.
   - Test: the `import retry` subtest asserts the warning and `written` "0".
   - Mutation 6 restores the batch-only carry, and the subtest fails (load 66.6 → 71.8).
2. P2: a refusal before launch dropped the redo. `attempt run` captured `Redone` only after the
   heartbeat's refusal check. For example, a held pending release of the run's own attempt is
   settled by the first heartbeat, which is then refused `FENCED`. `prepare` now records `Redone`
   before the refusal check, and every result before launch passes through `withRedo`.
   - Test: `TestCALV0260_AttemptRunRefusalReportsSettledRedo`.
   - Mutation 7 moves the capture back after the check, and the test fails (load 73.6 → 62.5).

## Owner decision: V1-1059 is not implemented

V1-1059 (P3) asks that barrier and redo refusals carry the intent-branch repair text that `Mutate`
carries, with a test on each path. Accepted `CTW-V0-007`
(`docs/specs/corvint-tasks-intent-worktree-v0.md`, line 79) appends that repair text only to the
`Init`, `Mutate`, `PolicyUpdate`, `Release` and `Lease` writers. It states that the other writers,
"cutover, execution cutover, reconcile, import, barrier, lease recovery and redo", keep their
refusal text without the fix. V1-1059 therefore needs an owner amendment of CTW-V0-007, which the
standing auto-accept does not cover. Two options:
- (a) Amend CTW-V0-007 to extend the repair text to barrier and redo, then implement V1-1059.
- (b) Close V1-1059 as superseded by CTW-V0-007.

## Rollback

Revert this change set. No store, receipt or wire format depends on it.
