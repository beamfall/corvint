## V1-2267: second dogfood-change pass appended citations

Problem: `cem prepare` resumes an uncommitted map and `cem cite` only adds evidence, so a second
pass with a corrected plan joined the earlier plan's citations; only a note after the fact named
the delete-and-rerun recovery.

Decisions:

- Refuse up front rather than replace. Replacing would need the bind loop to know which citations
  an earlier plan wrote, and staged binding (`docs/DOGFOOD.md`, more than 256 hunks) relies on
  citations accumulating over an uncommitted map. `DCW-V0-117` refuses, before any cite or mark,
  a row naming a hunk the map already cites when the row is an unknown row or cites a path, span
  and relation the hunk's basis does not hold. The fix line names the row and hunk.
- Same-plan replays (`docs/DOGFOOD.md` step 5 after the sidecar commit) and staged plans naming
  only `unknown` hunks still cite. The span check resolves line spans to bytes at `BASE` exactly as
  `cem cite` `evidenceSpan` does; a span that does not resolve is left to `cem cite`.
- The rule applies to committed and uncommitted maps alike: the trap is the same.

Evidence: `TestChangeDCWV0117RefusesARowThatRecitesACitedHunk` fails without the check (three
refusal cases cite). `TestDogfoodChangeNamesDeleteWhenACorrectedPlanJoinsEarlierCitations` now
asserts the refusal on the built binary.
