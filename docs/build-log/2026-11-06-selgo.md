# Selection: deleted fixtures, nested modules on the ci profile, record-entry readers

Date: 2026-11-06
Lane: selgo (branch `claude/sel-go`, base `4052b8540`), after merging `claude/selaudit`
(AFP-V0-2610 and the audit entry `2026-11-06-selection-audit`).
Tickets: V1-4931, V1-4932, V1-4933 (P1). Requirements: AFP-V0-2740 to AFP-V0-2745 in
`docs/specs/affected-plan-selection-v0.md`; STR-V0-064 is amended for the `ci` profile.
Owner goal: every local and CI run executes only the minimum tests the change can affect, every
time, and never fewer.

## Decisions

- **V1-4931, AFP-V0-2740 and AFP-V0-2741.** A non-Go file deleted or moved away from below a
  Go-hosted `testdata` directory is fixture data when no claimant lists a path of its fixture
  subtree, which is the first directory below `testdata`. AFP-V0-2440 asked that of the whole
  `testdata` directory. In #114, `cmd/corvint/testdata/runs-identity-setup-project` still held
  TypeScript files, so the moved `cmd/corvint/testdata/flows` tree stayed
  `UNINDEXED_SOURCE_PATH`. Absence is read from disk, as AFP-V0-620 and AFP-V0-821 read it. A
  sparse checkout keeps the entry. Rules (b) and (c) still select the hosting package and every
  unit that names the path. The CI selector needs no new admission: the plan carries no unknown,
  so both selectors read the same decision. A plan that keeps the entry is FULL in both.
- **V1-4932, AFP-V0-2742.** On the `ci` profile, `corvint test` now handles a well-formed
  `go:unobserved-module` frontier the way it already handled an `UNSELECTED_BINARY_CONSUMER`. It
  keeps the scope the rest of the plan earns and names `go -C <dir> test ./...` in `checks`. The
  confined runner still launches no module unit. CI runs the tests and vet of both nested modules
  (`interop/cem01-go`, `tools/local-authority`) in `go-static` (CIN-V0-008, AFP-V0-380), outside
  the Go shards. The AFP-V0-098 superset guard compares only Go shard packages, so it no longer
  sees a FULL shadow.
- **V1-4933, AFP-V0-2743 to AFP-V0-2745.** A record entry is a sealed CEM directly under
  `.corvint/changes/` or a Markdown file directly under `docs/build-log/`. A token selects a
  literal reader of such an entry only when it resolves to the entry or to its record directory.
  The planner and `gate-affected-select` both apply this, including the gate ledger's `-bounds`.
  A token that resolves to the root or to `.corvint` or `docs` (`".."` with a lone `.corvint`,
  or `"../../.corvint"`) no longer selects. Build-log entries get the resolution narrowing that
  AFP-V0-152 gave sealed CEMs. A unit that locates the root at run time resolves every token from
  the root, which adds no unit for a build-log entry: unbounded readers already select it there.
  For record entries it also closes a gap the AFP-V0-152 rule had, where only parent-only and
  `/` tokens anchored. The ratchet (`make unbounded-readers-check`, record
  `.corvint/record-readers.json`) fails when an undeclared Go test package names either directory,
  or an ancestor below the root a walk could descend from, and the record does not list it.
- **Not done: an unbounded-reader exclusion for `docs/build-log/`.** I measured the 35 recorded
  unbounded readers first. `internal/doccorpus/selfcorpus` runs `doccorpus.Inventory` over the
  whole checkout, which reads documentation. An AFP-V0-772 exclusion would therefore drop a real
  reader, so a build-log entry keeps selecting every unbounded reader (17 of #106's 54 shadow
  packages).

## Limits

- The baseline record lists ten current readers without a declared read scope. Nine are unbounded
  readers. The tenth, `internal/cem/corpusbinding`, really reads every committed CEM. Declaring
  their read scopes would shrink the list. That is follow-up work, and it does not change #106,
  where they are selected anyway.
- AFP-V0-2740 relies on rule (c) for a unit in a sibling fixture that loaded the deleted file. A
  load through a name no literal states is not seen.
- The audit's other causes remain: the `.github/` guard, the CI selector's own rule (d) closure
  (V1-2162) and the fixed shard overhead.

Rollback: revert the lane's three fix commits and the spec commit. Each requirement's Rollback
names the function to drop.
