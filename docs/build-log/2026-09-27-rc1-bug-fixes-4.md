## 2026-09-27 V1-0298 V1-0297 V1-0136 V1-0134 V1-0140 PRS-V1-002: pre-rc.1 adapter fixes, load-robust event tests, and the README as a 1.0 release candidate

One batch of fixes found by the pre-1.0 review, bound and checked once.

V1-0298. A blocked Stop reason was fixed text and dropped the evaluation's unmet reasons. It now
names the closed unmet categories of `policy.unmet` and the keyed `dogfood status` argv, never a
caller check ID. LCP-V0-008 is amended inline and keeps the V1-0295 other-session sentence.

V1-0297. When the adapter watchdog degrades an event that outlived its budget, the packet was not
delivered, but the abandoned worker could still record it. The adapter now refuses the session's
packet when its identity is already valid, and a worker that finishes after the watchdog records
nothing. URE-V0-008 is amended inline.

V1-0136. The provider-kit conformance runner's unsupported-profile probe had no timeout. A provider
that never exits is now reported as a timeout refusal and killed after `WaitDelay`.

V1-0134. The frontier and OCM runners each keep a `hostileStates` copy. One test parses both and
requires decision 0357's six states in order, so the two validators cannot drift.

V1-0140. The recipe test now requires `unsupported-impact-range` and `unsupported-impact-worktree`
each as one JSON error envelope on standard error, with nothing on standard output.

Load-robust event tests. On a host at load 280 to 330 on 12 CPUs,
`TestDogfoodEventSnapshotMissExpiryNamesStaleSnapshot` and
`TestClaudeAdapterStaleSnapshotNamesRemediation` failed twice in a row. Their 3-second event
deadline expired before the snapshot lookup finished, so the event reported the bare
`dogfood-event-deadline`. They now use the package's witnessed deadline: the deadline expires when
the build starts, and a one-minute bound is only a hang detector (decision 0082).
`TestHostAdapterJavaScriptHarnessInterruption` waited 20 seconds for a witness that exists only
after two Go builds. That wait is now a 30-minute hang detector, matching the builds' own bounds.

README. The README described `1.0.0-rc.1` as an experimental extraction alpha. It now presents
the 1.0 release candidate. The stability promise covers exactly the Core surfaces of
`corvint-1.0-product-and-release-v1.md` (`PRS-V1-001`, `PRS-V1-002`). The Status table gives each
surface its 1.0 label. The Core jobs are stated as the ledger records them: task orientation
`VERIFIED`, and change consequence and evidence-carrying completion `UNPROVEN` until `PRS-V1-008`
passes. The limits on retrieval quality, reviewer benefit, performance, platforms and host
authority are unchanged. The release-notes link points at `docs/RELEASE-NOTES.md`.
