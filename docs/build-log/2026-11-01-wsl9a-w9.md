# Tasks CLI friction batch (lane wsl9a, W9)

Lane wsl9a, branch `claude/lane-wsl9a-1101`, base `8daec98ce`. Fifteen tickets were assigned.
This lane delivered six of them, found seven already delivered on unmerged lanes, and skipped two.

## Delivered

- V1-3517, TCL-V0-990. A replay against the real beamfall core store showed the ticket's premise
  was wrong. CORE-0832 was not matched on one rare term: 24 query terms matched, every one in its
  very long acceptance-criteria body, at similarity 0.63. The first draft added an absolute idf
  floor of 3.0. That floor broke `TestTCLV0001` and `TestTCLV0004`, because idf scales with store
  size and the small CLI fixtures sit near idf 0.98. The floor was replaced, as a spec revision, by
  a title anchor: a duplicate verdict now also needs at least one matched query term in the
  candidate's title or ID field. In the frozen TCL-V0-009 eval, every candidate at similarity 0.6
  or higher already had a title term. The eval is therefore unchanged: recall@3 17/17, 10
  refusals, precision 0.50. The reason line keeps the format TCL-V0-002 pins.
- V1-3565, CTS-V0-990. `init` without `queue.json` or `policy.json` now refuses `UNINITIALIZED`.
  The refusal names the missing file, the template directory and `docs/TASKS-EXTERNAL-AGENTS.md`.
  It returns no error and writes nothing. UNINITIALIZED was chosen because the operator, not init,
  authors those files.
- V1-3566, CTS-V0-991. Two changes for a newer policy file. First, a policy with every required key
  plus an unknown top-level key now refuses `UNSUPPORTED_VERSION`, naming its profile and
  policyVersion. Second, every UNSUPPORTED_VERSION envelope names this binary's version. A missing
  required key stays MALFORMED.
- V1-3564, TCT-V0-990. A valued `--template` or `--skeleton` is refused with a message that says
  the flag takes no value and that the ticket kind belongs in the payload. This covers both `=X` and
  a bare word after the flag.
- V1-3515, TCT-V0-991. A `--request-id` over 64 bytes is refused `LIMIT_EXCEEDED`, naming the
  flag, its length and the maximum. The ticket body's assumed limit was wrong:
  `wire.MaxRequestIDBytes` is 64. Codex review found that the first fix covered only
  `mutateCommand`; other parsers such as `ticket note clear` loaded the store first and kept the old
  diagnostic. The spec was revised and the check now runs in `cli.Run` ahead of every parser,
  including the base ID of multi-target and `--batch` forms. Every command-tree node with
  `--request-id` carries the `requestId` member in verbose help.
- V1-3766, TCL-V0-991. The first draft put the original receipt in `receipt`. That broke
  `TestTMV0006_AS03` and `TestCALV0106`, which pin an empty `receipt` as the no-write marker. The
  spec was revised so that `receipt` stays empty on replay and a new `originalReceipt` member names
  the receipt that committed the original. Codex review found that a store on the writer
  checkpoint decided the replay in `mutateWriter` and returned without it. Both routes now share
  one helper, and `TestCALV0190_WriterRouteServesReplaysAndRefusals` asserts parity.

## Friction

- The lane brief asks for a self-seal (`dogfood-finish`), but the charter says not to seal.
  The charter was followed at first; the coordinator then asked for the self-seal.
- Both Codex P2s were gaps in the lane's own tests: each fix was tested on one route or parser
  only. No existing test sweeps every `--request-id` node or compares writer-route and
  complete-route report fields beyond ticket, attempt, generation and detail.
- The brief and the charter name different build-log files. The charter's name was used.
- The WSL ticket store is stale against the Mac store.
- The V1-3517 report misread its cause: the match came from a long body's vocabulary, not one rare
  term. Its reason line, which leads with "rarest term", points readers at the wrong cause.
- V1-3515 assumed a limit that does not exist; the real maximum is 64 bytes.
- TCL-V0-014 says to take the next TCL number, which conflicts with the lane ID block.
- `heavy.sh` needs `-run` or `HEAVY_WHOLE_REASON` even for small packages. A whole-package
  `internal/tasks/store` run exceeds the 600 s command cap.
- WSL `/tmp` (a 16 GB tmpfs) filled up mid-lane. The store tests then failed for that reason
  alone, until `TMPDIR` and `GOTMPDIR` were moved to `~/.cache`.
- The corvint MCP server failed to connect.
- zsh heredoc quoting breaks over ssh; scratchpad scripts piped to `python3 -` work around it.
