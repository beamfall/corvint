## V1-4968: a stale binary returned a narrower plan with exit 0

What was wrong: `corvint affected` and `corvint test` judged their own binary stale (AFP-V0-846)
and printed `DEGRADED self-binary-stale` on stderr, but still wrote the stale binary's plan with
exit 0. A lane or CI step reading stdout and the exit status ran a smaller selection (343 against
356 units in the mbfix observation).

Fix: `selfBinaryStaleRefusal` (`cmd/corvint/self_binary.go`); `degradeStaleAffected` now returns
the refusal for a `self-binary-stale` verdict unless `--accept-stale-binary` is given, for every
affected form (plan, `--full`, `--summary`, `--by-path`, `--snapshot`, text), and `runTest` refuses
the same way before planning. Exit 2, error code `self-binary-stale`, the AFP-V0-846 detail and a
`fix:` clause naming `go install ./cmd/corvint`, `go run ./cmd/corvint ...` and the flag; stdout
stays empty. With the flag, the AFP-V0-846/871 and ACX-V0-750/751 behaviour is unchanged.
`self-binary-unverified` keeps the degradation (retained limit: a stamped commit absent from the
clone could hide a stale binary; a 2-second Git deadline on a loaded host must not refuse plans).
`tools/selection-baseline` and `tools/affected-edit-oracle`, which run one binary over historical
or edited trees on purpose, pass the flag; their fixture planners now read the manifest path after
`--manifest` rather than as the last word. Help, the capability catalog (`make capability-catalog`),
`docs/CAPABILITIES.md` and `docs/LANE-ORCHESTRATION.md` name the refusal.

Tests: `TestStaleBinaryRefusesThePlanUnlessAccepted_AFPV09730` (new; fails on the exit-0 behaviour
because it asserts exit 2 and an empty stdout); the existing stale-binary tests pass the flag for
their accepted forms. Live, the lane head's build run in a checkout of `2f4447b3c`:
`affected --base` exit 2 with 0 stdout bytes and the `self-binary-stale` refusal (1788 differing
paths); `--accept-stale-binary` exit 0 with `degradations: [self-binary-stale]` and 280 units;
`test --dry-run` exit 2 with 0 stdout bytes; with the flag exit 0, `scope=NARROWED`, the
`DEGRADED` line.

## V1-5007: pre-commit selection ignored non-test `.go` edits

What was wrong: `script/heavy.sh` admits a whole package for a changed non-test `.go` file
(ASD-V0-2478), but the lane's pre-commit selector `script/test-run-pattern.sh` selected tests only
by changed-path and requirement-ID keys, so a source edit that broke an existing test printed no
run for that package and the lane ran only its new test with `-run`.

Fix (ASD-V0-3832): the script lists changed non-test `.go` files (committed, staged, unstaged and
untracked; a `.go` under `testdata` is data) and prints `whole: ./PKG reason=source-edit FILE` for
each package that has test files; heavy.sh admits that command without `HEAVY_WHOLE_REASON`. A
`_test.go`-only edit still narrows: the new-side hunk lines (every line of an untracked test file)
select the Test/Example/Fuzz function spanning them (`why TEST FILE:LINE changed`), mark a changed
helper so the fixed point selects the tests naming it (`... changed via HELPER`), and run the
package whole for a changed `TestMain`/`init`, a changed `var (`/`const (` block line or a changed
top-level code line no declaration spans (blank, comment, package and import lines are inert).
The SUMMARY line ends with `sources=S`. Test files now include untracked ones.

Tests: `script/test-run-pattern_test.sh` (`make test-run-pattern-test`): the source edit in four
states, the fault-injection fixture (`internal/e/lib.go` returns 2 while `TestAnswer` pins 1;
selected as `whole: ./internal/e reason=source-edit internal/e/lib.go`), `testdata` and testless
controls, edited test, edited helper, new test, untracked test file, import-only edit, changed type,
changed `TestMain`. Fault injection confirmed by hand before the toolchain run was removed from the
self-test (a shell self-test that runs `go` must declare a repository read it does not have,
docs/SHELL-TEST-REGISTRATION.md): `go test ./internal/e` on the fixture fails with
`Answer() = 2`. heavy.sh's side: `TestASDV02478SourceEditRunsExistingTests` PASS (36 s).
