## Contracts

1. V1-1427, `MCPV0-038`. The bridge previously folded gokernel's `repository-probe-timeout` into
   `repository-unavailable`. Now that code passes through unchanged on the `/0` profile, and its
   `/1` `reasonClass` stays `unclassified`.
   - A new code was chosen instead of a new `reasonClass` value. The reason-class set is closed by
     MCPV0-028 and decision 0383. The code set already lists repository codes per failure. V1-1038
     owns no code or class here.
   - Caller cancellation is checked first, so it still wins.
   - Wire change: one new closed `code` value, documented in the spec's failure-code table and in
     `docs/MCP-SERVER.md`.
2. V1-1428, `GLTP-V0-054`. Post-run authority is revalidation, identity observation and lease
   release. If every failed call failed only after its own deadline, and none reported drift, the
   refusal is now `ErrAuthorityUnavailable` ending in `: post-run authority deadline expired`.
   - Any typed drift stays `ErrAuthorityDrift: post-run revalidation`, even one returned after the
     deadline.
   - So does any failure returned in time, malformed observed digests, and a run-root layout
     failure.
   - Receipts and wire bytes are unchanged:
     - Only the nil-ness of the refusal reaches the receipt.
     - A post-launch refusal emits no `go-live-error/0` diagnostic.
   - GLTP-V0-053(b) and GLTP-V0-041's citations (`:454`, `:457`, `:1279`) are amended to match.
3. V1-1429, GLTP-V0-041. The parent verifier's tree walk is still sequential. Regular files are now
   hashed on at most eight concurrent readers (`min(8, GOMAXPROCS)`), and results are applied in
   walk order.
   - The digests, the input rows and the first refusal reported are the sequential walk's. Refusals
     are reported in this order: the earliest queued file's error, then the cumulative
     `MaxTreeBytes` limit, then the walk's own error.
   - The 15-second bound and GLTP-V0-027 are unchanged.

## Review

One Codex round (`codex exec -s read-only`, diff `21b241fed..3df67e676`) reported one P2 finding:
- After the hashed total crossed `MaxTreeBytes`, every file not yet read was skipped with
  `ErrLimit`. That included a file queued before the crossing position, whose read could have
  returned `ErrDrift`. The first refusal therefore differed from the sequential walk's.
- Codex reproduced this with a scheduling test under `-race`.

Fixed in this change:
- The hashers now record the highest queue position counted when the bound is first crossed.
- They skip only files queued after that position. The sequential walk refuses at or before it, so
  it never reads those files.
- Every earlier file is still read.

Evidence for the fix:
- `TestTreeHashersReadEveryFileBeforeTheLimitPosition` hashes the crossing file first, then an
  earlier drifted file, then a later missing file. It requires `ErrDrift`, then a skipped `ErrLimit`,
  and `finish` returning `ErrDrift`.
- Mutation: making the skip ignore the position (the reviewed behaviour) FAILS with "bound
  exceeded, want its own ErrDrift".
- The package passes under `-race`.
- `TestProviderCommandUsesPinnedLiveParentAuthorityE2E`, `TestProductionParentBindsNonASCIIRepositoryPath`
  and `TestExecuteNormalCompletionHasNoRecordedSurvivors` PASS at load 14-54.
- A GOROOT scan takes 0.82-0.91 s at load 48 with the same digest.

Codex also tried to record the finding as a Tasks note on V1-1429. The store refused it (`NOTE_SET`
for role `OPERATOR`). Codex reported no other findings, covering timeout classification,
malformed-digest handling and citations.
