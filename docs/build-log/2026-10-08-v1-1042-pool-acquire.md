# Pool acquire and early return during a live attempt (V1-1042)

Date: 2026-10-08. Ticket V1-1042; GitHub [#696](https://github.com/beamfall/corvint/issues/696).
Requirements: `CAL-V0-197`..`CAL-V0-203` (proposed) in `docs/specs/corvint-tasks-agent-leases-v0.md`.

## Problem

A pool member could be taken only by `claim --pool` and was held until the attempt ended. An agent
that found mid-task that it needed an isolated environment had to release and reclaim, which costs
a generation. An agent that was finished with one kept it occupied until completion.

## Decision

- Two new lease verbs:
  - `POOL_ACQUIRE` (`corvint-tasks pool acquire --attempt --generation --pool --request-id`) gives
    a live external-agent attempt one member. It is fenced like every attempt verb and admits by
    the pooled-claim steps (barrier, `requiresPool`, priority yield, `--exclude-member`,
    `--exclude-authors` for review or integrate attempts, health preparation, free-member scan).
    The attempt's own lease holder and stage stand in for the claim's `--holder` and `--stage`.
  - `POOL_RELEASE` (`pool release --attempt --generation --allocation --request-id`) quarantines
    the exact current allocation. It records `releasedPoolAllocation` on the attempt, which stays
    live.
- One allocation per generation. Acquire refuses an attempt that holds or has returned one. This
  keeps the CAL-V0-098 author history exact: an ended generation names the returned member through
  the fallback in `endedHistory` (CAL-V0-202).
- No change to the lifecycle verbs. `poolPosts` already acts on whatever allocation the attempt
  holds at write time. Completion and release with none are the unpooled path, and ending with an
  acquired allocation quarantines it as a claimed one does (CAL-V0-030).
- Refusals:
  - a shared allocation is not returned early;
  - a supervised attempt is refused by the existing attempt-verb guard;
  - an attempt that returned an allocation cannot attach to a supervisor, because supervised
    generations record no member history.
- Barriers: pool release is listed in `Cancels`, so it passes an `ALL` barrier. Acquire is
  `PAUSED` under any barrier.
- Store routing:
  - acquire goes through the pooled-claim health path, with the holder and stage read from the
    locked attempt;
  - `poolAdmissionSource` shares the clean-source and member-config checks with the claim path;
  - the replay result is read from the receipt's attempt post (`receiptAttempt`), not from the
    current attempt.
- CLI and help:
  - `pool acquire` always reports `poolAllocation` (null when refused);
  - `pool release` reports `releasedPoolAllocation`;
  - both are added to `ReadVerbs`, the usage list and the command-help usage and notes.
  - `claim --pool` is unchanged.

## Failure modes retained

- A binary that predates this change refuses the `releasedPoolAllocation` attempt key as
  `MALFORMED`.
- A clean handoff across a policy change refuses `STALE_POLICY` once the allocation differs from
  the first attempt record's allocation.
- Lane-untouched release is unavailable once the direct-origin binding is gone.
- The writer fast route does not cover the new verbs.
