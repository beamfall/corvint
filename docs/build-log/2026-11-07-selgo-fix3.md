plus the merge-forward rebind onto `origin/main` at `cb4037359`.
Ticket: V1-4931. Requirements: AFP-V0-2740 and AFP-V0-2741 in
`docs/specs/affected-plan-selection-v0.md` (wording amended, no new ID).
Owner goal: never fewer tests than needed.

## Finding

The PR review (Greptile, P1) flagged `seed`'s `deletedFixture` admission (AFP-V0-2740) together
with `participants` in `internal/liveverify/affected/select.go`.

- The admission drops the `UNINDEXED_SOURCE_PATH` fallback for a non-Go fixture deleted from below
  a Go-hosted `testdata` directory.
- `participants` decides which dirty paths are unowned through `claimantsOf`, and the claimant's
  `Owns` still claims the deleted file (Python for `input.py`). The path was therefore left out of
  every other plugin's unowned-path checks (AFP-V0-511).
- A test in a third language that reads the fixture by a computed name, such as a Ruby spec with a
  path-open `implicit-test-dependency` entry, lost that entry. With no unknown left, its suite need
  not run.
- Before AFP-V0-2740 the fallback forced FULL, so this gap was new with the round-1 fix. The spec
  already said the path "stays unowned" for `frontierUnknowns`; the code did not do that.

## Decisions

- **`participants` lists a deleted fixture among the unowned paths although a plugin claims it.**
  For a claimed dirty path below a `testdata` directory it asks `deletedFixture`, the same predicate
  `seed` used, so exactly the admitted paths are added. The claimant still takes part as the owner
  of a dirty path, so its own entries bear in full, as before.
- Every other plugin then applies the ordinary unowned-path rules to the path: a path-open entry
  bears, a source-bound entry does not, and a fixture-closed entry outside the fixture does not
  while the plugin lists nothing below that `testdata` directory. The deleted fixture is treated
  like any other unowned fixture path, with no special case.
- The frontier hint still says "no plugin owns the dirty path". That is true at unit level (no unit
  lists the file), though the claimant's `Owns` matches it. The wording was left unchanged.
- **AFP-V0-2740's text now says this outright**: the path stays unowned although the claimant's
  `Owns` claims it, and a third plugin's path-open entry still bears. Rollback now covers both call
  sites. AFP-V0-2741 now says the plan carries no unknown *for the path itself*: an entry that the
  path bears under AFP-V0-511 is the same unknown in both selectors.

## Tests and fault injection

- `TestDeletedFixtureStaysUnownedForOtherPlugins_AFPV2740`
  (`internal/liveverify/affected/deletedfixtures_test.go`). Setup:
  - a deleted `pkg/testdata/flows/app/input.py`, with a Python unit left in the sibling fixture
    `pkg/testdata/kept`;
  - a Ruby-shaped plugin (`reaching`) whose spec has a path-open `rb:implicit-test-dependency`
    entry, a source-bound `rb:relative-load` entry and a fixture-closed `rb:ambiguous-framework`
    entry.

  The test asserts:
  - the deleted path raises no entry of its own;
  - the implicit entry bears, with the hint naming the deleted file and a `UNOWNED_DIRTY_PATH`
    bearer for language `rb`;
  - the source-bound and fixture-closed entries do not bear;
  - the claimant's own entry still bears;
  - the scope is `UNKNOWN`;
  - `go:pkg` is selected and `go:other` is not.
- Fault injection: with the test added and `select.go` unchanged (merge `2a029d04d`), the test fails:
  `frontier [py:dynamic-import:…]: the computed reader's rb:implicit-test-dependency:spec/reader_spec.rb
  must bear through the unowned deleted fixture`. It passes with the fix.
- `TestDeletedFixtureIsFixtureData_AFPV2740`, the AFP-V0-2440, AFP-V0-446 and AFP-V0-511 fixture and
  unowned-path tests, and `TestSeamWidensRatherThanNarrowingOnUnknownInput` pass unchanged. The
  whole `internal/liveverify/affected` package passes (157 s), and so does `internal/gateselect`.
