## Test slices: not regenerated (residual)

`ci-test-slices generate --root . --revision 5163d1ed… --run-url …/38485555207 --shards 8` refused
before any work:
`shard-2.json: package github.com/Beamfall/corvint/internal/tasks/store has two terminal outcomes`.
Since AFP-V0-041 landed (#736), every full run executes the split store package as two slices in two
shards, so each run holds two terminal outcomes for it. AFP-V0-041 (5) requires generate to refuse
a repeated outcome. The tool therefore cannot regenerate the slice file from any hosted run made
while the file splits a package, and no go1.27.2 run predates the split. `replay` refuses for the
same reason. Regenerating from such a run needs a spec amendment and a tool change: combine a
split package's slice outcomes, as `ci-shard-costs refresh` already does. That is outside this
lane, which adds no requirement and edits no tool, so it is left to the orchestrator as a follow-up.

`.github/cishards/test-slices.json` stays as committed (source run 38078093034, `3b428343`,
`go1.27.1`). It remains valid under `SourceGoVersions`, and its catch-all keeps tests added since
generation in exactly one shard. In this run the catch-all took 534.0 s and the named slice
361.6 s, so a re-cut would rebalance the store halves.
