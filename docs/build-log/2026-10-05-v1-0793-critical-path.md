# 2026-10-05: V1-0793 corvint-tasks critical-path read

## Intent

Owner request [issue 588](https://github.com/beamfall/corvint/issues/588) (ticket V1-0793), with owner
answer 2026-10-05 (D8). On 2026-10-04, two handoffs circulated a wrong path to a gate because finding the
real open dependencies needed manual `ticket show` walks. `corvint-tasks critical-path <ticket>` returns
that closure as one bounded read.

## Requirements

`CAL-V0-079` (command, closure, chains, node facts), `CAL-V0-080` (bounds, truncation, cycles) and
`CAL-V0-081` (pure read, forward-compatible blockers, `NOT_OBSERVED` estimate). They are defined in the
`## Requirements` section of `docs/specs/corvint-tasks-agent-leases-v0.md` (subsection "V1-0793
critical-path read (issue 588)"), so the OCM reader enumerates them. The trailing amendment keeps scope,
failure modes and evidence. The IDs sit six above the highest CAL ID
seen on main and the batch branch (CAL-V0-073). Integration can renumber them without other changes.

## Change

- **New verb:** `internal/tasks/cli/critical_path.go`, registered in `ReadVerbs` and command help.
- **Profile:** `taskman-critical-path/0`, a single item inside the existing command-result envelope.
- **Closure:** a DFS walk that follows unsatisfied and `NOT_OBSERVED` dependency edges. It does not
  follow edges inside one dependency cycle.
- **Chains:** one longest root-to-frontier path per frontier node, longest first. This avoids
  enumerating every path.
- **Bounds:** 256 nodes and 32 chains, as D8 set them. The item carries counts and `truncated`.
- **Node facts:** each node merges certain blockers and unknowns, and carries a live-attempt block
  (attempt ID, phase, holder, stage, member, `phaseSinceSeq`, `lastHeartbeatAt`). Any fact the read
  could not observe is the string `NOT_OBSERVED`.
- **Cycle helper:** `ticket.Inventory.CycleMembers` exposes the existing Tarjan components.

## Review repair

The first Codex review returned CHANGES_REQUIRED with three findings, repaired as follows:

1. **Planner parity.** Blockers now come from `transaction.ClaimBlockerObservations`, the planner's own
   derivation, exported from `claimBlockerObservations`. They cover pool, pause, cutover,
   enforced-budget, view blockers and unknowns except `COVERAGE_UNKNOWN`, and `RETRY_EXHAUSTED`.
   `firstBlocker` is the first certain blocker, else the first unknown, which matches `plan preview`.
   A nil reservation set leaves attempt liveness `NOT_OBSERVED` instead of panicking. The item names
   its scope with `blockerScope: RECORDED_DEFAULT_EXTERNAL_AGENT_PLAN`.
2. **Linear cycles.** The walk keeps compact records and reads cycle identity through
   `Inventory.CycleKey`. It calls `CycleMembers` once per cycle, and derives blockers only for
   returned and human-chain nodes. A 10,000-ticket ring measured about 139 MB of total allocation,
   with 256 blocker derivations. The source-estimated cost before the repair was several GB.
3. **OCM visibility.** The requirements moved into `## Requirements`. A scratch OCM parse
   (`requirementsFromBlob`, since removed) enumerated CAL-V0-079..081 (72 IDs, limit 256).
   CAL-V0-073 still sits in its own trailing amendment, outside this ticket's scope.

## Non-goals

- Duration estimates (D8)
- Dispatcher-private progress history
- Prerequisite, LOOP_DETECTED or ESCALATION_PENDING producers. Blocker codes and `waitingOn.kind` are
  open sets, so these can appear later without a profile break.
- Paging or owner-set bounds

## Failure modes

- An unknown ticket refuses.
- A malformed argument returns `MALFORMED`.
- A cycle is reported once with `CYCLE` and never loops the walk.
- A missing dependency stays a `DEPENDENCY_MISSING` blocker.
- A journal-absent store reports attempts as `NOT_OBSERVED`.
