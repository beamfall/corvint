# Lane dogfood-r (wave 7): dogfood-change run counts, test-hook analysis

Lane dogfood-r, base `5ffe8ed4a37eb67af5f5176ff17eb6df6e8911bb`, branch `claude/lane-dogfood-r-1101`.
Requirements: `ASD-V0-955` (V1-1629) and `ASD-V0-956` (V1-2426) in
`docs/specs/corvint-self-development-v0.md`. `make requirement-ids-free PREFIX=ASD-V0 RANGE=955..959`
reported the block free at origin/main; 957..959 are unused.

## Problem

- V1-1629 acceptance 3 asks for the median dogfood-change runs per lane over the next batch, with
  the counts retained. `ASD-V0-907` (dogfood-w5) writes each run to
  `<git-dir>/corvint/dogfood-change-runs.tsv`. For a linked worktree that is
  `.git/worktrees/<name>/corvint/`, which `git worktree remove` (run by `script/lane-clean.sh`)
  deletes. So the counts were lost as soon as a batch's lanes were cleaned, and no command read
  them across lanes.
- V1-2426: the perf-1022s lane (beamfall/corvint#1552) chose which `internal/tasks/store` tests
  could run in parallel by hand. It missed the hook setters in `export_test.go`
  (`SetPublishFaultForTest`) until injected publication faults leaked into parallel peers. The
  analysis was never committed, so nothing guards against the same mistake.

## Decisions

- V1-1629 (`ASD-V0-955`): `script/dogfood-change.sh` also appends each run, with branch and
  worktree columns, to `$(git rev-parse --git-common-dir)/corvint/dogfood-change-runs.tsv`. That
  ledger outlives worktree removal and holds every lane worktree of one repository on a host. The
  per-worktree file of `ASD-V0-907` stays as it is, because finish-lane's `RUNS` line reads it.
  `make dogfood-change-runs SINCE=<UTC>` prints a `run-count BRANCH N` line per lane and the
  median. A lane is keyed by its branch, not its worktree path: each lane has one branch, while
  its path can be reused. A detached run counts under its worktree path. The trim runs only past
  10000 lines, so a concurrent append is rarely lost. Appends are single short `printf` writes to
  an `O_APPEND` file. No lock is used, because macOS has no `flock(1)`.
- V1-1629 measurement method: the ledger is per host. `script/lane-transcript-metrics.py`
  (`ASD-V0-834`) gives the transcript count on each host. Both are needed: the ledger keeps only
  runs made through the script, and the transcripts keep only runs whose session still exists.
  `docs/LANE-ORCHESTRATION.md` §7 now tells the orchestrator to run the report on each lane host
  before `lane-clean.sh`.
- V1-2426 (`ASD-V0-956`): `internal/tasks/testhooks` is a syntactic analysis built on `go/ast`. It
  needs no build and no type checking. Only functions declared in `_test.go` files count as
  writers. The first probe also read production files and flagged about 300 store tests, because
  `Lease`, `claim` and others write package caches. Those are not test hooks. A method call on a
  package variable, such as a keyed `sync.Map` seam (`SetStorePublishFaultForTest`), is not a
  write. This matches the keyed seams the perf-1022s lane introduced to make tests parallel.
  Calls are matched by name and closed over calls between test-file functions, so a setter in
  `export_test.go` reached as `store.SetX` from `package store_test` is found, directly or through
  a helper. The package sits under `internal/tasks/` so the store guard test needs no
  `boundary_test.go` exception.
- The guard (`TestASDV0956NoParallelTestWritesAPackageHook`) covers only `internal/tasks/store`.
  A probe on the base found 74 hook users there and none parallel. `internal/tasks/cli` (135
  users), `journal` (36) and `service` (38) had none parallel either. Guarding them is a one-line
  test each and is left out of this ticket's scope.
- Files outside this lane's area: `internal/tasks/testhooks` (new) and
  `internal/tasks/store/test_hooks_guard_test.go` (new test only) are in the tasks lanes' tree.
  `script/lane-scripts_test.sh` group 21 (the analyzer-output fixture) failed on the base. Its
  empty `plan.tsv` is refused as `CITATIONS:empty` (`ASD-V0-903`, dogfood-w5) before the analyzer
  check it exercises. The fixture now has one plan row. This test-only fix is in the V1-1629
  commit.
