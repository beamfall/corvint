# batch-1107x: selbatch, mbrescue, mbapproved, selgo and unbrd on one branch

The owner asked on 2026-11-07 to "merge the 6 together here and then ci the completed 1". mbfix
(#130) had already merged into `origin/main` `c3b29cbb54d31c8526d3cce4ad74356b6fb9b943`, so the
batch is based there and carries the other five lane PRs. CI runs once on the combined result.

## Method

The batch follows the batch-1104b method. Each lane is one code-only work commit built on the
current batch tip. That commit is bound and sealed with `BASE` set to the tip, then merged into
`claude/batch-1107x` with `git merge --no-ff` and no hand resolution. The lane's net change is
taken from the mainline commit of its last merge-forward (or its fork point) to its sealed head,
without `.corvint/changes`, `.corvint/change.cem.json` and `.github/**`.

- selbatch and mbrescue were applied as a three-way patch (`git apply --3way`).
- mbapproved forks at `4052b8540`. It shares sub-lanes with mbfix (second merge base
  `0b5ef4676`), so a squash merge (ort, virtual merge base) was used instead. That method was then
  kept for selgo and unbrd, which have the single base `cb4037359`.
- Every lane's `.github` edits are on `claude/ci-1107x`, which lands after this batch.

## Decisions where lanes met

Each work commit's message lists its resolutions in full. These are the ones where two lanes, or
a lane and main, did not simply add text side by side:

- **Bridge constructors (V1-3916, fixed in mbfix and mbrescue).** Every exported `New*` returns
  `error` (mbrescue). Main's unexported `*Error` helpers and exported wrappers stay. Main's
  `typedRegistry` adapter is removed as dead. Two main tests that reused an `error` variable for a
  `*Error` result now use a fresh variable.
- **V1-4169, implemented twice.** It is mbfix DCW-V0-7403 and mbrescue DWC-V0-3726. mbrescue's
  later duplicate check falsely refused mbfix's at-limit-raw-over case, so it is removed. mbfix's
  refusal now also prints the DWC-V0-3726 fix and the nothing-bound line.
- **Accepted mainline rules over experimental lane expectations.**
  - DCW-V0-7401 admits a bare anchored `-run` name, so DWC-V0-3722's caret refusal now only
    hints on lines refused for another reason.
  - DWC-V0-926/927 drop the unanchored same-change guess that DWC-V0-749 expected.
  - The affected specs carry amendment notes for both.
- **Release-artifact read scope.** mbrescue's later rescue-c fail-closed decision (PUB-V0-671)
  keeps `conformance/release-artifact-v0` on the UNBOUNDED_READER floor with no read-scope
  declaration. AFP-V0-2361 and AFP-V0-2363 (mbapproved) are amended to match.
- **Reader resolution (AFP-V0-2203 against AFP-V0-2743..2746).** Main's no-placement rule holds
  for every path except a CEM and a record entry. Record entries take selgo's `reachesRecord`
  rule.
- **Selection-baseline workers.** Main's ASC-V0-777 formula stays, with mbapproved's memory bound
  applied in `replayJobs`. mbapproved's replay test turns main's ASC-V0-778 result cache off.
- **AZU-V0-006 with AFP-V0-2992.** unbrd's code-runner walk now selects the exec user's test. The
  plan runs that test, so AZU-V0-006 counts it as an observer, and the selbatch case expects no
  gap.
- **`.corvint/shell-foreign-callers.json`.** It is written in compact array form because the
  union exceeds `MaxShellForeignCallerBytes` (64 KiB) in the expanded form. It is now 65,290 bytes.
