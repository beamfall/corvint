# 2026-10-10: CI shard cost table refresh (V1-0714)

Contract: AFP-V0-022 in `docs/specs/affected-plan-v0.md` (cost bytes regenerated by
`tools/ci-shard-costs refresh` from one complete hosted run). Procedure:
`docs/build-log/2026-10-04-ci-shard-cost-refresh.md`. Partition logic and membership rules are
unchanged.

## Finding

The table last refreshed in 3fcf9aa5 (2026-10-05, run 37280783904) had drifted. Against main run
<https://github.com/beamfall/corvint/actions/runs/38055182050> (main at `e0ef9aa8`, 320 packages,
7,684.8s of package test time), `tools/ci-shard-costs check` on the six `go-product-shard` logs
reported 5 `drift` and 7 `missing` lines. The largest was `internal/tasks/store`, recorded at
870,752ms and observed at 1,871,826ms; `internal/appmap` (131.7s) had no entry. Observed shard wall
times were 2348/1265/1295/977/1292/1490s; replaying the run's package times through the old table
gives shard test sums of 2100.8/1113.2/1148.7/863.9/1145.4/1312.8s against an ideal of 1280.8s.

## Change

`.github/cishards/package-costs.json` is regenerated by
`go run ./tools/ci-shard-costs refresh --revision e0ef9aa891edbd84b19b1f30f12bc6ed13635a96
--run-url https://github.com/beamfall/corvint/actions/runs/38055182050` over the six shard logs.
The refresh did not refuse: no package the old table listed was absent from the logs, so
`--allow-removed` was not used. Seven packages were added and none removed.

## Evidence

- After the refresh, `check` on the same six logs prints nothing and exits 0.
- `go test -count=1 ./.github/cishards/... ./tools/ci-shard-costs` passes.
- Replaying the run's per-package times through the partition built with the new table, on the
  `go list ./...` universe of `e0ef9aa8` (every universe package observed), gives shard sums of
  1871.8/1162.8/1162.8/1162.8/1161.8/1162.8s. Shard 0 holds `internal/tasks/store` alone.
- `internal/tasks/store`, at about 1872s, exceeds the ideal per-shard sum of 1280.8s by itself.
  Package-level partitioning cannot bring the slowest shard below that package; the predicted
  critical path drops from 2100.8s to 1871.8s of test time, about 229s. Shortening it further
  needs that package to get faster, which is separate work.

## Limits

- The sums are a replay of one run's times, not a hosted measurement: hosted shard timing after
  this change is `NOT_OBSERVED` until a run on the merged table.
- Per-run variance is not measured; `internal/tasks/store` alone moved from 372–871s to 1872s
  within a week. When it gets faster, `check` will report drift and the table should be refreshed.
- The partition digest (`ci-shards --profile`) changes with the table bytes, as with every refresh.

## Rollback

Revert this change. The previous table bytes and partition digest return; an invalid or missing
table still yields the complete lexical round-robin partition.
