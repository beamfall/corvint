### History of the chi preregistration

The chi preregistration was amended three times before this seal. All of it was local; the
superseded versions survive only as digests.

**Deviation 1** (6d26dd82). The first smoke showed completion could not pass by construction:

- Each loop clone now gets the six DCW-V0-023 adopter ignore entries.
- Loop variants run at the L0 run 1 path.
- The run refuses a missing archive, and a candidate whose `--version` is not the target.

**Deviation 2** fixed nine defects from an independent review:

- the preregistration digest seal;
- the real L3c commit past the bind;
- checked mutation commits;
- the started-run marker;
- Git and Corvint isolation;
- `NOT_PRODUCED` observations;
- named candidate refusals.

**Deviation 3** takes the owner fork left open after smoke 4. L3c and L1-L3 rerun
`corvint dogfood change BASE` after their commit, and the verdict comes from `dogfood check`. It
also:

- resolves `--work` to an absolute path;
- counts a refused designated case as informative only when its declared refusal is among its
  refusals;
- names the cause of every `dogfood-report-drift`;
- tightens the savings claim (V1-0369);
- scrubs inherited `CORVINT_*` variables;
- adds `--benchmark-dir`, `corpusPathspec` and `pathExclusions`. An excluded path is also never
  the L1 stale probe, as in daily-loop-v1. chi sets neither field, and its corpus derives byte for
  byte as before (`corpusSha256`
  `2cce3e8bb2e55b5ae69b6d9da91af641e427ff77f0b7ac9f5820ca16342d79c3`);
- looks for the CEM-level bind only among the loop's own first-parent commits after the pin.
  Otherwise, in Corvint, a failed L0 bind would have been replaced by a CEM that Corvint itself
  committed earlier.
