## Decisions

- **V1-1554: compare digests as sets, in the TEST phase.** The runner does not parse the APK
  manifest, so it cannot pair each APK with its package. Comparing the installed set with the
  bound set catches a reinstall, a missing app and an extra APK. The check runs in the same
  `adb shell` session as the instrumentation and prints a fixed line. A separate DISCOVER phase
  would rely on adb's exit status, which `TRE-V0-087` already treats as droppable. Historical raw
  captures therefore no longer parse as complete; the fixture files are unchanged, and tests
  prepend the line.
- **V1-0819: the run identity is the stream's SHA-256.** Two real runs differ in timings, so they
  are two runs, and identical bytes are one recording. That gives idempotent rerecording without a
  caller-supplied run id. Provenance is declared by flags and is `NOT_OBSERVED` when absent. A
  stand-alone `tools/` binary keeps it out of Core, MCP and every read path.
- **V1-2232: decline a chunked or delta snapshot store for 1.0 (measured).** The index was built
  with the base source (`go build ./cmd/corvint` at `6c967b21`) in a scratch clone at the base.
  The cold snapshot was 166,680,126 bytes, 9,003 sources. After a one-line edit of one Go file
  and a commit, `corvint index` took 16.8 s wall (`buildMilliseconds` 10,694, with IDX-SNAP-V0-037
  reuse) and wrote a new 166,680,217-byte snapshot. Comparing the two files:
  - The common prefix is 113 bytes. Fixed 4 KiB and 64 KiB chunks reuse 56.5%.
  - Content-defined chunking (gear hash, average 8 KiB) finds 98.3% of the new file's bytes
    already in old chunks, so about 2.8 MB would be written. With a 64 KiB average, 94.2%.
  - The read side costs more. Reassembling the 11,874 chunks from a chunk store took 235–267 ms,
    against 77–95 ms for one-file reads (warm cache, Python, three repeats), on every read verb.

  The trade is roughly 164 MB fewer writes once per `HEAD` move, against about 160 ms more on
  each of many reads. It would also need a new on-disk format with chunk garbage collection,
  which invariant 7's benchmark/format gate would have to admit. The snapshot stays one file for
  1.0. A segment format that keeps a single sequential read, such as an append-only pack with a
  chunk index, stays a post-1.0 option, and these numbers are its baseline. The scripts were
  scratch, not committed.

## Friction

- `go test ./tools/local-authority` from the repository root fails with "main module does not
  contain package". The directory is its own module, and the earlier build log cites its test
  without saying so. Repro: `go test -run TestPLEV0013CodecPackageAdmitsTestdata ./tools/local-authority`.
- The installed `corvint` is build 30 at `71c4b196`, not the lane base, so any measurement of base
  behavior needs a 75 s `go build ./cmd/corvint` first. Repro: `corvint --version` in a base
  worktree.
- The host lacks `/usr/bin/time` and `bc`, so wall time and RSS of a measured command need ad hoc
  `date +%s%N` arithmetic. Repro: `command -v time bc`.
- `make spec-requirements` enforces the 160-character Agent digest Claim only when it regenerates,
  after the spec is staged. Repro: stage a spec whose Claim is 161 characters, then run
  `make spec-requirements`.
- The LSP FEATURE ticket bodies run to about 30 KB each of compressed narrative, with words run
  together ("alltuplesUNQUALIFIED"). Finding which criterion is still open takes a full read. Repro:
  `corvint-tasks ticket show V1-0481`.
