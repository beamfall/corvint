# go1.27.3 admitted as a patch revision of the go1.27.2 pin (V1-2118, decision 0547)

Date: 2026-10-20. Base: `9a63cf8f7` (`origin/main`). Owner, in chat: "allow 1.27.3 — it's only a
revision, not a big deal". Decision: `docs/decisions/0547-go-1-27-3-revision-admitted-2026-10-20.md`.

## Failures reproduced on the go1.27.3 host

- `make go-version` and therefore `make windows-vet` refused, because the check named only
  go1.27.2.
- `TestCEMV1144StableStructuralMark` (`internal/cem/workflow`) failed: the import-reorder case was
  UNSUPPORTED with exit 2 instead of ACCEPT 0. The root cause was the `CEM-V1-050` structural
  runtime gate, which admitted only go1.27.1 and go1.27.2, so go1.27.3 refused with
  `unsupported-structural-runtime`. Admitting the tuple fixes it. The test is unchanged.
- Five `cmd/corvint-go-test-provider` tests failed: `TestProviderCommandUsesPinnedLiveParentAuthorityE2E`,
  `TestProductionParentBindsNonASCIIRepositoryPath`, `TestExecute{Normal,Interrupted}…NoRecordedSurvivors`
  and `TestProductionParentDriftAndTransportAreDistinct`. Each reported "provider fixture requires
  go1.27.2". The provider's frozen tuple is go1.27.2 by design (`provider.GoVersion`, decision 0522).
  The fixture defaulted to the harness's own GOROOT. With `CORVINT_GO_LIVE_TEST_GOROOT` pointed at
  the official go1.27.2 module-cache toolchain, the package passes unchanged. The fixture now finds
  that toolchain itself when the harness compiler is a different revision. The exact
  `go version` assertion and `TestProviderFixtureRejectsUnpinnedToolchain` are unchanged.

## Structural tuple packet `protocol/cem-1.0/structural-tuples/go1.27.3/`

It was produced the same way as the go1.27.2 packet (decision 0522, build log 2026-10-11), on
darwin/arm64. Three toolchains were compared:
- the official `golang.org/toolchain` go1.27.1 module from the module cache;
- the official go1.27.2 module from the module cache;
- Homebrew go1.27.3.

Each run used `GOTOOLCHAIN=local GOENV=off` and an explicit GOROOT.

- Standard library source. The `go list -deps go/format go/parser go/scanner go/ast go/token`
  closure is the same 70 packages under all three toolchains, and its listing digest
  `f2fe3f7e…` matches the go1.27.2 packet. All 2323 files directly in those package directories
  are byte-identical between go1.27.2 and go1.27.3. Against go1.27.1, only the four packages that
  0522 recorded differ. The eight structural trees have identical digests under all three
  toolchains. The tree-digest method is recorded in `TUPLE.json`. It is not the go1.27.2
  packet's unrecorded method, so its digests compare only within this packet.
- Behaviour corpus. A scratch `_test.go` harness in a detached scratch worktree (never committed)
  read a `git archive` extract of `9a63cf8f7`. It covered 4621 `.go` files (list digest
  `54e0a162…`) and the 12x12 `testdata/structural` matrix. It recorded the same per-file
  observations as the 0522 harness, with `ast.Fprint` filtering `Scope`. For go1.27.1, the scratch
  worktree's `go` directive alone was lowered. The output was 1791406 bytes with sha256
  `2fefcab4…`. It was byte-identical under go1.27.1, go1.27.2 and go1.27.3, and a repeat go1.27.3
  run was identical.
- S0E results. With go1.27.3 admitted, `TestStableS0EPublicCases` (54 cases pass, and the two
  go1.24.13-recorded cases stay NOT_RUN as on go1.27.2) and `TestStableS0ELinkedControl` pass
  through the tuple binding. The only substitution is `runtime.goVersion`.

`predecessorTuple` is `go1.27.1`, because the frozen S0E packet records that release. The packet
consumers (`internal/{doccorpus,witness,witnesscollapse,console}`, `internal/cem/cli`) require
it. Qualification stays `EXPERIMENTAL_TUPLE_PENDING_FULL_CORPUS`. Linux, Windows and CI-hosted
go1.27.3 runs were NOT_RUN.
