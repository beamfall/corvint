## Landing review fix (2026-11-04): subtest failure before the alarm

The landing review found that the event sink dropped every event whose test name has a `/`, so a
`TestAdd/check` assertion failure followed by a hang left `TestAdd` with no outcome, and
`alarmEnded` scored the mutant BUDGET_EXCEEDED instead of a kill, against FPK-V0-740. The sink now
records a subtest's `fail` as its top-level function's failure (the name before the first `/`); a
subtest's pass or skip still leaves the function unattributed. `TestFPKV0740MutantAlarmIsNotAKill`
and `TestFPKV0740GroupedMutantAlarmIsNotAKill` add a subtest failure then the alarm, and
`TestEventSinkLeavesAnUnfinishedFunctionUnattributed` covers nested subtests and the fold; all three
fail against the previous sink. On the grouped path the kill comes from the claim's alone re-run,
which records no witness.
