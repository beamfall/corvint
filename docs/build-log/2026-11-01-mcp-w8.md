## V1-3700 (P1): unusable `--root` exits before the handshake — MCPV0-950

Decisions:
- Toplevel resolution is a physical filesystem walk (`rootbind.Resolve`): the root itself when it
  holds a `.git` marker, else its nearest ancestor that does. It does not spawn `git rev-parse
  --show-toplevel`. The walk gives the same answer for the marker kinds `rootbind.Bind` accepts. It
  needs no subprocess, and it cannot be moved by `GIT_DIR`, `GIT_CEILING_DIRECTORIES` or
  `safe.directory`. A root inside a `.git` directory is refused by name. The toplevel's marker
  still goes through `Bind`, so the MCPV0-001 identity pinning is unchanged.
- Only a single plain root starts UNAVAILABLE. Aliased roots, `--follow-ref` and
  `--corpus-artifact` still need a repository at startup. They still exit 2, and now name the
  reason. This keeps the MMR-V0 "no partial server" rule.
- The non-absolute plain root case (the empty and literal `${CLAUDE_PROJECT_DIR}` repros) also
  starts unavailable, which amends MCPV0-113. A mis-cased alias (`Core=/x`) is a plain
  non-absolute root, so it now starts unavailable too, with the same reason line. An aliased
  relative root still exits 2.
- In UNAVAILABLE mode the server lists the same tools a usable root would list, via the new
  root-free `bridge.Profile.Tools` and zero-value group registries. A test pins that equality for
  every profile. `corvint.help` still answers. Every other listed tool returns `invalid-root`
  under its own tool-error profile.
- Release smoke: the new step `mcp-unavailable-root` in `script/check-install-lifecycle.sh` runs
  under the upgrade binary B. B is this build in both release runs (the N-1 run installs N-1 as A),
  so the step never runs an older binary.

## V1-3702: hard-coded serverInfo.version — MCPV0-951

Decisions:
- `corvint mcp` reports the core binary's `--version` line without its name, for example
  `1.0.0-rc.3-dev (commit SHA, modified)`. The standalone `corvint-mcp`, the companion bundle and
  every in-process test caller keep `0.1.0-experimental`. This leaves the five profile goldens,
  the companion smoke and the VS Code oracle unchanged. The ticket's "golden tests accept the
  stamped version" is met by `TestMCPV0951ServerInfoCarriesTheBuildVersion` and the cmd/corvint
  test that compares `corvint mcp --version` with `corvint --version`.
- Plugin compatibility comes from an env declaration in `.mcp.json`:
  `CORVINT_PLUGIN_VERSION=claude-code/0.3.8` and `CORVINT_PLUGIN_TOOLS=...`. A CLI flag would make
  an older binary refuse the args and close the connection again. "Compatible" means the server
  lists every tool the plugin expects, which is exactly the skew the audit found (4 tools served
  where 7 were expected). The verdict goes in `corvint.status` `_meta` and one text block; the
  status receipt is unchanged.
- `host-package-versions-check` requires a version bump when shipped plugin content changes, so the
  plugin moved to 0.3.9 with `make host-package-version-bump PKG=claude-code`, and `.mcp.json`
  declares `claude-code/0.3.9`. `script/host-package-version.sh` cannot rewrite the prefixed env
  value, so tests pin it to `plugin.json` instead: a later bump that forgets `.mcp.json` fails
  them.

## V1-3703: bare -32602 — MCPV0-952

Decisions:
- The diagnosis runs after the existing refusal decision. It reads only the request and the listed
  schemas, so it never changes which calls are refused. It lives in `internal/mcp/toolgroup` so
  `corvint-mcp` and the three dedicated servers give the same data.
  `TestMMRV0013ParityWithDedicatedServers` caught the first, cli-only version.
- `server.sanitize` passes only the closed `protocol.InvalidParamsData` through. Any other handler
  data is still dropped, and an echoed field over 1,024 bytes drops the data.
- A rule the advertised schema does not state, such as a path that resolves outside the
  repository, reports `invalid-argument` with field `arguments`.

## V1-3701: 182-414 KB help — MCPV0-953, CAP-V0-950

Decisions:
- `corvint help --json COMMAND` is a compact `corvint-capability-command/0` slice. The `docs`
  entry's flag tables alone are about 5,000 bytes, so the bound is 5,119 bytes (under 5 KiB), and
  only trailing `writeStatements` are dropped and counted. The budget test covers all 53 commands;
  `docs` is 5,065 bytes.
- `corvint.help` now defaults to the guide (10 KB of text; the default answer is under 32 KB on
  the wire). `{"command": NAME}` returns the slice. The full catalog needs `topic: "catalog"`.
- For "outputSchema or stop duplicating": every tool with `structuredContent` now declares an
  `outputSchema`. The text block stays, because hosts that read only text still need it. The
  schema is deliberately loose (`tool` string, `mutates` const false, nothing required) so the
  bridge, group, corpus, multi-root-status and tool-error objects all meet it. The flows tools
  have no `structuredContent` and declare none.
- One command-tree spelling: `corvint-tasks help --tree` and `corvint-test help --tree` alias
  their `help --json`. `corvint help --json` is the catalog, so corvint's `--tree` became the
  shared spelling. This is a one-line dispatch edit in `internal/tasks/cli`, which the fric lanes
  own.

## V1-3704: initialize refusal text, nested $schema, lookahead patterns — MCPV0-954

Decisions:
- A 2026-07-28 `initialize` is told that 2026-07-28 has no initialize handshake and to use
  `server/discover`, with `data.method`. A legacy client keeps the restart flag.
- The five lookahead path patterns are now generated by `bridge.PathRule.Pattern` as a segment
  grammar with no lookaround. Equivalence is tested against a predicate that spells out each
  replaced rule, over every string of up to five characters from a 14-character adversarial
  alphabet, with `.go` and `.tsx` suffixes. ECMA's `.` is spelled as "not LF or CR". An ECMA
  validator also refused U+2028 and U+2029 there, and the new class admits them; runtime path
  validation is unchanged. This is an accepted divergence.
- `snapshotSchema` drops the nested `$schema`. A test walks every profile's schema for nested
  `$schema` and for patterns RE2 cannot compile.

## V1-3707: read-only Corvint Tasks MCP profile — TMR-V0-950..954 (new spec)

Decisions:
- This is the smallest complete slice: five tools (`queue_status`, `receipt_audit`, `roadmap`,
  `ticket_search`, `ticket_show`). Each runs the installed `corvint-tasks` read verb in the bound
  root with `CORVINT_TASKS_READ_ONLY=1` and returns that CLI's own `taskman-command-result/0`
  envelope, so the CLI stays the authority. Paging is the CLI's `offset`/`limit`, and
  `page.total` and `page.truncated` say whether to fetch more.
- The first version was a `corvint-tasks mcp` verb that imported `internal/mcp`.
  `batch-precheck` refused it twice: `TestImportDirection` (decision 0397: Tasks imports no Core
  package) and `TestCurrentTasksSourceArchiveBuildsOffline` (the Tasks archive closure). Rather
  than add a 0397 exception, which is an owner decision, the profile moved to the Core side as
  the `tasks` tool group of `corvint mcp` (amends MMR-V0-012). `internal/mcp/tasksread` imports
  only `internal/tasks/wire`, which 0397 allows, and the tasks-side shim was reverted.
- The schemas do not copy the ticket package's status, kind and priority enums: Core may not
  import that package, and a copy would drift. They are bounded words (`^[A-Z][A-Z_]*$`,
  `^P[0-9]$`), and the CLI refuses other values as `CLI_REFUSED` with its codes.
- Writes are a non-goal under their own future spec, as the ticket asks.
