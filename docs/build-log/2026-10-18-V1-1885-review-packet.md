# V1-1885: bounded review packet for review-stage sessions

Date: 2026-10-18
Ticket: V1-1885 (GitHub issue beamfall/corvint#1169).
Requirements: ERG-V0-017..021 (`docs/specs/corvint-tasks-external-reviews-v0.md`) and ATR-V0-141
(`docs/specs/corvint-tasks-attempt-runner-v0.md`). They are accepted under the owner's standing
auto-accept of lane requirements (2026-10-11). Nothing was added to the agent leases spec (CAL-V0),
which is at its bound.

## Decisions

- **A read verb plus a dispatch opt-in.** `gate packet` builds the packet from native records only:
  the review gate history (PASS trees, newest RETURN), the newest attempt's branch and base, the
  obligation ledger and an optional ATR-V0-105 hand-off note. A ticket role opts in with
  `reviewPacket`; the dispatcher asks the queue for the packet and appends it after the carry-over
  block. The operator, not the dispatcher, decides which role is a review role.
- **Delta base.** The newest ancestor whose tree is a PASS TREE candidate. Without one the packet
  falls back to the full diff (attempt base, first parent, then empty tree) and says so.
- **Cap.** Item codes and statuses, files, the base and the omissions are always kept; item text,
  hunks and the checkpoint fill the remaining room. Every part left out is named by section, path
  and line range; a skeleton over the cap refuses LIMIT_EXCEEDED.
- **Touched status is lexical.** An item is TOUCHED when its text names a changed path or a
  distinctive base name. It does not prove the item was fixed, and the spec says so.
- **Checkpoint commit binding is NOT_OBSERVED.** A hand-off note records no commit, so the packet
  cannot claim the checkpoint was taken at the reviewed commit.
- `taskman-review-packet/0` is an output-only profile (classified for TestCALV0131); nothing stores
  it.

## Residuals

- Hand-off notes carry no commit; binding a checkpoint to the reviewed commit needs a note field.
- Review history is read to 200 events per gate; older PASS events are named as omitted, not read.
- `gate record --reason` refuses unsorted reasons (MALFORMED, canonical sort) instead of sorting
  them at the input boundary.

## Review round (Codex, PR #1189)

One Codex round. Three of its four counted findings concern the packet; each now has a regression
test that fails on the reviewed head 53546a8c3 and passes after the fix.

- **The pre-launch claim hid the candidate (medium, fixed).** A `holdPool` review role was claimed
  (ATR-V0-120) before its packet was read. That claim opens a generation without the submitted
  candidate, so the build failed with "no submitted candidate branch" and the session launched with
  no packet.
  - The dispatcher now reads the packet before the claim and applies it where it did before.
  - `TestATRV0141_PacketReadBeforePoolClaim` uses a queue that refuses packets after any claim. On
    the old code the prompt has no packet and the only operation is the claim.
  - `gate packet` without `--commit` after such a claim now refuses with
    `CANDIDATE_CLEARED_BY_CLAIM:`, naming the attempt, generation and stage.
  - `TestERGV0017_ReviewClaimNamesClearedCandidate` shows a pre-claim packet of the candidate commit
    and the named refusal after the claim. On the old code the refusal is the bare message.
- **Metadata-only changes vanished (medium, fixed).** `splitHunks` dropped every header line, so a
  mode-only change or an empty new or deleted file showed `hunks: []`.
  - Header lines that carry a change of their own now form a leading `metadata` hunk (ERG-V0-019).
  - `TestERGV0019_MetadataOnlyChangeKeepsHunk`: on the old code the mode-only diff gives no hunks.
- **RETURN recency used seconds (medium, fixed).** On equal `recordedAt` seconds across gates, the
  gate that sorted first won.
  - Recency is now the receipt sequence (ERG-V0-020).
  - `TestERGV0017_ReturnRecencyIsReceiptOrder` covers it. A mutation that keeps the first RETURN, as
    the old tie did, fails it.

Residual: there is no native way to recover the candidate after a claim. Attempt records keep
`LoopEvidence.CandidateTreeOid` only under the loop-detection policy. A manual reviewer who claims
first still passes `--commit`.
