# Jasmine fixed experimental runner profile

Date: 2026-10-08
Task: V1-0860 (decision 0437 Jasmine addition under V1-0592); TRE-V0-031..033 (proposed)
Base: 2a93b5a182966f72836cd28bf569dc44c0f5220c

Decision 0437 accepted Jasmine into the CEM 1.0 main-framework set, but no runner profile existed.
This change adds the dynamic profile `jasmine` for one pinned tuple: `jasmine` 7.0.0 with
`jasmine-core` 7.0.2 from the npm registry, run by Node 22.23.3 on macOS 26.6.2 arm64.

Native report decision. Jasmine 7 has no machine-readable file reporter. The only official reporter
package, `@jasminejs/reporters` 1.1.0, contains only a console reporter; its tarball hash is
retained. The profile therefore embeds one closed, pinned shim, `reporters/jasmine.cjs`, loaded with
Jasmine's own `--reporter=` option. It copies named fields of the native `jasmineStarted`,
`suiteDone`, `specDone` and `jasmineDone` events into `jasmine.json` and decides no outcome. The
Go parser owns validation. Identity is the root-relative file plus the native `fullName`, which is
cross-checked against the reported `parentSuiteId` chain. Jasmine's silent skip of a missing spec
file (exit 0) is closed by selector reconciliation.

Acquisition. `npm pack` tarballs were fetched into lane scratch. Their npm sha512 integrity values
were recomputed from the tarball bytes, and the tree was installed from that lockfile with
`--ignore-scripts`. The tarball sha256 values, the lockfile, the entry-point and Node hashes and
the shim hash are in `internal/testrunner/dynamic/testdata/jasmine/provenance.json`. The seven
committed reports were generated by that pinned Jasmine with the shim and are hash-checked by the
tests.

Evidence:

- Failing before. With the base `build.go` and `parse.go`, the new tests fail with
  `unknown dynamic runner "jasmine"` (`TestJasmineBuildIsFixed`, `TestJasmineRunnerGeneratedReports`).
- Passing after. Focused `go test -p 1` passes for `internal/testrunner/dynamic`,
  `internal/testrunner/registry`, `internal/testrunner`, `cmd/corvint-test-runner` and
  `internal/specindex`. `go vet` passes on the touched packages and gofmt reports no changes. The
  doc gates (spec-requirements, requirement definitions, traceability, decision numbers, line
  citations, error-code ownership, unbounded readers, use-case receipts, diagnostic coverage) pass.
- Live common-executor qualification. The opt-in `TestJasmineBuildExecuteParse`, run with
  `CORVINT_TEST_JASMINE` pointing at the pinned `jasmine.js`, passed three cases:
  - Mixed pass, deliberate failure, `xit`, `pending()` and nested case: exit 3, complete, 2 passed,
    1 failed and 2 skipped.
  - A missing selected file: exit 0, incomplete with `jasmine-selector-without-specs`.
  - A spec-file load error: exit 1, no report, so the run is refused.

Non-goals:

- Jasmine affected-test selection.
- Parallel mode, which refuses as unqualified.
- Browser Jasmine (`jasmine-browser-runner`) and Karma.
- ESM and TypeScript loader qualification.
- Default `spec/support` config discovery in a configured project.
- Any change to the shared executor or another profile.

Failure modes. Each of the following makes the observation incomplete and leaves no PASSED state:

- a failed spec, a suite `beforeAll`/`afterAll` error or a top-level global error;
- focused (`fit`/`fdescribe`) or empty runs, which report `incomplete`;
- an identity or parent-chain contradiction, a spec-count mismatch, or an outcome or overall-status
  contradiction;
- a file outside the root, an unselected file or a selector without specs.

Exit codes 1, 2 and 4 stay unadmitted, so they also report `runner-exit`. A missing report refuses
the run at the executor.

Known limit. A symlinked source root (for example `/tmp` → `/private/tmp`) is expected to fail
safe as outside-root or unselected if Jasmine reports resolved filenames. This is inferred and
NOT_OBSERVED; the live test resolves its root first.

Rollback. Remove the `jasmine` case from `build.go` and `parse.go`, `jasmine.go`,
`reporters/jasmine.cjs`, the tests and `testdata/jasmine`, then revert the spec section and the
code rows. No shared contract, store or frozen wire changes.

NOT_RUN:

- `make gate` and `go test ./...` (shared loaded host; lane policy).
- Other Jasmine, jasmine-core and Node versions; Linux and Windows.
- Parallel mode.
- Transitive dependency-closure proof.

Corvint dogfood events were degraded in this session
(`corvint-event-rejected:dogfood-event-deadline`), so no CEM bind was produced by this lane.

Review. The independent Codex review found one P1: Jasmine 7 dispatches any argument equal to a
subcommand name (`init`, `examples`, `help`, `version`, `enumerate`) as that subcommand. `init` and
`examples` write project files, so a bare selector of that name would mutate the source tree before
the missing report could refuse the run. Such selectors now refuse at Build, with regression cases
in `TestJasmineBuildIsFixed`.

The re-review confirmed the P1 fix and found one P2: identity validation joined the whole parent
chain for every spec. A bounded 3.6 MB report with a long suite description and 4096 specs was
calculated to allocate about 12 GiB. Each suite's and spec's reported fullName is now checked
against its parent's reported fullName in place, so no joined name is built.
`TestJasmineIdentityValidationDoesNotAmplify` bounds allocation for a deep 4000-suite chain with
4096 specs at 256 MiB; it measured as passing in 0.04 s. The old code was not run against it
(NOT_RUN: the expected multi-GiB allocation is unsafe on the shared host).

parallel Mocha lane shifts the same citations by +1, so whichever lands second re-anchors them.
