## Fix round 1: hidden packages in the import-set comparison

The independent review found one P1. Discovery now indexes hidden Go packages such as
`.github/lib` (AZU-V0-005, AZU-V0-9920), but both import-set paths of AFP-V0-2202 still dropped
their files through `GoIgnoredPath` as files the go tool never builds. `./...` skips them, yet an
import still builds them. An import added to a hidden dependency therefore changed no import set.
The `go list` readers of its ordinary importers were not selected, measured (`ImportSetRecords`)
or assumed (`unknownImportSets`). Before AZU-V0-005 the file was unindexed source and forced FULL,
so the merge itself opened the gap.

`Graph.GoPackageFile` replaces `GoIgnoredPath` in both paths. A `.go` path is a package file
unless it lies under `testdata` or `.git`, `.hg` or `.svn`, or it is hidden, no unit owns it, and
`.corvint/non-source-paths.json` declares it (AZU-V0-9921). A removed hidden package changes the
module's import graph, as a removed ordinary package already does. AFP-V0-2202 and AZU-V0-005
record the amendment.

`TestHiddenPackageImportSetSelectsObserver_AFPV02202` builds the reviewer's scenario.
`cmd/tool` imports `.github/lib`; `observer`'s test runs an all-literal `go list -deps` on
`cmd/tool`; `.github/lib` has its own test. Fault injection: adding an import to
`.github/lib/lib.go` must select `observer` as `IMPORT_GRAPH_READER` in both paths. The measured
witness chain must be `.github/lib -> cmd/tool -> observer`. A real `go list -deps` confirms
that the listing changes. The controls are a body-only edit, a hidden `testdata` fixture and a
declared `.agent-evidence/` dump; none of them selects the observer. With the old predicate
restored, the test failed: three measured cases and both selections, for six errors. With the
declared-output exclusion removed, it failed on that control.

Live qualification ran in a throwaway Git repository with the same layout. The observer test
passes at the base and fails after the hidden import. A binary built from `566feebc8` selected
only `.github/lib` for `--base` and `--path`. The fixed binary selects `.github/lib` and
`observer`, scope BOUNDED, with no unknowns.

The other `GoIgnoredPath` callers were checked. There were exactly two, and both are fixed. The
function is removed. Similar hidden-directory predicates that describe what `./...` covers were
also reviewed and left unchanged:

- `cmd/corvint` `goIgnoredDirectory`: advisory `go vet ./...` per dirty go.mod. It is advisory
  only, and a hidden nested module stays outside the observed modules.
- `internal/dogfoodflow` `verify_run_match`: whether a VERIFY `go test ./...` covers a
  package. `./...` really does skip hidden packages.
- `tools/gate-ledger` `compiledIgnored`: ignored files that `./...` would compile.
- `internal/sessiontest` `run.go`: already lists hidden packages explicitly beside `./...`.
- `internal/liveverify/affected` `readers.go` `hiddenPackagePath` and `internal/gateselect`
  `declaredOutput`: these are AZU-V0-005's own retention and exclusion rules.

The CI deciding selector takes the plan's selections, so it inherits the fix.

## Fix round 2: scoped-reader callers and the shared browser gate

Greptile left two findings on PR #125. Both were confirmed against the code and fixed.

**Skipped tests counted as coverage (P1, AZU-V0-006).** Before this lane, every changed unit with
no test was `NO_SELECTABLE_TEST` unknown. AZU-V0-006 replaced that with `coverageGap`, which walks
the unit's callers and readers and counts their tests as observers. `testlessReaderUsers` selects
the caller closure only of literal and glob readers, so a testless helper whose declared read
scope holds the changed file was selected alone. Its callers' tests were then counted without
being selected. In the reviewer's case (testless `data/data.go`, a testless helper scoped over
`data/`, a consumer test importing the helper), the plan was BOUNDED, selected nothing and
reported nothing.

The fix works at two levels:

- `testlessReaderUsers` also carries a testless scoped reader of an unowned, untested-owner or
  hidden Go path, unless traversal already followed it. A dirty read-scope declaration alone
  carries no caller.
- `coverageGap` counts a caller only when the plan runs its tests: the caller is reached, and not
  reached only by the ownership audit. A declared consumer counts only when its command was
  rebuilt. When no running test observes the unit and some caller with tests or consumers is left
  out, the unit stays unknown. A caller that additive narrowing alone left out (ADN-V0-005) cannot
  observe the change, so the gap stays a gap. The walk no longer starts from `testReach`, whose
  forward edges are all reverse edges the walk follows.

`TestAZUV0006TestlessScopedReaderCallers` selects the consumer through the helper and a
non-test importer's tests. It keeps a scoped reader that has its own tests untraversed, and
excludes a helper scoped elsewhere, its user and an unrelated package.
`TestAZUV0006CoverageCountsOnlyRunCallers` covers three cases: an exec user of a testless
reader that is not selected keeps the unit unknown, a reader with its own tests still proves
coverage, and an additive-narrowed importer leaves the unit uncovered. Before the fix, four
subtests failed: the two selection cases, the exec user and additive narrowing. On this
repository, all 533 testless units planned with a one-file change gave identical results before
and after the fix: 299 stay `NO_SELECTABLE_TEST` and 234 stay covered. The only testless
read-scoped package, `tools/dogfood-guard-hunks`, has an empty scope and no callers.

**Browser gate ran twice (P2, AZU-V0-007).** Both web-flows consumers declare
`bash script/web-flows-gate`, and `Invocations` planned one invocation per declared unit.
Declared units on one shard with identical, nonempty argv now share one invocation. Its
`Outcomes` keep one terminal outcome per unit, so both consumers keep their unit, outcome and
manifest entry. A unit whose declaration names no command keeps its own invocation, so its
INCOMPLETE reason still names it. `TestAZUV0007IdenticalDeclaredCommandsShareInvocation` covers
grouping, a different argv, another shard and missing commands.
`TestAZUV0007SharedConsumerRunnerRunsOnce` launches a shared runner once and records PASS or
FAIL for both units; before the fix it ran twice. Live check, in a throwaway clone with
`cmd/corvint-web-flows` touched: `corvint test --dry-run` is NARROWED and plans one
`bash script/web-flows-gate` invocation carrying both consumer units.
