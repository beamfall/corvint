## V1-2023: portable verdict ledger reader

Decision: a new read-only portable command, `cem01-go read-verdict-ledger --repository ABS --commit
REV` (CEM-V1-754, experimental under the lane auto-accept). It narrows the CEM-V1-271..279 non-goal
"no portable reader" to the writer alone. The reader re-implements the native `readLedger` from the
spec text and the native code, with no shared code because the module is independent. It checks the
same closed record, the same canonical re-encoding, the same 256-line and 1 MiB bounds, and the same
state precedence (absent, malformed, chain-broken, scope-mismatch, conflict, verified). It prints the
native `verdicts` member's members, `ref`, `trust`, `authority`, `state` and `records`, with records
only when the state is `verified`. Refusals use the native codes: `repository-object-unavailable`
for an unresolvable commit and `invalid-arguments`. The `--verdicts-tip` rollback read stays native
only. No verify route reads the ledger, so CEM-V1-278 holds.

Parity evidence: `TestCEMV1754PortableVerdictLedgerMatchesNative` (`internal/gitnotes`) builds the
module and compares, for each of 14 ledger cases, the native `ProvenanceWithVerdicts` member with
the portable line as decoded JSON values. It also checks that the repository store is unchanged
after each portable read. An empty note is not a case, because `git notes add` refuses an empty
blob. A mutant that drops the tree half of the scope check fails the `record names another tree`
case. `internal/gitnotes` and the `interop/cem01-go` module (`go test`, `go vet`) pass on Unraid.

## Independent review fixes (Codex, one round, at fe62960aa)

Codex raised six P2 findings. All six held against the source. Each fix has a regression test that
fails on fe62960aa and passes after.

1. `script/check-bash32.sh` failed open. Under Bash 3.2 a here-string needs a temporary file, and if
   that file failed, the rule loop was skipped and the gate still printed ok. The `|| true` on the
   grep pipeline also hid grep errors. Fix: one awk scanner reads every script with `getline`, an
   unreadable script exits 3, and the gate exits 2 (`incomplete scan`) on a scanner failure, a
   missing summary or a scanned count that differs. No temporary file is used. Tests 8 (mode 000
   script, exit 2, no ok) and 9 (an unusable `TMPDIR` still fails a construct).
2. `[[ -n $x && -v y ]]` and `: {fd}>log` were missed. Fix: `test-variable-set` matches `-v`
   anywhere inside `[[ ]]` but outside a `$(...)` (three `$(command -v ...)` and `grep -v` lines in
   `lane-scripts_test.sh` were false positives of the first widening). `automatic-fd` matches
   `{name}>` after any word. Fixtures were added to test 3.
3. Quoted text and comments gave false positives. Fix: the scanner builds a code view without
   quoted text and comments. The three expansion rules read a view that keeps double-quoted text,
   where `${x,,}` still runs. Quote state carries across lines, and a here-document body is read
   with fresh quote state per line, so an apostrophe in its prose cannot hide later code (test 7).
   Negative fixtures are in test 6.
4. `read-verdict-ledger` admitted a subdirectory, a bare repository and an alternates-backed clone
   through `rev-parse --git-dir`. Fix: it admits with the canonical `stableAdmit`, which mirrors
   `gitauth.Open`. Its `unsupported-repository-envelope` (effective `info/attributes`) maps to the
   native `unsupported-repository-attributes`.
5. Notes enumeration was unbounded. Fix: `ledgerGit` bounds `git notes list` at 4 MiB (native
   `MaxListBytes`) and refuses `git-output-exceeded`.
6. A note over 1 MiB refused `repository-io` where native refuses `git-output-exceeded`. Fix: the
   blob read is bounded at 1 MiB, with the same code.

`TestCEMV1754PortableLedgerAdmissionAndBoundsMatchNative` covers 4 to 6 on both readers. The cases:
subdirectory, bare clone, `--shared` clone, `* -text` attributes, a linked worktree, a 1 MiB note
(`malformed`) and 1 MiB + 1 (`git-output-exceeded`), and 51150 notes (4194300 bytes, read) and
51151 notes (refused). Against the fe62960aa reader, six of its nine cases fail. Non-goal: on a
platform without the canonical stable route (outside Darwin and Linux amd64/arm64), the reader
refuses `unsupported-process-containment`, as `stableAdmit` does there.
