on the base with `unsupported-object-alternates` and passes with the fix. The `interop/cem01-go`

## V1-3774: benchmarks/snapshot-reader has no CI job

Decision: a recorded exclusion, not a CI step. The module is the closed AT-04 reader-format
experiment. Nothing in the product imports it and no binary ships it. A CI step would be a

healthy on this base: on Unraid, `go test -count=1 ./...` gave `ok` (0.9 s) and `go vet ./...` was

## V1-2023: portable verdict ledger reader

Decision: a new read-only portable command, `cem01-go read-verdict-ledger --repository ABS --commit
REV` (CEM-V1-754, experimental under the lane auto-accept). It narrows the CEM-V1-271..279 non-goal
"no portable reader" to the writer alone. The reader re-implements the native `readLedger` from the
spec text and the native code, with no shared code because the module is independent. It checks the
same closed record, the same canonical re-encoding, the same 256-line and 1 MiB bounds, and the same
state precedence (absent, malformed, chain-broken, scope-mismatch, conflict, verified). It prints the
native `verdicts` member's members, `ref`, `trust`, `authority`, `state` and `records`, with records
only when the state is `verified`. Refusals use the native codes: `repository-object-unavailable`
for an unresolvable commit and `invalid-arguments`. The `--verdicts-tip` rollback read stays native
only. No verify route reads the ledger, so CEM-V1-278 holds.

Parity evidence: `TestCEMV1754PortableVerdictLedgerMatchesNative` (`internal/gitnotes`) builds the
module and compares, for each of 14 ledger cases, the native `ProvenanceWithVerdicts` member with
the portable line as decoded JSON values. It also checks that the repository store is unchanged
after each portable read. An empty note is not a case, because `git notes add` refuses an empty
blob. A mutant that drops the tree half of the scope check fails the `record names another tree`
case. `internal/gitnotes` and the `interop/cem01-go` module (`go test`, `go vet`) pass on Unraid.

## V1-3812: Bash 3.2 doc gate

every tracked file whose first line names bash. It fails naming the rule and `file:line` for each

parameter transformation, negative indexes, `[[ -v`, globstar, `coproc`, `|&`, `&>>`, `;;&`,
`{fd}>`, `wait -n` and brace steps. It is in `DOC_GATE_TARGETS` and `GATE_STEPS`, so
`make doc-gates`, batch-precheck (through the doc-gate expansion) and CI run it on Linux.

line's first quote or `#`. Four Perl lines in `script/lane-guard.sh` that name `|&` and `&>>` in
regexes carry `# bash32: allow`; `lane-scripts_test.sh` (40 groups) still passes. The gate skips
its own rule table, and the fixture test spells every construct from split fragments, so neither
file trips the gate. The tree is clean (195 scripts).

Test evidence: `script/check-bash32_test.sh` (`make bash32-test`, a `shell-test` prerequisite)
checks that a clean tree passes and `declare -A` fails naming `bad.sh:3`. It checks every other
