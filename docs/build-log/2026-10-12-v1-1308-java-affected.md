# 2026-10-12 Java affected-test adapter (V1-1308)

Branch `claude/v1-1308-affected-java`, stacked on V1-1301 (`claude/v1-1301-affected-objc-c-shell`)
because both edit `languages.All()`, `shell.ForeignSourceSuffixes` and the seam conformance list.
Spec `docs/specs/java-affected-test-v0.md`, requirements `JAT-V0-001..010`, accepted under the
standing lane auto-accept of 2026-10-11; amends the Kotlin/JVM spec's mixed-tree paragraph.

## Intent

`corvint affected` had no Java plugin. A dirty `.java` path was `UNOWNED_DIRTY_PATH`, and any `.java`
file in the tree raised the global `kotlin:jvm-sibling-source-present`, so every Kotlin plan in a
mixed JVM repository was UNKNOWN. This slice adds static planning only.

## Decisions

1. `java` owns `.java` only. Build files stay unowned, so a dirty `pom.xml` or `build.gradle` keeps
   the plan UNKNOWN (`UNOWNED_DIRTY_PATH`); the module graph is not modelled, and edges follow fully
   qualified names across modules, which only widens.
2. A file is a test only with both a runner signal and a test location, so a helper under `src/test`
   stays a source unit and a test reaching it through the helper is still selected.
3. Kotlin↔Java reach is a unit frontier on the reached unit (`java:kotlin-dependent`,
   `kotlin:java-dependent`), not a cross-namespace edge and not a global frontier. A global frontier
   would keep every mixed-tree plan UNKNOWN; a unit frontier makes only plans that reach a
   cross-language-referenced unit UNKNOWN. The global `kotlin:jvm-sibling-source-present` is retired.
4. Unresolved first-party imports and reflection are unbounded reads with `LocatesRoot` on non-test
   units, as in `NSA-V0-009`: a unit frontier would apply only when the unit is reached, and generated
   or reflectively loaded code may reach the dirty path without an edge.
5. The flows impact golden embeds the affected-graph digest, which changes whenever a plugin is
   registered; it was repinned here and in V1-1301 (whose shard-0 CI failure was exactly this).
6. Decision 0132's anchored citation of the `languages.go` import block was repinned to `8-17` after
   reading it: it still names the six adapter imports, now with `java` among them.

## Codex review (one round, all findings)

One read-only Codex round on `efc6dcff3` raised nine findings; all were fixed, each with a
regression test, and no second round was run.

1. Qualified references needed three contiguous segments: `new p.Core()`, `com . ex . core . Core`
   and `com.ex.core./*c*/Core` gave no edge. A chain scanner now reads dotted names across
   whitespace and blanked comments, from two segments (`JAT-V0-003`).
2. Reflection markers needed adjacent punctuation (`.loadClass ("x")`); they now match code with
   whitespace removed (`JAT-V0-007`).
3. `Class.forName("p.Outer$Inner")` missed the nested type; a binary name is also looked up with
   `$` as `.`.
4. The lexer ignored Unicode escapes (a `\u000a` in a `//` comment hid code) and ended line comments
   only at LF. Escapes are translated first, a malformed one is `java:unparsed-source`, and CR ends a
   line (`JAT-V0-004`).
5. `@ Test` and `@/*c*/Test` were not runner signals; annotations now use the chain scanner.
6. A subclass of a test base with no annotation of its own was a source unit. A supertype that
   resolves by an edge to a signalled file now passes the signal on, to a fixpoint (`JAT-V0-002`).
   A library base class outside the sources stays a recorded gap.
7. A generated type named through a first-party on-demand import, or in the same package, had no
   unbounded marker. The new `java:unresolved-name` covers a capitalised name nothing observed
   declares or imports when a first-party package could supply it (`JAT-V0-006`). This deliberately
   widens; behind an external on-demand import only, the name is attributed to that package and the
   gap is recorded.
8. A comment before `package` broke the cross-language header parse on both sides; headers are now
   read from comment-blanked text, falling back to raw text when it does not lex.
9. The Kotlin facade for `core.kt` was `coreKt`, not `CoreKt`, and `@file:kotlin.jvm.JvmName(...)`
   or a spaced `@file:JvmName (...)` was missed; Java qualified names on the Kotlin side now
   tolerate spacing (`JAT-V0-008`, Kotlin spec amendment).

## Rollback

Remove `java.New()` from `languages.All()`, the conformance list and `ForeignSourceSuffixes`, and
revert the Kotlin amendment. No stored format or wire contract changes.
