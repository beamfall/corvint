## Design decisions

- **V1-4262 (GL-V0-1920).** `prune` globbed N names, stat-ed them, and sliced
  `records[:len(records)-maxRecords]`. A concurrent prune that removed some of those names between
  the glob and the stat left fewer survivors than the bound, and the slice went negative. The fix
  is a generic `overflow(records, keep)` that returns nothing at or under the bound. The hunk
  avoids every line that lane glc-w34 (V1-4241, already in batch-1102a) rewrites, so the two
  merge cleanly. glc-w34's interval-gated prune still carries the same slice, so this guard is
  needed after it lands too. The race test asserts only the absence of a panic, because the
  record count it leaves is the retention policy glc-w34 changes.
- **V1-4261 (PUR-V0-1920, PUR-V0-1921).** Pause is a frozen-format `barrier.json` whose admin
  digest gains no field here, so the lane chose "guarded" over "self-expiring". Every writer,
  `pause` included, goes through `authority.acquireLock`, and the guard sits there. A Go test
  binary (argv[0] `*.test`; no `testing` import in production code) refuses the common directory
  of the checkout its source path resolves to. Before any test runs, it exports that directory as
  `CORVINT_TASKS_FORBID_COMMON_DIR` for children. Any process, a built `corvint-tasks` included,
  refuses the store that the variable names. Reads take no lock and are unaffected. The tests
  exercise the guard on fixture stores only and never lock the live one.
- **V1-3496 (ASD-V0-1922).** `make tasks-reconcile` (TCD-V0-872) already existed, but nothing on
  the merge path ran it. The orchestrator's landing step, `script/pr-landing-watch.sh`, now runs
  it on the first pass that sees `MERGED`, once per PR. That pass prints
  `RECONCILE status=N log=FILE`, and debt or a refusal goes to the alerts file the Monitor tails.
  The reconcile applies a proposal only with `--act` and the operator's `RECONCILE_APPLY`. Rule 2
  of the charter forbids Tasks writes, so the default stays propose-only. The default runs the
  literal `script/tasks-reconcile.sh` from the checkout root. A computed `$here/...` name kept the
  TSP-V0-960 foreign-invocation frontier and failed `shell-foreign-callers-check`.
- **V1-4317 (ASD-V0-1923).** `doc_gate_rows` was extracted from `steps()`, so each static row is
  byte-for-byte the full run's row and carries the same ledger key across runs. Within one run,
  `run_one` prints REUSE for a row in `$dir/static.pass`. The phase runs before
  `select_plan` (the planner), so a static failure costs seconds. `bash32-check` gained
  `BASH32_INCLUDE_UNTRACKED=1`. Reusing its untracked-superset pass for the tracked row is sound
  because the row scans a subset. `go build`/`go vet` cover root-module directories that hold a
  changed or untracked `.go` file; nested modules are left to their own jobs.
- **V1-1467 (DWC-V0-001, DWC-V0-002).** batch-check derives a merge as `regenerated-specs` only
  under three conditions:
  - ort's sole conflicted path is `docs/specs/REQUIREMENTS.tsv`.
  - The merge tree differs from ort's written tree only in the three generated spec files.
  - A private clone of the merge, running its own generator `--all`, stages exactly the merge tree.

  INDEX.json and README.md conflicts stay unbound. They are projections onto kept files, and a
  regeneration from one side could drop the other side's hand edits. The merge side is
  `script/merge-regenerate-specs.sh`, which `docs/DOGFOOD.md` batch step 2 names (batch-assemble.sh
  is not on BASE). The Go test uses a fake generator in its fixture, because a real-script read
  through a `../..` locator made all 27 path tokens in the package root-relative under
  `test-read-scopes-check`. The real generator is exercised by the lane-scripts group instead.
