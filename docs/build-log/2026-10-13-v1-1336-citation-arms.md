## Intent

The 2026-10-13 CEM 1.0 confidence panel found that the `anchored` citation tier rewards lexical
coincidence: forged-ID and path-inventory maps anchor more hunks than an honest careful map, and a
grep bot that reads only the diff anchors far more than authored maps. This lane makes that
measurable in the maintained baseline tool, pins the defect in tests, records a kill criterion
that authored maps must beat mechanical producers, and registers the prospective run before its
maps exist.

## Decisions

- All scoring calls `verify.ComputeCitation`, the verifier's own tier computation, on a synthetic
  map that keeps the authored hunks and the canonical patch and swaps only bases and evidence. No
  tier rule is reimplemented, so a tier redesign changes the arms with it. The authored arm's
  anchored count must equal the status citation's (`arms-authored-mismatch` otherwise); it did on
  every scored map.
- The derangement null uses a per-source pair table (one `ComputeCitation` per distinct source,
  every hunk citing it alone) instead of 200 full synthetic maps. A hunk anchors a set iff it
  anchors some member, so the table reproduces the real count; the tool checks that and refuses
  the map (`arms-pair-mismatch`) when it does not. It never did on the corpus.
- The grep bot and the preimage arm follow the panel's reference scripts (ported, not called; no
  Python runtime dependency). The panel's 2.1% [1.7, 2.5] used its own null and arm code; the
  numbers here are this tool's and are the ones the registration binds.
- The corpus measurement needs `CEM-V1-104` T' targets: 615 committed maps no longer equal their
  bind commit's `.corvint/change.cem.json` (V1-1277 rewrote them to `cem/1.0` in place), so the
  stable verifier refuses them at the bind commit with `excluded-artifact-mismatch`, as the V1-1277
  entry recorded. `--targets` (`DCW-V0-056`) names a per-map target. A scratch script, not
  maintained tooling, built each T' in a throwaway clone: `git hash-object -w` of the map, the bind
  tree with only that blob replaced (`git mktree` twice), and `git commit-tree -p <bind>`. The
  canonical patch excludes the sidecar, so T' changes nothing the arms read; the run also checks
  each patch against `patchSha256`.
- K2b is named so because decision 0523 already numbers K3 to K6.

## Failure modes

Closed `armsIssues` codes (`DCW-V0-052`): `arms-map-not-accepted`, `arms-map-unreadable`,
`arms-patch-unavailable`, `arms-patch-digest-mismatch`, `arms-hunk-not-in-patch`,
`arms-git-failed`, `arms-evidence-unreadable`, `arms-pair-mismatch`, `arms-authored-mismatch`. A map
with any of them has `arms: null` and null members; it is counted in `armsIssueMaps`, never
scored as zero. A malformed `--targets` line refuses the run with exit 2.

## Independent review

One Codex round (`codex exec -s read-only`, diff f8ea0758e..HEAD): CONCERNS, four findings, all
confirmed against the source and fixed in this change.

- The grep bot takes the first two IDs that resolve to a defining line and falls back to the
  basename only when none resolves, while `DCW-V0-052` read as "at most 2 IDs; fallback for a hunk
  with no IDs". The code's rule is the intended one; the requirement text now states it.
- `git grep` and `git cat-file` ran outside any bound. Both now run through one helper with a
  5-minute timeout and a 256 MiB output cap; exceeding either is `arms-git-failed` (`DCW-V0-052`).
- A hunk whose old path had no blob at the base silently got an empty preimage basis. It is now
  `arms-git-failed`; `TestBaselineDCWV0052PreimageWithoutABlobIsAnError` covers it and the
  created-file case.
- The seed test only checked repeatability. It now compares all 200 draws with an independent
  derivation from the `DCW-V0-053` text (seed words parsed from the hex digits) and pins the first
  draw for its fixture digest.

The scorer OID in the registration is the post-fix `main.go`.
