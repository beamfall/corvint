## Intent and decision

The lane charter supplies the human-owned request: `ticket show ID --root DIR` must read
that store, and automatic citation drafts must stop guessing across files, stop citing Markdown
headings, and prefer stable BASE governing requirement definitions for spec amendments.

`TCL-V0-926` extends the existing Tasks CLI companion. `DWC-V0-926`, `DWC-V0-927` and
`DWC-V0-928` extend the existing daily-workflow companion because its parent already holds
256 requirements. Each ID was checked with `git -C /home/russell/projects/corvint log --all -S
'<ID>' --oneline` before use; all four searches were empty, and the staged collision check passed.
These rows use standing acceptance, not an owner read-back claim.

Decision: apply one anchor rule across all freshly drafted routes, including sibling, move,
seal, repin and same-file fallbacks, and recheck automatic rows after stability vetting can move
them. Use the existing `verify.SpanAnchors` rule rather than a second anchor implementation.
Missing anchors become explicit unknown rows. Author-reviewed refresh rows keep their existing
semantics. For amendments naming an ID, try the unchanged BASE definition before heuristics;
use the precise citation verifier to admit unchanged context and reject removed/repeated text.
ATX headings and Setext titles/underlines are excluded. No wire format or citation authority changes.

This deliberately supersedes old tests requiring unanchored fallback guesses or a low unknown
rate regardless of evidence. Their historical move, sibling, stacked-seal and multi-file fixtures
remain exercised; every emitted citation is checked against the CEM anchor verifier. Separate
positive regressions require useful path, basename and requirement anchors, so an all-unknown
implementation does not pass the suite. Rollback is a revert of this change; stored records and
reviewed plans need no migration.

## Observed final-check blocker and repair

The first final `make dogfood-check` agreed on verifier output but failed `dogfood-report-write`.
The report and Git staging file were writable; `check.record` staged under the absolute Git
metadata directory and `os.Rename` crossed distinct sandbox mount points. The staging file was
retained, and a shell `mv` recovered it by copying; that is not an atomic-write solution.

Decision: `DWC-V0-929` stages a mode-0600 temporary file beside the ignored report, closes it
before atomic rename and removes it on return. Add the temporary-file ignore glob to the adopter
list and this repository. No permission broadening or override verifier is needed. The ID was
checked across all Git branches before use. `TestCheckDWCV0929ReportStaysOnWorktreeMount`
requires a successful report replacement with an unavailable Git staging directory and checks
private mode, intact input on refusal and no leftover temporary files. The final gate is rerun
with the repaired tree; the initial refusal stays in the handback. Rollback restores Git-directory
staging and its cross-mount failure. This is a required integration blocker discovered by the
lane, not an expansion into a new capability.
