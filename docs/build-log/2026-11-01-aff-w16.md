  - The bulk of each plan is unbounded readers. These are units with a `..` or `--show-toplevel` literal, units that call `os.Getwd`, or shell tests that run a toolchain. Each one may read the changed file.
  - Decision: do not narrow them in the planner. A unit leaves these plans only when it declares a read scope, together with a test that the declared reader stays selected for a path it reads.
  - Those declarations live in `.corvint/` read-scope files, which the charter excludes. Until then, focused runs use `--summary` and `--pins`.
  - The "<20 units" (V1-3788) and "only the readers of those rows" (V1-3587) criteria are therefore unmet. The remainder is per-unit read-scope declaration work.

## Friction

1. The installed WSL `corvint` (build 39, b7ffc233) was stale for this lane, so the lane built its own binary.
2. The corvint MCP server failed to connect on the Mac.
3. The charter's `internal/affected*` path does not exist. The planner is in `internal/liveverify/affected`.
4. TSP-V0-940, 950, 951 and 960 are already used inside this lane's block 940-959.
5. ssh heredocs containing apostrophes break under zsh. Piping a scratch script into `python3 -` works.
6. `corvint affected --path` refuses a dirty worktree, so probes need a second worktree at the base.
7. heavy.sh needs `HEAVY_WHOLE_REASON` even for a tiny package such as `internal/capcatalog`.
8. The V1-3507 acceptance criteria name the external-test-selection spec, but the rule lives in TSP.
9. `make spec-requirements` exits with rc 2 and no message while the spec is unstaged.
10. Changing the `corvint test` usage line forces `make capability-catalog`, which regenerates `catalog.json` and `trees/corvint.json`.
11. `traceability-tests-check` resolves any backticked `Test*` word, including fixture test names written in prose.
12. Spec-only plans stay at about 48-71 units until unbounded readers declare scopes. That work spans many packages and the `.corvint/` declarations.
