# 2026-10-07: cross-ticket know-how notes pinned to file blobs (V1-0955)

## Intent

GitHub issue beamfall/corvint#655 (ticket V1-0955) asks for a Corvint-owned record of know-how
that agents learn while working: short notes anchored to files, pinned to the blob each file had
when the note was written, and delivered to later claimants whose touch paths intersect those
anchors. Freshness must be computed when the note is read, so a note whose file has since changed
is reported STALE and never presented as current.

The first slice is specified in `docs/specs/corvint-tasks-know-how-notes-v0.md` (KHN-V0-001..007).
The requirements are proposed, pending owner acceptance (V1-0955). Delivery is experimental.

## Decisions

- **Shape.** The record follows the TEA-V0-001 pattern: an optional `knowHow` member on the home
  ticket record, an append-only ledger written by two ordinary mutations, `KNOWHOW_ADD` and
  `KNOWHOW_RETRACT`. A write bumps `revision` and leaves `acceptanceRevision` unchanged. It adds no
  derived events and no new receipt kind. This is the cheaper of the two designs; owner question 1
  asks whether ON-V0-style derived events are wanted instead.
- **Home ticket.** Only live (DRAFT, OPEN, HELD) native tickets accept a write. COMPLETED is
  refused because its record is bound by the release digest. ARCHIVED and IMPORT tickets are
  refused too.
- **History.** Supersede (an ADD that names an earlier entry, with a reason) and retract (with a
  reason) act only on active entries of the same home ticket. Entries are never rewritten, so the
  ledger is the audit trail.
- **Roles.** OWNER by default. OPERATOR only through an explicit policy row. WORKER cannot be
  granted: a WORKER row is undecodable (fail closed; owner question 4).
- **Secret screen.** The text, reason, routes, anchor paths and evidence path go through `secretscreen.MatchString` before the
  write. A hit is `VALIDATION_FAILED`/`MALFORMED` with the stable detail prefix
  `KNOWHOW_SECRET_DETECTED:`. This needs one exact Core edge, from `internal/tasks/mutation/know_how.go`
  and its test to `internal/secretscreen`, recorded as the V1-0955 addendum to decision 0397 and
  enforced by `TestImportViolationControls`.
- **Pins.** The CLI resolves the writer's commit and every anchor blob with one
  `git cat-file --batch-check` process: the commit first, then each anchor as
  `<commit oid>:<path>`, so a concurrent commit cannot mix two commits. Absolute paths, `..` segments, and anchors that are not regular
  blobs in that commit are refused. The created commit is stored with the entry.
- **Freshness.** One `git cat-file --batch-check` process resolves `HEAD^{commit}` and then
  asks each path as `<head oid>:<path>`, ignoring the dirty tree. Equal blob: CURRENT. Different blob: STALE. Missing path,
  non-blob, unborn HEAD, no checkout, or any Git failure: UNKNOWN, never CURRENT. A note is STALE
  if any anchor is STALE, otherwise UNKNOWN if any anchor is UNKNOWN, otherwise CURRENT. Nothing is
  stored; the Git environment disables optional locks.
- **Delivery.** `claim` and `claim-next` add a `knowHow` member computed when the response is
  built (a replay shows current freshness). Notes intersect when an anchor equals a touch path, or
  sits under a touch path that ends in `/`. Order: CURRENT, UNKNOWN, STALE; newest first; then
  ticket id and seq. The compact projection is the longest prefix such that the whole member,
  envelope and hint included, fits 2048 canonical bytes, plus an omitted count, so the order is
  never reshuffled to fill the cap. An inventory read error gives
  `UNAVAILABLE` and never fails the committed claim.
- **List.** `corvint-tasks ticket know-how list [--path P]... [--ticket ID] [--limit N]` is read-only and returns the
  full form (pins, provenance, supersession).
- **Trust.** Every delivery carries `trust: UNTRUSTED_AGENT_AUTHORED_DATA`. Know-how never feeds
  ranking, evidence or authority. `TestKHNV0007_KnowHowNeverReachesRankingEvidenceOrAuthority`
  fixes the allowlist of production files that may name it.

## Limits and NOT_RUN

- NOT_RUN: `make gate`, the full `go test ./...`, the interop module, the Core units the affected
  plan selected through `internal/tasks/wire` only, and CEM binding and seal (the orchestrator owns
  them).
- Not witnessed: the archive round trip of a ticket with know-how; concurrent writers and redo
  after a crash mid-write (the ordinary mutation path covers both, but no KHN-specific witness);
  the claim-delivery `UNAVAILABLE` branch.
- A retried add needs the same `--commit` and `--issued-at` to replay, because both are part of the
  mutation payload.
- Pre-existing, outside this change: `TestCALV0131_EveryLiveFormatRefusesANewerVersion` fails
  whenever `TMPDIR` crosses a symlink, including macOS's default `/var/folders` (`/var` links to
  `/private/var`). `snapshot.Probe` refuses the symlinked state directory as
  `UNSUPPORTED_FILESYSTEM` before it reads `VERSION`. It fails the same way at base `8af2bf62`.
- Follow-ups (non-goals of this slice): delivery in Core `corvint_query` packets, symbol-level
  anchors, LTA-V0-006 skill export, automatic re-confirmation of STALE notes, a WORKER grant,
  cross-ticket supersede, attempt verification, COMPLETED home tickets, and a dedicated
  `SECRET_DETECTED` code.

## Independent review

Codex (`gpt-6-astra`, read-only) reviewed `8af2bf62..4ee46b6c`. All five findings were confirmed
in the source and repaired with regressions:

- P1: pins and freshness resolved `HEAD` and each `HEAD:<path>` separately, so a concurrent
  commit could mix commits. Now one process resolves the commit, then asks `<oid>:<path>`. There
  is no deterministic race witness; the existing pin and freshness tests cover the new path.
- P2: a missing-anchor error echoed a secret-shaped path before the mutation's screen ran. The
  CLI now screens every raw argument first (`mutation.ScreenKnowHowArgs`); regression cases
  "secret path" and "secret route" in `TestKHNV0006_KnowHowThroughTheCLI`.
- P2: Core accepted a RETRACT with a null reason that the Tasks codec refuses. Core now refuses
  it; parity cases in `TestKHNV0002_ReaderKnowHow` and `TestKHNV0002_RecordCodecRefusals`.
- P2: only the notes array was budgeted, so the member could exceed 2 KiB.
  `TestKHNV0006_DeliveredMemberFitsTheCap` failed against the old budget (2207 bytes) and passes
  now.
- P3: the first item was charged a separator, so an exactly fitting prefix lost its last note;
  an exact-fit case was added to `TestKHNV0006_SelectionAndProjection`.

A second Codex round reviewed `4ee46b6c..a0b14fbd`, confirmed all five repairs and found two
more, both repaired:

- P2: the envelope was reserved for the largest omitted count, so a prefix that fit exactly could
  lose a note. `store.ProjectKnowHow` now measures each candidate prefix with the envelope it
  would carry (its own omitted count and hint) and keeps the longest that fits.
  `TestKHNV0006_DeliveredMemberFitsTheCap` now sweeps every text size with uniform and mixed
  notes and checks that one more note would not fit.
- P3: the Git observation leaked a pipe descriptor when a later pipe failed to open. It now opens
  both pipes with `os.Pipe` and closes them on every failure path.
