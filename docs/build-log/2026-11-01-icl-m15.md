# Incremental closeout: one prepare, pre-bind drift with a bound carry, early input refusal — V1-1629 (lane icl-m15)

Problem: lanes reran `dogfood-change` 4 to 19 times each (855 runs, about 28 h) where the protocol
needs about 2 per lane. Inside one `make dogfood-closeout`, two costs repeated or arrived late:

- The closeout's pre-flight and `dogfood-finish`'s own pre-flight each ran `cem prepare`.
- Every batch-drift go test ran only after the bind. A failure that the bind could not affect,
  such as `TestImportDirection`, therefore surfaced only after a full bind and cost another closeout.

A missing input was also refused only after `heavy.sh` admission, which queues on host load.

Base: origin/main b7ffc233396da54e2ac5a094ec314dc3b067f6fb. Spec: `docs/specs/incremental-closeout-v0.md`
(`ICL-V0-001`, `-010`, `-020`, `-021`, `-022`, `-030`; proposed/experimental).

## Decisions

- Preflight reuse (`ICL-V0-010`). A repeated inputs-check whose `DCW-V0-887` key matches a passing
  receipt replays its prepare lines and keeps the receipt for the finish run. Before, it removed the
  receipt and prepared again. The key already binds BASE, target commit and tree, outcome, stage
  count, the executable digest and every input digest, so no new binding was needed.
- `@prebind` marker (`ICL-V0-020`). Six drift entries whose packages read Go source and fixtures,
  never `.corvint/` evidence, run in the closeout's first precheck:
  - gate-ledger `TestGoTestKeys`
  - lrfrepo spec enumeration
  - tasks `TestImportDirection`
  - tasks/store, tasks/journal and tasks/safeopen `TestCALV0070_`

  Their failure now stops the closeout before the bind. The remaining entries stay held for the
  sealed head.
- Carry rule (`ICL-V0-021`). The second precheck reuses a pre-bind pass only when all of these hold:
  - the commits since the recorded head touch evidence paths only;
  - the toolchain and environment salt is equal;
  - the real planner (`corvint affected --path`) over those paths gives a clean verdict and does
    not select the entry's package.

  The rule rests on the planner, not on a hand-kept list, so a new reader of `.corvint/` is caught
  by the planner. Any doubt runs the entry again and prints why.
- Early refusal (`ICL-V0-030`). An unadmitted first recipe line runs only the missing-input check
  (`DOGFOOD_FINISH_INPUTS_ONLY=1`). The admitted line is unchanged, so `ASD-V0-930` admission still
  holds for every build.
- Not delivered (non-goals in the spec): a tree-verifier, check or seal carry across a fix commit,
  and doc-gate carry, which needs `tools/gate-ledger` scopes outside this lane.
- Repaired a stale assertion in `script/dogfood-cache_test.sh`. It failed at BASE because its
  closeout-recipe parse predates the `BATCH_PRECHECK_SKIP_DRIFT=1` line (V1-3550). It now asserts
  that the first precheck is the skip-drift one.

## Friction

1. The missing-input refusal waited about 120 s behind `HEAVY_ADMIT`. Fixed here (`ICL-V0-030`).
2. `corvint affected --path` refuses a dirty worktree, so the replay needed clean scratch checkouts.
3. The `..` literal in `internal/tasks/boundary_test.go` makes every `.corvint/` path select
   `internal/tasks`, so `TestImportDirection` cannot carry.
4. `heavy.sh` refuses a whole-package test without a reason, even for a small package.
5. The focused `cmd/corvint` run took 130 s, of which about 120 s was the load queue.
6. zsh glob error on an unquoted `--include=*.go` grep argument.
7. The `DCW-V0-887` text said the closeout prepares once. It prepared twice before `ICL-V0-010`.
8. The installed `corvint` (built at b7ffc233) printed a stale-binary DEGRADED warning during the replay.
9. `script/dogfood-cache_test.sh` failed at BASE: its closeout-recipe assertion predates V1-3550.
10. The `spec-requirements` digest checks (one line, at most 160 characters) report one limit per
    run, so two reruns were needed.
11. Naming `heavy.sh` in a comment of a script makes it an undeclared foreign caller
    (`TSP-V0-005`). Only the 6-minute `doc-gates` run reported it; nothing in the focused script tests did.
12. The other structural input checks (verify-line syntax, intents byte order) still run after
    admission and the tree build. Three input-fix tries here queued 120 s, 120 s and 30 s.
13. `propose-citations` proposed a BASE span for a bootstrap-intent hunk (the new spec). It also
    gave the build-log hunk a non-bootstrap unknown. Then `inputs-check` refused both
    (`bootstrap-intent-not-unknown`) until they were rewritten as bootstrap unknowns.
