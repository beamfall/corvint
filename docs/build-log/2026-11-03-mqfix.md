## V1-4446: a PR adding an unindexed non-Go file forced every shard FULL

Evidence: run 41714153849 (PR 85), artifact `ci-narrowing-5`: `base ""`, `effectiveBase ""`,
reasons `the change set is unreadable`, `not a full commit id`, `driver: selector: FALLBACK the
plan names the unknown UNINDEXED_SOURCE_PATH`, `the shadow wrote no plan`.

Two defects, one cause each:

1. Base `""`. `narrow.sh` took the effective base only from a driver selection with an empty
   `Reason`. The selector's FALLBACK set a `Reason`, so the jq filter printed nothing and the base
   was `""`, although the event base was the tested merge's first parent. With `""`, the
   `.github/` check could not run and the shadow got `--base ""`. CIN-V0-2300: on a fallback,
   `narrow.sh` proves parent 0 itself (two parents, the second the head, the event base an
   ancestor of the first) and keeps that base; the record stays FULL on the driver's reason.
2. The FALLBACK. The Ruby plugin drops `testdata` files in a Go-module root
   (RUBY-AFFECTED-V0-041) but its `Owns` still claims `*.rb`, so the nine Ruby fixtures of the new
   package `internal/rubylinecov` were `UNINDEXED_SOURCE_PATH`, which no allowlist admits.
   AFP-V0-2440: a non-Go claim on a file below a Go-hosted `testdata` directory, under which the
   plugin lists no path, is fixture-only, and the path is `UNOWNED_DIRTY_PATH` (allowlisted; the
   selector's rules (b) to (d) select its Go readers). Go claims, unhosted directories, indexed
   fixtures and paths outside `testdata` keep `UNINDEXED_SOURCE_PATH`.

Live replay at PR 85 (base `64321325b`, head `15ddb96e5`) with the lane's `corvint` and
`gate-affected-select`: the plan has no `UNINDEXED_SOURCE_PATH`; the selector answers `run` with
248 of 437 packages, `internal/rubylinecov` among them; the shadow
(`corvint test --profile ci --dry-run`) is NARROWED with 238 Go units, all inside the driver's
248. Under the base tools every shard ran FULL. The CI tools build from the compared `main`
(CIN-V0-011), so the planner fix takes effect for pull requests based after it lands.

## V1-2691: the Go build cache on the WSL tmpfs /tmp

The host's 16 GiB `/tmp` tmpfs was full during this lane (135 MiB free). Most of it was per-lane
caches set by callers (`/tmp/<lane>-go-cache`, about 8 GiB); the base `lane-scripts_test.sh`
failed group 62 on ENOSPC. heavy.sh moved only an unset cache. ASD-V0-061 now also moves a
caller cache under the tmpfs root, and a `CORVINT_GOCACHE` derived from a `TMPDIR` there. ASD-V0-104
also trims the Makefile's default `/tmp/corvint-go-build-cache` on a tmpfs (2 GiB, entries over an
hour old). Decision on the Makefile: `CORVINT_GOCACHE`'s default stays as it is. STR-V0-006/908
require the `make gate` ledger's cache to resolve from the Makefile text alone to the declared CI
environment, so it cannot depend on a host probe. `make windows-vet`, the Go step lanes run
directly, takes `WINDOWS_VET_GOCACHE` instead: the home-disk cache when the default's directory
is a tmpfs, a caller's `CORVINT_GOCACHE` otherwise kept. On this host a plain `make windows-vet`
now writes `~/.cache/corvint-go-build-cache`. `make test-commands-check` still passes.

## Independent review

One read-only reviewer pass over the staged diff found no soundness hole in Go-shard narrowing and
five lower findings, all fixed with tests that fail on the reviewed scripts:

1. `accept.sh`'s incremental listing carried the verdict's window rows but not its markers, so
   two markers in the window plus one since stayed MET. It now adds the verdict's
   `rowAbsence.absent`, and an incremental verdict without that count is FULL.
2. `collect.sh` named a `.github/`-editing pull request's missing shadow. That pull request could
   trip the switch for every other pull request, so such a run is no longer named.
3. The parent-0 proof also ran for a selection with no `Reason` whose `EventBase` mismatched, and
   `narrow.jq` does not check `EventBase`, so that case turned NARROWED. The proof now runs only
   for a non-empty `Reason`.
4. AFP-V0-2440's text overstated the frontier behaviour. A fixture-only path keeps its claimants,
   so it does not raise other plugins' frontiers.
5. A blank line split the CIN traceability table.
