## V1-3348: a package whose source and tests both changed (TSP-V0-861)

### Decisions

- The union of the two existing slices, each under its own proof, rather than a new joint model:
  TSP-V0-006's reach over the head test files (the changed ones included) decides which tests of
  unchanged files can observe the changed functions; STR-V0-063's checks over the changed test
  files (no initialization effect then or now, no shared name with an unchanged test file, the
  same imports) decide that only their own tests can observe the test edits. A test skipped by the
  union is skipped by both proofs. Either proof failing keeps the package whole with its reason;
  a union holding every test keeps it whole naming that.
- The `go:linkname` refusal was a byte search, so `cmd/corvint` (whose slicer source names the
  directive in prose and a string literal) could never be sliced: the most expensive package in
  `package-costs.json` (1045 s). It is now decided on the parsed comments, `//go:linkname` being the
  only form the compiler honours (any indentation still counts).

### Replay

- Batch replay (TSP-V0-860 set, lane binary at this commit): source-and-test whole packages 50 to 0,
  whole 4631 to 4631, sliced 0 to 0, narrow 13 / 19, 0 misses.
- Per-commit replay (`benchmarks/results/v3348-source-and-test-slices-2026-10-31.json`): every one of
  the 87 non-merge commits of `origin/main` that changes a package's source and tests in one
  directory, `corvint test --base C^ --dry-run`. Base: 135 packages whole only for "its test file
  changed too". Lane: 0 for that reason, and 0 newly sliced. With the test-file barrier gone each
  of those packages stops on the next TSP-V0-006 proof: 93 are also selected through another dirty
  path (64 `DEPENDENCY_PATH`, 19 `PATH_LITERAL_READER`, 4 `UNBOUNDED_READER`, 4
  `ENCLOSING_PACKAGE`, 2 `BINARY_EXEC`), 36 change more than plain functions, 16 change a function
  with a reference-typed parameter or result, 3 add a file, 3 use a changed function as a value,
  1 reaches a package variable. The 60 most recent commits give the same picture (16 to 0, no new
  slice; after the `go:linkname` fix the four `cmd/corvint` cases move to the signature proof).
- So the ticket's premise does not hold on this repository's real commits: the source-and-test rule
  was the first proof to fail, not the only one. The next levers, by count, are a cross-package
  reach for a package also changed through its dependency (93) and method or type edits (36);
  neither is a scoping fix.

## V1-3347: a computed shell run keeps the foreign-invocation frontier (TSP-V0-863)

### Decisions

- A strict reading (any unresolved `$`-word is a computed run) found 315 runs in 50 repository
  shell files, mostly binaries and environment arrays (`$corvint_bin`, `$go`,
  `${default_env[@]}`), and made the repository's foreign-caller declaration invalid, which would
  have undone TSP-V0-005 for `script/heavy.sh` on every plan. The rule is therefore shape-based: a
  target counts only when its base-name shape (expansions as `*`) has a literal part and matches a
  known shell file. One expansion alone (`"$heavy"`) is a whole value whose text this file or its
  caller holds, which the TSP-V0-005 text scan already sees; the caller's own arguments (`"$@"`,
  `$1`) are in the caller's text.
- A variable bound only by one `for NAME in` literal list, and never assigned, read or declared
  otherwise in the file, expands to its words, so `bash "$root/script/$helper.sh"` over
  `for helper in dogfood-change dogfood-check dogfood-bind-range` names three scripts rather than
  every `*.sh`.
- Completeness fails only when a computed shape matches a declared script's file name and the
  running file's text does not hold that name: a file that does hold it is found by the scan, so
  its listing is already checked.
- The frontier on a computed caller bears on every plan that reaches it (not only on its
  dependents), test file or not, and a declaration does not clear it from a declared script: what
  the file runs is unmodelled, whoever runs the file.
- On this repository 8 shell files carry a computed run after the change (all test scripts:
  `batch-precheck_test.sh`, `check-analyzer-python-offline-build_test.sh`,
  `check-instruction-conflicts_test.sh`, `check-release-artifact-reproducibility_test.sh`,
  `dogfood-bin-reuse_test.sh`, `dogfood-cache_test.sh`, `lane-scripts_test.sh`,
  `runtime-environment_test.sh`). `script/batch-precheck_test.sh` reused `w` (`read -r w s`) as a
  loop variable that runs `$w.sh`, a `*.sh` shape matching every declared script; its loop now uses
  the unique `wrapper`, so the repository declaration verifies
  (`TestRepositoryShellForeignCallersComplete_TSP_V0_005`).

## V1-3354: which UNKNOWN plans the CI selector may narrow (CIN-V0-860)

### Decisions

- The rule is the AFP-V0-935 one, now stated for the pull-request tier: `Select` runs an `UNKNOWN`
  plan narrowed only when every unknown is a `LANGUAGE_FRONTIER` (it already falls back on a
  module-level one). The safety argument is in the spec: the selector attributes every dirty path
  under its own rules (a) to (d), and a unit frontier names what a language model cannot see inside
  units those paths already reach, which are selected whole. Any other unknown means the planner
  could not attribute a path, and nothing documented the selector's own attribution as a
  substitute; the merge-queue reuse already refused those plans.
- The check reads the unknown list, not only the scope, so a `BOUNDED` receipt that names another
  unknown also falls back, and an `UNKNOWN` receipt naming none is malformed. A reason that is not
  an upper-case identifier is reported as "a malformed reason", so the verdict line stays one line.
- Only `Select` changes. `SelectStructural` (`corvint test`, the shadow) keeps narrowing such
  plans, so the deciding driver's FULL stays a superset of the shadow (AFP-V0-603), and local lanes
  keep their focused runs.

### Effect

On the TSP-V0-860 replay, narrowed merged changes drop from 13 to 4 of 19 (#3, #5, #18, #22), with
0 misses. The 9 that now run FULL name `UNOWNED_DIRTY_PATH` (among them `Makefile`, `LICENSING.md`,
`protocol/cem-1.0/**`, `conformance/release-artifact-v0/manifest.json`, `.corvint/*.json`,
`tools/corvint-pr-tests/README.md`, a stray `test-read-scopes-check` file) and some also
`NO_SELECTABLE_TEST` or `UNINDEXED_SOURCE_PATH`. Making those paths owned (a documentation or
data-reader declaration the planner attributes, as ADN-V0-010 does for documentation paths) is
the lever that would restore narrowing safely; it is a planner change, not part of this ticket.

## V1-3332: a forward-row absence trips the kill switch (CIN-V0-861)

### Decisions

- A first design matched the eligible completed `CI` runs of the window (REST listing) against the
  rows. It was dropped before commit: a pull-request row is named by its tested merge commit
  (`row.jq` `$rowSha`), not the head commit the listing gives, and the listing's `pull_requests` is
  empty for many runs once their pull request has merged (seen in the V1-2892 listing), so runs
  cannot be joined to rows reliably. Instead the collector, which knows why it wrote no row, names
  the run: `NOROW` (an outage) or `EPOCH` (an earlier epoch, excluded on purpose).
- The absence count shares bar.jq's window shape (latest 20 (pull request, commit) entries, INFRA
  and NARROWED taking no place, a re-run's newer entry replacing the older) and the `INCOMPLETE`
  threshold of 3, so an outage trips exactly where the same runs would have tripped as INCOMPLETE
  before CIN-V0-001.
- Residual: a collector that never runs (the `ci-control-plane` workflow disabled or failing before
  `collect.sh`) names nothing; the spec's failure mode (3) says so.

### Wiring (not applied: no `.github` edit in this lane; for the orchestrator's workflow PR)

1. `git mv tools/ci-forward-row/absence.jq .github/forward-rows/absence.jq`, and in
   `tools/ci-forward-row/absence_test.go` run `script(t, "absence.jq")` instead of `"absence.jq"`.
2. `.github/forward-rows/collect.sh`:

   ```diff
   @@ if [ -z "$epoch" ] || [ "$epoch" != "$FORWARD_EPOCH" ]; then
      say "forward row: the selection run ${selection_run:-none} stamped no single forward epoch, or epoch ${epoch:-none} rather than $FORWARD_EPOCH (CIN-V0-001); no row"
   +  # CIN-V0-861: name the run, so the kill switch counts an outage and excludes an earlier epoch.
   +  printf '{}\n' > "$dir/row.json"
   +  if [ -n "$epoch" ] && [ "$epoch" -lt "$FORWARD_EPOCH" ]; then
   +    echo "name=ci-forward-EPOCH-pr$pr-$HEAD_SHA-e$epoch" >> "$GITHUB_OUTPUT"
   +  elif find "$dir/selection" -name selection.json -type f 2> /dev/null | grep -q .; then
   +    echo "name=ci-forward-NOROW-pr$pr-$HEAD_SHA-e$FORWARD_EPOCH-rmixed" >> "$GITHUB_OUTPUT"
   +  else
   +    echo "name=ci-forward-NOROW-pr$pr-$HEAD_SHA-e$FORWARD_EPOCH-rnodoc" >> "$GITHUB_OUTPUT"
   +  fi
      exit 0
    fi
   ```

   `ci-control-plane.yml`'s "Retain the forward row" step already uploads `row.json` under
   `steps.row.outputs.name` whenever it is set, so it needs no change; `$pr` must be non-empty (a

3. `.github/forward-rows/verdict.sh`, after the `bar=$(jq ...)` line:

   ```diff
   +absence=$(jq -R -s -c --arg epoch "$FORWARD_EPOCH" -f "$here/absence.jq" < "$dir/names") ||

   +  '.rowAbsence = $absence | if $absence.killSwitch == "TRIPPED" then .killSwitch = "TRIPPED" else . end')
   ```

   and `rowAbsence: ($bar.rowAbsence // null),` beside `killSwitch` in the verdict document.
4. `.github/forward-rows/accept.sh` re-runs the kill switch over its incremental listing

## V1-3348, second pass (orchestrator request 2026-10-31)

### The dependency barrier (63 of the 93 "also selected" packages)

Measured on the 87 source-and-test commits (manifests of the TSP-V0-861 planner): for every
package kept whole because a dependency is also dirty (`also selected by DEPENDENCY_PATH`), the
dependency's own change already fails TSP-V0-006 in the same plan: 32 are themselves reached
through a further dirty path, 19 change more than plain functions, 3 fail another TSP-V0-006
proof (a reference signature, a new file, a package variable), 7 carry another witness (4
`ENCLOSING_PACKAGE`, 3 unnamed), and 2 are no unit. In 0 of 63 did the dependency change only plain
functions. Any sound cross-package slice needs that much at least (the dependent's skipped tests
must provably not observe the dependency's change, which means a TSP-V0-006 proof of the
dependency plus reach through it), so its ceiling on this history is 0. Decision: not built. A
weaker proof (for example, keeping only the dependent's tests that name the dependency by an import
qualifier) would be unsound: initialization, types, interface dispatch and transitive calls cross
the package boundary without such a name.

types 2 (plus 2 with methods), added consts 2 (plus 2 combined with changed declarations), and 2
