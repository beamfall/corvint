## V1-2881: no aggregate admission wall (`IDX-SNAP-V0-910`, `IDX-SNAP-V0-911`)

Decisions:

- The aggregate refusal is removed, not raised: `validateBlobAdmission` and the query rename
  (`queryAdmissionError`) are deleted, and `fetchBlobs` reads in chunks of at most 32 MiB of framed
  `cat-file --batch` output (`maxBatchBytes`, was the 128 MiB whole-set buffer). Each chunk's
  buffer is its exact expected size and its blobs alias it, so the total is held once and no single
  read scales with the repository. A chunk is a separate `git cat-file --batch` process; for 575 MB
  that is about 18 processes, negligible beside parsing.
- Incremental consumption (direction 2) is not attempted: the compiled `Index` keeps every
  source's `Data` (snippets, spans and the snapshot need it), so peak memory is bounded by admitted
  bytes plus the derived index whatever the read pattern. Recorded as the measured residual below.
- `maxIndexedSources` (200,000) and the 64 MiB tree listing stay. Both bound bookkeeping before any
  blob is read, the listing at 200,000 entries is about 14 MB, and no observed repository is near
  either; lifting them needs a streamed `ls-tree` and is not needed for any criterion.
- The receipt gains `source_bytes` and `build_ms` (`IDX-SNAP-V0-911`); that is the read-only
  report: report fields only, no snapshot byte.
- Tests whose trigger was the aggregate refusal: `TestIndexBuildingCommandsRecordUnsupportedRefusal`
  now asserts the 135 MB fake tree is not refused (`..._IDXSNAPV0910`); the prove checkpoint
  subtest "coded Build error" is removed because no coded unsupported Build refusal remains on that
  path (the codeless path stays covered by `TestPlainProveCodelessBuildErrorStderrIsUnchanged`);
  `TestValidateQueryBlobAdmissionUsesFullEagerBound` and the language-free message test are removed
  with the message.
