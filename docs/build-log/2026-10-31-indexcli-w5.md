## V1-2881: no aggregate admission wall (`IDX-SNAP-V0-910`, `IDX-SNAP-V0-911`)

Decisions:

- The aggregate refusal is removed, not raised: `validateBlobAdmission` and the query rename
  (`queryAdmissionError`) are deleted, and `fetchBlobs` reads in chunks of at most 32 MiB of framed
  `cat-file --batch` output (`maxBatchBytes`, was the 128 MiB whole-set buffer). Each chunk's
  buffer is its exact expected size and its blobs alias it, so the total is held once and no single
  read scales with the repository. A chunk is a separate `git cat-file --batch` process; for 575 MB
  that is about 18 processes, negligible beside parsing.
- Incremental consumption (direction 2) is not attempted: the compiled `Index` keeps every
  source's `Data` (snippets, spans and the snapshot need it), so peak memory is bounded by admitted
  bytes plus the derived index whatever the read pattern. Recorded as the measured residual below.
- `maxIndexedSources` (200,000) and the 64 MiB tree listing stay. Both bound bookkeeping before any
  blob is read, the listing at 200,000 entries is about 14 MB, and no observed repository is near
  either; lifting them needs a streamed `ls-tree` and is not needed for any criterion.
- The receipt gains `source_bytes` and `build_ms` (`IDX-SNAP-V0-911`); that is the read-only
  report: report fields only, no snapshot byte.
- Tests whose trigger was the aggregate refusal: `TestIndexBuildingCommandsRecordUnsupportedRefusal`
  now asserts the 135 MB fake tree is not refused (`..._IDXSNAPV0910`); the prove checkpoint
  subtest "coded Build error" is removed because no coded unsupported Build refusal remains on that
  path (the codeless path stays covered by `TestPlainProveCodelessBuildErrorStderrIsUnchanged`);
  `TestValidateQueryBlobAdmissionUsesFullEagerBound` and the language-free message test are removed
  with the message.

Measurements (`/usr/bin/time -f %e/%M`, `CORVINT_INDEX_REUSE=0`, cold `corvint index` in a scratch

## V1-3310: the refresh writer converges under load (`IDX-SNAP-V0-912`)

Decision (the fork the ticket names): a CPU-time work budget under a longer hard wall, not
adaptive backoff. The writer cancels its build after 55 CPU-seconds (getrusage self plus reaped
children, checked every second) and records `expired`; its hard wall is 10 minutes (work context
ends at 550 s). Backoff alone would stop doomed writers but never deliver context while the load
lasts; with a long wall the single-flight lock already stops later hooks from starting writers
(`already running`), so both acceptance branches hold. The V1-0607 numbers fix the size: 8 CPU-s
idle, about 3.6% of a CPU for a nice +10 writer under 36 nice-0 loops on 12 CPUs, so about 220 s.

Second finding while qualifying: with the wall bound lifted the writer still failed, after 266 s,
with `Git repository index exceeded its deadline` (12.7 CPU-s used). The shared 30 s
`DCW-V0-075` deadline wraps the build's Git phase and is a wall bound too. The worker now marks
its context in-process (`contextindex.WithWriterBounds`), and only that context drops the 30 s
deadline; `DCW-V0-075` notes the exemption. Every other build keeps 30 s.

Live qualification (`~/lanes/indexcli-w5-scratch/refresh_qual.py`, real
`corvint adapter claude-code user-prompt` hook under `timeout 2` on a `--no-local` clone of the
base, 36 nice-0 `sh` loops; driver, loops, hooks and writer pinned to CPUs 0-11):

## V1-2585: Git start errors name their class (`DRC-V0-910`)

Decision: a closed class, not the errno text. `contextindex.GitStartErrorClass` maps the retained
start error to `ETXTBSY`, `ENOENT` (including `exec.ErrNotFound`), `EACCES`, `EPERM`, `ENOEXEC`
or `other`; the uncoded `emitError` envelope adds `"git_start_error"` between `error` and `ok`
only for that cause. The `error` bytes stay `Git error: cannot start Git`, and no path or errno
string is emitted, so the member needs no secret screen. The fallback the ticket observed was a
test's own failure text; any caller that records a fallback reads the same function.
`TestGitStartErrorClass_DRCV0910` starts a real missing executable (ENOENT) and a real executable
held open for writing (ETXTBSY, the V1-2585 race), and an exit failure that names nothing.

## V1-2746: reference and import extraction without regexp

Decision: exact byte scanners, not a prefilter. `documentReferences` (every maximal chain of two
or more non-empty `[A-Za-z0-9_.-]` segments joined by single slashes, which is what the
leftmost-first greedy regex finds) and `genericImportSpecifiers` (one deterministic parse per
`from`/`import` start, the oracle's Unicode space class, skipped matches still consuming their
span) in `internal/contextindex/reference_scan.go`. The regexes move to
`reference_scan_test.go` as the oracle; `TestReferenceScannersMatchTheirRegexes` compares both
over every tracked file of the checkout (under the 1 MB source bound) and 50 edge fixtures

output digest is unchanged (this also covers the V1-2881 and V1-3310 edits to audited inputs), and

## V1-3313: `corvint version` (`PRS-V1-910`)

## V1-3312: a successful empty hook is distinguishable (`AHI-910`)

Decision: use the hosts' own schema rather than a new key. A Claude Code or Codex
`SessionStart`/`UserPromptSubmit` hook that ran and found nothing actionable prints
`{"hookSpecificOutput":{"hookEventName":EVENT}}`: both hosts accept it and inject nothing, and an
unknown top-level key risks host-side output validation. Faults keep their `FALLBACK degraded:`
message; unhandled events, a non-repository `cwd` and `SessionEnd` stay `{}`. The kernel opt-in
suffix and the unplanned-read packet record treat the marker as empty, as they treated `{}`.
Tests: `TestAHI046SilentProjectionRendersNothing` (both hosts, suffix, and fault/context/empty
negatives), `TestAHI046CodexPromptSilenceAndProjection`, `TestClaudeNativeDogfoodLifecycle`;
`./conformance/host-lifecycle-v1` passes. `TestHostAdapterJavaScriptHosts` (Node 22.22.1) passed 2 of 3 runs after the change; the failing run's subtest was not captured (see Friction).

## V1-3423: the kill-deadline banner shows once per cause (`AHI-911`)

Decision: reuse the `SOL-V0-010` ledger's own deduplication key (host, event, code, UTC hour) as
"once per cause" instead of a new state file, which invariant 4 would not admit.
`observations.AppendNew` reports whether the row was new; `Append` keeps its signature. For every
Claude Code event except `SessionStart` and `UserPromptSubmit` (whose fallback explains that
prompt's missing context and stays as it was), a repeat within the hour prints `{}`, and a new one
keeps its frame and adds a line naming the action (`corvint --root ROOT index --if-stale`, and
`corvint --root ROOT observations` for repeats). A failed, unignored or late (over 50 ms) append is
never a repeat, so a fault is not hidden. Note: `PostToolUse` is a context event in this adapter,
so the banner reaches the model as `additionalContext`, which is why it repeated on every Bash
call. Test: `TestAHI911KillDeadlineBannerOncePerCause` (first banner with argv, quiet repeat, one
ledger row, unchanged `UserPromptSubmit`).

## V1-3301: a .dev build of an RC is older than the published RC (`UPD-V0-910`)

## V1-3299: PUB-V0-024 on the WSL lane host (`WQO-V0-910`)

Root cause recorded: the host umask is `0002`. `t.TempDir()` creates its numbered directory with
mode 0777 less the umask, so it is `drwxrwxr-x`, group-writable without the sticky bit, and the
work binding's unsafe-parent rule (WQO-V0-049) refuses the installed binary under it. The same
umask makes the `go build -o` output 0775, which the executable rule refuses next. TMPDIR is not
the cause (the sticky `/tmp` itself is admitted); under TMPDIR=~/lanes the refusal now names
`/home/russell/lanes has mode drwxrwxr-x`, as the lane's own run showed. Fixes: the refusal names
the parent and its mode (`WQO-V0-910`), and the PUB-V0-024 fixture sets its root to 0700 and its
binary to 0755, as V1-3220 did for the work fixtures. The test now passes on this host with the
default TMPDIR (18.9 s). New tests: the `unsafe-parent-named` row of
`TestWorkInitRejectsUnqualifiedExecutableWQOV0049` and `TestWorkInitAdmitsAStickyParentWQOV0910`
(a 1777 sticky parent binds). Mac status NOT_OBSERVED.

## V1-1555: TestIssue502_InfraSessionKeepsTierAndResetsSuffix cleanup

returns. Evidence: `-count=20` of the whole `TestIssue502` group passed at load 65-83 before the
fix (the race is rare), and `-count=20` of this test passes at load 51-62 after it.

## Friction

1. `/tmp` is a 16 GB tmpfs shared by every lane, and the Makefile defaults
   `CORVINT_GOCACHE ?= /tmp/corvint-go-build-cache` (14 GB on this host). It filled `/tmp` to 0 B
   free; `go build` and the Claude Code harness then failed (`no space left on device`). Repro:
   `df -h /tmp; du -sh /tmp/corvint-go-build-cache`. Workaround: `CORVINT_GOCACHE=$HOME/.cache/...`
   and `GOTMPDIR` on disk.
2. A hook on a `git clone --shared` checkout (object alternates) prints only
   `FALLBACK degraded: corvint-event-rejected:dogfood-event-unavailable`; the underlying
   `unsupported-object-alternates` is not named. Repro: `git clone --shared REPO x && echo
   '{"session_id":"s","hook_event_name":"UserPromptSubmit","cwd":"'$PWD/x'","prompt":"p"}' |
   CLAUDE_PROJECT_DIR=$PWD/x corvint adapter claude-code user-prompt`.
3. heavy.sh refuses a whole-package `go test` without `HEAVY_WHOLE_REASON`, but
   `corvint affected` printed a 77 KB selection that does not reduce to a usable `-run` list for
   `internal/contextindex`; focused regexes were the only practical path.
4. `TestHostAdapterJavaScriptHosts` failed 1 of 3 runs on this host after the AHI-910 change and
   passed the other two; the Go wrapper prints only `--- FAIL`, not the failing node subtest,
   so the flake cannot be attributed without rerunning with the raw node output.
5. `make doc-gates` cannot finish within the lane's 600 s command bound: `selection-baseline-check`
   alone ran past it. Workaround: run `DOC_GATE_TARGETS` without it; selection-baseline NOT_RUN.
6. The line-citation checker validates the staged copy, not the worktree: edited citations kept
   failing until `git add`. Its message does not say so.
7. Any edit to an audited contextindex input requires `script/analyzer-schema.sh bump` even when
   output is unchanged; nothing earlier than `doc-gates`/the schema test tells the lane.
8. Umask 0002 on the WSL lane host breaks fixtures that rely on `t.TempDir()`/`go build -o` modes
   (V1-3220, V1-3299); more tests likely share it.
