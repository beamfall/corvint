## Design decisions

- The table is the existing capability inventory, `internal/capcatalog` `MCPTools()`, with new
  columns: server, also-on servers, availability, description, opt-in, input schema source, a
  description for every input property, output profile, closed tool-error codes, CLI equivalent,
  parity test, replaced names and a note. `CheckMCPTools` names every broken row; it refuses a
  duplicate name, a shared description, an input property without a description, a row without
  `server-busy` and `cancelled`, a name off `corvint.<area>_<verb>`, a Tasks-named row on a
  server, a CLI equivalent without a parity test, and a table without the Tasks "no MCP tool" row.
- Server values beyond the two product servers: `none` for the Tasks row (R17), and
  `corvint-test-validity-mcp` for `corvint.test_validity`, which M12 removes from `corvint mcp`
  but whose retiring binary still serves it until its removal batch. `corvint.help` stays one row
  with an also-on column, because both servers list it from the same code and the spec requires
  unique names. `corvint.docs_how` is a `planned` row that no server registers yet (HOW-V1-011);
  the drift test treats planned and serverless rows as naming no registration, and so does
  `tools/capabilities-check`.
- Input-property descriptions live in the table, which is the column DMF-V1-008 checks. The
  servers' registered schemas carry no property descriptions in this tree (the docs-mcp-hardening
  lane adds them in `corpusbridge`), so the drift test compares property names, not text, and the
  generated document prints the table's descriptions. Injecting the table's descriptions into
  `tools/list`, or requiring the schema text to equal the table's, is left for when DMF lands.
- `docs/MCP-SERVER.md` is generated by `tools/mcp-server-doc` (`make mcp-server-doc`); the doc
  gate `mcp-server-doc-check` fails on any difference and, for MTT-V1-009, when a row's named
  parity test is not defined in its package. The prose sections live in the generator. The results
  and error section is placed ahead of the per-server tables so the glossary's line citations into
  it survive row changes; they were repinned once.
- `corvint-docs mcp` cannot reuse the `corvint mcp` server package: the import ratchet puts
  `internal/mcp/cli` in the tests area and `cmd/corvint-docs` in the docs area, and areas import
  only `shared` (decision 0594 item 8). It is a new docs-area package, `internal/mcp/docsserver`,
  on the shared transport and tool groups: `--root` and optional `--corpus-artifact`, single
  root, no profiles. It always lists every corpus tool; without an artifact each corpus call is
  the `corpus-refused` tool error naming the flag, so the surface never silently narrows. The
  draft and consume tools still run the `docs-tool` verb, which finds the running `corvint-docs`
  itself, so the server needs only that executable (MTT-V1-004).
- Removing the `docs`, `corpus` and `test-validity` groups from `corvint mcp` deletes their code
  from `internal/mcp/cli` rather than leaving it unreachable. A request for one, or
  `--corpus-artifact`, exits 2 before any MCP byte with `corvint-mcp: invalid arguments:
  profile-moved: ...` (naming `corvint-docs mcp`) or `group-removed: ...`. The corpus artifact
  tests (MMR-V0-014, MMR-V0-017, MCPV0-950) moved to `internal/mcp/docsserver` with the
  behaviour; the multi-root follow-ref union test now uses the `test-evidence` group. The
  import-ratchet baseline loses its `internal/mcp/cli -> internal/mcp/corpusbridge` edge.
- Flow tools are renamed without aliases: `corvint.flows.<x>` becomes `corvint.flows_<x>`, and
  each row lists the old name in Replaces. Whether old names stay as deprecated aliases is an open
  owner question in the design; an old name is now the unknown-tool error.
- `CORVINT_SELECTION` does not exist anywhere in this tree; its grammar is owned by NMS-V1-008
  (change `narrowing-measurement`). This change adds only the shared parser
  `internal/selectionswitch` (exactly `full` or `full:<runner>[,<runner>]`) and the MCP half: any
  non-empty value makes `corvint.affected` answer a successful `affected-select-all/1` result
  (scope FULL, reason `kill-switch` or `kill-switch-value-unknown`, the value, the runners, a
  detail and a one-line hint) without running the planner. The planner has no per-runner full
  form, so `full:<runner>` is widened to every test, and the detail says so. The CLI exit 2 on an
  unknown value is NMS-V1-008's to build. The reason name follows NMS-V1-008's
  `kill-switch-value-unknown`, not the design's placeholder `SELECTION_UNKNOWN_VALUE_FULL`, as
  the design asked.
- On a stale binary the planner still refuses with `self-binary-stale`; the tool now turns that
  one refusal into the same select-all answer, with the planner's message as its detail and a
  rebuild-and-restart hint. Every other planner refusal stays a tool error. The CLI keeps exit 2.
- Parity (MTT-V1-009): a row with a CLI equivalent names its parity test. Existing tests cover
  `corvint.affected` (`TestV15254MCPAffectedMatchesCLI`), the twenty corpus tools
  (`TestCorpusTypedCLIMCPEndToEnd`) and `corvint.docs_draft`
  (`TestDocsToolVerbAnswersInOneEnvelope`); new tests cover help, impact, test evidence, the six
  flow tools and consume. `corvint.impact`'s receipt equals the `context` record of
  `corvint impact` (the CLI adds only `ok`, `tool` and `mutates`); consume's text differs from the
  CLI only by its trailing newline, so the tests compare records. `corvint.status` has no CLI
  equivalent (`corvint status` does not exist), and the retiring `corvint.test_validity` row
  claims none.
- `test_evidence` is labelled preview by a `Preview:` prefix on its tool description and the
  table's `preview` availability.

## Differences from the proposal's tree

The proposal was checked against an older tree (integ 9ec3a29d0). In this tree: the
`corvint-docs-mcp` usage named `corvint-mcp --tool-profile docs` as its unified equivalent and now
names `corvint-docs mcp`; `corvint-test-validity-mcp`'s usage named a group that no longer exists
and now says it is retiring; there are 20 corpus tools because `corvint.docs_recommend_tests` is
still registered (docs-mcp-hardening removes it under DMF-V1-009 and should then drop its row);
`CORVINT_SELECTION` has no CLI implementation (see above). Scope was not widened for any of these.
