# unbrd review fix 7: every computed-target bound is a cut (2026-11-07)

Lane unbrd (V1-4283, PR #131). The independent review of round 6 raised one blocking P1, a
test-selection soundness gap in the shell plugin's computed-target expansion (TSP-V0-960). This
entry records the verdict, the fault-injection tests and the fix, under AFP-V0-3146 to
AFP-V0-3148 in `docs/specs/affected-plan-selection-v0.md`.

## Finding: CONFIRMED

`named` in `internal/liveverify/affected/shell/computed.go` returned the wildcard for a name given
more than 16 values (`maxNameValues`) without setting `cut`. `constructed` then read a value such
as `\x00/check` like an environment input. AFP-V0-3144 (round 6) does expand an extensionless
target whose file name an owned script carries. But the value's file name `check` has no shell
suffix, so `constructed` dropped it: no edge, no constructed name and no `shell:dynamic-source`.

Reproduced at `aa16cbf1a` with the review's case:

- `script/check` has a shell shebang and `. "$ENVFILE"`, so it is itself a dynamic source.
- `use/wrap_test.sh` runs `for dir in a b c d e f g h i j k l m n o p script; do "$dir/check"; done`.

The wrapper test had no imports and no unbounded witness. An edit of a configuration file, or of
`script/check` itself, did not select it. The round 6 regression covered only the 64-value
Cartesian bound, which already set `cut`.

## Audit of the bounds

Each place in `computed.go` that returns the wildcard was classified by one question: did it drop
values the file gives?

| Site | Drops given values | Before | After |
| --- | --- | --- | --- |
| `named`: more than 16 values | yes | wildcard, no cut | cut (AFP-V0-3146) |
| `named`: depth 4 | yes | wildcard, no cut | cut (AFP-V0-3147) |
| `braced` default `-`, `:-`, `=`, `:=` at depth 4 | yes | wildcard, no cut | cut (AFP-V0-3147) |
| `braced` alternative `+`, `:+` at depth 4 | yes | wildcard, no cut | cut (AFP-V0-3147) |
| `expand` / `named` / `braced`: 64 values | yes | cut | unchanged |
| `commandStrings` (`shell.go`): any bound in `sh -c "$cmd"` | yes | cut discarded | cut makes the unit a dynamic source (AFP-V0-3147) |
| `named`: a name the file never sets | no | wildcard | unchanged (environment input, TSP-V0-960) |
| `$1`, `$@`, a command substitution, an unfollowed operator, an empty `:+` alternative | no | wildcard | unchanged |
| an unterminated backquote or `${`/`$(` | no (malformed) | wildcard | unchanged |

The new helper `truncated(cut)` sets the cut and returns the wildcard. Every bound that drops
given values now calls it. The caller already turns a cut into `UnboundedReads =
shell:dynamic-source`, and a non-test unit also gets `LocatesRoot`. So the truncated expansion
keeps the conservative wildcard protection instead of passing for an environment input.

The other `max*` constants in the shell plugin bound declaration files. Exceeding one is a
refusal, not a silent drop, or sets `PathTokensBounded`, which is already a flag. They do not
follow this pattern.

The pattern was considered as a whole, not only for extensionless targets. A shell-suffixed
target such as `"$dir/run.sh"` under the same 17-value loop used to become only a constructed name.
A test unit (a leaf) got no frontier and no edge from it. It is now a dynamic source as well.

## Parity

`internal/gateselect` (the CI selector behind `tools/gate-affected-select`) has no shell analysis
of its own. It reads the affected-plan receipt that `corvint affected` builds with this shell
plugin, so the fix reaches it unchanged and there is no parity counterpart to amend. Its parity
tests were rerun, as listed in the handback.

## Fault injection

`internal/liveverify/affected/shell/computed_bounds_test.go`:

- `TestPerVariableBoundKeepsTheCallerSelected_AFPV03146` covers the review's reproducer. The
  wrapper is `shell:dynamic-source`, and edits of `config/settings.env` and of `script/check`
  select it.
- `TestEveryExpansionBoundIsACut_AFPV03147` makes a test `shell:dynamic-source` for each of these
  inputs:
  - 17 plain and 17 braced assignments
  - a five-name chain
  - a five-deep `:-` default
  - a five-deep `:+` alternative
  - a 17-valued `sh -c "$cmd"`

  It has two controls. An environment-input directory (`"$SDK/go"`, `"$TOOLS/check"`) stays
  bounded. A 16-value loop links `script/check` with no unbounded witness.

All seven cut cases failed at `aa16cbf1a` before the fix, and both controls passed. All of them
pass after it.

## Repository effect

Measured with `corvint affected --path PATH --format json` on a clean worktree. "Before" is a
binary built at `aa16cbf1a`; "after" is built from this round's code. Columns are selected units /
units with `anyDirtyPath` / Go packages.

| Path | Before | After |
| --- | --- | --- |
| (a) `.github/workflows/ci.yml` | 291 / 102 / 50 | 292 / 105 / 50 |
| (b) `script/heavy.sh` | 324 / 31 / 72 | 324 / 31 / 72 |
| (c') `docs/DOGFOOD.md` | 283 / 52 / 48 | 283 / 52 / 48 |

The first build of the fix, before AFP-V0-3148, made five repository scripts newly
`shell:dynamic-source`. A temporary in-package probe, deleted afterwards, found which bound each
one hit:

- `script/gen-spec-requirements_test.sh` puts `$mode` in command position through the bats `run`
  prefix. It gives `mode` the same flag lists in 7 loops: 25 words but 6 distinct values. That was
  a false cut, because identical text expands identically. AFP-V0-3148 counts distinct values, so
  the test stays bounded.
- `script/dogfood-change.sh`, `script/dogfood-check.sh`, `script/dogfood-batch-check.sh` and
  `script/dogfood-finish.sh` each set `corvint_bin="$PWD/$corvint_bin"` (dogfood-finish.sh also
  has `static_bin`). The self-reference unrolls to depth 4, a genuine cut. The plugin does not
  prove that the unrolled values add no edge or name, so they stay dynamic sources. Their callers
  were already selected on every change through `script/heavy.sh`. The net cost is the Makefile
  `dogfood-check` and `dogfood-batch-check` targets and `script/dogfood-change_test.sh`.
- TSP-V0-831 then refused `script/dogfood-change_test.sh`'s TSP-V0-950 read scope, because the
  test reaches an unbounded reader. The scope is removed and the test is recorded in
  `.corvint/unbounded-readers.json` with that reason, as round 1 did for
  `script/dogfood-cache_test.sh`. `make unbounded-readers-check` passes.

`script/heavy.sh`'s `"$sdk/go"` keeps the AFP-V0-3144 shortcut, because no owned file is named
`go`. Its `prev_go`, which has more than 16 values, is no run target, so heavy.sh is unchanged.

A narrower rule for a self-reference that the plugin could prove is not adopted here. Such a rule
would unroll once when the prefix before a trailing self-reference already holds an unknown part.
It is recorded as a follow-up idea in the lane handback.

## Not changed

A value whose unknown part is an environment input (`"$TOOLS/check"`) stays outside the model, as
TSP-V0-960 and its failure mode (12) state. No bound dropped a value the file gives there, and
modelling environment inputs is a separate decision. This is recorded as a non-goal of AFP-V0-3146
and AFP-V0-3147.
