# 2026-11-03 PWP-V0-961: independent review of the report-level Node version fallback

One independent review covered `PWP-V0-961` (report-level `process.version` as a fallback for an
unobserved receipt Node version, `docs/specs/playwright-external-provider-v0.md`, "Report-level
Node version amendment"). Base: `af470712c01d8039bc03abda4d5eb903cb1ee5e2`; reviewed HEAD:
`962d7813`; repair: `35f9107f`; PR beamfall/corvint#65. The reviewer checked four constraints:
a disagreement with any per-test browser identity Node version stays unobserved, missing evidence
stays unobserved, the admitted runtime tuples are unchanged, and the code matches the spec text.
It found nothing material. Its focused Go cases and the Node reporter suite (26/26) passed.

Finding 1 (low, no fail-open): `recordedNodeVersion` skipped any test whose `project.browser` was
`"none"` before validation. A report could mark a test `browser: "none"` and also give it a
conflicting `use.corvintBrowser.nodeVersion`. The receipt then recorded the report-level version.
`bindQualifiedReport` still refused that test as `project-location-unknown` (the browserless `use`
must be exactly one `corvintBrowserless` reason), so nothing qualified. The refused receipt still
named a Node version that a per-test value contradicted, which breaks the disagreement constraint
as written.

Decision: skip only a test that `browserlessReason` accepts (runner 1.63.0 or 1.64.0, at least one
attempt, the closed `PWP-V3-015` shape). Any other `browser: "none"` record must carry an agreeing
per-test version, like a browser test. The spec text was tightened in the same change.

Finding 2 (low): no test reached the `runExternal` step that passes the decoded report into the
fallback. A regression passing `nil` there would have left every new test green. Decision: the
step is now `fillRecordedNodeVersion(&r, report)`. `TestPWPV0961BrowserlessNpxRunTupleCandidate`
calls it, and also proves that a version an executable source observed is never replaced.

Finding 3 (informational): on runner 1.60.0, any observed Node version makes the tuple
`candidate`, so a 1.60.0 run with no tests can now record a version. No test qualifies from it.
This was kept, and recorded as a non-goal in the amendment.

Evidence: two mutations confirm the new tests. Restoring the `Browser == "none"` skip fails the
forged-version and no-attempt cases. Turning the fallback off fails the all-browserless cases and
the `unobserved` to `candidate` assertion. After the repair, focused tests passed for
`./internal/jstestprovider`, `./cmd/corvint-js-test-provider` and `./internal/testvaliditydoc`,
plus the Node reporter suite, `go vet`, `make windows-vet` and `make doc-gates`. The repaired
change bound and sealed with `cem=accepted`, 14/14 hunks supported. An automated Greptile review
of the sealed head reported no actionable findings.

Not run: a live bare-`npx` browserless run on an admitted tuple (the lane host's Node v22.23.4 is
outside the table), `make gate`, and the exhaustive suite. `guarding-tests` is `NOT_PRODUCED`.
