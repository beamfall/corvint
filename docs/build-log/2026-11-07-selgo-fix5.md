# Selection: a bearing non-Go frontier adds its language suite in both selectors (review fix round 5)

Date: 2026-11-07
Lane: selgo (branch `claude/sel-go`, PR #128), review fix round 5 after `2026-11-07-selgo-fix4`.
Ticket: V1-4931. Requirement: AFP-V0-2750 (new) in `docs/specs/affected-plan-selection-v0.md`,
amending AFP-V0-982 (`docs/specs/affected-plan-v0.md`), the STR-V0-004 language set of
`corvint test` and the CIN-V0-860 audit lines. AFP-V0-2749's closing sentence now points here.
Owner goal: never fewer tests than needed.

## Finding

The independent fix-only review of round 4 returned one blocking P1. Round 4 (AFP-V0-2749) makes a
Ruby spec that reads repository files by a computed name bear on a deleted Go source through its
path-open `implicit-test-dependency` entry. But `gateselect.AllowedUnknown` admitted every non-Go
`LANGUAGE_FRONTIER`, so both `corvint test` (`sessiontest.Build`) and `gate-affected-select`
(`unknownNarrowing`) dropped that entry. `corvint test` takes its execution languages only from
selected units and `NO_SELECTABLE_TEST` entries, so a declared Ruby suite never ran. The round-4
regression checked that the plan kept the entry, not that anything executed it.

Checked against the code: confirmed. This was friction item 2 of the round-4 handback.

## Decision

The orchestrator decided this one: fail closed. A non-Go frontier that names a reader of a changed
or deleted path adds that language's declared suite to execution in both selectors, and Go
selection is not widened.

No non-Go frontier in a plan is unrelated to a changed path. `frontierUnknowns` names an entry only
through:

- a participating plugin;
- a reached or narrowed unit;
- a dirty path that no plugin owns;
- a terminal plugin's cross-language entry.

A clean plan names none. So the blanket allowance is removed, with no class left behind it.

`AllowedUnknown` now admits only these frontiers:

- `go:build-constraint-variants` and `go:nested-module-frontier`, as before;
- `driver:` frontiers. Driver units are make targets and CI jobs. No adapter or declared command
  runs them, so neither a narrowed run nor a FULL run has a suite to add. This follows the
  existing `NO_SELECTABLE_TEST` exclusion of the driver namespace (AZU-V0-9704).

The new `gateselect.FrontierSuite(reason, detail)` reads every other `LANGUAGE_FRONTIER` whose
detail is `<language>:...`, where the language is a plain lowercase name other than `go` and
`driver`. Both selectors call it:

- **`corvint test`:** `Build` adds the language to the set it runs through `declaredLanguage`. A
  declared command runs as `declared:<language>`. On the `ci` profile it is named as a check that
  is still required. A `none` declaration records the no-suite assertion. An undeclared language
  leaves the run `INCOMPLETE`, which is the fail-closed outcome. The scope stays `NARROWED`.
- **`gate-affected-select`:** it writes one `suite <language> <- <detail>` audit line per language
  before the verdict, naming the first such entry. The Go verdict does not change. Every consumer
  (`tools/corvint-pr-tests`, `script/gate-affected.sh`, `tools/str-parity`,
  `tools/selection-baseline`) reads only the last line.

A detail with no language prefix, an empty detail, or a malformed name is outside both rules and
still forces FULL. `tools/shell-test-select` keeps its own shell rule. It also keeps admitting the
other non-Go frontiers, because they are other languages' suites, which that selector does not run.

### Repository declaration

The replays below raise `cfamily:link-graph-unmodelled` and `cfamily:unresolved-include` for a
deleted Go source. `.github/cishards/test-commands.json` had no `cfamily` entry, so every Go deletion
here would have made `corvint test` `INCOMPLETE`, and CI FULL through the AFP-V0-098 shadow check.

The repository's only C sources are fixtures: `internal/liveverify/affected` and
`internal/analyzernativebridge` testdata, and `tools/beamfall-shadow` fixtures. So the declaration
now says `cfamily: none`. `tools/test-commands-check` refuses a `none` language it knows no runners
for. It now names `bazel`, `cmake`, `ctest`, `meson`, `ninja` and `scons` as C and C++ runners, so it
can confirm that no `make gate` step runs one (STR-V0-006).

manifest, or any other failing exit, still fails the replay. Its CI rule, which is the selector

The rerun passes: `narrow=33/43 merged`, `misses=0` (floor `narrow>=30 misses<=0`). Every one of
the 58 changes replays. 36 record `testIncomplete`, and each of those reasons is the missing
`cfamily` declaration. Trees from this change onward declare it.

## Not covered

another plugin's unowned-path checks, so no frontier entry exists for either selector to act on.
Covering it needs a planner design change (an owned edit exposed to path-open readers), not a
selector rule. It stays open in the handback.
