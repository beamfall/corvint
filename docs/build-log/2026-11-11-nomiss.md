# Location sources reach rule (d) (V1-3999, lane nomiss)

Base `origin/main` b55635262. Requirements AFP-V0-3660 to AFP-V0-3665 in
`docs/specs/affected-plan-selection-v0.md`, all proposed and experimental; no owner acceptance is
claimed.

## Problem

Rule (d) of AFP-V0-012 holds a package whose reads no literal bounds. It matched `os.Getwd`, the
`--show-toplevel` literal and literals that climb from a test's package directory. A package that
rebuilt the repository root from `runtime.Caller`, or read a directory named by the environment,
carried no such literal and was treated as bounded, so a change to a file it read selected
nothing. `TestLocationSourceReads_AFPV03660` (first commit of this lane) pins eleven such reads
bounded on the base, in the gate index and the planner alike.

## Decision: a pass keyed on sources, not the earlier port, not (a), and (b) only where it exists

**The earlier attempt** (`refs/orphans/rule-d-computed-root`, AFP-V0-2770 to AFP-V0-2775, never
merged) is a per-file taint pass from frame and environment sources to a list of sinks. Its
default is "bounded unless the value reaches a listed sink". The set of functions that can turn a
string into a read is open: every helper of the package, every method, every other package and
every standard-library call that takes a path. Each of its two reviews found more sinks (walk
callbacks, method receivers, `Args` stores, `parser.ParseDir`, `os.WriteFile`, `net.Dial`), and
its residual list still admits values that leave the file through a function or a method. That
shape cannot be closed by listing. It is not ported. Kept from it: the source list, the
measurement method, the plain-literal join conditions (no `.`, `..`, glob or backslash
component), the `go list` interaction with `internal/closureguard`, and the observation that host
and helper-process environment reads exist.

**Alternative (a)**, holding a package whose sink argument the scanner cannot reduce to literals,
needs the same open list of sinks to know which calls take a path, so it has the earlier
attempt's hole at the other end. Applied to every call that takes a non-literal string it holds
almost every package: production code reads computed paths by design (`filepath.Abs` alone is in
185 files). It was weighed on paper and not built.

**Alternative (b)**, run-time confinement, exists for part of the repository. `.github/testconfine`
(AFP-V0-023) is the `go test -exec` wrapper every CI shard runs; it confines each package declared
in `.corvint/test-read-scopes.json` with Landlock to its own directory and its declared entries,
inherited by every child process, and fails closed. The selector already relies on it: a declared
package is dropped from rule (d) (`undeclaredUnresolved`) and from rule (c) readers outside its
scope (`boundedReaders`, TSP-V0-980). `TestExecConfinedDeniesUndeclaredRepositoryReads_AFPV0023`
shows a confined child cannot read an undeclared path that a shell builds at run time. So for the
198 declared packages a constructed read outside the declaration is refused in the reference run,
whatever the static rule says; 126 of the 151 bounded packages that name a frame or environment
source are declared. It gives no guarantee for an undeclared package, which runs unconfined, nor
for an unconfined local run. Extending (b) to every package would need `.github/**` and CI
changes outside this lane. `internal/unplannedread` measures agent reads of context packets and is
unrelated.

**Chosen**: a static pass keyed on sources. A path that names a repository file without a literal
token naming it has to take its location from a value that discloses one. The pass enumerates
those values (a closed set: the channels below), and a reference to one holds the package unless
every value it yields is used in one of a short list of ways that cannot form a path. The default
is hold; a use the list does not name costs precision and never a test. The data flow is one
file, by object identity, through locals only: a value that leaves the file through a call, a
return, a store or a package-level variable holds the package, so no interprocedural argument is
needed.

## The rule

- AFP-V0-3660, sources: `os.Getenv`, `os.LookupEnv`, `os.Environ`, `os.ExpandEnv`,
  `syscall.Getenv`, `syscall.Environ`, `syscall.Getwd`, `runtime.Caller` (the file),
  `runtime.FuncForPC` (its `FileLine` file) and `runtime.CallersFrames` (a frame's `File`), under
  any import name or a dot import, called or not; a file with a `//go:linkname` directive or
  `import "C"` holds too.
- AFP-V0-3661, safe uses: discarded or assigned to `_`; bound to a local whose every read is safe;
  an operand of a comparison, a switch tag, the argument of `len`, `strconv` parsing or
  `time.ParseDuration`; the value of a `NAME=value` entry that is an element of a string slice; the
  whole environment as an `Env` field or key, directly or through `append`, `slices.Clip` or
  `slices.Clone`; a frame's or function's non-path members. A pure path transform
  (`filepath.Dir`, `Join`, `Clean`, `FromSlash`, `ToSlash`, `Abs`, `+`) is followed: its result is
  a location value judged by its own uses.
- AFP-V0-3662, bounded joins: a location joined to plain literal components (`+ "/a/b"`,
  `filepath.Join(v, "a", "b")`, at least one component a whole rule (c) token) is bounded by those
  tokens (AFP-V0-2203, AFP-V0-2240) while it only reaches a read at or below it (`os.ReadFile`,
  `Open`, `OpenFile`, `Stat`, `Lstat`, `ReadDir`, `filepath.WalkDir`, `Walk`), a further plain join
  or a flag use. `filepath.Dir`, a return, a store, a command and any other call widen it and hold.
- AFP-V0-3663, reasons: `<file> calls <source>, whose value may name a repository path`, marked
  after every literal and locator reason of the package; a non-test file locates the root for every
  dependent, as `os.Getwd` does.
- AFP-V0-3664, command directories: a location whose only unproven use is the `Dir` of a
  single-assignment `exec.Command` local is held by the gate, and by the planner unless
  `goListScanFile` proves that call a `go list` reading only the import graph from a proven
  directory (AFP-V0-2200), or the source is a frame and the call is any `go list`, which keeps the
  whole-module fallback AFP-V0-9600 gives it.
- AFP-V0-3665, the residuals below are named, not checked.

## Closed-world argument

A test reads a repository file only by handing the kernel a path (open, stat, readdir, exec,
chdir) in its own process or a child. The path is built from bytes the process has: string
literals of its Go source, and values from outside its code. A path that names a repository file
with no literal token naming it must start from a value that discloses a location at or above the
repository. Every channel through which a Go process obtains such a value:

| Channel | Treatment |
| --- | --- |
| Working directory: `os.Getwd` | checked, rule (d) and AFP-V0-2950 |
| Working directory: `syscall.Getwd` | checked, AFP-V0-3660 |
| Working directory: relative literal paths | checked: they resolve against the package directory and climb only through a `..` component, which rule (d) holds in a test file; `filepath.Dir` of a relative path never climbs above `.` |
| Working directory: `filepath.Abs` of a non-source value, then climbed | residual R1 |
| Compiled-in source positions: `runtime.Caller`, `FuncForPC().FileLine`, `CallersFrames().Next().File` | checked, AFP-V0-3660 (a `//line` directive changes the text, not the hold) |
| Compiled-in positions as text: `runtime.Stack`, `debug.Stack` | residual R2: needs parsing a `file:line` field out of a trace |
| Environment: `os.Getenv`, `LookupEnv`, `Environ`, `ExpandEnv`, `syscall.Getenv`, `Environ` | checked, AFP-V0-3660; no host or opt-in variable is excepted |
| Environment read by the standard library for you: `os.UserHomeDir`, `UserCacheDir`, `UserConfigDir`, `TempDir`, `t.TempDir`, `os.MkdirTemp`, `exec.LookPath`, `os/user`, `go/build.Default` | residual R3: host locations, assumed to name no directory inside the checkout that a test walks (on GitHub runners `HOME` is an ancestor of the checkout) |
| Argument vector and flags: `os.Args`, `flag` | residual R4: the reference run passes none that names the repository |
| Executable location: `os.Executable`, `/proc/self/exe` | residual R5: the test binary lives in the go tool's work directory |
| Another process: a child's output (`go env GOMOD`, `go list -f {{.Dir}}`), pipes, sockets | residual R6; the `--show-toplevel` literal is checked by rule (d), and a helper process that is the test binary itself runs code this pass scans |
| File contents: a path read out of a manifest, `go.mod` or JSON | residual R7 |
| Kernel pseudo-files: `/proc/self/cwd`, `/proc/self/environ` | residual R8: the literal is a root-anchored token, not a climb |
| An absolute literal naming the checkout's host location | residual R9 |
| A tracked symbolic link followed by a read of a computed path | residual R10 (literal reads through links are AFP-V0-9450's) |
| Calls the scan cannot see: `//go:linkname`, cgo | checked, AFP-V0-3660 |
| Calls the scan cannot see: assembly, `unsafe` reads of process memory | residual R11; the repository has no `.s` file |
| Functions of third-party modules that read the environment, the working directory or frames | residual R12; this repository's `go.mod` requires no module |

What the argument assumes about the code, each checked or named:

- A source is a function value. Go reaches a package-level function only by naming it (reflection
  cannot look one up by name), and any reference that is not a call or a discard holds: checked.
- Object identity is per file (go/parser's resolution). A value another file can see lives in a
  package-level variable, which holds: checked. A closure's read is a reference in the same file:
  checked.
- A `NAME=value` entry read back out of its slice and opened as a path: residual R13.
- A bounded join relies on rule (c) naming every path below it by its literal tokens, at any depth
  (AFP-V0-2240, AFP-V0-2241); a path below it climbed again from a derived value (a walk callback's
  path, a `ReadDir` name joined back) is R1.
- AFP-V0-3664 relies on the AFP-V0-2200, AFP-V0-9010 and AFP-V0-9600 proof of `go list`. A
  frame-rooted unproven listing keeps the planner's base behaviour; nothing new is trusted.
- The reference run is the CI run. Environment reads are held whatever the variable, so an
  operator who sets one does not leave the static guarantee; only R3's indirect host locations
  remain.
- The code is not adversarial: obfuscated construction of a `..` component (rune arithmetic,
  decoding) is out of scope, as for every literal rule.

The six "dormant opt-in" reads the earlier attempt left unflagged are held here: each reads a
path from a variable and skips when it is unset, and nothing bounds the run where it is set.

## Implementation notes

The pass is `internal/gateselect/locationsources.go`, copied byte for byte but for its package
clause into `internal/liveverify/affected/golang`; `TestLocationSourceReads_AFPV03660` holds the
two rule (d) sets equal, cold and warm memo. The gate marks source reasons after every file of the
package (`sourceReads`), and so does the planner (`sourceRead`); the first version marked them per
file, and `TestRepositoryScriptsAreBoundedSources_V14283` (liverepo) caught `cmd/corvint` naming
`affected.go`'s `os.LookupEnv` instead of `init_adopt.go`'s `os.Getwd`. A non-test source still
replaces a reason of test files alone, as any non-test reason does (AFP-V0-3663), so
`cmd/corvint-docs`, `conformance/release-artifact-v0`, `internal/liveverify/mutate`,
`tools/release-binary` and `internal/worklistadapter` now name a non-test source and locate the
root for their dependents; the measured sets below include that. In the planner the go list proof
ran inside `applyBinaryExecs`; it now runs before the gated-locator step, so a contingent read
(AFP-V0-3664) is decided on the same scans `literalExecs` uses. `goListFile.lists` records every
`go list` call, proven or not.
