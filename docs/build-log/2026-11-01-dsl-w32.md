## Friction

1. `corvint-tasks ticket show ID` refuses in a lane worktree on wsl-lanes.
   - Repro: run it in `~/projects/corvint-lanes/dsl-w32` or `~/projects/corvint`.
   - Expected: the ticket.
   - Actual: `journal-absent ... not in this checkout's intent projection`. Only
     `ssh mac corvint-tasks ticket show ID` works, and only through its verb gate (a `cd` is
     refused).
2. The resume brief said there was an uncommitted V1-3340 spec edit. The worktree was clean.
   - Expected: a brief that matches the worktree.
   - Actual: the edit had been reverted, probably because `make spec-requirements` refuses edits
     to the frozen Intent status line (SRG-V0-980). The ticket was already delivered.
3. Ticket screening misses work on unmerged lanes when the ticket ID is not in the commit subject.
   - Repro: `git log --all --grep=V1-3850` finds dgf-w16's `f8a2f8d93`, but V1-3623 (on main
     since `769a7e8ac`) and V1-3340 (`d4651eccb`, which names V1-3458) were still dispatched.
   - Expected: dispatch screening by AC as well as by ID.
   - Actual: three of seventeen tickets were already delivered.
4. This lane's closeout Makefile hunk conflicts with batch-1101d (dgf-w16's V1-3850 split).
   - Repro: `git merge-tree --write-tree claude/batch-1101d HEAD`.
   - Expected: no two lanes edit the `dogfood-closeout` recipe in one wave.
   - Actual: five conflicted files; the resolution is in the merge note above.
5. `make spec-requirements` regenerates `REQUIREMENTS.tsv` but does not stage it.
   - Repro: stage a spec, run `make spec-requirements`, commit.
   - Expected: the generated row lands in the same commit.
   - Actual: the row stays unstaged, and `spec-requirements-check` later fails with "differ between
     the working tree and the index".
6. `git grep -n -F` with hundreds of `-e` patterns is quadratic in Git (104 s against 1.4 s for
   `-l` on the same 928 files). Fixed afterwards by `DCW-V0-754`, at the owner's request.
   - The check's anchor search builds one such grep. It is bounded at 60 s (`DCW-V0-818`), and in
     practice only the below-anchored hunks feed it.
   - New hot spot, not fixed here: on a large change with many below-anchored hunks, the budget is
     the limit. A fix is `-l` first, then an in-process leftmost-longest match.
7. `heavy.sh` refuses `-run` patterns on a whole package without `HEAVY_WHOLE_REASON`, even inside
   `lane-scripts_test.sh`. The test log fills with `REFUSED whole-reason-missing` lines on a passing
   run, which reads as a failure.
