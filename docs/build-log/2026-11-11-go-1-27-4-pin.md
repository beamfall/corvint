# Go toolchain pin moves from go1.27.3 to go1.27.4 (V1-5408)

Owner instruction 2026-11-11: pin go1.27.4 (decision 0557 remains the exact-pin rule; only the
version changes).

## Staging

The move lands as three branches so main stays green while hosted CI still runs 1.27.3:

1. **B, code** (`claude/go1274-b`): no `.github`, no `go.mod` change. Every assertion about the
   toolchain accepts go1.27.3 and go1.27.4: the Makefile `go-version` target, the
   `TestASDV0880GoVersionPinsAgree` transition set `pinMove`, the Windows-vet parity test, the
   workflow-reading tests in `tools/ci-reuse-plan`, `tools/ci-forward-row` and
   `tools/ci-flake-report`, `admittedGoVersions` in `tools/corvint-pr-tests`, the compat-trial
   build identity, and the core-freeze and canonical CEM-status goldens (the runtime `goVersion`
   in them is the live toolchain, so those tests accept go1.27.4 against a go1.27.3 golden).
2. **A, `.github`** (`claude/go1274-gh`): workflows move to `go-version: "1.27.4"` and the
   `cishards` source-version set admits go1.27.4. It lands after B because B accepts both.
3. **C, pin** (`claude/go1274-c`, on B): `go.mod` and the nested modules to `go 1.27.4`, the
   Makefile target and `AGENTS.md`/`README.md` Verify checks to exactly go1.27.4, `pinMove`
   removed, release tooling (`internal/corerelease`, `internal/releasecandidate`,
   `conformance/release-artifact-v0`), the live-test provider tuple and the exact-version docs
   and specs.

## Rollback

Revert C, then A, then B. Reverting only C leaves B and A, which accept both versions.
