## Decisions

- V1-3518 (`ASD-V0-920`). `script/heavy.sh` already read `HEAVY_REMOTE_HOST` from
  `~/.config/corvint/heavy.env` (V1-3222), so a lane needs no export once the host's file sets it.
  What was missing was any sign of the choice: every run now prints `heavy.sh: host=H why=W`,
  naming the environment or the config file as the source, or that neither set it (with the file
  path and `(absent)`). No repository-tracked host setting: hosts differ per operator.
  `docs/LANE-ORCHESTRATION.md` tells offloading lane hosts to set it in that file.
- V1-3470 (`STR-V0-920`). `GATE_STEPS` and `shell-test:` are backslash-continued, one entry per
  line, ending in a comment line. `GATE_STEPS` keeps its first five steps (`host-adapter-test
  go-version go-test go-vet cross-vet`) in order and sorts the rest; `shell-test` is sorted. Sorted
  lists make two lanes adding different steps insert at different lines. Rejected: `+=` (rule (d)
  of test-commands-check needs one assignment) and a Makefile merge driver. The readers:
  test-commands-check already joins continuations; `TestSTRV0004ShellTestIsTheGateShellSteps` and
  the no-python reader now read logical lines. The replay is a Go test
  (`TestGateStepsTwoLaneMergeIsClean_STR_V0_920`) on a copy of the real Makefile.
- V1-3243 (`ASD-V0-921`). Two script tests were 100644: `release-env-compat_test.sh` and
  `runtime-environment_test.sh`. Both are now 100755 and their targets start them directly. The
  check is a Go test reading the Git index (`git ls-files -s`), run in doc-gates through
  `shell-test-registration-check`.
- V1-3338, V1-3448, V1-3437 (`SRG-V0-920..922`). `make spec-requirements-resolve` is the batch
  step: with nothing unmerged it regenerates and exits 0. It now also treats the use-case receipts
  and ledger as derived. A conflicted ledger restarts from this side, then takes the other side's
  pin for any receipt whose bytes match it exactly, and `repin-use-case-receipts.sh` repins
  subject changes. A generated file staged with its conflict markers restarts from HEAD.
  `make spec-requirements` refuses an unmerged or marker-holding generated file with one line
  naming the resolve. Rejected: a `.gitattributes` merge driver. It needs per-clone config and
  runs per file mid-merge, before the specs it derives from are resolved.
- V1-3342, V1-3408, V1-3413 (`DCG-V0-920`, `ASD-V0-922`). `--repin --changed [--base REV]` writes
  the diff-mapped token that DCG-V0-045 only suggested. It prints each rewritten span for a read.
  The full `batch-regen` run uses it against `${BATCH_REGEN_BASE:-origin/main}` and also runs
  `make documentation-paths`; `--mechanical` stays moves-only. The changed-content refusal names
  `--hash PATH:SPAN` for the exact span, plus the `--changed` rewrite. `--hash PATH:A-B` already
  printed range anchors.
- V1-3412, V1-3413 second criterion (`DCG-V0-922`). These are scope decisions, documented in the
  spec and the script header. Code-comment `path:N` references are out of scope. An unpinned legacy
  citation gets no heuristic "wrong line" detection: that cannot be decided without an anchor. The
  fix is to read the citation and pin it.
- V1-3323 (`DCG-V0-921`). `corvint affected` selects test units, and its selector belongs to the
  affected lane, so the selection lives in the lane focused set instead:
  `make line-citations-selects BASE=` (`check-line-citations.sh --selects REV`) lists the pinned
  citations into files changed since REV. `docs/LANE-ORCHESTRATION.md` adds it to the lane's
  focused checks.
- V1-3469, V1-3442 (`ASD-V0-924`, `ASD-V0-925`). `DOC_GATE_TARGETS` now starts with
  `line-citations-check spec-requirements-check`. Every doc-gate `go test` runs through
  `script/heavy.sh` (`DOC_GATE_GO_TEST`). The long pole was `selection-baseline-check`, whose 26
  serial replays alone ran past 300 s. It now replays on up to 4 workers (CPUs/3), each in its own
  shared clone, and keeps the result order. That touches `tools/selection-baseline/main.go`, which
  is outside this lane's script area; the change is the smallest one, and its verdicts are
  unchanged. Rejected: `make -j` for doc-gates, because macOS make 3.81 has no `--output-sync`.
- V1-3362 (`SRG-V0-923`). `spec-requirements-worktree-check.sh` (run by spec-requirements-check)
  fails when a generated index file differs between the worktree and the index. Its existing
  "staged and regenerated" case now stages the regeneration, which is the corrected fix.
- V1-3471. The `--all` refusal case asserts the frozen-header diagnostic (`its Intent status
  names FRZ-V0-002` and `(SRG-V0-980)`). That text is printed only by the guard, so the case fails
  with the guard removed.
- V1-3341 (`ASD-V0-923`). `batch-precheck_test.sh` refuses dash and POSIX-mode bash with a
  POSIX-parseable guard, and checks this by running itself under `sh` and `bash --posix`.
- V1-3492. The `ai-trailers --list` case ran in a fixture with no workflow, so awk printed
  `cannot open .github/workflows/ci.yml` twice. The fixture now carries its workflow, and the case
  requires an empty stderr. This is a test-only change with no spec entry.

## Friction

- `make spec-requirements` refuses a new ID in a spec's frozen Intent status header
  (SRG-V0-980), but a long header such as corvint-self-development-v0.md's, listing every
  amendment, reads as the place to append one; the rule surfaces only at regeneration.
  Repro: add `ASD-V0-920 (...)` to the corvint-self-development-v0.md status line, stage it, run
  `make spec-requirements`; it exits 255. Recording the note on the requirement line works.
- Line citations into the Makefile move with every Makefile edit. Each commit that touched the
  Makefile needed `script/check-line-citations.sh --repin` (3 to 18 citations each). Repro: insert
  a line near the top of the Makefile, then run `make line-citations-check`.
- Inserting a helper between a cited comment block and its `sub` split a pinned span, which then
  read as "changed", not "moved". Repro: insert lines inside `script/check-line-citations.sh:247-253`.
- `batch-precheck_test.sh` needs node (case 1b) and more than about 4 GB free in TMPDIR (case 9). On
  the Unraid lane host `/` has 3.8 GB free, so the test fails unless TMPDIR is moved. Repro: run
  `make batch-precheck-test` on the Unraid lane host.
- `gate-receipt_test.sh` runs the real gate graph and fails without node
  (`host-adapter-node-test`). Repro: run `script/gate-receipt_test.sh` on a host without node.
- `dogfood-cache_test.sh` needs `rg` and has no grep fallback, unlike `dogfood-bind-range_test.sh`
  (DCW-V0-811). Repro: run `script/dogfood-cache_test.sh` with no rg on PATH.
- `corvint affected` printed `DEGRADED self-binary-stale` (the installed corvint was built from
  `f1680433b107`), and its plan for a script and Makefile change was UNKNOWN with 86
  LANGUAGE_FRONTIER entries.
- `~/lanes/heavy.sh` on Unraid is still the prototype mkdir-slot wrapper, while
  `docs/LANE-ORCHESTRATION.md` says it delegates to `script/heavy.sh`, so the ASD-V0-920 host line
  never prints from it.
- `corvint dogfood propose-citations` (and `cem prepare`) refuse a mode-only change
  (`metadata-only-change-unsupported`), so a fix whose whole substance is `chmod +x` (V1-3243)
  cannot be bound until each file also gets a textual hunk; this lane added a one-line comment to
  both scripts. Repro: commit only `git update-index --chmod=+x script/x_test.sh`, then run
  `corvint dogfood propose-citations BASE`.
