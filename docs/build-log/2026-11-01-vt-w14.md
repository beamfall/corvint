# Lane vt-w14: VanillaTwisted appmap and Playwright tickets, per-module coverage

Lane `vt-w14` on the WSL host, branch `claude/lane-vt-w14-1101` from `origin/main`
`e9a5d6c803cb0a1cce3d4eebf74ab1da84dcd4e1`. Requirement IDs come from the lane block 600-609:
`TJAA-V0-600..601` and `AMAP-V0-600..601`. Each spec amendment is its own commit, ahead of the
commit that implements it.

## Decisions

- V1-3933 (TJAA-V0-600/601): the Playwright `use` layer parser reads a shorthand property `name` as
  `name: name`. Before this change, an item without a colon refused the whole configuration.
  - A shorthand identity key (`browserName`, `channel` and the rest of `PlaywrightUseIdentityKeys`)
    refuses with `identity key <name> is a shorthand property`. A non-identity shorthand passes the
    existing side-effect check (`playwrightPureFailure`). It can only add `playwright:use-value-unverified`.
  - A device spread the table does not model (`iPhone 13`, `Pixel 5`) no longer refuses at the
    spread when a literal `browserName` appears in either the project or the shared layer. The
    refusal moves to `playwrightInheritedUse` and fires only when no layer names a browser, so its
    detail is unchanged for that case. This is what lets VanillaTwisted's projects resolve.
- V1-3932 (AMAP-V0-600): `/new` matched both `/new` and the `/*` splat, so the goto stayed
  `ambiguous-template` and the spec was attributed to no screen. The render guard was not the cause.
  - The builder's screen index ranks React Router candidates as React Router's `computeScore`
    does. Only a unique highest score where every candidate is a `react-router/0` screen counts as
    a match. Ties and mixed dialects stay ambiguous.
  - The ranking is held only in the builder's index (`compile.go`), with no map format change.
    Other readers that rebuild a `screenIndex` from a `Map` (observe, refs, site knowledge,
    uirecords) stay unranked, because the map does not record a screen's dialect. Making them
    rank would need a map field and a builder version bump. That is a follow-up, not done here.
  - The incremental `--from` path re-derives sources through `b.routers`, so it ranks the same way.
- V1-2770 (AMAP-V0-601): `flows appmap coverage --map FILE` is a read-only, map-only projection
  (`application-map-coverage/0`).
  - A module is the declaring router file (`screens[].anchor` repo and path). A screen is
    reached when it has any spec attribution, and `reached_by_basis` counts reached screens per
    basis. `count_sources` names the map field behind every count.
  - A screen whose status is not `RESOLVED` is listed under `unknown`, and is counted in neither
    `total` nor `reached`. When the map's `test_join` is `UNKNOWN`, every module's
    `unreached_status` is `UNKNOWN` (`test-join-unknown`).
  - Abstract screens are counted on their own and are left out of `total`.
  - The MCP surface is not extended: `internal/mcp` is owned by other lanes.
- No jslex or shared escaped-identifier reader (env-w13, AMAP-V0-880) was touched.

## Friction

- `heavy.sh` prints `HEAVY_REMOTE_HOST unset` on every local run, even when running locally was
  intended.
- The `dogfood-change` prechange receipt instructions name the main clone's
  `.git/worktrees/<lane>` path. Reaching that path from a lane worktree is not obvious.
- The corvint MCP plugin failed to connect in the orchestrator session (`CONNECTION_CLOSED`), so
  the lane had no MCP context reads.
- There is no VanillaTwisted checkout on the lane hosts, so adopter acceptance criteria cannot be
  qualified in a lane.
- Appmap ranking needs the screen's dialect, which the map does not record. Each reader that
  rebuilds an index from a map would need its own ranking, or a map format change.
- The ticket store's `effects.coverage INCOMPLETE` blocked these tickets from being claimable.
