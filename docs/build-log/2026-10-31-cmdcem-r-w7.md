## V1-2685: command trees for the ten subcommand companions

What was already on the base: the cmdcem-mac lane gave `corvint-cem-candidate` and
`corvint-cem-experiments` trees (CAP-V0-930..932) and left 50 binaries on the ratchet. The ticket
text was not in this host's Tasks projection; the acceptance criteria were read from
`internal/tasks/similar/testdata/corpus-2026-10-30.jsonl`.

A `clitree.ScanDirs` survey of the 50 ratchet binaries found ten whose dispatch code matches a
subcommand word: `corvint-corpus-republish`, `-dashboard-snapshot`, `-go-test-provider`,
`-intake`, `-js-test-provider`, `-postmerge-connect`, `-postmerge-metrics`, `-postmerge-workflow`,
`-pulse` and `-ruby-test-provider`. Each now ships a tree (CAP-V0-972), and the ratchet falls from
50 to 40. The other 40 match no subcommand word: 16 analyzer processes, 4 folded shims, 4 MCP
servers and 16 single-mode tools.

Decisions:

- A shared `clitree.CompanionTree` and `clitree.Help` (CAP-V0-973) replace the per-binary
  `help.go` copies the first slice used. Each binary keeps only its synopsis text, summaries and
  its optional authored detail. `internal/clitree/clitreetest.CheckCompanion` (CAP-V0-974) is the
  shared per-binary test. The two CEM companions were left as they are, to avoid churn in another
  lane's code.
- A node's help is `Render` followed by the binary's authored detail. So `negate --help` still
  prints `Usage of negate:` with its flag defaults, and `corvint-js-test-provider --help` and
  `corvint-ruby-test-provider --help` keep their authored usage, followed by the command list. The
  test therefore checks that stdout starts with `Render`, not that it equals it.
- `corvint-ruby-test-provider rspec --help` used to print its flag defaults to stderr. They now go
  to stdout, after the node's `Render`. `corvint-intake --help` used to print one line; it now
  prints the generated root help, whose title keeps the `NOT_OBSERVED` wording.
- The provider mode of `corvint-go-test-provider`, which has no subcommand word, is a
  `Help.RootForms` synopsis. Its self-attachment argument `--corvint-go-live-authority` is an
  internal entry point with a reason.
- `corvint-pulse` requires `--root ROOT` before `serve`. A synopsis preamble must be bracketed, so
  the synopsis is `[--root ROOT] serve --stdio`, and the summary and example state that `--root` is
  required. Known limit: `--root R serve --help` reaches the binary's own parser and refuses.
- The ticket's retained evidence, "`corvint ocm link --help` omits `--expected-base` and
  `--target`", still reproduced on the base. The ocm synopses of link, status, verify and report
  now name both. `TestCAPV0044OCMHelpNamesTheStablePins` pins this.

NOT DELIVERED: the 16 single-mode tools and 4 MCP servers still have no tree, so their flags remain
ungated by a tree. Criterion 1's "every flag" is met only for the binaries that have a tree.

## V1-2209: heavy-slot queue

Before: 344 s waiting for a heavy slot, at load 125, on the Mac with the old mkdir semaphore (ticket
body). After: since the flock-slot rewrite (V1-3222, 8 slots), this host's
`~/lanes/heavy-selection.log` holds 1059 local runs (2026-10-30T16:41Z to 2026-11-01T03:35Z). The
maximum slot wait was 0.1 s (median 0.0 s). For the 79 `cmd/corvint` runs it was 0.0 s, with a
median run of 15.8 s. The slot wait is therefore reduced, but the queue moved: `HEAVY_MAX_LOAD`
waits up to 120 s before the slot, and that wait was printed only after it ended and never logged.
In this lane it cost 10 to 41 s per run at load 38-41.

ASD-V0-970 makes heavy.sh print `heavy.sh: queued for host load L > HEAVY_MAX_LOAD=M (at most Ns)`
and `heavy.sh: queued for a slot (N/N held)` when the wait starts. Each local log line now carries
`loadwait=Ns load=L`, so later before/after numbers can be filtered to a comparable load.
BLOCKED for the comparable-load criterion: the "before" was measured on the Mac at load 125, and
reproducing that load on this shared WSL host would slow the other lanes running on it.

## V1-1451: guarding-test candidates

Candidate counts were measured with a throwaway harness that ran the real `loadGoPackage` /
`closure` / `testsMentioning` on every non-test Go hunk of a pair:

| pair | hunks | candidates before | after |
| --- | --- | --- | --- |
| PR #934 `85ba6321a..95622955d` | 70 | 5228 (store 3940, cli 362) | 5098 (store 3840, cli 362) |
| `3465dd98c^1..3465dd98c` | 39 | 2120 (`cmd/corvint` 1306) | 1498 (`cmd/corvint` 889) |
| `6e0ce750c^1..6e0ce750c` | 8 | 5537 | 5207 |

TCQ-V0-970 drops identifiers that the parser resolves to a declaration's own locals. Decision: a
shared target baseline per directory (one run of the union of the candidates, instead of one run
per hunk) would roughly halve the runs. It was rejected, because tests run together can pass or fail
differently than the per-hunk subset, which could create a false guard (CEM-V1-692 isolation).
Finding: every `internal/tasks/store` hunk of the PR #934 pair reaches the same 821 names and 384
tests, because the package's callers form one connected component. Name-based narrowing cannot cut
that without losing real guards.

NOT DELIVERED: the criterion is wall time on three pairs at up to 1200 s each. The charter bounds a
command to 600 s, the store packages are not narrowed, and no CEM map exists for those pairs.
