## V1-5237: release archives omit corvint-docs, so corvint docs fails on a released install

**What was wrong.** Since decision 0594 item 3 `corvint docs` is an exec-only shim onto the
`corvint-docs` executable, and the MCP servers are their own executables, but the release was
the five `corvint` archives alone: `internal/releasecandidate/verify.go` admitted exactly five
targets of binary `corvint` with six members each, `script/go-archive-gate` listed the same five
archives, and `corvint-release-install` installed one executable. An install made from released
archives answered every `corvint docs` verb with `not-installed` (reproduced on this host: the
built `corvint` alone in a directory with an empty `PATH` answers `docs` with
`{"code": "not-installed", ...}`, exit 2).

**Design decision (recorded as `ARTIFACT-BIN-V0-509` in
`docs/specs/release-artifact-integrity-v0.md`).** Two designs were open: the `corvint` archive
carries the core-set binaries, or the installer installs the core set together. The second is
the smaller one, on this evidence:

- decision 0594 item 8 releases each binary on its own so a docs-only fix ships without
  rebuilding the rest; one multi-binary archive re-couples them;
- the `corvint.release-go-archive-report.v2` schema fixes `targets: 5` and
  `membersPerArchive: 6`, and every reader of it (`internal/releasecandidate`, `internal/update`
  binding `RetainedBinary` to the one archive binary, the gate's own `archive_report.go`) would
  need a new schema for a multi-binary archive;
- the archive gate builds every target twice with cold caches (`ARTIFACT-GO-V0-005`); eight
  binaries would make eighty cold builds per gate run instead of ten;
- the core already looks for its apps beside its own executable first
  (`internal/docsenvelope.Locate`), which is how `make install-local` has always installed the
  set into one directory.

So the `corvint` archive and its gate are untouched (`verify.go` and `go-archive-gate` still
agree on the five archives), and the release is the `corvint` archive set plus one archive per
other member of the catalog's `core` version set, installed together.

**The fix.**

- `internal/releasecandidate/apps.go` (new): `CoreSetApps` (the seven core-set apps, held equal
  to the catalog by `TestCoreSetAppsMatchTheCatalogVersionSet`); `verifyApps` binds each
  `apps/NAME_<goos>_<goarch>.tar.gz` to the release-binary `release-manifest.json` the candidate
  carries as `evidence/release-manifest.json`, and that manifest to the candidate's version,
  source commit, toolchain and `core` set with no declared skew; `verifyAppArchiveBinary`
  rechecks each archive's inventory, inner checksum, binary digest and embedded build identity
  through the generalised `verifyArchiveBinary`; `installApps` extracts each app's executable
  beside `corvint` (only when its inner `SHA256SUMS` row binds it and its notices equal the
  installed ones), rewrites the installed `SHA256SUMS` as one row per executable, and probes
  every app's `--version` against `corvint`'s line; `probeDocsShim` runs the installed
  `corvint docs --help`. The candidate profile is `corvint-core-release-candidate/1`;
  `corvint-release-candidate` takes `--apps-dir DIR` (the `release-binary` output); the candidate
  bounds grow to 48 files and 6 directories.
- `docs/INSTALL.md`: the core set, installed into one directory, with the version and
  `corvint docs --help` checks.

**The follow-up: per-binary version stamp (`ARTIFACT-BIN-V0-508`).** Only `cmd/corvint` declared
`main.build` and `main.sourceCommit`, so the linker dropped the stamp for every other product
binary and an extracted `corvint-docs` printed `corvint-docs 1.0.0-rc.3.dev`. Now
`internal/companioncli.Spec` carries `Build` and `Commit`, `cliapp.AnswerStamped` passes them,
and every non-analyzer product binary declares the two variables in `version_stamp.go`
(`TestProductBinariesDeclareTheVersionStamp`). A stamped build prints
`corvint-docs 1.0.0-rc.3 (build 183, commit <sha>)` and `--version --json` carries `build`,
the stamped `commit` with `commitState` `clean` and `release: true`; an unstamped build prints
`corvint-docs 1.0.0-rc.3.dev` as before. Analyzer `--version` output is a protocol receipt
(`corvint-analyzer-java/v0`, or the `NONCANONICAL_REQUEST` sentinel for most families) owned by
the analyzer contracts, so the analyzers are not stamped; the release manifest records their
version and commit.

**The follow-up: `CMS-V0-002` beside refusal (`ARTIFACT-BIN-V0-512`).**
`internal/docsenvelope/version.go` (new): `Beside`, `ProbeVersion` (one bounded `--version`
line, either form), `Mismatch` (versions must agree; stamped commits must agree) and
`CheckBeside`. `cmd/corvint/docs_shim.go` refuses `version-mismatch`, exit 2, before forwarding
`docs` or a `--corpus=FILE` read to a `corvint-docs` beside it at another version;
`cmd/corvint-docs/corpus_integration.go` refuses a beside `corvint` the same way. A sibling on
`PATH` is forwarded to unchecked, as before.
