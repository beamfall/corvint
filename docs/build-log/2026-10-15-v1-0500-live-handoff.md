# V1-0500 live receiving-host qualification of the portable task bundle

Date: 2026-10-15. Base: `3337f5f6db262a2e0f75b548814e7d06dbbcdd05` (origin/main).
Ticket: V1-0500, acceptance criterion 4. Contract: `SESSION-V0-020..022` in
`docs/specs/session-context-dividend-v0.md` (accepted by decision 0472). Raw evidence:
`docs/experiments/v1-0500-live-handoff-20261015.json`.

## Intent

Criterion 4 asks for a real receiving session that consumes the bundle, live wrong-key and
changed-input refusals, and explicit host/provider limits with no mocked host. Decision 0472 left
the receiving host, agent benefit and cross-provider continuity `NOT_OBSERVED`. This entry records
live runs. It changes no source, wire contract or requirement text. Only a status and evidence
paragraph is added to the spec's portable task bundle slice.

## Method

- Binary: `corvint` 1.0.0-rc.3 (build 0), built from the base.
- Fixture: a disposable Git repository with one spec (`RL-V0-001`, `RL-V0-002`) and one Go file.
  It sits in a lane scratch directory, outside every user checkout.
- Enrollment: `dogfood begin` under the sender key. The receiver is given a second, unrelated
  key for the wrong-key cases.
- Sender: this Claude Code builder session (Opus 5.5). It wrote the task state (`RL-TASK-7`, two
  scope paths, two decisions, one feedback item, one unknown, two next actions). It then ran
  `dogfood handoff --session-key KEY --anchors "RL-V0-001 RL-V0-002" --task-state FILE`, which
  exited 0 with a 3648-byte bundle.
- Receivers: separate headless sessions in the fixture. Each had the same prompt: run exactly one
  `dogfood handoff --session-key KEY --bundle FILE` command, read no file, carry out no next action,
  and answer with one JSON object reporting what the command returned.
- Claude Code 2.1.293 receiver: `claude -p --output-format json --max-turns 4 --tools Bash`, with
  Bash allowed only for `<corvint> dogfood handoff`, `--permission-mode dontAsk` and no MCP servers.
- Codex CLI 0.162.0 receiver: `codex exec -s read-only|workspace-write --ephemeral --json`.
- Fixture state: a manifest of HEAD, porcelain status and every file under `.git` (except
  objects) and `.corvint` was taken before and after each case.
- Host load average was about 50 during the runs, from other lanes. Each case was one foreground
  session.

Each Codex transcript contains exactly one command execution, the prescribed one. Each final
message agrees with that command's output. No receiver created a file. The fixture still holds
only `limit.go` and the two fixture commits.

The receive command itself wrote nothing. On a second disposable fixture, plain CLI receives with
the right key (exit 0), the wrong key (exit 2) and after a spec commit (exit 1, the same four drift
rows, nothing returned) left the manifest unchanged (`diagnostics.cases` in the raw evidence). Two
kinds of change were observed during the host sessions. We attribute both to the hosts' own
installed Corvint adapters, not to the receive command; this is an inference from the ledger rows
and the unchanged plain-CLI manifests:

- `adapter-degradation` rows appended to the private `.corvint/self-observations.jsonl` ledger
  (allowed by invariant 4; retained as `diagnostics.hostAdapterLedgerRows`). Their codes were
  `adapter-host-kill-deadline` (Claude Code), `corvint-event-rejected:dogfood-event-deadline`
  (both hosts) and `corvint-event-rejected:dogfood-event-index-snapshot-stale` (Codex).
- A context index snapshot built for the new tree.

### Read-only Codex root cause (V1-0514)

The plain CLI receive was rerun under macOS `sandbox-exec` with `TMPDIR` set to the per-user
temporary directory (`diagnostics.cases`):

- Denying writes under `TMPDIR` returned exit 2 `local-completion-failed`. A temporary build of
  the base that printed the masked error reported
  `Git status cannot safely observe repository metadata: private metadata scratch directory cannot be created`
  (`internal/gitstatus/status.go:158`).
- Allowing writes only under `TMPDIR` returned exit 0 `reresolved`. Allowing them only under the
  fixture's `.git` or `.corvint` returned exit 2.
- A wrong key still refused with `handoff-session-key-mismatch` while `TMPDIR` was denied.

During diagnosis (not retained), `corvint context` failed the same way in that sandbox, as
`repository-probe-failed`. So the read-only failure is, by inference, a host limitation shared by
the Git-status readers. `dogfood handoff`
hides it behind the generic `local-completion-failed` code. That diagnostic is V1-0514's scope, and
this change does not alter it.

### Claude Code receiver unavailable

`claude auth status` reports `loggedIn: false` on this host (`diagnostics.claudeAuthStatus`). The
retained attempt ended with an expired OAuth session before any tool call. Retries with a cleared
environment failed the same way but were not retained. Signing in is an owner action, so the
Claude Code receiving cases are `NOT_OBSERVED`.

## Qualification status

- Real receiving session consuming the bundle: `OBSERVED` (Codex, workspace-write).
- Live wrong-key refusal: `OBSERVED` (Codex, both sandboxes).
- Live changed-input refusal: `OBSERVED` (Codex, workspace-write; HEAD, tree and anchor drift
  together).
- Claude Code to Codex delivery in one checkout: `OBSERVED`. The sender was a Claude Code session
  using the native CLI, not a host adapter.
- Codex read-only receiver: unavailable host (V1-0514).
- Not observed:
  - Headless Claude Code receiver, and so Codex to Claude Code delivery.
  - Delivery across checkouts or hosts.
  - Separate HEAD-only or anchor-only drift cases (only the combined drift was run live).
  - Agent benefit: no paired outcome trial was run.
- No mocked host was used. Unit fixtures cover the malformed, oversize, symlink and per-field
  drift cases (`TestDogfoodHandoffBundle*`). Delivery stays experimental, and promoting it is an
  owner decision.
