# 2026-10-20 External criterion form for cem/1.0 (V1-2100, GitHub #1332)

Human-owned intent: `docs/specs/cem-stable-v1.md`, section "External criterion (V1-2100, GitHub
#1332, 2026-10-20)", `CEM-V1-330..337`, accepted under the owner's standing auto-accept
(2026-10-11).

BASE: `253bc9a1dcf3284cca302aa320f57310d3a8673a`.

## Decision

The plain criterion binds only a span in the verified repository. The issue asked for an external
document binding that is verified when its repository is supplied and NOT_OBSERVED otherwise,
without a wire bump. The chosen form is `{id, criterionIndex, criterionSha256, externalRepository,
externalBlobOid, externalSpan}`:

- It is a third closed key set, selected by key presence after the Tasks set and before the plain
  set. No existing map changes its form, members or identity, so the change is additive.
- The repository is a consumer-side name, never a path or URL. `--external-repository NAME=PATH`
  maps it to an absolute local root, so verification needs no network and no new trust root.
- The blob ID plus span digest is checkable from Git objects alone. The alternative in the issue,
  a content digest plus a declared locator, would have needed an unverifiable locator grammar.

## Fork recorded for the owner

The result profile `cem-stable-verification/1` has no per-criterion observation member. Adding one
would change the frozen result bytes (`CEM-V1-091`). The narrowest safe reading is that an
unobserved external criterion makes the whole verification abstain: `UNSUPPORTED`,
`artifact-unavailable`, stage `artifacts`, exit 2, never `ACCEPT`. The stderr line names the
missing repository. A per-criterion NOT_OBSERVED member stays an owner decision.

Also recorded, not changed: `RESULT.schema.json` describes `references.criterionBindings` with the
Tasks form only, though both consumers already echo plain criteria there.

## Limits

- No producer emits the external form yet; the public map was generated by a scratch script and
  checked by both consumers.
- Core read paths (`cem verify`, `status`, `report`, console) do not take external repositories, so
  an external map abstains there.
- Containment and timeout mapping (`CEM-V1-335`) is covered by code review, not a fault-injection
  test.
