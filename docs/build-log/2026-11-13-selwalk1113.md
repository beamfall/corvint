## V1-5217: the two forms left open (AFP-V0-9710, AFP-V0-9711)

`docs/build-log/2026-11-11-shellwalk.md` delivered the awk-option and git log/reflog forms and left
two NOT_DONE. On origin/main:

- Environment behind a wrapper. The AFP-V0-9976 assignment rule already looks through wrappers
  (`command env`, `nohup env`), but it knew only interpreter startup names, so
  `nohup env GIT_SSH_COMMAND=./tools/ssh.sh git fetch` and `command env PAGER=./x.sh git branch`
  were quiet. AFP-V0-9710 adds the command-running names (pager, editor, ssh, askpass, external
  diff, proxy, less filters) and the git directories `GIT_EXEC_PATH` and `GIT_TEMPLATE_DIR`. A
  value that is empty, absolute, or one bare PATH command word (`GIT_EDITOR=true`, `PAGER=cat`) is
  not counted. `GIT_CONFIG_GLOBAL` is left out: repository tests point it at temporary roots, and
  `script/heavy.sh` assigns it from a variable, so counting it would hold `heavy.sh`.
- `node --import ./x.mjs` and `node -r x`. On origin/main `programOperand` already refuses a first
  operand that starts with `-`, and `node` is a toolchain, so the form was already fail-closed but
  had no rule or test. AFP-V0-9711 pins it.

No repository shell file mentions any AFP-V0-9710 name except `GIT_EDITOR=true` and `GIT_ASKPASS=`,
neither of which is counted, so no repository selection changes.

Fault injection (each change reverted right after; `TestX` in `internal/liveverify/affected/shell`):

| Fault | Test | Result |
|---|---|---|
| F1 `holds.go` back to origin/main | `TestCommandRunningNamesBehindWrappers_AFPV09710` | FAIL: all 9 held rows |
| F2 option check removed from `programOperand` | `TestInterpreterPreloadOptions_AFPV09711` | FAIL: `bun_preload_joined` |
| F3 `node` removed from `Toolchains` | `TestInterpreterPreloadOptions_AFPV09711` | FAIL: all 4 test rows |
| F4 `programFile` call disabled | `TestAwkProgramFiles_AFPV09974` | FAIL |
| F5 `log` and `reflog` removed from `gitTreeReaders` | `TestGitPathOutputWalks_AFPV09973` | FAIL: `log_names`, `reflog` |

So each of the four V1-5217 forms has a named test that fails without its rule.

Fix round 1 (independent review P1). `outsideValue` exempted any value whose `:`-separated parts
each start with `/`, so `command env GIT_SSH_COMMAND='/bin/sh tools/ssh.sh' git ls-remote ...`
was quiet and an edit to a file `tools/ssh.sh` reads left the caller unselected. Now each part
must be one unquoted word with no blank, quote, escape, shell operator or expansion, and a quoted
or escaped value counts unless it is empty. `TestAbsoluteCommandValueWithArgumentsHolds_AFPV09710`
pins the example and five variants (escaped blank, `PAGER` with an argument, a `;` chain, a quoted
single path, a `PERL5LIB` part with a blank) and checks that `tools/ssh.conf`, which the helper
reads, selects the caller. Fault F6, both checks removed from `holds.go`: the test fails on all six
held rows and on the `tools/ssh.conf` selection. No repository shell file assigns a startup or
command-running name a quoted value or an absolute value with a blank, so no repository selection
changes.

`paths.go` edit now selects neither converted guard, while affmeasure saw flow-guide-check selected

- `fixture-maintenance-check`'s predicate `git` equals its guard's own filter
  (`strings.Contains(source, "git")`), but the guard reads only `_test.go` files, and a content
  predicate cannot say so. Making it narrower means changing the guard or the predicate grammar.
- No listing-only conversion is sound today. `tools/cli-discovery-gen`'s `cmd/` entry looks
  listing-only (`os.ReadDir("../../cmd")`), but `rootTree` in `main.go` also reads the sources of
  named `cmd/<binary>` packages. `internal/langplugin` follows into the analyzer directories.

Note: `corvint affected --worktree --path FILE` on an unmodified file selected both guards even for
the control. That mode does not evaluate content predicates and falls back to the whole tree, so it
cannot measure this criterion.
