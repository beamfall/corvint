# One host queue for every heavy lane command — V1-3626, V1-1628, V1-1627, V1-3518

Lane heavyq-sp1, base `origin/main` 8daec98ce4349c1583186692726d2c3a782ac647. Governing spec:
`docs/specs/corvint-self-development-v0.md`, new requirements `ASD-V0-930` to `ASD-V0-936` (their
own commit, before the code).

Problem: an audit of the multi-lane runs found that lanes piled heavy commands onto one host (the
Mac at load 47 to 170 on 12 cores), that `script/heavy.sh` admitted only `go test`, `go vet` and
builds while closeout, finish, doc gates, the batch precheck and codex ran unqueued, that the load
gate was an absolute `HEAVY_MAX_LOAD=10` whatever the core count, that offload knew one host
(WSL) while the Unraid box stayed idle, and that darwin-only packages were offloaded to Linux,
where they neither build nor run.

## Decisions

- Admission of the non-test targets (ASD-V0-930). The `Makefile` variable `HEAVY_ADMIT`
  (default `script/heavy.sh`, empty when `CI` is set) prefixes `build`, `tasks-build`, both
  `doc-gates` lines, `batch-precheck` and `dogfood-finish`. `dogfood-closeout` is admitted through
  its precheck and finish steps rather than as one admission, so its recipe (pinned by DCW-V0-349
  and DCW-V0-960) is unchanged. `script/codex-review.sh` runs `codex exec` through
  `CODEX_REVIEW_HEAVY`; its login preflight takes no slot. CI keeps its own runner capacity, so the
  prefix is empty there. `script/batch-precheck.sh` parses the `doc-gates` recipe textually
  (V1-3232), so its `doc_gate_expansion` now strips the prefix before comparing.
- Nesting (ASD-V0-931). An admitted `batch-precheck` or finish calls `heavy.sh` for its own
  steps. Letting those steps take a second slot deadlocks a host whose slots are all held by such
  coordinators, and letting them pass through unbounded lets one lane run its precheck's parallel
  steps on one slot. Chosen instead: the holder exports `HEAVY_HELD`, and a nested admission takes,
  without blocking on either, its holder's token `slotN.inner` or any free host slot. So the
  coordinator's steps run one at a time on its own slot and spread only onto idle slots. Nested
  runs skip the load gate, which the holder already passed.
- Load gate (ASD-V0-932): `floor(HEAVY_LOAD_PER_CPU x CPUs)`, multiple 1.0 by default (12 on a
  12-core host, near the old 10); `HEAVY_MAX_LOAD` still wins. The documented Mac cutover config no
  longer sets `HEAVY_MAX_LOAD=10`.
- Several remotes (ASD-V0-933, V1-3518). `HEAVY_REMOTE_HOSTS` takes a list; with two or more the
  wrapper probes each host with the same file in probe mode (load and CPUs), tries hosts in load
  per CPU order and moves on from an unavailable one before the existing retry and fallback. Hosts,
  users and ports stay configuration (`ssh://user@host:2222` or `~/.ssh/config`). Per-host
  overrides of the other settings are a non-goal: both reference hosts take `bash -s` over their own
  sshd on port 2222, and `~` paths expand per host (the clone path now expands `~` like the env
  file already did). V1-3518's text was not readable in this checkout (see Friction); the brief's
  reading, "configured remotes are used", is delivered as the list that sets `HEAVY_REMOTE_HOST`.
- Darwin (ASD-V0-934): only on a Darwin host is a darwin-only package kept local, with a stderr
  line and `darwin-local` fallback- and selection-log lines. On a Linux lane host neither side
  builds those files, so the old notice-and-offload stays.
- Queue and run times (ASD-V0-935): the local selection-log line gains `load=` and `queue=` after
  the existing fields, so readers of `local wait=` keep working, and every local holder prints
  `heavy.sh: done queue=Ns (load=Ns slot=Ns) run=Ns rc=N`.
- Lane cap (ASD-V0-936, V1-1627): `script/lane-pressure.sh` turns the ASD-V0-013 table into one
  command, with hysteresis from `--level`. The orchestrator still enforces two agreeing samples and
  launches lanes itself. That keeps the dispatcher's own signal (V1-0694, `CAL-V0-068`) as the
  definition: the script reads the same inputs, and the dispatcher code is not linked, because
  agent lanes are not dispatcher workers.

## Addenda and review (2026-11-01)

The orchestrator added the free-space floor and the default `go test` timeout to V1-3626, V1-2691
(remote Go cache and work files on disk) and V1-3628, V1-3629, V1-3630, V1-3631 and V1-3632. They
are specified as `ASD-V0-937` to `ASD-V0-939` in their own spec commit, before the code; the
fixes that change no contract (V1-3629, V1-3631, V1-3632) carry tests but no requirement.

- Disk floor (ASD-V0-937). The remote half is authoritative: it checks its per-run scratch and its
  `GOCACHE` file system after creating them, and below `HEAVY_MIN_FREE_GB` (3) it exits 97. So the
  existing host loop, retry and logged fallback handle it with no new path. The probe adds `free=`
  only for ordering. A local run cannot go elsewhere, so it warns and logs and still runs.
- Timeout (ASD-V0-938, V1-3630) is inserted after selection logging and before offload, so the
  selection log records what the lane asked for and both hosts run the bounded command.
- V1-2691. The remote `GOCACHE` default was already the remote disk (ALREADY-DELIVERED, the
  "Remote build cache" header paragraph of `script/heavy.sh`); `GOTMPDIR` now follows the per-run
  disk directory. The WSL `/tmp/corvint-go-build-cache` predates that default or comes from runs
  local to WSL (the `Makefile` `CORVINT_GOCACHE ?= /tmp/...`). Migration: nothing is moved or deleted. A
  host can trim the old cache with `make go-cache-trim APPLY=1`, and later offloads fill
  `~/.cache/corvint-go-build-cache`.
- `sh -c` (ASD-V0-939, V1-3628): a perl tokenizer accepts only quotes and escapes and rejects every
  operator, expansion and glob, so an unwrapped command is exactly what the shell would have run.
  The base already offloaded `sh -c 'go test ...'` by substring, but it skipped the selection and
  darwin rules, which read the arguments, and a compound string ran on the remote unchecked.
- V1-3629: `slot_perl` (and the new tokenizer) are quoted heredocs read with `read -d ''`, not
  single-quoted strings. The perl body now holds an apostrophe, and a test re-inserts one and runs
  the script.
- V1-3632: every `"${a[@]}"` in `heavy.sh` and the lane scripts uses the guarded
  `${a[@]+"${a[@]}"}` form, and a static group fails on any new unguarded one. bash 3.2 itself is not
  on this host, so the guard is checked statically.
- V1-3631: the suite now unsets every `HEAVY_*` variable (and `CODEX_REVIEW_HEAVY`) before its
  exports, and the fake remote gets only `PATH`, `HOME`, `TMPDIR` and `LC_ALL` (`env -i`), as sshd
  would. Every fixture already ran under the suite-wide `HEAVY_MAX_LOAD=999999` on the base, so load
  never delays it. Found on the way: the load gate reported a 1 s "wait" whenever `SECONDS` ticked
  over during a gate that never slept, which is the flake the per-CPU group hit. Fixed: only a gate
  that slept reports a wait.

Independent review (one subagent pass over the first commit, read-only). Each finding and its
disposition:
1. HIGH, fixed: `heavy.sh` classified the codex prompt (`... go test ...`) as a go command and
   refused or offloaded it. `heavy.sh --admit-only` admits a command without reading it, and the
   `HEAVY_ADMIT` default and `codex-review.sh` use it.
2. Fixed: `HEAVY_REMOTE_HOSTS` overrode an explicit empty `HEAVY_REMOTE_HOST`; that empty value
   is honoured again, and the suite unsets every `HEAVY_*` variable.
3. Fixed by `--admit-only`: a plain `make build` and `make tasks-build` no longer go through build
   offload (no silent `CGO_ENABLED=0` cross-build, no second offload attempt).
4. Fixed: a trailing slash or symlinked spelling of the lock dir deadlocked a nested admission;
   the lock dir is resolved with `cd -P` before use.
5. Fixed: `make -n` executed the admitted `$(MAKE)` line and took a slot; under a dry run
   `--admit-only` runs the command directly.
6. Fixed: host ordering sorts under `LC_ALL=C`.
7. Kept as specified: on a Darwin host, darwin-only files anywhere under `./...` keep the whole
   command local (ASD-V0-934 failure mode).

## Codex review (orchestrator, 2026-11-01)

Three P2 findings, each fixed with a regression case that fails on the previous head (checked by
running that head's `heavy.sh`, `lane-pressure.sh` and `Makefile` line):
1. `script/lane-pressure.sh` read a failed Darwin pressure query or Linux meminfo without swap lines
   as calm (`--level 2` gave `level=0 admit=4`, exit 0). Now the platform's memory signal is part
   of the sample: when it is missing, the script prints `level=CURRENT ... unreadable` and exits 3.
   ASD-V0-936 names the signal.
2. `make dogfood-inputs-check`, the closeout's first step, built the tree binary outside the
   queue. Its recipe now carries `$(HEAVY_ADMIT)` (ASD-V0-930). The test holds the only slot and
   checks that the target waits behind it.
3. The `sh -c` tokenizer kept a backslash-newline as a newline argument. It now drops the pair, as
   the shell does (ASD-V0-939), and the test compares the unwrapped argv with the shell's own for a
   multi-line string.

In the same pass, the load gate takes its start time after validation, so a short bound is not
spent before the first sample. The per-CPU group uses a 2 s bound, because 1 s is at `SECONDS`
granularity.
