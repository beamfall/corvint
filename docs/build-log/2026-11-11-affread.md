# Lane affread: self-declared runtime-readers registry (V1-5009) and the affected headline (V1-4321)

Lane affread, 2026-11-11, base `b55635262788687c3eea9a08a94378e4ab8856a4`. Two fixes to
`corvint affected`.

## V1-5009: the registry already owns an edit to itself

Repro on the base: a scratch commit adding one entry to `.corvint/runtime-readers.json`, then
`corvint affected --base <its parent> --format json` with the lane binary built at the base
(build 167). It printed `scope=BOUNDED dirty=1 selected=135 excluded=488 unknown=0`, with the
registry under `DECLARED_RUNTIME_READERS` and no `UNOWNED_DIRTY_PATH`. The ticket's
`UNOWNED_DIRTY_PATH` (rscope lane, 2026-11-07) was removed on 2026-11-09 by `ce5f1df5e`
(AZU-V0-8910). That commit lets the registry declare each parser-owned control declaration, itself
included, by exact entry; `auditControlDeclaration` is the exception in `readRuntimeReaders`.
Criterion 1 therefore held on the base, and no test of it could fail there.

The file's own readers and why the plan leaves some out: `internal/liveverify/affected` (the
planner), `tools/declaration-compat-check` and `internal/liveverify/affected/shell` declare empty
read scopes, because their tests write fixture copies to temporary roots. AFP-V0-152 therefore
drops their path literals. `tools/ci-forward-row` names the path only inside a fixture document.
`cmd/corvint` (`help.go`), `liverepo`, `golang` and the unbounded readers are selected, and so is
the `make declaration-compat-check` driver target.

What changed:

- `internal/liveverify/affected/runtime_readers_self_test.go` pins the behaviour. An edit to a
  self-declaring registry selects its literal and read-scope readers and the ownership audit,
  with no unknown. In the fault-injection cases, a registry without its own entry that a unit
  reads keeps `UNOWNED_DIRTY_PATH`, a new `.corvint` record beside it keeps `UNOWNED_DIRTY_PATH`,
  and any further literal or unbounded reader is selected.
- `internal/liveverify/affected/liverepo/runtime_readers_self_repo_test.go` checks the real
  registry. It takes this repository's actual registry bytes, adds one entry, and runs the real Go
  plugin: the edit owns itself and selects its literal reader.
- AFP-V0-2404 (`affected-plan-selection-v0.md`) and AFP-V0-602 (4) (`affected-plan-v0.md`) still
  said the registry "stays `UNOWNED_DIRTY_PATH`". Both now cite the AZU-V0-8910 exact entry.

Finding, not changed: the probe with the real Go plugin found one invisible reader. A test that
opens the registry only through a computed name with no root locator (`os.ReadFile(os.Getenv(..))`)
raises no witness, and the plan stays `BOUNDED`. That is the trust AFP-V0-602 states in its
failure modes for every declared entry, not something special to this file. A terminal literal
reader's own frontier is also left out, by the AFP-V0-560 reader-selection rule, so a frontier
fixture cannot model an "unbounded" reader either.

## V1-4321: a bounded stderr headline (AFP-V0-3642)

Problem: `corvint affected --base main~1` printed one canonical JSON line of 255,266 bytes on the
day the ticket was filed (105,572 bytes for this lane's plan).

Options (charter): (a) a bounded headline on stderr with stdout unchanged; (b) the JSON reordered
and line-broken so `summary` comes first. Option (b) was rejected because the default stdout bytes
are pinned three times over:

- AFP-V0-003: "one canonical JSON line";
- AFP-V0-398: the bytes equal `CanonicalJSON(receipt)` plus a newline;
- RGV-V0-015: `review.affected` is byte-equal to the default document, and the `affectedFull`
  digest is sha256 of the `--full` stdout.

Changing them would mean editing `repository_guidance_test.go`, `affected_test.go`
(`extractJSONObject`), `affected_path_test.go` and the e2e-safe goldens. Every CI, Makefile, script
and tool consumer parses the JSON (`jq`, `json.Unmarshal`) and reads stderr only on failure
(`mq-narrow.sh`, `Makefile` `shell-test-affected`, `ci.yml` line-index, `gate-affected.sh`,
`selection-baseline`).

Design (a), as AFP-V0-3642 states it, is `cmd/corvint/affected_headline.go` plus one call in
`runAffected`. The headline has at most ten lines of at most 200 bytes:

1. the summary line with revision and base;
2. the tier counts;
3. the five most frequent unknown reasons with a count and one detail each, then a count of the
   rest;
4. the warning;
5. the commands that read the plan without jq.

It is written only for the compact plan, only to a stderr that is a file, and not when stdout and
stderr are one pipe or file. That last rule is AFP-V0-871's rule for the degradation line, so
`2>&1 | jq` keeps parsing.

Limit recorded in the spec: this lane's agent shell runs every command with fd 1 and fd 2 on the
same regular file (`ls -l /proc/self/fd/1 /proc/self/fd/2`), so a bare `corvint affected` there
shows no headline. No single byte stream can carry both the headline and a document that the
`2>&1` readers can parse. In such a harness the reader runs `--summary --format text`, or sends
stdout to a file.

Live, from a binary built from this worktree:
`corvint affected --base b55635262788687c3eea9a08a94378e4ab8856a4 --accept-stale-binary
>plan.json 2>plan.err` wrote a 5-line, 657-byte headline and an unchanged 105,572-byte plan. The
same command with `>merged 2>&1` wrote one JSON document with no headline line.
