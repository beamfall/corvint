# V1-0632 S5a: OCM/LRF stable admission

Date: 2026-10-11. Native work: V1-0632 slice S5a, migration row C05. Spec:
`docs/specs/cem-stable-v1.md`, section "OCM/LRF stable admission (V1-0632 S5a)",
`CEM-V1-051..059` (proposed).

## Decisions

- The owning admission is `lrfrepo.VerifyStableUniverse`, separate from the legacy
  `VerifyUniverse`. It first runs the complete stable verifier over the exact original bytes with
  the explicit repository root, base, target and artifact root. It then re-derives the canonical
  patch, verifies the OCM against the exact original map digest through the existing OCM checks,
  and projects the LRF request. So the OCM binding, intent pinning, claim and obligation checks are
  the same code as for `cem/0.2`, not a second implementation.
- The returned `StableUniverse` keeps the full stable identity: spec `cem/1.0`, the original-byte
  digest and the complete accepted verifier result. It holds no legacy `*wire.Map`; the mechanics
  view used by the shared OCM steps is private and never returned. Consumers get the full
  document only through `Document()`, a fresh parse of the authenticated bytes.
- `lrf/0` is frozen, and its canonical form hard-codes `"profile":"lrf/0"`. Letting it evaluate a
  `cem/1.0` context would relabel a frozen profile. So `lrf.Evaluate` keeps refusing, and the slice
  adds only `lrf.ValidateStableRequest`: the frozen request checks plus admission of a `cem/1.0`
  context. It shares the frozen context checks through `validateContextSpec`, parameterized only by
  the admitted spec, and refuses a valid `cem/0.1` context, which those checks would otherwise
  admit. `validateRequest` takes an optional context admission, so `evaluate.go` is untouched.
- A verifier refusal is returned as `StableRefusal`, which keeps the full 21-field result and exit
  so no evidence is lost. It unwraps to an adapter `*Error`, so `CodeOf` reports its code
  unchanged.
- Every edit before an existing line keeps the file's line count: new code is appended at file
  ends, and in-place changes replace a call or a return on the same line. Specs and the
  divergence register cite many lines in these five files, and the first draft shifted them (the
  `line-citations-check` gate found six blank targets). The stable admission lives at the end of
  `adapter.go`, which already imports every package it needs.
- The legacy routes (`VerifyUniverse`, `readOCMBytes`, so `ocm read` and `ocm link`, and
  `PrepareOCM`) now refuse a `cem/1.0` map explicitly with `unsupported-spec`, naming the stable
  admission. Before, they reached `wire.ParseMap`, whose stable refusal named only the Core stable
  read, or reported an `invalid-cem` OCM verdict. Every `cem/0.x` path is byte-for-byte unchanged.

## Evidence

- Lane start: `corvint --version` 1.0.0-rc.3 (build 407). `corvint affected --base a8c05c4f4`
  gave PLAN_ONLY, scope UNKNOWN, an empty selection and 20 LANGUAGE_FRONTIER unknowns, so the
  packages were selected by importers of `internal/lrfrepo`. `corvint context` was READY, but
  reported a revision other than BASE (likely a stale index), so it was used as orientation only.
- The positive case is real. A `cem/0.2` change with cited hunks, a prepared OCM and one linked
  case claim is built through the existing producers. It is converted to `cem/1.0` with a closed
  criterion/receipt/link graph and six artifact files under a separate artifact root. Its exact
  bytes are committed as the target's sidecar, and the OCM is rebound to the new target and digest.
  `VerifyStableUniverse` returns ACCEPT/EXACT with six artifact checks; the unsatisfied
  `OCM-TEST-002` stays `unknown`/`unassessed`.
- Failure controls cover:
  - a tampered artifact (REJECT, exit 1, result retained);
  - a missing artifact (`artifact-unavailable`);
  - a swapped stable map (`excluded-artifact-mismatch`);
  - an OCM bound to the `cem/0.2` digest (`cem-map-digest-mismatch`) or to a stale target
    (`target-mismatch`);
  - a stale caller target or base;
  - an OCM missing an obligation;
  - every missing authority argument;
  - profile swaps in both directions;
  - legacy read, prepare, link and evaluate over `cem/1.0`.
  Each returns no universe.
- Focused tests: `go test -p 1 -count=1` for `internal/lrfrepo`, `internal/lrf`,
  `conformance/ocm-v0`, `internal/dogfoodocm`, `internal/frontierrepo`,
  `internal/frontiernextrepo`, `internal/localcompletion`, `internal/tcq` and
  `internal/cem/workflow`, plus `cmd/corvint -run 'LRF|OCM|Lrf|Ocm|Frontier'`. All passed on
  go1.27.2 (darwin). `go vet` passed for `internal/lrf` and `internal/lrfrepo`.

## Remaining limits

These are not claimed.

- Stable LRF evaluation. There is no `cem/1.0` LRF result document. Producing one needs an accepted
  stable LRF profile amendment: `lrf/0` is frozen, and the LRF spec is outside this slice's paths.
  C06 needs that profile before the stable frontier can evaluate.
- No CLI or MCP route. `corvint lrf`, `ocm read`, `ocm prepare` and `ocm link` refuse `cem/1.0`.
  Exposing the stable admission needs `cmd/corvint/lrf.go` and `ocm.go`, which are outside the C05
  paths, and the C06..C09 consumer decisions.
- OCM writers remain `cem/0.x` producers. A stable OCM is prepared against the `cem/0.2` map and
  rebound, as in the test fixture; a stable OCM producer is not part of this slice.
- Qualification is bounded to darwin go1.27.2. Linux, Windows and go1.27.1 are NOT_RUN. The
  fixture skips on hosts other than Darwin and Linux. On a runtime outside the admitted structural
  tuples, the verifier refuses at its runtime stage, so the positive tests fail rather than pass.
- NOT_RUN: `./...`, `make gate`, the dogfood CEM bind and seal (forbidden for this lane), and
  independent external consumers.

## Rollback

Remove the stable admission types and functions and the explicit `cem/1.0` refusals listed in the
spec's rollback paragraph. No `lrf/0` or OCM profile, default, packet or stored evidence changes.
