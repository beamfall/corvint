## V1-1572: older binaries and slots (PSR-V0-080)

V1-1550 recorded that a binary predating slots refuses a store with slots, inferred from its closed
decoders. This lane executed it. corvint-tasks was built from source at tag `v1.0.0-rc.2`
(154d663f0) into a temporary directory (not installed) and run by the opt-in
`TestPSRV0080_OlderBinaryRefusesSlots` against temporary stores written by this build:

| Store | Older `queue status` | Older `attempt show` |
| --- | --- | --- |
| pools, no slots (control) | OK | not run |
| policy declares `slots` | ERROR `MALFORMED`: `policy.json: closed object violated (unknown keys: slots)` | not run |
| policy declares `slots`, a slot held | ERROR `MALFORMED` (policy refused first) | ERROR `MALFORMED` |
| policy updated without `slots`, entry still in `pools.json` | ERROR `MALFORMED`: `/: closed object violated (unknown keys: slots)` | not run |

The state tree was byte-identical after each refusal. The inference is confirmed; PSR-V0-080
records the compatibility statement and the rc.3 release notes carry it. Limits: one older tag, a
Darwin host, an unverified source build (version label `0.0.0-tcp01-unverified`); the published
`v1.0.0-rc.2` release binary was not run because installs are out of scope for the lane.

## V1-1586: member source identity and drift guard (PSR-V0-081..086)

Decision: the typed reasons (`SOURCE_NOT_ALLOWED`, `SOURCE_DRIFT`, `SOURCE_IDENTITY_UNPROVED`) are
detail and quarantine-reason tokens on existing wire codes (`OUT_OF_SCOPE`, `QUIESCENCE_UNPROVED`),
not new codes, so the closed code set and every older reader are unchanged. The identity command
runs in the lease observer against the state the transaction decides on, memoized over that state
so a retry over unchanged state does not rerun it; a first cut probed before the write with its own
full lease-proof read, which bypassed the writer-checkpoint route (`TestCALV0205_*` caught it). A drift or failure is a committed `BLOCKED`
receipt that records the observation and reason, so a replay returns it and frees nothing. `allowedSources`/`defaultSource` live outside the hashed
member definition, so narrowing the allow-list never strands a live allocation; the identity command
is inside it and is immutable while occupied. Identity and `safeReuse` are mutually exclusive in this
slice, so the sweep's delegated confirmation never meets a guarded member; a sweep identity probe is
a residual. Limits: whether a replayed confirm-safe runs the identity command depends on where the
observer runs relative to replay detection (NOT_OBSERVED); Linux runtime NOT_RUN (Darwin only).
