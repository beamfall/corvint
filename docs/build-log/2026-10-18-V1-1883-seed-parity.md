# 2026-10-18 V1-1883: seed parity between linked tests in test-validity

Ticket: V1-1883 (a migrated test can keep its title and assertions while seeding different data).
GitHub #1167.

## Decision

`TSA-V0-100` to `TSA-V0-109` are added to `docs/specs/test-source-analysis-v0.md`. They are
accepted under the owner's standing auto-accept of lane requirements (2026-10-11).

- The link is an explicit, repeatable `corvint tests validity --legacy NEW=LEGACY` argument, each
  side `path:line` of one example. The documentation-corpus legacy crosswalk was not reused: it
  links behaviours, needs a registry and an inventory, and has no test-to-test line. No link store
  is added.
- One setup form per language, read from committed blobs:
  - RSpec: FactoryBot `create`/`create_list`/`build`/`build_list` in the example body, its
    groups' `before`, `let!` and `subject!`, and the lazy lets that scope invokes; plus
    `fixtures :table` YAML records.
  - JS/TS: `create`/`build`/`createList`/`buildList` in the example body and applying
    `beforeEach`/`beforeAll`.
  - Anything else setup-like in scope abstains with a named reason, side and line. Parity and
    divergence are never reported when either side was not analysed (`SEED-PARITY-NOT-ANALYSED`).
- The shape is kind, summed count and explicit attributes. `build` and `create` are not told apart.
  Non-literal values are `<expr>` and never give a value divergence.
- Divergences are ordered first by whether an asserting line reads the kind (its name, plural or a
  bound name), and name both counts and the asserting lines on both sides.
- The aggregate finding reads only a plural group (the kind's plural or a plural bound name) next
  to an aggregate word. Reading the singular kind made `order.total` on an owner record a false
  finding in the first fixture.
- Every finding is advisory and the exit code is unchanged. `seedParity` is omitted without links,
  so existing output is byte-identical.

Implementation notes:

- The JS/TS reader is `seed_parity_jsts.go`: a `_js.go` suffix is a `GOOS=js` build constraint
  (the same trap V1-1858 hit).
- `rspecGroup` now records its lets and `fixtures` lines; the existing hygiene readings ignore them.

## Evidence

Real CLI built from this branch against a scratch repository with a committed legacy
`order_legacy_spec.rb` (an order with `status: :paid`, three line items, a `sum` assertion) and a
new `order_spec.rb` (a default order, one line item, the same `sum` assertion).
`corvint tests validity --legacy spec/models/order_spec.rb:2=spec/models/order_legacy_spec.rb:2`
exits 0 with status `diverges` and four findings:

- `SEED-PARITY-DIVERGES`: legacy seeds 3 line_item, new seeds 1, with both asserting lines.
- `SEED-PARITY-DIVERGES`: `order.status` explicit on the legacy side and default on the new side.
- `SEED-AGGREGATE-SINGLE-MEMBER` on each side's `sum` assertion.

Focused tests: `./internal/testsource` (`-run 'TestTSAV010'` and the existing validity readers),
`./internal/testvalidity`, and `./cmd/corvint` `-run 'TestTests|TestTSAV0108'`.

## Residuals

- No live qualification on a real migration (NOT_RUN); most real suites will abstain until more
  setup forms are read.
- Setup helpers whose names hold no setup word are not seen, so parity can be reported over them.
- Factory definitions, traits' contents and associations a factory adds are not read.

## Codex review fixes (PR #1178)

One Codex round found seven issues; each is fixed with a regression fixture that fails before the
fix (verified by reverting the three reader files and rerunning `-run TestTSAV010`):

- Conditional or deferred factory calls were counted. RSpec tracks block and keyword nesting per
  body line and rejects a call on a line with a condition, short-circuit or modifier; JS walks
  back from the call to its statement start. Both abstain with the new reason
  `seed-execution-unresolved` (`TestTSAV0107SeedConditionalAbstains`).
- An oversized `spec/fixtures` file silently fell back to `test/fixtures`; it now abstains with
  `seed-fixture-bound-exceeded`, and a non-regular file with `seed-fixture-unavailable`
  (`TestTSAV0107SeedFixtureOversizeNoFallback`).
- `<expr>` against a different literal gave parity. It now gives the advisory
  `SEED-PARITY-UNCERTAIN` finding and status `uncertain`; equal sets stay parity
  (`TestTSAV0103SeedExprVersusLiteralUncertain`).
- A named subject used through `is_expected` now resolves to its body
  (`TestTSAV0101SeedNamedSubject`).
- An inner `let` overriding an outer `let!` counts the inner body only
  (`TestTSAV0101SeedOverriddenEagerLet`).
- A comment after a quoted YAML scalar is stripped (`TestTSAV0101SeedYAMLQuotedComment`).
- A `.should` chain keeps its receiver, so `SEED-AGGREGATE-SINGLE-MEMBER` fires
  (`TestTSAV0106SeedShouldAggregate`).

The execution check is conservative: a call inside an argument list's callback, an object literal,
`begin`/`rescue` or a typed declaration with `|` abstains even when it would run. That is the
intended failure direction (TSA-V0-107).
