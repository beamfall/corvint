## Finding

The shared class: the reader gave a definitive `INELIGIBLE` (or a clean `ELIGIBLE`) where a line
reader cannot prove the behaviour. The cases were:

- spliced helpers ordered across files;
- the TSA-V0-054 resolver ignoring included overrides;
- an incomplete support set, a nested include in a shared context, or the first of two defs in a
  context treated as the definition;
- a `yield` in a default argument;
- assignment predicates of non-literals;
- `change { X.reload }` treated as proven;
- unknown helpers with unbound support;
- endless defs and one-line examples;
- a customized `it_behaves_like` in a loop;
- receipt reads without a description.

## Decision

rule. No fuller Ruby resolver was built.

- `RB-CHANGE-ON-IDENTITY` is advisory, because RSpec compares hashes and the receiver's
  semantics are unproven.
- `RB-ASSIGNMENT-IN-PREDICATE` fires only for a truthy literal.

TSA-V0-084/085/086/088/092 wording is amended in place under the 2026-10-11 standing auto-accept.
