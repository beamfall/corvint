# 2026-10-15 V1-0969, V1-1398: lifted test bounds for the dogfood-event, qualified-lifecycle and context-expand families

Base `55b0c0f0901ca516705b1d6d6b43651c071e6ccd` (origin/main after #914). The first V1-0969
measurements ran at the previous base `59d492017`. Every production bound is unchanged: the
dogfood event deadline (1600 ms, Claude Code `session-end` 600 ms), the Git probe bound
(`gokernel` 10 s) and the source deadline (`sourceGitDeadline`, 10 s). No requirement text or ID
changes.

All counts below ran under 16 `yes` burners on the shared 12-core host. Loads are 1-minute
averages before and after each run. Per decision 0082, a test deadline is a hang detector, not a
latency budget. Each lift uses the existing test-only context seams:
- `dogfoodEventDeadlineKey` and `liftedProbeBound` through `lifecycleDeadlineContext`;
- `liftedSourceDeadline` from #914.

## V1-0969: dogfood-event deadline tests

`TestDogfoodEventSpawnsOneBracket` re-executes the test binary. That helper process ran the event
under the production 1600 ms deadline and the 10 s Git probe bound, so under load the event
answered `dogfood-event-deadline` and exited 2.

The fix adds one environment variable, `CORVINT_TEST_HELPER_LIFTED_EVENT_BOUNDS=1`. Only
`main_test.go` reads it. It makes `TestCandidateHelperProcess` run the candidate under
`lifecycleDeadlineContext()`, and the bracket test sets it.

Three other tests now use the same lifts:
- `TestDogfoodEventRefusesRepositoryDriftInsideTheBracket` uses `lifecycleDeadlineContext()`.
- `TestDogfoodEventSnapshotMissExpiryNamesStaleSnapshot` lifts the probe bound for its first
  event and runs the refreshed half under `lifecycleDeadlineContext()`.
- `TestDogfoodEventSnapshotMissUsesRecordedBuildCost` lifts the probe bound.

A new subtest in `TestDogfoodEventDeadlineBelowDeclaredHostKill`, "production deadline unchanged
by the test seams", pins the product values from `dogfoodEventDeadlineOf(context.Background(), …)`:
- codex `stop`: 1600 ms;
- claude-code `user-prompt`: 1600 ms;
- claude-code `session-end`: 600 ms.

## V1-1398: six cmd/corvint families

**Selection.** The family runs used one combined selection:
`^(TestContextExpandRefusesWithoutSubstitutingContent|TestAffectedUntestedGoPackageIsUnknownScope|TestAffectedUnownedDirtyPathIsUnknownScope|TestDogfoodEventReadOnlyEnrolledStopAndPrompt|TestQualifiedLifecycle)`.

**Counts.** On BASE `55b0c0f09`, count 10 (load 22.8 -> 53.3), it failed 6 tests. On the head, the
same run (load 21.2 -> 72.3) failed 0.

**(1) Source-view cancellation (`TestSourceViewCancellationTerminatesGitProcessGroup`).** Not
reproduced. BASE `55b0c0f09` failed 0/10 (load 27.2 -> 34.1). No change. The test's 8-second wall
bound stays a residual at higher load.

**(2) Context expand.** On BASE, 1/10 failed:
`non-utf8-source: git-failed, cannot resolve the handle's blob identity`.

`expandContextHandle` wrapped its whole Git sequence in a fixed `10*time.Second`. That limit was
not covered by the per-command `sourceDeadline` lift. The wrap now reads `sourceDeadline(ctx)`, the
same function and the same 10 s product value, pinned by `TestSourceDeadlineReplacesFrozenBound`.
`runContextCommand` in `context_summary_test.go` passes `liftedSourceDeadline`. The `context_summary.go`
native digest is re-frozen in `benchmarks/selfuse-batch/source-views-manifest.json` (ESV-V0-005).

## Review

One Codex round (`codex exec -s read-only`, range `55b0c0f09..bc5a1f52c`) reported no P1 or P2 and two P3:

- This log called the `> 3 s` wall assertion in `TestQualifiedLifecycleInvocationDeadline` a lower
  bound. It is the upper end of a 1.5 s to 3 s window. Corrected above; it stays a load residual.
- The `internal/gokernel` probe test derives its expected value from `gitDeadline` itself, so no test
  independently pins the 10 s Git probe bound. This predates the change and is recorded as a residual.
  The dogfood event deadlines and the source deadline are pinned by literal values.
