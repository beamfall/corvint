# V1-1091: Linux process identity jitters with /proc/stat btime

Date: 2026-10-20. Ticket: V1-1091 (suspected). Lane: bugs-residuals.

## Mechanism

`supervisor.ProcessIdentity` on Linux is `linux:<btime>:<starttime>`. `starttime`
(`/proc/<pid>/stat` field 22) is fixed for the life of the process, counted in clock ticks
since boot. `btime` in `/proc/stat` is not stored: the kernel recomputes it on every read as
the realtime clock minus the time since boot, truncated to whole seconds. When NTP slews or
steps the realtime clock, or the boot instant's fractional second sits near a boundary,
successive reads can disagree by one second. The ticket's sample (3,000 reads in one Docker VM:
1,076 and 1,924 of the two values) is consistent with that. The mechanism is confirmed by
the kernel derivation and the recorded sample. It is not reproduced locally: the lane host is
darwin and has no `/proc`, and a Linux runner measurement is `NOT_RUN`.

## Change

`identity_linux.go` reads btime once per process and reuses the first valid value
(`bootIdentity`). The boot cannot change while a process runs, so every identity one process
computes for a live process is stable. Before this change, two reads in one process could
disagree, which is the in-process flake class. Starttime still has to match exactly, and a
failed or invalid read is not cached. Test:
`TestV11091IdentityStableAcrossBtimeJitter` alternates the btime it returns and checks for
one read and equal identities.

## Residual (not changed; out of the lane's scope)

An identity that another process recorded, such as a persisted lease, worker or service
record, can still differ from a fresh one by one second of btime. The fix for that would
compare `linux:` identities with btime tolerance ±1 and an exact starttime match. That is
safe because a reused PID within the same boot has a different starttime tick, and a
different boot within ±1 s of realtime would need a reboot within one second plus an
identical starttime tick. It would be applied at the identity equality sites outside
`internal/tasks/supervisor/identity_linux.go`:

- `internal/tasks/cli/attempt_detach.go`
- `internal/tasks/dispatch/{detached,loop,process_unix,reader,reader_recovery}.go`
- `internal/tasks/service/{descendants_linux,helper,lifecycle,run}.go`
- `internal/tasks/store/{program,program_control,program_run,workflow}.go`
- `internal/tasks/supervisor/{detached_unix,process_unix}.go`

That is 25 `ProcessIdentity` calls in total. Another option is to replace btime with
`/proc/sys/kernel/random/boot_id`, which needs an identity-format migration. Other lanes own
`internal/tasks`, so this stays open on V1-1091.

Verification: `GOOS=linux go vet ./internal/tasks/supervisor/` passed. The Linux test run is
`NOT_RUN` on this darwin host.
