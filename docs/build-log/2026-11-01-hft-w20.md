### V1-3971: the no-python scanner ignores quoted printf and echo fixture data

- `mask_fixture_data` is an awk shell-word reader. For a `printf` or `echo` in command position, it blanks the quoted arguments: single-quoted ones, and double-quoted ones without `$(` or a backquote.
- It does not mask unquoted names, later commands on the line, or command substitutions.
- Self-tests cover 4 fixture-data lines and 9 genuine calls. Each fixture line is also checked against the mutant without masking, which still flags it.
- Passes with GNU awk (WSL), BSD awk (macOS) and shellcheck.
- **Likely conflict:** lane sel-w14 (`910e95fb0`, V1-3842) edits the same script near `unexempted()`. This change sits in `scan()` and at the end of the file to keep the overlap small.

### V1-2815: TestCALV0143 orphans

The orphans did not reproduce at BASE. These runs were tried, and the dead-man reaper (ATR-V0-213) reaped the worker every time:

- `-race -count=3`
- `-timeout 3s`
- SIGKILL of the test binary at 0.3, 0.6 and 1.0 s

Delivered: every `testConfig` fixture now registers `failOnStrays`. After the V1-0948 reap, it looks for any process whose argv or `/proc/<pid>/cwd` is under the fixture root. If one survives a bounded wait, it is killed and the test fails, naming it. `TestStrayCheckFindsAnUnrecordedProcessRunningFromTheTestDirectory` proves the check finds a setsid stray and, on Linux, the stray's child.

Residual, not reproduced: an external kill that hits both the test binary and its dead-man reaper at once still leaves workers unreaped. Examples are a runner process-tree kill, a `pkill -f`, or RUNNER_TRACKING_ID cleanup. Two options were rejected:

- Pdeathsig: it fires on the death of the parent thread, not the parent process.
- A worker watchdog: it widens worker lifetime semantics.

Recommendation: leave it, unless a CI kill pattern is observed.

## Friction

1. heavy.sh counts `go test -c` (compile only) as a whole-package run. It also ignores `HEAVY_WHOLE_REASON` given as a `NAME=VALUE` prefix; the variable has to be exported in the shell.
2. V1-3776 and V1-3843 were fixed by commits that do not name them, so both stayed open as delivered-but-open drift.
3. The comment at `script/lane-scripts_test.sh:288` says the fake ssh drops only the cache variables. In fact it uses `env -i`.
4. `testsupport.NodeOrSkip` exists only on the unmerged hst-u16 lane. A coupled lane has to copy the file byte for byte to merge cleanly.
5. sel-w14 and hft-w20 both edit the no-python scanner.
6. The dead-man reaper shares its binary's name and environment, so one kill can take out both the test and its reaper. This is the V1-2815 residual.
7. The `corvint-tasks ticket show --json` record nests under `items[0].record`, and its id field is `ticketId`, so a naive parse prints nothing.
8. The TestNEAV0013 failure path discarded every cause: the hook's stdout and stderr are unread by design (NEA-V0-015), and the test reported only the missing runner.log. Fixed here, test-side.
9. `corvint affected` in a `git clone --shared` scratch clone reported goAdditive `BASE_UNREADABLE`. A plain local clone did not, so a shared clone gives a weaker plan. This is a suspected defect.
10. The installed corvint binary was stale against the lane's own `internal/testsupport/node.go` (`self-binary-stale`), so the affected plan carried that degradation.
11. The name `unraid-lanes` does not resolve from wsl-lanes; it is an ssh alias on the Mac only. A check run from one lane host against another has to go through the Mac.
