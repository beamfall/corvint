The 11-12 reds have these causes:

- Hostile matrix. `2695ec5fa` (change `context-proven-only`) deleted `internal/trace` and the

- `cross-vet`. Two unix-tagged test files called helpers that only exist under `darwin || linux`:
  `inventory_readers_unix_test.go` (`dac950736`) used `sessionDeclaration`, and
  `runner_contract_unix_test.go` (`743551bbf`) used `sessionFixture`. The fix moves the session
  fixture (`sessionFakeGo`, `sessionFakeMake`, `sessionDeclaration`, `sessionFixture`) unchanged into
  the new `cmd/corvint/session_fixture_unix_test.go` under `//go:build unix`. `go vet ./...` now

- `internal/flowdocs` and `cmd/corvint-docs` on macOS were fixed on main by #201 (`edb90d444`,

- `TestLazyPlanBudget` is the 100 ms p95 lazy-plan CPU budget. Tickets V1-5003 and V1-4553 track it.
  The Go macOS workflow sets `LINECOV_PLAN_P95_BUDGET`, but the release-gates full-gate job does
  not. Fixing that needs either a `.github` edit, which other lanes own this round, or performance
  work. Both are out of this lane's scope.

Why PR CI let the two regressions reach main:

- The hostile-matrix wrapper runs only in the nightly linux-core job, so deleting a listed package
  in a PR is never checked against the matrix.
- PR CI has no BSD or Solaris vet. A helper that is wider than its callers' build constraint
  type-checks on linux, darwin and windows, so nothing catches it before the nightly.

Both gaps belong in `.github` and are reported to the orchestrator for ticketing.

## V1-4695: repository-wide fixture identity search

The drift cause, recorded at V1-4719 (`CCF-V1-9800`, `83660e9c5`): `GIT_AUTHOR_*` and
`GIT_COMMITTER_*` take precedence over `-c user.*` and over config. An identity or date exported by
the caller therefore changed the fixture commit IDs that the frozen profiles carry.

Why CI did not catch it: no workflow exports those variables to `go test`. The only `.github` use
is a per-command assignment in `.github/forward-rows/mq-narrow.sh`. The failure appeared only
under the lane-host verify scripts, which run outside the repository and export a commit identity
(an inference from the ticket's observation on wsl-lanes).

V1-4719 closed that gap inside the ordinary CI run:

- `TestFixtureGitIdentityIsHermetic` sets a foreign identity and dates with `t.Setenv`, compares
  the fixture SHA, and reruns `TestCoreVerbsEmitTheFrozenProfiles`.
- `TestFixtureGitCommandsUseHermeticEnvironment` refuses a new unfiltered direct Git command.

Of the three goldens the ticket names, only `TestCoreVerbsEmitTheFrozenProfiles` still exists; the
other two were removed with the context packet (decision 0597). On this lane's darwin run, with a
foreign `GIT_AUTHOR_NAME/EMAIL/DATE` and `GIT_COMMITTER_NAME/EMAIL/DATE` exported, it passes along
with `TestFixtureGitIdentityIsHermetic` and the guard.

Search method, on this base:

1. Find every Go test package whose `_test.go` files run `git commit`. There are 92.
2. Classify each by whether it calls `testsupport.IsolateGit`, uses
   `testsupport.WithoutGitIdentity`, or sets the six identity variables itself.
3. Check the remaining packages for pinned 40-hex literals in `_test.go` files and `testdata`.

Results:

- 46 of the 92 packages already isolate through `IsolateGit` or `WithoutGitIdentity`.
- The other 46 are: benchmarks/selfuse-batch, cmd/corvint-go-test-provider, conformance/cli-parity-v0,
  conformance/go-live-test-v0, conformance/mcp-2026-07-28, conformance/mcp-test-validity-v0,
  conformance/release-artifact-v0, internal/analyzernativebridge, internal/browsercov,
  internal/contextindex, internal/corerelease, internal/docstools, internal/gitancestry,
  internal/gokernel, internal/jobinputs, internal/jstestprovider, internal/linecov,
  internal/linecov/watch, internal/liveverify/affected, internal/liveverify/parentverify,
  internal/observedstale, internal/releasegate, internal/rubylinecov, internal/runnerprotocol,
  internal/sessiontest, internal/testinventory, internal/testreuse, internal/testrunner/registry,

Dispositions for the 46:

- Fixed here, reusing the shared mechanisms as `CCF-V1-9800` allows:
  - `internal/analyzernativebridge`: its `TestMain` pinned the identity but not the dates. It now
    unsets inherited `GIT_AUTHOR_DATE` and `GIT_COMMITTER_DATE`, as `IsolateGit` does. The package
    pins fixture SHAs. It passes whole with a foreign identity and dates exported, on darwin and
    Linux.
  - `internal/jstestprovider` (`TestGitObservationSuppressesGraftAdvice`) now builds its
    environment from `WithoutGitIdentity`. Its commit is identity-insensitive (it asserts only a
    40-character ID), so this is hygiene, not a failure fix.
- Already hermetic without the shared helpers: `internal/contextindex` and `interop/cem01-go` set
  all six variables.
- Pinned literals checked: the other pinned literals are blob digests (the empty blob, fixed file
  contents), whose IDs do not depend on identity, or synthetic input revisions. No test compares a
  fixture-created commit or tree ID with them. Under a foreign identity and dates exported, these
  pass whole on Linux: `tools/ci-forward-row`, `tools/ci-reuse-plan`, `tools/ci-test-slices` and
  `internal/sessiontest`, which are the packages with the most testdata hashes.
- Identity-insensitive, no change: the remaining packages pin no commit or tree ID. A caller's
  identity changes only the commit metadata, which they do not assert.

No package was left failing. Hardening those packages anyway, so that a future SHA pin cannot
regress, is reported to the orchestrator as a ticket candidate rather than built here. Raw scan
outputs are in the lane's orientation directory (`commit-pkg-scan.txt`, `identity-sha-scan.txt`).
