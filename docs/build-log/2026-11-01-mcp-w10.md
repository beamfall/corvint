## V1-3737 and V1-3499: companion CLI contract (CAP-V0-700, CAP-V0-701)

Measured first: no companion answered `help --json` or `--version --json`. `corvint-console`
started work on any positional argument. `corvint-update` treated `--help` and `--version` as
actions. `corvint-dashboard-snapshot` and `corvint-web-flows` had no `--help` or `--version`.

Decisions:
- The companions are the eight binaries a release or the companion bundle ships beside
  `corvint` and `corvint-tasks`. Each answers through one helper, `internal/companioncli`, before it
  parses anything else, so the five forms behave the same in every binary.
- `help --json` is `corvint-companion-help/0` (the usage lines), not a command tree. These
  binaries keep their `CLI-RATCHET.tsv` rows; a tree is separate work.
- The version stays `0.1.0-experimental`, the version the MCP servers already report, so the
  companion smoke and VS Code oracle bytes do not change. The repository `VERSION` file cannot be
  embedded from an internal package. `--version --json` adds the build's VCS commit, `unknown`
  for a `-buildvcs=false` release build.
- `corvint-mcp` reads its usage through a new exported `cli.Usage()` in its own file, so this lane
  touches nothing else in `internal/mcp/cli`, which mcp-w8 changes heavily.
- The three dedicated MCP servers' usage texts gained an `Example:` line.

## V1-3706: overlapping tool names and the slow docs refusal (SDD-V0-700)

- Slow refusal: CONFIRMED and FIXED. A docs_draft or docs_consume whose owner source is missing,
  untracked or only staged took 2.1 to 2.6 s to refuse (an index build), while schema-invalid input
  took 10 ms. `doccompiler.PrecheckDraft` and `Registry.precheck` now refuse it before the build,
  with the identical code and message: `git cat-file -e HEAD:PATH`, plus the existing lexical
  package check. The index reads HEAD, so a path missing from HEAD can never be admitted. The test
  checks equality with `DraftSources` over a full index for four sources and both tools, under
  100 ms, with no build. Decision: an invalid package for a valid owner still needs the index,
  because its declarations decide it, so that refusal is unchanged.
- Name overlap: CONFIRMED, but kept by design. `corvint.help` is on all four servers, and
  `corvint-docs-mcp` and `corvint-test-validity-mcp` repeat the `corvint mcp` group tool names
  (observed `tools/list`). Those binaries are deprecated aliases kept for one release, which
  MMR-V0-013 requires to answer identically. MCP hosts namespace tools per server
  (`mcp__SERVER__TOOL`), so two enabled servers do not collide. The Claude plugin declares one
  server. Renaming would break that parity contract, which is an owner decision. The corpus
  `tools/list` size (18 tools) is unchanged.

## Friction

1. `/tmp` (16 GB tmpfs) stayed at 0 to 24 MB free all lane. It is also the harness's own temp
   volume, so every Bash call reported "Disk full" and dropped its output. Workaround: write all
   output under `~/.cache/mcp-w10` and read it back, with TMPDIR, GOTMPDIR and GOCACHE on disk.
2. A shell redirect to a directory created in the same command fails, because the redirect opens
   first (`{ mkdir ...; } > dir/out.txt` gives "No such file or directory"). The first setup call
   lost its output.
3. `claude mcp list` without `--plugin-dir` does not list the corvint plugin server on this host,
   although the desktop session uses it. A live plugin receipt needs `--plugin-dir` and a matching
   `corvint` on PATH.
4. perf-budget refuses `--scale smoke` against the committed full-scale budgets ("bound scale
   full"), so a quick smoke measurement needs a hand-edited budgets copy.
5. Merge risk: base has MCPV0-115 (missing-root fallback) in `internal/mcp/cli/main.go`, and
   unmerged lane mcp-w8 rewrites the same root handling (MCPV0-950). The batch merge will conflict
   there; MCPV0-950 should run after the MCPV0-115 fallback, or replace it.
6. Six of the ten tickets were already delivered on base or on an unmerged lane. The store dump
   carried no delivery status, so each needed a separate `git log --all --grep` triage.
