## Decision: a live tier that only the PR-shard step skips

A test joins the tier by calling `testsupport.RequireLiveTier(t)`. It runs by default and skips only
when `CORVINT_SKIP_LIVE_TIER=1` is set in an untagged binary; the `live` tag always runs it. Only the
`go-product-shard` Go test step of `ci.yml` sets the variable. Discovery (`cishards.LiveTests`)
reads the call from source, so the tier has no hand-kept list. A naming rule was rejected: renaming
25 tests would break every requirement trace that cites them.

The first version inverted this: the tier skipped unless the `live` tag or `CORVINT_LIVE_TIER=1` was
set, and `make live-test` was a `GATE_STEPS` entry. The independent review found that this skipped
locally selected tests in silence. `corvint test` derives its invocations without the variable, and
`.github/cishards/test-commands.json` sets neither mechanism. So a Tasks dependency change that
selected `internal/companionrelease` reported PASS while `TestCurrentTasksSourceArchiveBuildsOffline`
skipped. V1-4923 records the gap. With the default inverted, local `go test`, `corvint test`, the
test-commands consumers, `make gate` (through `go-test`), nightly gates and batch-precheck all run
the tier. `live-test` left `GATE_STEPS`, since `go-test` already runs the tier there. batch-precheck
now runs `make live-test` as an extra target. The doc gate and drift-step variable assignments were
reverted. `TestBrokenLiveTestFailsAnOrdinaryRun_AFPV02700` re-executes an injected failing live test
without the variable and requires the run to fail. A mutation that made every live test skip
failed it. The review also found that discovery missed module-root test files: `path.Dir` returns
`.`, which matched the hidden-directory rule. A root file is now accepted.

The tier holds 25 tests: 22 in `internal/liveverify/affected`, 2 in `companionrelease` and
`TestDocsHelpPrerequisitesAndWorkingExample` in `cmd/corvint`. `TestOwnershipAuditRatchet_AZU_V0_002`
stays out of the tier, because AZU-V0-002 has selection always select it.

| `TestDocsHelpPrerequisitesAndWorkingExample`, offloaded | 3.1 s | skipped (0.00 s) in a PR shard |

Local runs keep the "before" cost: the saving applies to PR shards alone.

The slices were generated with `--target 400s`, the AFP-V0-164 bound, so `internal/tasks/cli`
(515 s) stays split; the default target (the 661 s ideal share) would have run it whole. The replay
commands were `go run ./tools/ci-test-slices replay` on the 16 shard logs, with the old
tables and then the new tables. The "after" replay turns each live test's terminal event into a
skip and subtracts its seconds from its package's elapsed time. The committed cost table keeps the
measured run's provenance, so the live tests' seconds stay in it. The three
`internal/liveverify/affected` slices then run underloaded and the max stays 662.2 s. The next
non-PR refresh (AFP-V0-540) measures the skipped tier and brings the plan down to near the 552 to
574 s ideal. No synthetic table was committed.

The `go-live` merge-queue job runs `make live-test` without `-race`. The PR shards ran these tests
with `-race` before. Locally they take about 70 s in all without race, so the job is short beside
the shards; under `-race` on a CI runner they took about 1,393 s, longer than a shard.
