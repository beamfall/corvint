## V1-1309: `script/gate-affected_test.sh` exited 1 without a message

The deleted-file case expected `gate-affected: frontier example.com/fixture/core <- core/core.go`.
AFP-V0-012 makes the selector add its attributed packages to the plan's own selection, and
`internal/gateselect` prints `frontier` only for a package it adds. The plan already selects core,
mid and leaf there, so the selector prints `selected` lines for them. The script was right and the
expectation had drifted, so the script is unchanged. The case now accepts either line for each package
(`expect_reached`). Every failed expectation goes through `fail`, which prints the missing line and
the observed stdout and stderr. A run with the old expectation now prints
`FAIL: missing line: gate-affected: frontier example.com/fixture/core <- core/core.go` and the
`selected` lines. The test exits 0 under `sh` and `dash`.

## V1-1310: a signal during the build left the build running

POSIX non-interactive shells start asynchronous children with SIGINT and SIGQUIT ignored, so the
wrapper could not stop the build by forwarding INT. `go build` also does not stop its compiler
children when it is signalled. During the build the wrapper now stops the whole tree. It STOPs the
build and every descendant it finds in `ps -A -o pid= -o ppid=` until no new process appears, then
sends TERM and CONT to all of them. It reaps the build and exits 128+N without launching tests. A
signal that arrives between the fork and `child=$!` uses `$!`. Signals during the test run are
forwarded as before.

The test has a fake `go` that starts a `sleep 30` descendant and signals the wrapper with HUP, INT
and TERM. For each signal it asserts:

- exit status 129, 130 or 143;
- no `build-finished` marker;
- no build-failure message and no test launch;
- neither the build nor its descendant is alive after a bounded poll.

The unfixed wrapper fails with `FAIL: HUP: a build descendant outlived the gate`. The test
leaked a `sleep 30` from the earlier terminated-corvint stand-in. That stand-in now kills its
sleeper, and the test's cleanup kills any process it recorded. Under host load averages up to
about 187, a wall-clock bound flaked, so the test checks the marker instead.

## V1-1298: an additive declaration edit selected about 197 units

Repro in a scratch clone at the base: one commit adds `internal/zzzexample` (source and test), its
`.corvint/test-read-scopes.json` key and a `.corvint/unbounded-readers.json` entry.
`corvint affected --base 595359a1… --full` selected 199 units:

| Count | Witness | Dirty path |
|---|---|---|
| 136 | `DECLARED_READ_SCOPE` | `.corvint/test-read-scopes.json` |
| 36 | rule-(d) `UNBOUNDED_READER` floor | |
| 26 | `PATH_LITERAL_READER` | the edited paths |
| 1 | `DIRECT_SOURCE_CHANGE` | |

The only reason it was wide was AFP-V0-023's rule that the declaration "itself" bears on every
declared unit. `unbounded-readers.json` is a ratchet record and is not a selection input.

AFP-V0-050 (new; the highest ID on origin/main and in open PRs was AFP-V0-049) narrows this for the
planner. When the declaration is a changed path, `compileAffectedGraph` reads the declaration at
the base (`--base`, else HEAD) from immutable Git objects (`golang.CommittedReadScopes`). Against
that, the declaration path bears only on:

- a Go package whose key was added, changed or removed;
- a declared package whose subtree or entries hold the declaration path.

An unreadable or invalid base is unknown and keeps the AFP-V0-023 rule. An invalid current
declaration still raises `go:test-read-scopes-invalid`, and every package the base declared then
counts as removed.

Out of scope:
