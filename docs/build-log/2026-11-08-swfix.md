## Decision and failure reproduction

The failing fixture is the Swift package manifest
`internal/nativelinecov/testdata/live/swift/Package.swift`. The existing fixture-only
claim rule does not admit it: Swift lists target files under the same hosted
`testdata` directory. Reusing the earlier lane's Ruby-only reproduction would
miss this case. The original selector on the exact mbapproved tree
`12b66eb3907ea8da99e51216df9584cd84304bf6` produces a FULL manifest because of
`UNINDEXED_SOURCE_PATH` for this path.

A hosted Swift package manifest is fixture build metadata even when it controls
indexed Swift targets. Classify that claim as data while keeping its claimant,
bearing frontiers, Go readers and declared Swift suite. Other source claimants,
unobserved directories, unhosted manifests and ordinary source omissions retain
their conservative behavior. This is an explicit narrow exception for the
manifest, not a new blanket interpretation of `testdata`. No wire shape, error
code, stderr text, committed golden or execution-universe rule changes.

The second regression found a soundness bug: the confined-read-data shortcut
could erase an omitted compiled source before source classification. Classify
first and admit that shortcut only for data. The existing admitted-deletion rules
remain separate. Rollback removes these two selector changes and their new
witnesses; it restores the prior FULL fixture fallback and known source-omission
limitation without any migration.
