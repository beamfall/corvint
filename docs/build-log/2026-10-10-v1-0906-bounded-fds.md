# V1-0906: bounded change-guard and audit descriptors

Owner request: bound open descriptors on the complete mutation observation and its
fallback, independently of receipt count. CAL-V0-219..221 in
`docs/specs/corvint-tasks-agent-leases-v0.md` are proposed, pending owner acceptance
(V1-0906). No decision or wire-format change is made. Idle CPU (V1-0913) is excluded.

## Implementation and bound

Darwin change observation (`internal/tasks/authority/change_guard_darwin.go`) retains
at most 16 regular-file vnode descriptors across live watches, one kqueue descriptor
per live guard, plus one descriptor per watched directory (directory count, not
receipt count). Regular files beyond the budget retain the existing stat sweep;
directories are never silently moved to stat-only coverage. Linux already uses one
inotify descriptor; other platforms remain unsupported.

The first draft also capped admission at 512 watched directories and 512 audit
parents. The owner approved removing both caps on 2026-10-11, so directory count alone
no longer refuses a store (`TestCALV0219_ChangeGuardManyDirectoriesAdmitted`); OS
descriptor exhaustion and the existing traversal bounds still refuse.

The journal side is a characterization, not a change. The draft's retirement of
duplicate read pins on a parent switch was withdrawn by the owner on 2026-10-11:
`internal/tasks/journal/source.go` is the origin/main version, which keeps accepted
CAL-V0-070 item 3, one identity-pinned root per listed parent plus one pinned read
descriptor per read parent per audit attempt, a revisited parent reusing its pin.
CAL-V0-220 records that this is bounded by directory count, not receipts. The
inventory already retains only its current parent and read pin.

The bound is independent of receipt count and proportional to directory count.
Existing process descriptors and concurrent operations are excluded. This bounds
descriptor use, not memory, scan work or inotify watch resources. Rollback restores
the half-soft-limit file budget and its descriptor exhaustion risk.
