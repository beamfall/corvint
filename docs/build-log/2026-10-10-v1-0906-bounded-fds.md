## Implementation and bound

Darwin retains at most 16 regular-file vnode descriptors across live watches,
one kqueue descriptor, plus one descriptor per watched directory (directory count,
not receipt count). Regular files beyond the budget retain the existing stat sweep;
directories are never silently moved to stat-only coverage.
Linux already uses one inotify descriptor; other platforms remain unsupported.

A journal audit retains one identity-pinned root per listed parent. Only one
additional read-parent descriptor is cached; changing parents closes that duplicate,
not the original root. Complete observation
and fallback share this reader. The inventory already retains only its current
parent and read pin, and closes them before returning.

Measured peaks at 100,000 receipts are below; the bound is independent of receipt
count and proportional to directory count. The audit and inventory run
sequentially. Existing process descriptors and concurrent operations are excluded.
This bounds descriptor use, not memory, scan work or inotify watch resources.
Rollback restores the old strategy
and its descriptor exhaustion risk.
