## V1-4232: full-record delta for moved-base and stacked entries

Mechanism: `tools/ci-reuse-plan` names, for a FULL merge-queue decision with `--base` and the new
`--commits DIR`, a `scope: "FULL"` delta from the first admitted pull-request run whose full
AFP-V0-170 record names the entry's head and shard count but another tree; the record base is the
first parent of the record's target, read only from a retained commits API response whose parents
bind that target to the head (AFP-V0-100). The docs-plan step retains those commit responses,
passes `--commits` only to a tool that lists it, and no longer stops for a stacked entry: it builds
the tool from `merge-base Q origin/main` and hands on only the delta, never REUSE (AFP-V0-101).
`mq-narrow.sh` accepts the FULL scope under every AFP-V0-813 check except the record-range plan, so
the entry reuses S \ D and runs S ∩ D (AFP-V0-102). Narrowed (AFP-V0-812) deltas, their reuse
record and every decision made without `--commits` are byte-identical
(`TestAFPV0100WithoutCommitsIsByteIdentical`, "a narrowed reuse record carries no record scope").

Fork decided: `.github/forward-rows/mq-narrow.sh` and its test in `tools/ci-forward-row` are
outside the charter's `.github/workflows/` exception, but they are the only consumer of the delta;
without them the mechanism is inert. Edited minimally (one new branch in `reuse_`) for the
orchestrator to ship with the workflow PR. `narrow.sh`/`narrow.jq` (the pinned selection paths) are
untouched, so the change does not stale the CIN-V0-010 pin.

## Independent review

A separate reviewer read the diff against BASE. It found no high- or medium-severity
soundness bug: a forged commit response fails closed, or still rebuilds the tested tree through the
AFP-V0-813 `merge-tree` check; Rs = S holds for stacked entries; a stacked entry cannot decide
REUSE; and the wait loop admits only through the unchanged two-job and one-line check. It raised two
low-severity findings, both fixed. (1) A skipped hit step could be a false hit when an earlier step
of its job failed, so a step conclusion now signals only in a passed job (test: "a skipped hit step
in a failed job is no hit"). (2) The docs-plan delta filter accepted `"scope": null`, which
mq-narrow.sh refused anyway; the filter now accepts only an absent scope or `FULL`.
