**Finding (acceptance 2).** Only one of the 67 unknowns adds Go packages: the unowned
`.corvint/test-selection.json`, which `NCM-V1-006` also runs everything for. Every frontier adds
only a non-Go suite or is allowlisted. The Go package count therefore does not come from the
unknowns. It comes from four full-run causes, peeled one at a time on throwaway probe commits of
the head (each commit restores paths to their base content):

1. `corvint-config .corvint/shell-foreign-callers.json` (`NCM-V1-006`).
2. `corvint-config .corvint/test-selection.json` (`NCM-V1-006`).
3. `never-narrowed-path Makefile: make edit: variable "DOC_GATE_TARGETS" changed in a make file
   that names a variable by a computed reference` (`NCM-V1-012`). This is a false positive, fixed
   below.
4. After that fix: `make target "doc-gates" runs a command or make goal that does not resolve:
   make:makeflags-assignment:MAKEOVERRIDES, shell:unfollowed-command:command, ...:env, ...:go run,
   ...:script/doc-gates-summary.sh, ...:script/heavy.sh, ...:stat` (`NCM-V1-013`, fail-closed
   by design).

With all three paths restored, the plan narrows to 290 Go packages. The witnesses are:

The same rule dominates the selection-baseline corpus. Five of its six slowest changes run
everything through `NCM-V1-006`: `pr-41`, `ci-cbc790640` and `ci-0df97c8c7` through
`.corvint/documentation-paths.json`, and `pr-43` and `ci-8db625151` through
`.corvint/cem-lineage.tsv`.

**Fix: make's escaped dollar is no computed reference (`NCM-V1-012`).** `computedReference` read
`$$(` as a reference whose name holds `$`, so the shell arithmetic `$$(( $$(date +%s) - t0 ))` in
the head's `closeout_step` made every changed variable run everything. GNU make reads `$$` as a
literal dollar, and the requirement text names only references whose variable name is expanded,
so the scanner now skips both bytes of an escaped dollar. A real computed reference after one
(`$$$($(NAME))`) still runs everything. Test: `TestAttributeMakeEditEscapedDollarIsNotComputed_NCMV1012`,
which fails without the fix. The fix changes the outcome of `AttributeMakeEdit` for 2 of the 29
make-file edits in the 58-change corpus (`pr-43`, `ci-8db625151`: refused before, attributed to 14
targets now). Both still run everything through `NCM-V1-006`, and both replayed with identical
results.

**Not met (acceptance 3).** The range still runs everything (464 packages), and narrowing it
needs owner decisions: (a) whether `NCM-V1-006` may let specific `.corvint/` files narrow to their
known readers, as the 2026-11-13 amendment did for the read-scope declaration. Candidates are
`shell-foreign-callers.json` (read by the shell plugin and `tools/declaration-compat-check`),
`test-selection.json`, `documentation-paths.json` and `cem-lineage.tsv`. (b) Whether `NCM-V1-013`
may follow the commands the `doc-gates` recipe runs. The "no missed failing test" half is NOT_RUN,
because no narrowing of the range was produced.

## V1-5162: doc-gates replay cost

On base, the job limit is already 45 minutes (`7a1022340`). A routine pull request already defers
the replay (`CIN-V0-4753`). The doubled replay is gone (`AFP-V0-9498`). The source-slicing plans
are bounded (`TSP-V0-006` as amended). The cause of the 1684 s run is recorded in
`2026-11-08-selection-baseline-scope-trigger.md` (`ASC-V0-9852`: a cold result cache on a fresh
runner, plus the concurrent `selection-contract-check` replay) and in
`2026-11-11-selection-baseline-profile.md` (per-change planner CPU, mostly the uncached
whole-tree Go observation).

**New evidence.** An instrumented `corvint test --dry-run` of the batch probe observed the same
464-directory Go tree three times in one process: 6.9 s for the plan graph (cold graph cache),
then 4.0 s and 4.0 s through `affected.BuildPartial`, both inside one
`gateselect.SelectQualifiedIndexed`: the record-addition admission (`AFP-V0-3423`) and the
qualifying proof (`AFP-V0-9500`). 54 of the corpus's 58 changes add a sealed CEM or a build-log
entry, the input that starts the admission's observation.

**Change (`AFP-V0-11134`).** The two share one partial observation held on the repository index.
Only a successful build is kept, and a different root or a selection with no index builds fresh.
`Graph`'s `With` methods are already copy-on-write, and `finish()` fills its token tables at
build time, so neither caller can change the other's inputs. Tests:
`TestPartialGraphObservedOncePerIndex_AFPV011134`, and a build count in
`TestAddedRecordEntryBothSelectors_AFPV3423` (2 builds without the share, 1 with it).
