# V1-1580: read-only `corvint-tasks plan batches` (issue 1023)

Added the read-only Tasks verb `plan batches` and requirements NTP-V0-020..025 in
`docs/specs/native-taskman-planning-v0.md`. The owner's standing auto-accept of lane requirements
(2026-10-11) covers these IDs.

Owning spec: the brief named NTP-V0 as the owner when it fits. CAL-V0 owns `plan preview` (CAL-V0-014),
but it already enumerates 250 requirements, and open PRs #1015, #1016, #1018 and #1020 reserve
CAL-V0-320..349. Adding requirements there would push it past the 256 OCM cap. NTP-V0 enumerated 8
requirements, so it now has 14. The new subsection records that the verb sits beside `plan preview`
and is not part of the fixture planner.

Design:

- Candidates come from the lock-free TM-V0-008 store read and are taken in plan order. Each is the
  highest-generation BUILT/CHECKING/REVIEWING/READY_FOR_INTEGRATION attempt of an OPEN or HELD
  ticket.
- Git observation runs after the read.
- Grouping is first-fit:
  - A candidate's changed paths may not overlap any group member's, except declared shared paths.
    Overlap means an equal path or a directory prefix.
  - A dry `git merge-tree --write-tree` of the candidate onto the group's merged tree, over the
    candidate's base, must be clean.
  - A conflict is reported in `splits`, and the candidate moves on to a later or new group.
- A candidate that conflicts with the intent tip is STALE_TREE. A candidate that cannot be resolved
  is MISSING_EVIDENCE. Both stay ungrouped.
- Every Git run uses a throw-away `GIT_OBJECT_DIRECTORY`, with the repository's objects as an
  alternate, and the directory is removed afterwards.

Finding: Git freshens, meaning it updates the mtime of, an existing loose object or pack in the
alternate when a merge recreates an identical object. The first test, which compared the whole
`.git` directory, caught this. Object content, object count, refs and every non-object byte and
timestamp stay unchanged. NTP-V0-022 records the mtime refresh as a known limit, and the test
ignores only object-file mtimes.

Evidence: `TestNTPV0020`..`TestNTPV0025` in `internal/tasks/cli/plan_batches*_test.go`.

Rollback: remove the verb, its help entry and these requirements. No store migration is needed.

Review repair (independent Codex review of fc0afbe8d, one round, six findings, all fixed with a
test that fails without the fix):

1. P1: repository config could run a merge driver during the read. Fixed: Git now reads refs only
   from the repository's Git directory. Every object read, diff and merge runs in a throw-away bare
   view whose only link to the repository is an object alternate.
   Test: `TestNTPV0025_RepositoryMergeDriverDoesNotRun`.
2. P2: SIGINT or SIGTERM skipped the cleanup. Fixed: a signal-scoped context kills the Git run, and
   the view is removed before the read refuses. Test: `TestNTPV0022_InterruptRemovesTemporaryDirectory`.
3. P2: the deadline did not kill descendants. Fixed: each run gets its own process group, which the
   deadline kills, and `WaitDelay` bounds the wait for inherited pipes.
   Test: `TestNTPV0022_GitDeadlineKillsProcessGroup`.
4. P2: shared-path collision was asymmetric. Fixed: an overlap is exempt only when both paths are
   shared. Test: `TestNTPV0021_SharedPathCollisionIsSymmetric`.
5. P2: a candidate joining a group skipped the tip check. Fixed: every candidate is merged onto the
   tip first. Test: `TestNTPV0022_JoiningCandidateIsCheckedAgainstTip`.
6. P2: any `diff-tree` failure became MISSING_EVIDENCE. Fixed: only a missing tree object found by
   `rev-list --missing=print` does; any other failure refuses. Tests:
   `TestNTPV0024_FatalDiffFailureRefuses` and `TestNTPV0024_MissingNestedTreeIsUngrouped`.
