# Lane mk1114: the make edit reach fails closed on an assignment to the make flag variables

Date: 2026-11-13. Branch `claude/mk1114`, on top of the V1-5551/V1-5552 delivery
(`docs/build-log/2026-11-13-mk1114.md`). Ticket V1-5561, a defect already on origin/main, found by
the final review of that delivery. Requirement amended: NCM-V1-019 in
`docs/specs/non-code-map-v1.md`; no new ID.

## Reproduction

GNU make 4.4.1, `PKG ?= ./other`, `MAKEFLAGS += PKG=./tool`, `top: ; $(MAKE) check` and
`check: ; go test $(PKG)`: make runs `go test ./tool`. The reach of `top` was bounded to `other`
(reason empty), and Select and SelectStructural printed `run <module>/mkread <module>/other`. The
expander reads `$(MAKEFLAGS)` as empty and nothing looked at a file that assigns it. Make gave
`./tool` for every one of these forms too:

- `MAKEFLAGS =`, `:=`, `override MAKEFLAGS +=` and `define MAKEFLAGS`;
- a target-specific assignment (`top: MAKEFLAGS += ...`) and a pattern-specific one (`%: ...`);
- an assignment on another target (`gate: MAKEFLAGS += ...` with `gate: top`, when `gate` runs);
- a plain `PKG = ./other`, which the override beats;
- `MAKEOVERRIDES =` and global `MAKEOVERRIDES +=`;
- a computed name (`N = MAKEFLAGS` and `$(N) += ...`);
- an included file;
- a non-recursive `top: check`, because make 4.4 applies an assignment placed in MAKEFLAGS to its
  own run.

A target-specific `MAKEOVERRIDES +=` gave `./other` alone, but `./tool` as soon as the outer make
had any command-line variable (`make top X=1`), which the reach cannot know. `MAKEFLAGS ?=`,
`MFLAGS +=` and `GNUMAKEFLAGS +=` reached nothing in the probe. They are marked anyway: the ticket
names them, and the probe does not cover the environment of every caller.

## What changed

- The make parser records each assignment to `MAKEFLAGS`, `MFLAGS`, `GNUMAKEFLAGS` or
  `MAKEOVERRIDES`, in every form above, or `computed-name` for an assignment whose name contains a
  reference. This covers global, `define`, and target- or pattern-specific lines, including those
  on special or computed targets.
- The driver opens every target's run set of such a file with `make:makeflags-assignment:<name>`.
  The selector therefore runs everything. As with the recipe shell, the mark lives only in the
  reach; the planner's units and computed sites are unchanged.
- An included file needed no change: every include already opens every target with `make:include`.
  The new rows pin that.

## Effect on the repository's own Makefile

`gate: override MAKEOVERRIDES += CORVINT_REQUIRE_NODE=1` (Makefile line 139) is such an
assignment, and a real channel: it passes `CORVINT_REQUIRE_NODE=1` to every sub-make of `gate`'s
steps. Each probed target (gate-affected, focused-docs, doc-gates, go-vet, windows-vet,
changed-checks, gate, build, spec-requirements) gains exactly one reason,
`make:makeflags-assignment:MAKEOVERRIDES`. With that one reason removed, the reasons, paths,
workflows and selectors are byte-identical to before. Every one of those targets was already
unresolved, so no selection changes.

## Evidence

- `TestReachMakeFlagsAssignment_NCMV1019` (`internal/liveverify/affected`): before the fix, all 20
  assignment rows failed (reason empty, paths `[other]`) and both include rows passed with
  `make:include`. After the fix all 22 pass, and the MAKEFLAGS-reference control stays bounded to
  `other`.
- `TestNCMV1019SelectorMakeFlagsAssignment` (`internal/gateselect`): before the fix, 8 of the 9
  rows failed with `run <module>/mkread <module>/other`; only the include row passed. After the
  fix all pass from Select, SelectStructural and SelectQualified, and the reference control still
  narrows to `mkread other`.
