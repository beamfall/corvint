# Interrupted progress accounting, durable carry-over invalidation and wrapped secrets (V1-0769, V1-1793, V1-1792)

Date: 2026-10-20 (lane dispatch-supervisor). Requirements: ATR-V0-167..169 in
`docs/specs/corvint-tasks-attempt-runner-v0.md`, accepted under the owner's standing auto-accept
(2026-10-11).

## Decisions

- V1-0769 is a confirmed defect. `admitProgress` saved the ledger without the granted worker before
  `finish` reset the CAL-V0-057 ladder and settled the infrastructure episode, and those changes were
  saved only by the tick-end save. The fix applies the same accounting to the staged ledger in the
  progress save. `account` and `infraEnded` now wrap ledger-parameterised forms, so `finish` repeats
  them with no further change. No new ledger field.
- V1-1793: the carry-over entry records the work fingerprint (`Fingerprint(obs, key)`, the same value
  `finish` compares for progress). Offer and append both filter on it, so a removal that failed before
  a restart cannot surface stale entries. The in-memory `carryStale` mark is kept as the same-process
  fast path. An entry without the member is never offered; the field is optional, so the profile stays
  `taskman-dispatch-carry-over/0`.
- V1-1792: dispatch cannot import `internal/secretscreen` (decision 0397 boundary), so the span API
  goes through the existing `obligation` edge (`SecretScreenSpans`), backed by a new
  `secretscreen.MatchIndexes` over the unexported writer matcher. A first draft joined every line;
  it redacted the lines around a `password=` assignment, because the field prefix and the value
  absorb neighbouring text. The delivered screen joins only runs of lines that do not match alone
  (for wrapped tokens) and screens the whole text with its line breaks (for PEM and PGP blocks). Only
  matches that span more than one line add redactions.

## ATR-V0-161 follow-up (V1-0951)

The full package run after this change found three tests that the earlier ATR-V0-161 commit broke:
`TestATRV0086_MalformedOrAmbiguousOverridesRefuse` and `TestCALV0177_FragmentRefusals` expected the
member decoders' own refusal text, and `TestCALV0176_ConfigWithoutFragmentsUnchanged` asserted the old
last-value-wins behaviour that V1-0951 removes. The repeat check now runs after the strict decode, so
those decoders keep their specific errors, and the CAL-V0-176 test now expects the refusal. The
ATR-V0-161 text states the order. The full `internal/tasks/dispatch` package passes on Darwin.
