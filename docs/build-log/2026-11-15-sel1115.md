## V1-5367: a unit dropped by change-status narrowing leaves no record

Premise held at the base: AFP-V0-9960 to AFP-V0-9963 are wired (`planAffectedGraph` passes
`WithChangeStatus` with `--base`), and the plan said nothing about a unit they dropped.

Decision: the record is defined by a counterfactual, not by instrumenting the two narrowing
sites. `plan.changeStatusNarrowed` lists each unit that the same plan with every status read as
`unknown` selects and this plan does not. That definition is exact whatever later step
(traversal, test users, declared consumers) a narrowed read feeds, and it cannot drift from the
selection, because the selection code is not touched. The gate is read from the unit
(`AFP-V0-9963` for a name-only walker, `AFP-V0-9962` for a name-listing read), then from the
first such unit on its unknown-status witness chain (`via`), and `AFP-V0-9960` when neither
explains it. Paths are the dirty paths a listing token names and no content token names for
AFP-V0-9962, every dirty path otherwise, at most 16 with `pathCount`.

Cost: the second plan runs only when a dirty path is `modified` and some unit holds a
name-listing read or a name-only walk. No unit of this repository does (the affstatus and
affgate counts: 0 of 250 shell units), so its own plans are planned once and are byte-identical
to the base's; the member is omitted when empty.

Wire: an optional member of `affected-plan/0` and `affected-plan/1` under CCF-V1-006, so no
profile change; `--format text` prints `status-narrowed UNIT gate GATE [via UNIT] paths N
PATH:STATUS...`. Acceptance item 3 asks for a fingerprint or schema change "if the wire shape
changes": the freeze contract classes an added optional member as compatible, the plan has no
fingerprint of its own, and `sessiontest.Digest` over the compact plan changes with the content
whenever the member is present. No core-freeze golden changes, since no golden plan narrows.

Known limit: a dropped unit still appears in `plan.excluded` with the reason
`NO_DEPENDENCY_PATH_TO_DIRTY_UNIT`. Changing that reason value is a change to a registered
enumeration (CCF-V1-007), so it is left for the owner; the new member is the record.

Tests: `TestChangeStatusNarrowedRecord_AFPV011054` (`internal/liveverify/affected`): an edit of
`script/a.sh` and `docs/x.md` records the lister under AFP-V0-9962 with `script/a.sh:modified`
and the walker under AFP-V0-9963 with both paths, selects neither, and keeps `ls -l` selected;
20 edits bound the path list at 16 with `pathCount` 20; an addition, a type change, an unknown
status, no status and an edit beside an addition record nothing; in every row selected plus
recorded equals the unknown-status selection. `TestAffectedChangeStatusCLI_AFPV09960` reads the
record from the compact JSON and the text form, and none without `--base`.

Mutation: dropping the assignment in `selectPlan` fails the library test; dropping the compact
projection member fails the CLI test (JSON and text).
