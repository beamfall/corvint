# Source-change test slices for `corvint test` — V1-2806 (TSP-V0-006)

## Question

V1-2806 asks `corvint test` to give a Go package selected for a changed source file a per-test `-run`
set when the changed symbols bound the reached tests, with a reason when the package stays whole, and
to show that the sliced set still catches what the whole package catches.

## Decision

TSP-V0-006 (experimental, `docs/specs/test-selection-precision-v0.md`) slices a package selected only
by `DIRECT_SOURCE_CHANGE` when every changed file differs from base only inside receiver-less
functions other than `init`. The changed names are those functions. A test function is kept when its
lexical closure over top-level declarations holds a changed name; external-package tests are always
kept. A package stays whole, with the reason printed, when any proof is missing: its own test file
changed too, another dirty path selects it, a non-Go or `go:linkname` or cgo file is present, a file
is new or removed, a change sits outside plain functions, a changed function is used other than by a
call, initialization reaches it, or it reaches a package variable. The source blobs at base are read
in the same two Git processes STR-V0-072 already bounds.

The skipped tests are assumed independent of the kept ones except through package variables, as in
STR-V0-063; that is the one modelled assumption, and it is named in the spec's failure modes.

## Evidence

Mutation check (binary from this tree, 36 `panic("tsp-mutant")` mutants, one per function, in 12
small `internal/` packages; each mutant run once with the slice and once whole):

| Outcome | Mutants |
|---|---|
| Sliced, mutant fails whole and fails sliced | 15 |
| Sliced to `^$` (no test reaches it), passes whole and passes sliced | 2 |
| Sliced, fails whole but passes sliced (under-selection) | 0 |
| Whole: every test reaches the change | 7 |
| Whole: reaches a package variable | 10 |
| Whole: initialization reaches it | 1 |
| Whole: used other than by a call | 1 |

Replay of the last 29 first-parent commits of `origin/main` with a parent (`test --dry-run --base
PARENT` on each commit's tree): 5242 Go execution units, of which 59 packages were selected by
`DIRECT_SOURCE_CHANGE`. 2 of the 59 now slice (3.4%). The 57 that stay whole: own test file changed
too 44, changes more than plain functions 5, also selected by `DEPENDENCY_PATH` 5, by
`UNBOUNDED_READER` 2, by `PATH_LITERAL_READER` 1.

heavy.sh whole-run share: the Mac selection log `/tmp/corvint-heavy-501/selection.log` showed 113
whole of 757 selected runs (13%) before this change. The share after is `NOT_OBSERVED`: no lane has
run heavy.sh with a binary carrying TSP-V0-006 yet. The replay predicts a small effect, because real
commits usually change a package's source and its tests together.

Tests: `TestTSPV0006DryRunSlicesSourceChanges`, `TestTSPV0006PlainFunctionsAndQualifiers`, and the
existing STR-V0-018/063/072/073 tests (`TestSTRV0072SliceWalksDoNotGrowWithPackages` holds at two
Git processes with a source change present).

## Residual lever

Combining STR-V0-063 test-file slicing with TSP-V0-006 for packages whose source and test files both
changed would address 44 of the 57 whole packages; it is recorded as open question 3 in the spec and
needs its own design for the union of the two proofs.

## Rollback

In `testGoSlices`, stop collecting `sources`; every `DIRECT_SOURCE_CHANGE` package then runs whole
with its original reason. No stored state depends on it.
