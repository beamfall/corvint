# V1-5694 installed receipt validation and provider selection

RMV-V1-009 keeps the installed core and editor comparisons. Each poll now reads the
same descriptor it inspects for file type and size. The core launcher regression places
a writerless FIFO in a retained receipt slot before a provider starts. The editor
digest-wait regression places a file one byte over the limit in that slot.

The decoder accepts the unprofiled Vitest unit and provider-owned Playwright E2E
forms that these fixtures produce, plus terminal Go session events under profile /0.
It checks typed members of build identities, test observations, anchors, artifacts,
and Playwright attempt details before comparing the five native axes. A profile or
member outside those forms fails qualification. The regression covers both a string
duration and an unfamiliar member inside a Playwright attempt.

Under AFP-V0-762 and AZU-V0-007 each installed driver declares its Make invocation
against both provider commands. The existing build graph supplies transitive imports.
The repository regression plans each provider main and an imported source file for each
provider in isolation. In separate CLI replays, a Go main edit and a JS dependency edit
each selected the two runnable consumers. Both plans retained language-frontier unknowns.

Reverting the change restores the earlier polling paths, decoder, consumer declarations
and editor guidance. The installed release and editor host still need their own qualification.
