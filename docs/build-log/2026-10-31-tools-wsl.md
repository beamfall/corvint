  is an in-process `corvint-tasks` mutation that re-reads and decodes every ticket of the store
  (`transaction.loadTickets` -> `ticket.Decode`/`wire.Parse`, 30% of CPU), audits the journal
  (`journal.Reader.AuditForWriter`, 13%) and reloads the intent tree (`intent.LoadExpecting`, 11%),
  with 17% in file-read syscalls, so each write is O(n) and gen is O(n^2): 500 tickets took 187 s and
  the next 500 about 380 s (CPU profile of a 600-ticket run, 266 s). A linear gen needs an
  incremental or memoised store load in `internal/tasks/transaction` and `internal/tasks/store`,
  owned by the in-flight tasks lanes; a harness-side shortcut would stop exercising the product
  writers, which is what the harness measures.

## Friction

1. `corvint affected --path P` on a single prose path takes 10-40 s and reports the
   same UNBOUNDED_READER units for every path, so finding "no specific test reader" for 16 candidate
   docs needed one call per path and manual set subtraction. Repro: `corvint affected --path
   docs/GLOSSARY.md --format text | grep -v UNBOUNDED_READER` vs the same for
   `docs/agent-memory/fixes.md`.
2. `corvint affected` printed `DEGRADED self-binary-stale` on every call after the first commit
   (the installed binary is build 34); the lane cannot rebuild the shared install. Repro: any lane
   commit touching Go, then `corvint affected --path X`.
3. `heavy.sh` refuses a whole-package run of a small `tools/` package over 48 KiB of tests
   without `HEAVY_WHOLE_REASON`, although `corvint affected` selection for such packages is the
   whole package anyway. Repro: `~/lanes/heavy.sh go test ./tools/cem-trial`.
4. `make spec-requirements` refuses an amended Intent status header longer than its frozen length,
   but the error is only found after staging; adding a requirement range there is the natural first
   edit. Repro: append "CAP-V0-960 to 962 accepted ..." to the capability-catalog Intent status.
5. `tools/capabilities-check` had no way to say which subcommands a row lists; rows mixed
   subcommands, flags and examples in backticks. CAP-V0-961 now relies on a "Subcommands" sentence
   convention that is prose, not structure.
6. `tasks-scale gen` cannot reach 10,000 tickets in a 600 s foreground limit (1,000 tickets took
   9.5 min), so scale tests at the frozen queue limit are not runnable by a lane at all.
7. The V1-2861 measurement needs tiers.jq over historical merges with each target's own `go list`,
   which needs a checkout per merge; there is no replay tool, so this lane approximated with the
   current package graph.
