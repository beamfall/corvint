# 2026-11-11: affected output ergonomics, `--head` replay, EILSEQ skip and CI base identity (lane affux)

Tickets V1-4399, V1-4799 and V1-5211. Requirements AFP-V0-9987 to AFP-V0-9989 in
`docs/specs/affected-plan-selection-v0.md`. Branch base `b55635262788687c3eea9a08a94378e4ab8856a4`.

## What changed

- **AFP-V0-9987 (V1-4399 a).** The default `affected-plan/1` document carries `selectedFlat`, one
  `{unitId, test, witness, dirtyPath, reason}` per selection in plan order, and
  `summary.unresolvedPackages`, the selected `go:` units whose witness is `UNBOUNDED_READER`. Both
  are derived after selection. The two core-freeze goldens `affected-committed-range.json` and
  `affected-worktree.json` gain only these two members (regenerated with
  `CORVINT_UPDATE_GOLDEN=1`; the diff is two additions each). `TestAFPV0510AffectedSummaryRestatesThePlan`
  now expects the new summary member, computed from the plan. The `corvint review` document embeds
  the same compact projection, so it carries both members too.
- **AFP-V0-9988 (V1-4399 b, c).** The witness wire is unchanged. TSP-V0-7311 already used one
  decoder; the new test decodes the compact, `--full` and `--by-path` witnesses into one type that
  rejects unknown members and checks that the members agree across forms. `--json` is accepted as
  `--format json`. Its output is byte-identical to the same call without it, and it is refused
  with `--format text`.
- **AFP-V0-9989 (V1-4399 d).** `--base BASE --head COMMIT` plans a clean checkout of COMMIT. The
  checkout is a local `git clone --no-checkout` of the repository's objects into private
  temporary scratch, checked out detached, with the hermetic Git configuration and hooks off. The
  scratch is removed before exit. These are refused before anything is cloned: every option whose
  input is a file, the worktree or a local record, and a tree holding a gitlink or symlink.
- **V1-4799.** `requireRawFilenames` already skipped on EILSEQ (5c9e5502c). The decision is now
  `rawFilenameSkipReason`. It skips only on `errors.Is(err, syscall.EILSEQ)`, names EILSEQ and the
  error, and leaves every other error failing. A unit test feeds it a fake EILSEQ `PathError`, an
  EACCES `PathError`, a lookalike text error and nil. No AZU-V0 text changed.

## Decisions made in the lane

- **ID block.** The assigned block was AFP-V0-9980..9989. The unmerged local branch
  `claude/guardsel` (967b71afb) already defines AFP-V0-9980..9986 (V1-5364, V1-5365, V1-5337 and
  V1-5351), and `make requirement-ids-free PREFIX=AFP-V0 RANGE=9980..9989` reports the block as
  partly taken. The delta was therefore consolidated into the free AFP-V0-9987..9989.
- **`--shared` was rejected.** The first `--head` build used `git clone --shared`. It selected
  529 units where a plain scratch clone selected 447. A strict superset is safe, but it does not
  match `--base`. The cause is the alternates denial of the Git readers (CEM-V1-323,
  `internal/cem/gitauth`): it refuses a borrowed object store, and the plan widens as designed. A
  local clone copies the objects instead: 178 MB in 0.27 s on this host, removed with the
  scratch.
- **`--head` wire.** It follows `tools/selection-baseline`, which already replays history by
  cloning and checking out a head. `--head` gives the same receipt without a scratch clone the
  operator has to manage. The AFP-V0-9730 stale-binary judgement applies to COMMIT.
- **Repins.** The use-case receipt UC-CHANGE-CONSEQUENCE pins `cmd/corvint/affected.go`, so it
  was repinned by `make repin`. Its record-entry source binding in
  `.corvint/record-entry-read-scopes.json` was repinned too. The unit's reads did not change: the
  receipt only gained a new `repositoryRevision` and one subject digest. A script that reproduces
  `RecordEntrySourceDigest` matched the committed binding at HEAD before it computed the new one.

## V1-5211: REFUTED (no consumer narrows on a stale event base)

The event `base.sha` does often differ from the tested merge's first parent. Over the last 60
first-parent merges of `origin/main` (`git log --merges --first-parent origin/main -n 60`), 39
merged a branch based behind its first parent. Using that older base as the diff base selected
13,745 paths where the true first-parent diff has 5,915. It dropped 0 paths. The diff from an
older main commit is a superset unless main changed a path and changed it back between the two
commits, and even then the content equals that green main base.

The consumers were read statically. None diffs from an unproven base in a way that can narrow:

- `effectivePRBase` in `tools/corvint-pr-tests/main.go` (AFP-V0-800) requires a two-parent merge
  whose second parent is the event head and whose first parent the event base is an ancestor of.
  It then plans against the first parent. Any failure goes FULL with a `pr-base-*` reason.
  `.github/forward-rows/pr-base.sh` and `narrow.sh` repeat the proof in shell.
- Cadence and `tools/docs-ci-plan` require the exact `target base head` topology, otherwise
  `merge-topology-mismatch` (FULL).
- `mq-narrow.sh` requires the queue base to be an ancestor of the tested merge, otherwise FULL.
- The `shell-test-selected` job uses `git merge-base HEAD BASE_SHA`. For a stale base that is the
  base itself, so it only over-selects.

No Go change is needed and no regression test was added. Hosted `pull_request.base.sha` values
were not compared: this host has no `gh` auth, so they are `NOT_OBSERVED`. One optional `.github`
edit would cut the over-selection in `shell-test-selected` only. It belongs in a separate PR and
was not made here:

```diff
-          base=$(git merge-base HEAD "$BASE_SHA")
+          if [ "$GITHUB_EVENT_NAME" = pull_request ] && p0=$(git rev-parse --verify -q HEAD^1) &&
+            git merge-base --is-ancestor "$BASE_SHA" "$p0"; then base=$p0
+          else base=$(git merge-base HEAD "$BASE_SHA"); fi
```
