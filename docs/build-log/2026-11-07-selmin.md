## V1-5026: a line-less runtime site reaches its declared edge (AFP-V0-9009)

`inboundRuntimeSite` cut the site after `typescript:e2e-runtime-dependency:` at the first `:`. The
TypeScript plugin names a site `path`, `path:LINE`, ``path `token` `` or ``path:LINE `token` ``
(`siteWithToken`). A line-less site therefore kept `` `playwright` `` in its "file", found no owner
and never reached the directory runtime edges that `.corvint/runtime-edges.json` declares for the
live-1.61.1 trees. `inboundRuntimeSiteFile` drops the trailing backquoted token (at the last
space-backquote), then a trailing all-digit line. A malformed token, a truncated `+N` entry and
an unowned file still name no caller, so the entry stays unknown. The self-review found that a
test whose real name ends in a backquoted word or in `:digits` could be stripped onto another
declared test. So the whole site text wins when it is itself a test, and a site whose two
readings are both tests stays unknown (`TestInboundRuntimeSiteAmbiguity_AFP_V0_9009`).

Repro, `corvint affected --path extensions/vscode/src/extension.ts` on this tree, with a binary
built from the base and one built from the lane head:

| | selected units | unknowns |
|---|---:|---:|
| before | 264 | 67 |
| after | 267 | 64 |

The fix adds exactly three selections and closes their three `e2e-runtime-dependency` unknowns:

- `typescript:playwright:internal/doccorpus/testdata/behavior-events/live-1.61.1/tests/items.spec.cjs`
- `typescript:playwright:internal/jstestprovider/testdata/route-stubs/live-1.61.1-residuals/tests/residuals.spec.cjs`
- `typescript:playwright:internal/jstestprovider/testdata/route-stubs/live-1.61.1/tests/stubs.spec.cjs`

## V1-5029: a test file that keeps its package's test import sets selects no proven reader (AFP-V0-9010)

AFP-V0-2202's package header held one line per `.go` file, test files included, keyed by name. So a
new or edited test file with no new import changed its package's "import set". Every import-graph
reader of that package's importer closure, and every whole-module reader, was then selected.
Those readers are `cmd/corvint`, `cmd/corvint-test`, `internal/swiftimpact`,
`tools/test-read-scopes-check`, `internal/liveverify/affected`, `internal/liveverify/affected/golang`
and seven named-closure readers.

A scan of the repository found that `cmd/corvint` (`core_network_boundary_test.go`, a `{{.}}`
inside `range`), `cmd/corvint-test` (`howaccept_test.go`), `tools/test-read-scopes-check` and both
`affected` packages read the whole module through unproven calls. The narrowing sits in the
header, and (after the review below) applies only to proven readers. When a
directory's non-test files share one clause N, every *unconstrained* test file (no build line, no
GOOS/GOARCH name as `go/build.Context.MatchFile` decides it, no `import "C"`) declaring N or
`N_test` folds into one summary line. That line holds the import set of the N test files, the
import set of the `N_test` files, and their embed lines. The sets are kept per role because
`go list` exposes `TestImports` and `XTestImports` separately, and an external test package's edge
to an import is a new edge even when the package itself imports it. Anything else keeps its own
line: a constrained test file, a foreign clause, or a test-only directory.

### Review fix: the fold narrows only proven readers

The first version wrote a trust boundary into AFP-V0-9010: unproven readers were modelled as
listing only the import graph, and a reader of test file *names* (`TestGoFiles`, `-json`) was
declared outside the model. The independent review (P1) showed that this loses a real reader.
`lib/a_test.go` imports `testing`; another package's test checks the output of `go list -f
'{{.TestGoFiles}}' example.test/g/lib`. Adding `lib/b_test.go`, which imports only `testing`,
kept the folded header, so `ImportSetRecords` reported no change and `importGraphReadersOf`
returned before it reached the reader. The directory literal could not rescue it either, because
foreign test files are excluded unless their file names are named. The finding was confirmed
against the code, and the fixture's own `-json` reader `wide` showed the same gap: the old
regression asserted that it was *not* selected.

The fix splits the readers. The Go plugin now marks any unit with a `go list` call that is not
proven (and any unit that names `GOFLAGS` or `GOENV`) as `Unit.ImportGraphReadsFiles`. The
comparison keeps both headers: the folded one and the unfolded one, with one line per file. A
directory whose folded header is kept but whose unfolded header differs records its unit in
`ImportSetChanges.Files`. Only `ImportGraphReadsFiles` readers are selected through it, with the
chain changed unit, reader. A body edit of an existing test file changes neither header and selects
no reader. No new requirement ID was needed; AFP-V0-9010 now states the split, not the
exclusion. The new regression is `TestFoldedTestFilesKeepUnprovenReaders_AFP_V0_9010` (a
duplicate-import file added, and a test file renamed). Mutation run: disabling the
`ImportGraphReadsFiles` case in `importGraphReadersOf` fails it and the updated
`TestTestFileImportEdges_AFP_V0_9010` (`names not selected through lib's file set`; `wide` not
selected).

Measured on the base tree, from a scratch worktree with one commit that adds
`internal/gitstatus/selmin_measure_test.go` (`package gitstatus`, imports only `testing`, which the
package's tests already import), then `corvint affected --base <base>`:

| binary | selected | `IMPORT_GRAPH_READER` witnesses | unknowns |
|---|---:|---:|---:|
| base | 290 | 13 | 67 |
| head, first version (unsound) | 292 | 0 | 64 |
| head, after the review fix | 292 | 5 | 64 |

The five readers are exactly the unproven ones: `cmd/corvint`, `cmd/corvint-test`,
`tools/test-read-scopes-check`, `internal/liveverify/affected` and
`internal/liveverify/affected/golang`. The seven named-closure readers and `internal/swiftimpact`
are proven readers, so a kept-set test file no longer selects them through the import graph. Of
them, only `internal/swiftimpact` leaves the plan; the others stay through other edges. The +3 are
the V1-5026 selections above. For a new test file, the unproven readers keep the selection they had
on the base, so the benefit for `cmd/corvint` and `cmd/corvint-test` needs their `go list` calls
proven and their unbounded and declared read scopes narrowed. Both are outside this change.
Fault injection on the same tree: the same file importing `hash/crc32` (new to the package's tests)
brings back all 13 `IMPORT_GRAPH_READER` witnesses (293 selected, `internal/swiftimpact` again by
`IMPORT_GRAPH_READER`).

### Review fix 2: an unproven reader runs on any Go source change

The independent re-review (P1) found the same class one level down. A test that builds its target
path at run time and checks `go list -f '{{.Doc}}' target` is an unproven reader. An edit of the
target's package comment changes no header, so `Changed` and `Files` were empty and the reader was
skipped. The computed target names no edge, and the test need not import the target. This gap
predates the lane: the base selects no reader on a comment edit either. It was confirmed against
the code.

Orchestrator decision (2026-11-07, under the owner delegation of 2026-11-02): close the class. A
package may be narrowed by headers only if it provably cannot observe package metadata or source
text. Unknown or unprovable means run. Two changes implement it:

- Classification (`golang/sourcereaders.go`, called from `goListUnits`): a reader stays proven only
  if every `go list` call is proven and no file of its package can observe metadata or source text
  by another channel. Unknown counts as observing. The channels are:
  - another `os/exec` command (`go build`, `git`, a computed command);
  - an import of `go/build`, `go/parser` or another go/ parser, `runtime/debug`, `debug/buildinfo`
    or another executable reader, `embed`, `plugin` or `syscall`;
  - any import outside the standard library (a helper whose code is not inspected);
  - a `//go:embed` line;
  - a file read, walk, stat or file server, except a literal path below the package's own
    `testdata`;
  - a dot or shadowed import of a file-reading package;
  - a file that does not parse.

  Any of these marks the unit `ImportGraphReadsFiles` and makes it a whole-module reader.
- Selection: `ImportSetChanges.Files`, the round-1 file-set signal, is replaced by `Source`, the
  least dirty `.go` path whatever its header. Every `ImportGraphReadsFiles` reader is selected
  through it. `Files` only ever held a subset of these changes, so the unfolded header is gone too.
  With no comparison (nil), `Source` is computed the same way.

Regressions:
- `TestPackageDocReaderSelected_AFP_V0_9010`: the review's exact case, a computed target with
  `{{.Doc}}` and a comment-only edit, selects `docs` with chain `lib`, `docs`, and not `guard`.
  Dropping `Source` loses it.
- `TestUnknownReaderFallsBackToRun_AFP_V0_9010`: 16 channels each turn a proven reader into an
  unproven one that a body-only edit selects. An own-testdata read and an environment read stay
  proven and unselected.
- The fixture's `mixed` package (`go list` plus `go build`) is now a whole-module reader.

Mutation runs: disabling the `Source` case fails all four AFP-V0-9010 tests. Making
`observesSource` return false fails all 16 unproven channels.

## V1-5030: library planning compares import sets from its base (AFP-V0-9011)

`affected.Select` with no import sets assumes every dirty Go file changes its package's import set.
That fallback is sound, but it made library callers disagree with `corvint affected --base`. The
lane rscope repro is a comment edit to `internal/cem/verify/guards.go`, which gave
`cmd/corvint-analyzer-rust` an `IMPORT_GRAPH_READER` witness that the CLI does not give.
`affected.Select` has no base and cannot depend on the Go plugin, so the decision is to compute the
import sets by default in the shared language package. `languages.SelectAt` takes a pinned
commit and `languages.SelectBetween` takes two trees. The callers that measure from a base now use
them: `prove`'s affected-test rows, `appflows.FlowImpactAt` (`flows impact`) and `delta.Compile`. So
does `corvint affected --snapshot`, the CLI's own counterpart with the same gap, which selected
without a comparison although the snapshot pins its base. A caller without a base, and an
unresolvable base, keep the conservative fallback.

`internal/gateselect` has no import-graph reader and no inbound-runtime parse (its rule (c) stays
broader than the planner by design, see the spec's Non-goals), so it has no counterpart to fix. Its
tests pass unchanged.
