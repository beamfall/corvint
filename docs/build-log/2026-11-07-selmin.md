## V1-5026: a line-less runtime site reaches its declared edge (AFP-V0-9009)

`inboundRuntimeSite` cut the site after `typescript:e2e-runtime-dependency:` at the first `:`. The
TypeScript plugin names a site `path`, `path:LINE`, ``path `token` `` or ``path:LINE `token` ``
(`siteWithToken`). A line-less site therefore kept `` `playwright` `` in its "file", found no owner
and never reached the directory runtime edges that `.corvint/runtime-edges.json` declares for the
live-1.61.1 trees. `inboundRuntimeSiteFile` drops the trailing backquoted token (at the last
space-backquote), then a trailing all-digit line. A malformed token, a truncated `+N` entry and
an unowned file still name no caller, so the entry stays unknown. The self-review found that a
test whose real name ends in a backquoted word or in `:digits` could be stripped onto another
declared test. So the whole site text wins when it is itself a test, and a site whose two
readings are both tests stays unknown (`TestInboundRuntimeSiteAmbiguity_AFP_V0_9009`).

Repro, `corvint affected --path extensions/vscode/src/extension.ts` on this tree, with a binary
built from the base and one built from the lane head:

| | selected units | unknowns |
|---|---:|---:|
| before | 264 | 67 |
| after | 267 | 64 |

The fix adds exactly three selections and closes their three `e2e-runtime-dependency` unknowns:

- `typescript:playwright:internal/doccorpus/testdata/behavior-events/live-1.61.1/tests/items.spec.cjs`
- `typescript:playwright:internal/jstestprovider/testdata/route-stubs/live-1.61.1-residuals/tests/residuals.spec.cjs`
- `typescript:playwright:internal/jstestprovider/testdata/route-stubs/live-1.61.1/tests/stubs.spec.cjs`

No selection is removed. The same three selections appear on any code-bearing change, as
AZU-V0-8902 already required for located sites.

## V1-5029: a test file that keeps its package's test import sets selects no reader (AFP-V0-9010)

AFP-V0-2202's package header held one line per `.go` file, test files included, keyed by name. So a
new or edited test file with no new import changed its package's "import set". Every import-graph
reader of that package's importer closure, and every whole-module reader, was then selected.
Those readers are `cmd/corvint`, `cmd/corvint-test`, `internal/swiftimpact`,
`tools/test-read-scopes-check`, `internal/liveverify/affected`, `internal/liveverify/affected/golang`
and seven named-closure readers.

Splitting proven from unproven readers would not fix this. A scan of the repository found that
`cmd/corvint` (`core_network_boundary_test.go`, a `{{.}}` inside `range`), `cmd/corvint-test`
(`howaccept_test.go`), `tools/test-read-scopes-check` and both `affected` packages read the whole
module through unproven calls. The narrowing therefore sits in the header itself. When a
directory's non-test files share one clause N, every *unconstrained* test file (no build line, no
GOOS/GOARCH name as `go/build.Context.MatchFile` decides it, no `import "C"`) declaring N or
`N_test` folds into one summary line. That line holds the import set of the N test files, the
import set of the `N_test` files, and their embed lines. The sets are kept per role because
`go list` exposes `TestImports` and `XTestImports` separately, and an external test package's edge
to an import is a new edge even when the package itself imports it. Anything else keeps its own
line: a constrained test file, a foreign clause, or a test-only directory.

The trust boundary is written into the requirement. Unproven readers are still modelled as
listing the import graph. A reader of test file *names* (`TestGoFiles`, `-json`) is outside that
model, as a reader of `Stale` is for body edits today.

Measured on the base tree, from a scratch worktree with one commit that adds
`internal/gitstatus/selmin_measure_test.go` (`package gitstatus`, imports only `testing`, which the
package's tests already import), then `corvint affected --base <base>`:

| binary | selected | `IMPORT_GRAPH_READER` witnesses | unknowns |
|---|---:|---:|---:|
| base | 290 | 13 | 67 |
| head | 292 | 0 | 64 |

Twelve of the thirteen readers stay selected through other edges (for example, `cmd/corvint`
through `UNBOUNDED_READER` and `cmd/corvint-test` through `DECLARED_READ_SCOPE`). Only
`internal/swiftimpact` leaves the plan. The +3 are the V1-5026 selections above. The full benefit
for `cmd/corvint` and `cmd/corvint-test` therefore also needs their unbounded and declared read
scopes narrowed, which is outside this change.
Fault injection on the same tree: the same file importing `hash/crc32` (new to the package's tests)
brings back all 13 `IMPORT_GRAPH_READER` witnesses (293 selected, `internal/swiftimpact` again by
`IMPORT_GRAPH_READER`).

## V1-5030: library planning compares import sets from its base (AFP-V0-9011)

`affected.Select` with no import sets assumes every dirty Go file changes its package's import set.
That fallback is sound, but it made library callers disagree with `corvint affected --base`. The
lane rscope repro is a comment edit to `internal/cem/verify/guards.go`, which gave
`cmd/corvint-analyzer-rust` an `IMPORT_GRAPH_READER` witness that the CLI does not give.
`affected.Select` has no base and cannot depend on the Go plugin, so the decision is to compute the
import sets by default in the shared language package. `languages.SelectAt` takes a pinned
commit and `languages.SelectBetween` takes two trees. The callers that measure from a base now use
them: `prove`'s affected-test rows, `appflows.FlowImpactAt` (`flows impact`) and `delta.Compile`. So
does `corvint affected --snapshot`, the CLI's own counterpart with the same gap, which selected
without a comparison although the snapshot pins its base. A caller without a base, and an
unresolvable base, keep the conservative fallback.

`internal/gateselect` has no import-graph reader and no inbound-runtime parse (its rule (c) stays
broader than the planner by design, see the spec's Non-goals), so it has no counterpart to fix. Its
tests pass unchanged.
