## 2026-10-05 V1-0790: a clean release records the next stage

Human-owned intent: owner request [issue 587](https://github.com/beamfall/corvint/issues/587) part 1,
ticket V1-0790, owner decision D6. Workers could say which stage should run next only in free-form
release prose, and routing loops built on that prose consumed about 26 sessions on one ticket.

Requirements: `CAL-V0-082..085` in `docs/specs/corvint-tasks-agent-leases-v0.md` (V1-0790
amendment, inside `## Requirements`), the first IDs assigned to this lane by the coordinator.

### Change

- CLI and writer: `release` accepts `--handoff-to implement|review|integrate` and an optional
  `--handoff-reason CHANGES_REQUESTED|STAGE_COMPLETE|STAGE_INCOMPLETE` only with a clean `HANDOFF`
  or `REVIEW_RETURNED`, checked after the existing clean-handoff verification. `REVIEW_RETURNED`
  may target only `implement`; the reasons constrain the target relative to the generation's stage.
  Every other combination refuses `MALFORMED` without ending the generation. The keys enter the
  RELEASE request preimage only when supplied.
- Wire (D6): optional top-level `handoffTo` and `handoffReason` on the terminal `taskman-attempt/0`
  generation, and the same keys on the `priorGenerations[]` entry written when a retry admits the
  next generation (next to the V1-0788 prior-generation history keys, which must be present with a
  stage). The closed decoders enforce the same rules. Records without the keys round-trip
  byte-identical, and the `REVIEW_RETURNED` default (`implement`) is derived, never written.
- Reads: `ticket show`, each `plan preview` entry and the dispatcher ticket observation carry
  `nextStage`, derived from the highest-generation attempt: its recorded target, `implement` for
  an untargeted `REVIEW_RETURNED`, `null` when none is observed, and `STALE` when that generation's
  ticket revision differs from the current acceptance revision. The dispatcher renders it through
  the new `{nextStage}` placeholder (`NONE` for null) and records it in the `launched` event detail.
  `release --help` lists `handoffTargets` and `handoffReasonCodes`.

### Decisions and limits

- Advisory only: no claim, plan selection, role match or launch is refused or reordered by
  `nextStage`. Loop detection over the recorded history is a later part of issue 587.
- Retry accounting is unchanged; the CAL-V0-044 tests remain the regression witnesses.
- Downgrade: older closed decoders refuse attempts carrying the new keys (`MALFORMED`). Reverting
  is safe only before such a record exists; the spec rollback names the `jq` check. No rewrite
  tool is provided. Stores that never used the flags stay readable by the previous binary.
