## V1-3772: declared existence readers (AFP-V0-980, AFP-V0-981)

Repro on the base: `git rm integrations/codex/plugins/corvint/skills/corvint/SKILL.md`, then
`corvint affected` planned 66 units without `internal/specindex`. On this branch the same
deletion selects `go:github.com/Beamfall/corvint/internal/specindex` with witness
`DECLARED_EXISTENCE_READER`, and `corvint test --dry-run` (the shadow) plans it too.

Decisions:

- Of the ticket's candidate fixes, chose the project-owned declaration
  `.corvint/existence-readers.json` (package → manifests whose named paths its tests stat). An
  unconditional `go test ./internal/specindex` in go-static would cover one package only, would
  not reach `corvint affected` or the driver as the acceptance asks, and would cost about 60 s on
  every run. Treating every deletion as FALLBACK for such packages would need the same list
  anyway, and would select them on every unrelated deletion.
- Names are taken from each manifest as maximal runs of path bytes, kept as written and joined to
  the manifest's directory, so JSON paths and Markdown links (relative to their file) both match,
  without parsing either format. The names enter the graph digest and the cache entry; the
  declaration's stamp is required in a cached entry, so entries from before the declaration
  rebuild with no profile bump.
- Only a named path absent from the checkout selects the reader: an edited implementation path
  keeps existing, and selecting the 60 s specindex package on every edit of a Go file the index
  names would undo narrowing. With no disk root every named path counts.
- An invalid declaration, an unreadable manifest, or a package the Go plugin does not observe
  fails the build, as an invalid runtime-readers declaration does; a graph built without the Go
  plugin ignores the declaration.
- A dirty `.corvint/existence-readers.json` selects every declared reader and stays
  `UNOWNED_DIRTY_PATH` (it is not added to the AFP-V0-443 declaration class), which is sound.
- AFP-V0-981's lint (`test-read-scopes-check`) flags `os.Stat`/`Lstat`/`Readlink` of a
  `filepath.Join`/`path.Join` that starts with a parent-only literal and joins a non-literal.
  On this repository it found a third instance besides the two the ticket named:
  `internal/observations` (`TestFixedFrontierDegradationIsReportedByDesign` stats each decision
  record `degradationByDesign` names). It is now declared with
  `internal/observations/observations.go` as its manifest.
- `tools/capabilities-check`: `Check` stats each catalog link relative to `docs/` through its
  `linkBase` parameter in non-test code. The lint does not see that shape, so the package was
  checked by hand and declared with `docs/CAPABILITIES.md`.
- CI effect: the driver and shadow are built from the pinned `CORVINT_PR_TOOL_SOURCE` /
  `CORVINT_TEST_SHADOW_SOURCE`, so CI selects specindex only after a re-pin that carries this
  change (see V1-3748, stale pins). No `ci.yml` change was made for this ticket.

## V1-3749: one unknown allowlist (AFP-V0-982)

The driver's `gateselect.unknownNarrowing` admitted every non-module-level `LANGUAGE_FRONTIER`.
The shadow's `sessiontest.allowedUnknown` admitted only non-Go frontiers plus
`go:build-constraint-variants` and `go:nested-module-frontier`. Decision: both now call
`gateselect.AllowedUnknown`, which keeps the stricter shadow rules. Under the AFP-V0-098 superset
rule CI could already narrow only inside the shadow's list (a FULL shadow plan is never a subset
of a narrowed driver plan), so this changes no CI outcome. Locally, `script/gate-affected.sh`
now falls back on the narrowed `go:` frontiers. Rejected: pinning the shadow independently. That
is a workflow pin change that needs the owner's `ci-control-plane` review, and the ticket accepts
either option. Two named rules stay outside the shared list: the driver's CIN-V0-860 (4)
deleted-Go-source attribution, and a well-formed `go:unobserved-module` frontier. Both sides now
parse that frontier through one function, `gateselect.UnobservedModule`. The driver admits it,
and `corvint test` runs the module's own suite outside the ci profile. The first cut also took the
unobserved-module frontier out of the driver. That dropped `make selection-baseline-check` to
11/19 narrowed, against the floor of 12 that V1-3480 raised (`pr-2` and `ci-8de253042` went to
FALLBACK). Rather than lower an owner-raised floor, the driver kept that rule as a named exception
that the parity test asserts; the baseline is back at 12/19 with 0 misses.
`TestDriverAndShadowShareOneUnknownAllowlist_AFPV0982` compares the two sides over every planner
reason and Go frontier detail. Five entries diverged before the change.

## V1-3750: main FULL failures linked to narrowed PRs (AFP-V0-983)

Main push shards kept no outcomes (outcomes, with their flaky rerun, exist only for
`pull_request` and `merge_group`). Decision: do not enable that machinery on `push`, because it
would let a flaky rerun pass a main shard. A failed main shard instead keeps `failed.jq`'s
classification of its capture as `ci-failed-push-<shard>`. The new `ci-control-plane`
`main-miss` job runs `mainmiss.sh`. That job takes the newest earlier successful push run as the
last green full run, lists the merged pull requests in between (bounded to 100 commits and 20
PRs), and reads each PR's `ci-narrowing-*` records. A PR is a miss when a NARROWED record's
`skipped` holds a failed package. The row name carries the run, sha, epoch, miss count and PR
numbers, so `bar.jq` reports it from names alone. Decision: the count is advisory and does not
feed the AFP-V0-029 status or the AFP-V0-030 kill switch, since changing the bar is the owner's
call. Follow-up for the owner: whether MAINMISS rows should count as MISS.

## V1-3751: sampled full runs (AFP-V0-984)

`narrow.jq` samples a would-be-NARROWED pull-request shard when
`(hex(head[0:8]) + seed) % k == 0`, so every shard of a run agrees. A sampled shard runs FULL,
gives the reason, and records the driver selection as `sample.selected`. `row.jq` adds the
optional `sample` member (absent otherwise, so the closed row set is unchanged for other rows)
when every shard was sampled. `collect.sh` names `ci-forward-SAMPLE-…-k<k>-m<0|1>`, and `bar.jq`
reports the estimate with a Wilson 95% upper bound. Decisions: k = 10 and seed = 3751 in
`ci.yml` (about 10% extra CI on narrowed PRs); merge-queue runs are not sampled; the estimate is
advisory. It takes effect only after the owner's `ci-control-plane` review and a
`CORVINT_PR_TOOL_SOURCE` re-pin carrying the new `narrow.sh`/`narrow.jq`.

## Codex review fixes (three P2s)

1. The `ci.yml` step that classifies a failed main shard ran from the workspace root, where
   `.github/forward-rows/failed.jq` is absent (the job checks out into `source/`), so it wrote an
   empty `failed.json`. It now has `working-directory: source` and writes through a temporary file,
   so a failed classification retains nothing. `TestAFPV0983FailedMainShardStepRunsInTheCheckout`
   runs the step's own script, taken from `ci.yml`, in the workflow's layout and from the root.
2. `collect.sh` named a sample by the row's tested merge commit, so one PR head tested against two
   bases made two samples. It now uses the validated PR head. The collector test runs one head
   against two merge targets and checks that the bar counts one sample.
3. `mainmiss.sh` silently dropped a PR whose run lookup, artifact list or record download failed.
   Each such gap is now recorded and the job abstains: no row, and the summary names every gap. A
   readable run with no `ci-narrowing-*` record stays "ran in full", not a gap. The test fails one
   PR's download, then its artifact list, then its run lookup, while the other PRs read fine.
