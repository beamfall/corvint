## Problems

- V1-1733: `prove` could only run a compiled scenario; there was no way to ask whether an existing
  hosted test discriminates a change, and the F1 static-overlay falsifier had no required
  behaviour-removal control.
- CCE-V0-009 / V1-2373 / V1-2374: assertion attribution read marker text from the failure message,
  so a failure elsewhere with the same text counted as the assertion; the proof note did not name
  where the receipt located the failure; `cleanup-failed` was never produced.
- V1-1713: usefulness counted `PRESERVES`, so a no-op diff scored as useful (spike F2).
- V1-2378: CCE-V0-014's byte cap was not applied by any document.
- V1-1683: blocks could only come from the map and one hand-written declarations file; nothing
  proposed candidates from existing tests, and there was no human acceptance step.
- V1-1685: reach came from AMAP impact alone; runtime observation could not add a screen a
  changed backend or shared module runs on, and nothing guarded that such evidence never
  discharges an unknown span.
- Live: with a removed fixture-seed step the action waits until the test timeout; the timed-out
  receipt projected as infrastructure, so the `omitted-event:setup-1` control read
  `infrastructure_failed` and both compiled live proofs read `INCONCLUSIVE`.

## Decisions

- PWP-V3-008: the qualified reporter records the last attempt's `failureLocation`, the innermost
  stack frame inside the test file, else Playwright's error location. `prove` relativizes it
  against the test tree; a failure counts at the assertion only when that location is the
  scenario file and one of its assertion lines. A location inside the test file's own `finally`
  block reads `cleanup-failed`; other teardown failures read infrastructure (limitation).
- Hosted mode (CCE-V0-034..036): `prove --hosted-test FILE [--hosted-title T]`; the test is parsed
  from the head blob (one `test(...)` declaration, assertion lines, preceding `await` event lines),
  run with `--grep` on its escaped title, origin joined from the base blob. Required controls are
  one `omitted-event` per event line; the template controls need an emitted assertion and do not
  apply. Hosted runs use the generated runner configuration (recorded limitation).
- CCE-V0-037: `PRESERVES` never counts toward usefulness (it cannot tell a refactor from a
  no-op); its killed mutants still count toward parity.
- CCE-V0-039: a timeout is the test's own outcome when every other receipt qualification holds.
- CCE-V0-040: truncation drops from the end of one list per document, keeps the longest fitting
  prefix, sets `truncated` (omitted when zero); `e2e-document-over-cap` when nothing fits;
  `shadow` refuses a truncated window with `e2e-input-truncated`.
- CCE-V0-041..044 (V1-1683): `e2e harvest` proposes outcome and path blocks only from literal
  `expect(page.getByTestId('x')).<admitted matcher>('v')` and `page.goto('/u')` lines of tracked
  test files at the revision, with `harvested:<blob>:<line>-<line>` provenance and a content-only ID
  (moving a line keeps an acceptance; changing its meaning invalidates it). Everything else that
  looks harvestable is withheld with a reason; secret-shaped values are never emitted. The catalog
  admits a proposal only when `.corvint/e2e-acceptances.json` at the same revision accepts its ID
  and the harvester still proposes it; no ledger means no harvest, so existing catalogs are
  byte-identical. Obligations and compile flag acceptances the change itself adds
  (`acceptances_in_diff`). Harvested blocks carry no flow or screen yet, so compilation does not
  use them until V1-1684/V1 remainder binds them; the AC "never reaches compile" holds by
  construction and by test.
- CCE-V0-045..047 (V1-1685, runtime coverage only): `--coverage FILE` on obligations, compile and
  prove reads a closed `e2e-runtime-coverage/0` document bound to the head revision and head-map
  screens. A covered changed path becomes an extra impact hit with basis `runtime-coverage` after
  impact's hits, but is never marked placed, so every unknown span stands: coverage can add
  obligations and never turn `UNKNOWN` into `NONE` (or `REACHED`). Absence from coverage is not
  evidence. The recorder, the TJAA module graph, API contract joins and the ANL-V0 ledger stay in
  V1-1685 (ticket open). The ANL ledger was deferred because `appmap.Impact` uses it only for
  edges and test keys, not screens, so passing it would not widen obligations reach without an
  edge-to-screen rule that needs its own design.
- CCE-V0-010/013: tests pin that no proof or shadow field can select, skip or retire a hosted test
  and that no subcommand changes any repository file, ref or configuration.
