**V1-0435.** A `DOGFOOD_VERIFY_FILE` line over 512 characters made `dogfood-change` report only
`local-outcome: record-failed`, with no `fix:` line. The recorder caps each verification command at
`MaxCommandCharacters = 512` and a record at `MaxVerificationCommands = 50`
(`internal/trace/record.go:24-25`). A cap failure is a plain error, which the dogfood adapter reports
as the generic `record-failed` (`internal/tracerecordrepo/adapter.go:153`). The cause stays in
`<git-dir>/corvint/local-outcome.stderr`. The fix-hint table had no `local-outcome:record-failed`
entry, so the row missed the `fix:` line that `DCW-V0-014` already requires.

- **Fix.** A `local-outcome:record-failed` hint names `{evidence}/local-outcome.stderr` and both
  recorder bounds. `TestDogfoodChangeNamesVerifyLengthRemediation` fails without it and passes with
  it. The test also checks that the stderr file names the 512-character cause.
- **Not built: a distinct reason from a flow pre-check.** The ticket asked the flow to refuse an
  over-long line before recording, with a reason of its own. The recorder trims with
  `trimPythonSpace` before it counts (`internal/trace/record.go:267`). A flow copy of that rule could
  refuse a line the recorder admits. The other option was a new recorder code, which widens the
  closed `corvint record` and self-observation code sets (`internal/observations/observations.go`)
  during rc.2. The ticket's first criterion is amended to match what shipped.
