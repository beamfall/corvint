## Decisions and ticket disposition

- V1-4973: AFP-V0-9400 retains the existing computed-invocation fallback whenever
  the shell scanner skips a here-document. Looking only for an interpreter in argv
  is insufficient: an unknown wrapper can pass the body to one, and a writer can
  save it for a later interpreter. The conservative decision also covers nested
  output and unquoted body substitutions without pretending to parse their language.
- V1-5033: AFP-V0-9401 uses existing `PathGlobs` and `PATH_GLOB_READER` witnesses
  for literal `git ls-files`, `git grep`, `find`, `rg` and modelled `go run` commands.
  The anchored ancestor glob `/*` covers every repository path, including paths
  absent from the inventory. No narrower prefix is inferred from argv: symlinks,
  flags, computed directories and a Go program's runtime reads can escape it.
  AFP-V0-9402 follows the driver reader's dependents even for tested source.
  Existing computed frontiers keep their prior selection and witness, including
  the evaluated alternatives of the predecessor's V1-5000 regressions. This is a
  soundness repair, not a claim that all 64 historical frontier sites now resolve.
- V1-4684: already on the code base. `Driver.UnitsSource`, `driverRegistry.makeUnits`,
  `workflowUnits`, `driverSeed` and `driverSites` implement the claimant,
  literal edges, hunk attribution and computed fallback. `driver_test.go` retains
  `TestDriverClaimantOwnsDriverInputs_AZU_V0_001`,
  `TestDriverRecipeHunkSelectsItsTarget_AZU_V0_001`,
  `TestDriverRemainderHunkSelectsEveryTarget_AZU_V0_001`,
  `TestDriverWorkflowHunks_AZU_V0_001` and
  `TestDriverEdgesAndComputedSite_AZU_V0_001`.
- V1-4687: already on the code base. `shell/callers.go`, `callers_findings.go`,
  `callers_constructed.go`, `inbound_runtime.go` and `inbound_revision.go` retain
  verified callers and unclosed uncertainty. Existing witnesses include
  `TestRepositoryInboundCallers_AZU_V0_8901`,
  `TestConstructedForeignCallers_AZU_V0_8901`,
  `TestConstructedDirectoryRetainsUnknown_AZU_V0_8901`,
  `TestDeclaredInboundRuntime_AZU_V0_8902` and
  `TestInboundRevisionRejectsInvalidSnapshots_AZU_V0_8904`.
  The maintained `shell-foreign-callers-check` runs
  `TestRepositoryShellForeignCallersComplete_TSP_V0_005`.
- V1-4690: already on the code base under AZU-V0-007. The optional `run` argv,
  validation, graph/cache projections and `DECLARED_CONSUMER` selection already
  exist. Existing witnesses include `TestAZUV0007RunnableConsumer`,
  `TestAZUV0007InvalidRun` and `TestAZUV0007CLIExecutesDeclaredConsumers`.
- V1-5034: the exact `sh <<'A' | sh` nested-heredoc case is already conservative
  on the code base: the leading shell without a program operand sets `computed`
  in `driverShellScanner.simple`. The new AFP-V0-9400 regression retains that
  case and covers the previously missed wrapper variant. No explicit execution
  edge is claimed for the skipped nested body.
- V1-5087: left out (PARTIAL at lane boundary). The existing
  `TestRuntimeEdgesDeclarationRefusals_AFP_V0_819` explicitly requires
  `runs "g:gone" names no unit`; the charter forbids weakening it. The graph has
  no proof mapping an unknown unit ID to the full set of source files it can read,
  so merely selecting the edge's test holder and dropping the unknown is unsafe.
  A separate admitted compatibility route would also need integration in the
  trusted CI caller, which is outside this lane's allowed paths. The trusted base
  executable itself cannot acquire new behavior from changes on a PR head.
  Preserve the current refusal until the owner permits that compatibility route
  and its CI integration; do not advertise this ticket as delivered.
