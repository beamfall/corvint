## Decisions

- No new §11 code for a ticket that does not exist. `MALFORMED` is what the review and obligation
  reads already report, and a new code would change the closed set, its count test and `retries`.
- `usage()` stays code-free, because V1-3644 owns codes for every usage error. Only the
  unknown-verb result sets `MALFORMED`.
- Suggestions allow a distance of at most 2, and at most half the typed word's length, so `xyz`
  suggests nothing. There are at most three, nearest first. The two copies of the edit-distance
  function, in `cmd/corvint/suggest.go` and `internal/tasks/cli/refusal_codes.go`, are deliberate:
  `internal/tasks` must not import other internal packages.
- The conformance rows record each binary's current contract rather than one shared envelope.
  Unifying the 15 envelopes is a non-goal of ACX-V0-859. Its read scope matches
  `cmd/corvint-test`: `.github/cishards/`, `cmd/`, `go.mod`, `go.sum` and `internal/`.
- Files near other lanes, kept to the smallest change: `internal/tasks/cli/{cli,note,critical_path,
  escalation,refusal_codes}.go`, which sit near fric-a, fric-b and tasksaudit-w8, and
  `cmd/corvint/dogfood_flow.go`, which sits near the dogfoodflow lanes.
- The frozen requirement text in ASD-V0-019 and in `documentation-citation-gate-v0.md` still says
  `BASE ?= main`, so it was left as is. The comment in `script/dogfood-cache_test.sh` still says
  "(local main)", and that test matches only the refusal prefix.

## Review fixes (Codex, one round)

The independent review of 878840a3c returned five concerns. Four were fixed and one was settled
by a recorded decision:

1. `--worktree --path DIR` expanded the directory from HEAD only, so an untracked or ignored file
   there was not planned. It now lists the working tree under the directory (untracked and ignored
   files included), adds the files HEAD tracks there and refuses a nested repository
   (`affectedWorktreeFilesUnder`). Test: `TestACXV0851WorktreeDirectoryAndByPath`.
2. `--head` on the `--target` verbs could silently replace `--target`, because some verb parsers
   keep the last value. `withHeadAlias` now refuses `--head` given with `--target`, or twice, with
   `invalid-arguments`. `--target` given twice is still left to the verb's own parser. Test:
   `TestHeadAliasOnTargetVerbs_ACXV0858`.
3. `affected --worktree --by-path` dropped the worktree warning. The `affected-by-path/1` document
   now carries `warning` under `--worktree`, and its text form prints it. Test:
   `TestACXV0851WorktreeDirectoryAndByPath`.
4. `make help BASE="feature/o'brien"` was a shell syntax error. `help` now reads BASE through a
   target-exported `HELP_BASE`. Test: `TestMakeDefaultGoalIsHelp_ACXV0857`. The other targets
   that quote `'$(BASE)'` predate this lane and were left alone.
5. Decision: `--head` stays out of help. Help and the command trees name one canonical range-end
   spelling, `--target`, so the vocabulary table remains the single reviewed list of spellings.
   `--head` is an undocumented compatibility alias for callers who use the `changes`/`delta`
   spelling. ACX-V0-858 now states this, and the test comment says why the alias is absent.

The broader `cmd/corvint` run also found two tests that earlier lane commits had left stale:

- `TestAffectedBaseRangeJoinsCommittedPathsAndFailsClosed` still expected `--base main` to be
  refused, but `main` now resolves (ACX-V0-854). The case now uses an unknown ref.
- `TestAFPV0054WindowsVetTargetMatchesTheCIStep` matched the exact line
  `windows-vet: go-version`, which the help description now extends (ACX-V0-857).

Lesson: a lane's own focused `-run` selections missed both stale tests. Before handback, run a
regex broad enough to cover every test of the requirement families the lane touched.
