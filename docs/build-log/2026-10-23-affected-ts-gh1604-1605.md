## Decisions

- #1604 cause: the reporter's repository was not available (`NOT_OBSERVED`). The basic shape
  (`paths` with and without `baseUrl`, direct and relative-import reach) already selected on
  origin/main, so the gate of `TJAA-V0-037` was the likely blocker. Synthetic probes reproduced
  0 selected for two plausible causes: a Playwright config whose comment mentions `tsconfig`, and
  a non-Playwright runner that only a package dependency names. `TJAA-V0-050` stops both from
  blocking. A dependency assigns no runner and loads no module. A runner config, a configured runner
  or a test that runner owns still blocks. A real Playwright `tsconfig` option, `extends`,
  `rootDirs` and `moduleSuffixes` stay frontiers as `TJAA-V0-012` requires.
- `TJAA-V0-052`: frontier sites now carry their cause, so the next unexplained 0-selected plan
  names its blocker. The general adapter emits Ruby-style located entries
  (`reason:path:line` plus a backquoted token, at most 16 per reason, then `reason:+N`). AFP-V0-381
  `frontierSites` therefore counts sites, not reasons. The one exact-match consumer
  (`internal/appflows` `unbounded`) now compares the reason prefix. The Playwright profile keeps
  bare reasons internally and appends the token to its shared-graph detail. The graph digest of a
  TypeScript repository with a frontier changes, so one golden digest
  (`cmd/corvint/testdata/flows/impact.golden.json`) was updated.
- #1605 row 1 (`TJAA-V0-046`): a `)` that closes a call argument list makes the slash after it
  division. The check is a bounded 256-byte back scan with no literal, brace or slash inside the
  parentheses, and an opener after a member name, a non-keyword identifier, `)` or `]`. Statement
  heads (`if`, `while`, `for`, `with`) and keyword-led parentheses stay ambiguous.
- #1605 rows 2 and 3 (`TJAA-V0-047..049`): bracketed env reads were already admitted. The refusal
  came from `process.pid` on the right side of the top-level write, which refused the whole
  `process` root, so `baseURL` reported `process`. `process.pid`, `ppid`, `platform` and `arch`
  reads are now admitted. A write, call or alias of `process` still refuses the root.
- Not changed: the `TJAA-V0-018` identity key set (pinned to the `jstestprovider` reporter),
  `defaultBrowserType` widening, and the purity rule for non-identity values. A non-identity value
  that can call user code could rewrite a `devices` descriptor, so it still blocks.

## Independent review

One read-only reviewer found one MED issue. The call verdict read a bodiless signature
(`declare function f(a)`) followed by a line-leading regex as division, which dropped a
`require` edge. Only a same-line slash now takes the call verdict, and the probe rows are tests.
LOW fixes: the `tsconfig` search falls back to the raw text when an ambiguous slash could move a
comment boundary; source tokens stop at control bytes; a refusing tsconfig key is located at
`"key":`; tests now cover the window, `with`, a process-derived `browserName`, `process.pid++`,
`delete process.pid` and the appflows reason-prefix match. One residual is unchanged and
pre-existing: a backtick in JSX text can still hide a `require`.

A second review of PR #1616 found one P2 issue: a call through grouping parentheses
(`const n = (process.pid)();`) still admitted the `process` root, because the enclosing-group
check refused assignments only. Each enclosing group is now refused when it is called, optionally
called, tagged, constructed, deleted or updated, or when a member chain after it is a write target
or does not parse (`TJAA-V0-049`). This is fail-closed: a method call on a grouped read, such as
`(process.env.X || '').split(',')`, is still admitted because `constructor` and `Function` tokens
are refused anywhere in the config. The negative rows and grouped positive reads are in
`playwright_gh1605_test.go`.
