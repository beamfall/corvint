## Decision: a pre-cutover branch's own 0.x seal

A branch sealed before the producer cutover can still add a `cem/0.x` map that equals its bind
commit's sidecar. No converter remains to write a follow-up migration commit (`DCW-V0-050`), and
the stable verifier cannot read a 0.x map. Options considered:

- (a) treat it as a retired seal: not verified and no coverage, so its commits fail
  `unbound-commits` unless a verified `cem/1.0` constituent covers them; the fix is a merge
  forward and one `cem/1.0` rebind whose `BASE` precedes the retired bind;
- (b) keep a 0.x verifier path for sealed constituents only, which keeps the reader 0525 removes;
- (c) an allow-list of retired binds, which is a standing exception the batch cannot verify.

Chosen: (a). It keeps the coverage invariant (no commit is bound by an unverified map), needs no
rebase and no allow-list, and `dogfood change` admits the seal with a NOTE because that change
binds and cites the whole range itself.
