- **TSP-V0-785.** `testSourceParse` keys each parse by SHA-256 of path and bytes. A hit returns
  the stored file set, AST and test functions, which callers only read. The order of the
  linkname, cgo and test-file refusals is unchanged. A full cache (4096 files) is emptied.
  `TestTSPV0785ParsedFilesAreReusedAndEqual` checks four things:
  - A cold slice, a warm slice and a slice after emptying the cache are equal.
  - The warm slice reuses the same parsed files (pointer identity).
  - One edited test file adds exactly one entry, and the slice gains the new test.
  - Mutation: with the lookup disabled, the test fails at the pointer-identity check.

  Projected 510-call scan: about 230 s before, about 125 s after (0.24 s per warm call). The
  remaining cost is the per-change reach analysis, which depends on the changed set.
- **cli `t.Parallel` selection.** A scratch AST scan of the cli test files followed each slow
  test's calls through the test helpers. It excluded any test that reaches `t.Setenv`, `Chdir`,
  `ReapWorkersOnCleanup`, `runInterruptChild`, `cli.Build`, `os.Stdout` or `os.Stderr`, or writes a
  package-level variable. Process-signalling and reap tests (ATRV0310, CALV0130 survivor) were
  also excluded by hand. A first cut of 44 failed once at load 74:
  TestCALV0130_AttemptClaimedUnderBuildNContinuesUnderNPlus1 got `fork/exec .../bin/corvint-tasks:
  text file busy`. It writes an executable in process and then execs it, and a parallel test
  forked while the write descriptor was open (ETXTBSY). The scan then also excluded every test
  reaching an executable-mode literal, which dropped DSGV0012, CALV0130 AttemptClaimed, CALV0027
  NonfixtureReleaseBindings and SCCV0014 and left 40. Go resumes parallel top-level tests only after every serial one returns,
  so these tests never overlap a reaper check or a hook-writing test.

## New hot spots (untracked)

- H1 (fixed on owner request, ON-V0-786, `cbbdef779`): `store.OperatorNoteHistory` walks the
  note chain from head on every page to verify the cursor (ON-V0-008 requires it), so paging a
  whole chain is quadratic: TestONV0872 makes 82 pages and about 168k evidence reads. Each read
  opened the evidence directory's traversal from `/` (`safeopen.File`): sys time 8.8-11.5 s of
  14-24 s. The read now goes beneath one pinned descriptor (`ReadFileFromDir`, the CAL-V0-070
  pattern), with `intent.ReadFile`'s checks and error text, and falls back per path when the
  directory cannot be pinned. A cross-page memo was rejected: it would skip re-verifying events
  on disk, against ON-V0-008, and it helps no CLI read (one call per process). The walk stays
  quadratic. What remains (about 52% of CPU) is event decoding, which is the verification
  itself.
- H2: about 150 internal/tasks/cli tests are serial only because of `t.Setenv("CORVINT_TASKS_ACTOR")`.

## Friction

1. `script/heavy.sh` refuses every whole-package measurement without `HEAVY_WHOLE_REASON`, even
   for a profiling run. Repro: `script/heavy.sh env GOTOOLCHAIN=local go test -json ./internal/tasks/cli`.
   Expected: a profiling mode, or the refusal named once per lane. Actual: rc=2 after 0 s for
   every package, and a scripted sweep finished "successfully" with no data.
2. The ticket bodies' 230 s (V1-4109) and 418 s (V1-2740) figures are scan-harness and CI-shard
   numbers. Locally the same tests take 0.42 s per call and 26 s respectively. Expected: the ticket
   names the harness. Actual: it took a cross-lane log hunt (sec-u19 build log) to find what the
   number measured.
3. Several tickets in this list (V1-2342, V1-2366, V1-3433 AC1, V1-1522, V1-2211) were already met
   on BASE by the 1.0 snapshot, but their delivering commits exist only on the old private lineage
   (no merge base), so `git log --all --grep` names unmerged branches. Expected: the screening
   says "met on BASE". Actual: each one needed a re-measure.
4. `go test -json` gives a parent of parallel subtests an `Elapsed` of 0 (LGLV0009), so a
   top-level cost table under-reports parallel tests. Every lane needs the max-subtest workaround.
5. The first parallel cut failed once with ETXTBSY (`text file busy`) at load 74 (see the cli
   selection above). Expected: a test helper that installs an executable does so with a
   write-then-rename from a closed file, or under a package lock against concurrent forks.
   Actual: every in-process executable writer in internal/tasks/cli is unsafe next to any parallel
   test that forks, so it must stay serial.
6. This lane did not run `make dogfood-change` at change start. Charter 1101k does not name it,
   while AGENTS.md requires it for substantive work. The charter and AGENTS.md disagree.
