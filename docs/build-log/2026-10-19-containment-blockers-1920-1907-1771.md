# 2026-10-19 V1-1920, V1-1907, V1-1771: patch-equivalent containment, typed hold conditions, MCP deadline flake

Tickets: V1-1920 (GitHub #1186), V1-1907 (GitHub #1177), V1-1771. Contract:
`docs/specs/corvint-tasks-source-containment-v0.md` (SCC-V0-001..005, SCC-V0-010..014). The new
requirements are accepted under the owner's standing auto-accept of lane requirements
(2026-10-11). No accepted requirement is amended.

## Decisions

- Containment is one store read, `store.SourceContainmentOf`, next to the existing `isAncestor`
  in `internal/tasks/store`. Ancestry first; then Git's own patch-id rule
  (`git log --left-right --cherry-mark source...commit ^parent`), so EQUIVALENT means what
  `git cherry` means. Merges are never patch-equivalent (`MERGE_COMMIT`). A same-author and
  same-subject commit, or a shared `Change-Id`, with a different patch is reported as
  `PATCH_DIFFERS` so a conflict-resolved rebase is distinguishable from a commit that never
  landed.
- Every unobservable answer is UNKNOWN with a reason (missing ref or object, shallow history,
  failed or slow Git, the 10000-commit scan bound). None reads as ABSENT or as met.
- The existing ancestry sites stay strict; the spec's inventory names each one and its
  reason. The common reason is invariant 1: completion, CEM binding, witness and evidence
  freshness bind exact commits and trees, and equivalence would move evidence across a changed
  tree.
- A HOLD gains an optional closed `condition` (COMMIT_CONTAINED, PATH_EXISTS, SYMBOL_DEFINED)
  beside the required free-text reason. `queue status` and `doctor` re-evaluate it at each read;
  they never release or re-route the hold, because reads do not mutate (TM-V0-008).
- The free-text doctor scan tests commit and path tokens against `refs/remotes/origin/HEAD`, the
  local remote-tracking default branch that `git clone` writes. A configurable deploy ref was
  drafted as a doctor config member and reverted: it amends the accepted closed config key set
  TQD-V0-020 (or the TQD-V0-001 argv closure for a flag), which the standing auto-accept does not
  cover. That is left as an owner decision.
- #1177 is delivered for criteria 1, 2 (surfacing in status and doctor, not policy routing), 3 and
  5. Criterion 4 (role prompts and operator notes that pin a stale base) and policy routing are
  gaps; the PR references #1177 without closing it. #1186 is closed.

## V1-1771

The nightly failure (run 39121848489 at 0fce98369) of
`TestMCPV0038IndexDeadlineHasDistinctCode/caller_deadline` predates f8c33fba7 (2026-10-18),
which is in this branch's base. The failing subtest finished in 0.06 s, the old fixed 60 ms
sleep: under load the context's timer goroutine could still be pending when the sleep ended,
so the bridge saw no deadline. f8c33fba7 waits on `ctx.Done()`, after which `ctx.Err()` is
non-nil by construction; there is no sleep or retry. Product code is unchanged by this PR.
Evidence: `-race -count=200` of the test passed in 49.4 s at load averages 34.44/36.32/35.96.
Mutations: removing the `ctx.Done()` wait, and removing both `ctx.Err()` checks in the bridge,
each fail the test. Removing only `normalizeFailure`'s check survives, because `Call` checks
`ctx.Err()` itself first. No nightly has yet run on a commit that contains the fix.

## Independent review

One Codex round (read-only) found four defects; each is fixed with a regression test and a
killed mutation:

- The patch-id log omitted `--no-show-signature`, so a repository's `log.showSignature` started
  its `gpg.program`. Fixed; every containment command also disables hooks and the file-system
  monitor. `TestSCCV0003SignedCommitStartsNoVerifier` (a fake-signed commit and a marker
  verifier) fails when the flag is removed.
- Only the log had a deadline. One 60-second context now covers resolution, ancestry, depth,
  parents, count and log, and a passed deadline reads UNKNOWN `GIT_FAILED`, not a missing ref.
  `TestSCCV0003DeadlineCoversEveryCommand` (a git wrapper whose count hangs) and
  `TestSCCV0003DeadlineIsUnknown` fail when the commands use an unbounded context, when only the
  count does, or when the deadline mapping is removed.
- PATH_EXISTS `file/` was met by a file. A trailing `/` now requires a tree entry of that exact
  name; the mutations "any type" and "any listed name" are killed.
- The refname rule checked `.lock` only at the end; it now checks every component
  (`refs/heads/x.lock/y` is refused).

## Rollback

Revert the merge. Release or re-place any hold that carries `condition` before running an older
binary, whose closed hold decode refuses such records.
