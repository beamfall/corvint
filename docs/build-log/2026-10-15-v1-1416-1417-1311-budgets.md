# 2026-10-15 V1-1416, V1-1417 and V1-1311: Git and shard budgets that were not honoured

Lane V1-1416, V1-1417 and V1-1311. Base `f8a963e3882749814e066293fbe2a9175799def6` (origin/main).
The lane adds no requirement and amends none. Each fix implements an existing one:
`DLT-V0-002` (V1-1416), `AFP-V0-050` (V1-1417) and `STR-V0-015` (V1-1311). The host is a
12-core darwin machine. Load averages are the 1/5/15-minute figures `uptime` reported.

## V1-1416: the Go observer kept reading after git-budget-exceeded

Observed at BASE on this repository's HEAD with an operation-counting wrapper over the default
1,024-operation `RevisionFS` (scratch harness, not retained), load 17.6/23.5/33.9: 4,794
operations in all, 3,754 of them after the first `git-budget-exceeded`. `UnitsSource` returned no
error, 6 units and 4 spurious frontier entries, because the plugin tolerates an unparsable file
or an invalid declaration and so read each failed read as one of those. With the fix, at load
20.9/25.3/31.1: 1,040 operations, none after the failure, and the call returned
`git-budget-exceeded` with no units. The ticket's 1.5 to 2 minutes spent after the failure was
not reproduced on this host. Most of the time went before exhaustion, so the time saved here is
`NOT_OBSERVED`.

Contract: an immutable `affected.Source` already retained its first fatal read failure. It now
returns that failure from every later read, walk and stat without consulting the filesystem.
`golang.UnitsSource` returns `Source.Err()` instead of a partial unit set. A provider that
tolerates single failed reads can no longer keep walking the source after a fatal one, and the
graph is not admitted (`DLT-V0-002`).

Test: `TestUnitsSourceStopsAtGitBudgetExhaustion_V11416` covers a 40-package fixture over a
source that fails every operation after a limit. It asserts the coded failure, zero units, and at
most one operation after the first failure. Mutations: BASE code fails the test (0 units, `<nil>`
error); removing the short-circuit fails it (82 operations after the failure); dropping the
`root.Err()` check fails it (`<nil>` error).

`TestNestedFrontierReadsTheSuppliedSource_V1_0867` called `UnitsSource` on a plain `fstest.MapFS`.
That source cannot make a bounded open, and `BuildFS` would already have refused it through
`Source.Err()`. Now that `UnitsSource` surfaces that refusal itself, the fixture gains a bounded
open, as a Git revision has. The test's assertions are unchanged.

## V1-1417: the committed read-scope check used the fixed default Git budget

Reproduced at BASE. With 1,100 flat declared directories, and separately 400 at depth three,
`CommittedReadScopes` exhausted the frozen 1,024-operation budget. Because a Git failure was read
as absence, it then reported the declaration as naming a directory that "holds no Go package". So
a valid large declaration made every base unknown and widened the plan. The fixture run took 146 s
at load 17-23.

Contract: the declaration is read under the default budget. The per-directory checks then run in
a second repository whose operation count is the default plus two operations per declared path
component: one ancestor listing and at most one `go.mod` read. That pass gets the time remaining
in the default 30-minute total. A coded Git failure in those checks is returned, so the base is
unknown for the stated reason (`AFP-V0-050`(3)), never for an invented "no Go package".

Test: `TestCommittedReadScopesBudgetScalesWithDeclaration_V11417` lowers the base count through a
test seam to 16, which is the small fixture's fixed cost. With a scaled budget, 48 flat and 16
depth-three directories read back intact. With a zero per-component allowance, the call returns
`git-budget-exceeded`. Mutations: the unscaled budget fails the first assertion
(`git-budget-exceeded`, 0 packages); swallowing the Git failure fails the second ("holds no Go
package"). The 1,100-directory fixture was not rerun on the fixed code, because it costs minutes on
this host. The seam test covers the same boundary.

PR #929 (`claude/v1-1399-gateselect-narrowing`) was open when the lane started, and the lane
instruction was to merge it in if it stayed open. It merged to main during the lane. It changes
`internal/gateselect` and its fixtures, shares no file with this lane, and counts no Git
operations, so this branch stays on its base without merging it.

## V1-1311: discovery probes did not check the shard deadline

At BASE, discovery already ran under a context bound by the shard deadline (commit `1c12c3788`).
However, the version and `go list ./...` probes of one runner had no deadline check between them,
and the shard clock was the wall clock. A budget-ended discovery was also recorded as "runner
version cannot be read", after which discovery moved on to the next runner.

Contract: the shard clock is a seam (`time.Now` in production). Each probe refuses to start once
the deadline has passed. A discovery ended by the budget, through that refusal or through the
cancelled discovery context, records `<runner>: the shard's <budget> total budget ran out during
runner discovery; nothing launched`. After that, no later probe or adapter starts and the receipt
is `INCOMPLETE` (`STR-V0-015`).

Test: `TestSTRV0015DiscoveryStopsAtShardDeadline_V11311` uses a fixed clock that expires the
1-hour budget as soon as the first probe has run. It asserts that only that probe ran (no
`go list`, no declared runner's version probe), that nothing launched, and the receipt and reason.
It uses no sleeps. Mutations: without the probe check, the test fails (`go list` ran); without
the stop on a budget-ended discovery, it fails (the wrong reason, discovery continued).

## Review

One Codex round (`codex exec -s read-only`) over `f8a963e..` reported three P3 findings. All
were fixed before the final binding:

1. A cancelled parent context during discovery was reported as an expired budget. Now only the
   probe refusal, or the discovery deadline with the parent still live, records the budget
   reason. A parent cancellation keeps the existing cancellation path.
2. An uncoded revision-source failure, such as the 400,000-entry tree bound, was still read as
   "holds no Go package". Every source failure is now returned except an absent path or an entry
   of the wrong type.
3. The V1-1416 test did not cover the walk callback or later stat, lstat, read and walk calls.
   `TestSourceShortCircuitsAfterFatalRead_V11416` covers them. Two mutations both fail it:
   without the walk callback check, the walk ran 39 operations past the failure and returned no
   error; with `Stat` checking only cancellation, `Stat` reached the backend once more.
