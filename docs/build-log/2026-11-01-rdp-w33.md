# Lane rdp-w33: product read paths and hooks, measurement first

Lane `rdp-w33` on `wsl-lanes` (AMD Ryzen 9 5950X, 32 logical CPUs, WSL2 ext4), branch
`claude/lane-rdp-w33-1101`, BASE origin/main `35475f860d97bfde9bbaa6cccf1f2ba8f78ea44b`, Go
`go1.27.3`. The installed `corvint` was `1.0.0-rc.3.dev` build 44 at BASE; measurements use a binary
built from the lane tree. The host was shared with five other lanes: the 1-minute load average was
8 to 37 during every measurement and is in each row. Nothing here was measured on a quiet host, and
no number is compared with a macOS one.

## Method

Each row is one run of `/usr/bin/time -f '%e %U %S %M'` (wall, user+system CPU, peak RSS). Git spawns
are counted by a `git` shim first on `PATH` that appends each argv to a log file. Corvint strips
`GIT_*` variables from its children, so `GIT_TRACE2_EVENT` saw nothing. CPU profiles came from
`CORVINT_CPUPROFILE`. Repeated rows are separate runs.

Profiles behind rows 2, 5 and 6: with a fresh snapshot, about half the hook's CPU is loading the
177 MB gob snapshot (`.git/corvint/index/*.gob`). Most of that load is `internal/saferio.ReadData`:
gob reads one message larger than 10 MB in 10 MB chunks and appends them, so a 177 MB message is
regrown and copied many times (memmove 39%, growslice 32% of the hook profile). In `context`,
`evalSymbolChunk.collect` (query-independent per-symbol term sets over every symbol) is a further
25% of CPU. A profile taken while the snapshot was stale showed the hook's detached
`index --if-stale` worker. It inherits `CORVINT_CPUPROFILE` and writes over the hook's profile. Its
CPU (tokenise, posting build, go/scanner) does not appear in the hook's own wall time.

- **TLF-V0-805** (`tools/requirement-id-collisions`): `outermost` asked `merge-base --is-ancestor`
  for every ordered pair of heads (n² spawns). One `git merge-base --independent` over all heads
  prints exactly the heads no other head reaches. One `git grep` over the base and every head tree
  replaces one grep per head. A branch tip that `for-each-ref --no-merged` already admitted gets no
  second ancestry check. `TestTLFV0805_BatchedReadsEqualPerHeadReads` compares the batched results
  with pairwise and per-commit reads.
- **ASD-V0-805** (`script/requirement-id-collisions.sh`): branch tips are classified with one
  `for-each-ref --no-merged=BASE --contains=<each base root>`. Only a worktree HEAD that is no branch
  tip keeps the two per-commit `merge-base` calls. One `git cat-file --batch` reads every open ref's
  `REQUIREMENTS.tsv`. Batch output does not tell an absent index from an unreadable blob, so a
  `missing` answer falls back to the old per-ref path: no index is still a `NOTE`, and an unreadable
  blob still exits 2 naming the ref. The test adds a detached worktree whose block ID must be named.
  The pre-change script passes the same extended test.
- **EEP-V0-805** (V1-0562): see below. It is a bounded-read fix, not a speed change.

## Found, not changed (no ticket)

- **Snapshot load copies the 177 MB gob message many times.** `encoding/gob` reads a message over
  10 MB through `saferio.ReadData`, which appends 10 MB chunks to a growing slice. In the hook and
  `context` profiles that is 27 to 39% of CPU. Every snapshot reader (hooks, `context`, `impact`,
  `query`) pays it. Writing the snapshot value as several messages under 10 MB, or a non-gob
  encoding, removes it, but either changes the on-disk format and needs the benchmark/format gate
  (invariant 7, IDX-SNAP), so it is not done here.
- **`context` recomputes query-independent symbol term sets on every call**
  (`evalSymbolChunk.collect`, 25% of `context` CPU). Precomputing them at index time is again a
  snapshot-format change. `internal/contextindex` also has large unmerged lane work in
  `claude/batch-1101d`.
- **The index refresh worker inherits `CORVINT_CPUPROFILE`/`CORVINT_MEMPROFILE`** and overwrites
  the profile of the hook that started it, so a hook profile can show the background index build
  instead of the hook. The env filter in `spawnSnapshotRefresh` drops `GOMAXPROCS` and the internal
  markers but not the profile knobs.

## Friction

1. `GIT_TRACE2_EVENT` cannot count Corvint's Git spawns. Repro: `GIT_TRACE2_EVENT=/tmp/t corvint
   affected --base <sha>`; `/tmp/t` stays empty. Expected: a supported way to count a read
   command's Git subprocesses. Actual: the child environment drops `GIT_*`, so a PATH shim is the
   only way.
2. A hook's CPU profile can be another process's profile. Repro: with a stale snapshot,
   `CORVINT_CPUPROFILE=p corvint adapter claude-code user-prompt < in.json`; `p` shows the index
   build. Expected: the profile of the hook. Actual: the detached refresh worker inherits the knob
   and overwrites it.
3. V1-4172 names no hook. Repro: read the ticket and the aff-w23 friction item 8 ("each commit's
   hook runs about 4 minutes of heavy checks"). Expected: the hook's name or host. Actual: no Git or
   Claude Code commit hook is installed on wsl-lanes, so the lane cannot reproduce or fix it.
4. `heavy.sh` refuses a whole-package test of the package the lane changed without
   `HEAVY_WHOLE_REASON`. Repro: `script/heavy.sh go test -count=1 ./internal/extevidence`.
   Expected: a directly changed package admitted as whole. Actual: refused; rerun with a reason.
5. `git worktree remove` has no `-q`. Repro: `git worktree remove -q --force DIR` exits with
   "unknown switch". Expected/actual: noted for test authors; the lane test uses `--force` only.
6. `tail -3` fails on this host (`tail` is uutils). Repro: `tail -3 file`. Expected: the last 3
   lines. Actual: "unexpected argument '-3'"; `tail -n 3` works.
7. A previous rdp-w33 incarnation left a registered worktree at `~/lane-scratch/rdp-w33/taw`
   (detached `3dc2f1258`). Every open-ref scan now counts it. It is not removed here (not this
   lane's to delete without the orchestrator).
8. `unraid-lanes` does not resolve from the WSL host. Repro: `ssh unraid-lanes`. Expected: the
   charter host list is reachable from a lane. Actual: "Temporary failure in name resolution".
9. `dogfood-inputs-check` checks the VERIFY file's syntax only after about 24 s of work. Repro:
   a verify line `go test -run '^TestA|^TestB' ./pkg`; `make dogfood-inputs-check ...`. Expected:
   the syntax refusal in under a second, before the tree binary is built. Actual: REFUSE
   unsupported-verify-syntax after 24.63 s wall and 63.8 s CPU.
10. A broad filesystem search for the friction source file ran past the tool's 120 s limit and
   was moved to the background. Repro: `find / -name friction-pending.md`. Expected/actual: lanes
   should get the friction file's path in the ticket body.
