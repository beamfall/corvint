## V1-3041: AHI-024 host-check interrupt test (delivered, 6386fb445)

Reproduced: 1 of 1 failed at load 31-40 (`native detached child reached` false after 27 s).
Two root causes in `integrations/pi/host.test.mjs`:

1. The interrupting child runs the whole AHI-002 lifecycle test (a `cmd/corvint` build and every
   Pi step) before it writes the witness, but the parent waited a fixed 25 s and bounded the child
   at the default 45 s. The parent now waits on observed progress: the witness appears or the child
   exits, and an exit before the witness fails with the child's own `not ok` excerpt (the child env
   drops `NODE_TEST_CONTEXT`, which otherwise makes its output v8-serialized). `run()` takes a
   `timeoutMs` option; 900 s only detects a hung child.
2. After the group SIGKILL the test asserted `kill(-group, 0)` ESRCH with no wait. With fix 1 alone,
   3 of 13 loaded runs failed there. The test now waits (bounded, 10 s) until both the descendant
   and the group are gone and names the remaining members from `ps` if not. Inference, not
   observed: the reparented group leader stays a zombie group member until reaped.

No assertion was weakened; AHI-024 already traces to this test. Pi 0.99.1 was installed lane-locally
from npm (`--ignore-scripts`) because the lane host has none (the indexcli-w5 blocker), and removed
at closeout. Evidence, `node --test --test-name-pattern "interrupting the host check"
integrations/pi/host.test.mjs` through heavy.sh: 50 of 50 consecutive at host load 38-55 (chunks of
16, 17, 17); with burners 5/5 (32 burners), 9/9 (24), 13/14 (16). The one failure is a different
cause: inside the child the AHI-002 assertion that every RPC context carries
`BEGIN CORVINT REPOSITORY DATA` failed because the adapter's 1.7 s native-context deadline abstained
under load (adapter design, filed as friction below).

## Friction

1. heavy.sh's load gate holds a loaded-flake reproduction until the load is gone; it needs
   `HEAVY_MAX_LOAD=1000`, which no doc names for this purpose.
2. With background jobs forbidden, a loaded run needs a hand-written `xargs -P` burner harness;
   there is no shared `script/` load generator.
3. Pi is absent on the lane hosts; host-adapter tests block until a lane installs it by hand.
4. A node test that runs its own file as a child inherits `NODE_TEST_CONTEXT=child-v8`, so its
   failure output is unreadable v8 bytes.
5. AHI-002's lifecycle test asserts every RPC context carries repository data, but the adapter's
   1.7 s deadline abstains under load (1 of 14 at 16 burners).
6. Other fixed 1 s reap waits in host.test.mjs (AHI-024 harness cancellation, AHI-025 PTY) have the
   pattern fixed here.
7. Shas cited in earlier logs (eea277b93, afeeefb2b, 756ac657b) are old-lineage, not ancestors of
   origin/main, so `git log --all --grep` screening returns them without saying so.
8. `~/.cache/go-build` (126 G) on wsl-lanes is never trimmed; WSL `/tmp` is a 16 G tmpfs.
9. internal/tasks/store as a whole package exceeds the 595 s split bound, so CI-like whole-package
   flake triage cannot run as one lane command.
10. `script/gen-spec-requirements.sh` silently skips four-digit requirement IDs while lane charters
    hand out four-digit blocks.
11. The installed `corvint` on wsl-lanes is stale (built from 9652cb25c81b) and every command says
    DEGRADED self-binary-stale.
12. The corvint MCP plugin failed to connect (CONNECTION_CLOSED) in this session.
