# Compact line-coverage index: bounded uvarint deltas (V1-5163)

Ticket V1-5163 (1.0 scope, P2 bug). Governing requirement: GLS-V0-002 in
`docs/specs/go-line-selection-v0.md` (a damaged linecov-index/4 index decides nothing). This is a
fail-closed bug fix; it adds no requirement and changes no encoding.

the index) where a decoded unsigned value is converted to a signed type, sizes an allocation, or

## Fix

`decodeSection` now compares each delta, as an unsigned number, with the room left below its
limit before converting or adding it, and a delta past that room gets the existing
`linecov: malformed index: ...` error. It does not clamp the delta or skip the entry:

| Site | Bound | Test |
|------|-------|------|
| 1 `ids()` | `d >= uint64(limit-next)` fails, where `next` (the previous id plus one, from 0) is at most `limit` | `TestCompactRefusesIDDeltaOverflow` |
| 2 block start | `ds > uint64(maxLine-prev)` fails, `maxLine = 2^31-1`, `0 <= prev <= maxLine` | `TestCompactRefusesBlockStartOverflow` |
| 3 block end | `de > uint64(maxLine-Start)` fails | `TestCompactRefusesBlockEndOverflow` |

The encoding and every valid decode are unchanged. `TestCompactHandEncoderMatchesEncode` shows that
the tests' hand encoder writes the same bytes as `Encode`, and that a valid index round-trips to the
same bytes. Each test sends its hostile sections to `decodeSection`, to a whole `Decode` and to a
lazy `Open`. On the unchanged decoder all three readers accepted them, as test id -1 or a duplicate
id 0, a block starting at line -1, a truncated start, or an end below the start. The one exception
was id -1, which a whole `Decode` refused only through `checkSegments`.

Mutation: removing each bound in turn (for site 1, putting back the range check after the
addition) makes that site's test fail.

`FuzzCompactDecode` fuzzes the section decoder under a checksum that verifies, with test and
segment limits up to 2^31, and also runs a whole `Decode` behind a valid header. Its seeds are a
valid section, a segmented section and every hostile case. It checks that decoding fails, or that
ids are ascending and below their limit and that `0 <= Start <= End <= 2^31-1`, and that nothing
panics. A run of `-fuzztime=60s` with 2 workers made 262,955 executions, found 19 new interesting
inputs and no crasher. On the base decoder its seeds fail.
