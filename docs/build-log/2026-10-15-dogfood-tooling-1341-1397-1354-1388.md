## Decisions

- V1-1341: the verify grammar stays the recorder's shell-syntax-free `safeCommand` (`DCW-V0-034`
  makes widening it a non-goal). The `unsupported-verify-syntax` fix line now names the escape: a
  script committed with the change, listed as `sh path/to/script.sh` (`DCW-V0-065`).
  `docs/DOGFOOD.md` says the same.
- V1-1397 has three observations, each checked on a scratch clone with the base binary.
  - (1) Silent `finish-lane`: reproduced. A context ended mid-run unwound with `ErrInterrupted`
    and printed nothing on either stream. Now the run prints `STEP INTERRUPTED` and the
    `NOT_PRODUCED` block, and the interrupted pass prints its captured output (`DCW-V0-067`).
  - (2) Stale `citation-plan-binding` after an amend: partly a false positive. The `DCW-V0-029`
    refusal is correct when the plan was kept from the earlier map. It is a false positive only
    when a plan rewritten for the amended map happens to repeat the earlier bytes; identical bytes
    cannot tell the two apart. `DCW-V0-014` freezes reason codes, so the code stays
    `citation-plan-map-mismatch`. The fix line now says the binding is stale and names the moved
    row, the hunk, both ordinals and both remedies (`DCW-V0-066`).
  - (3) Sidecar removed mid-run: reproduced. `cem cite` and `cem status` print
    `{"code": "map-unavailable", "error": "cannot read CEM map", "ok": false}`, exit 2, with no
    path. That CEM CLI text is oracle-frozen (`internal/cem/cli/cli.go`, CCF-V1-004), so the dogfood
    fix line names the map path, the retained stderr and both remedies (`DCW-V0-068`).
- V1-1354: `internal/dogfoodflow` has one Git stdout reader, `flow.readGit`, capped at 16 MiB
  (`maxGitOutputBytes`, equal to the earlier `maxRequirementsBytes` coverage cap).
  - `flow.git` and `batch.runScratch` refuse with `git-output-over-bound` on overflow.
  - `boundedGit`, used by the OCM coverage reads, keeps its `NOT_OBSERVED` outcome.
  - No caller sees truncated output (`DCW-V0-064`).
- V1-1388: an end-to-end test drives the built binary's `dogfood finish` to each `OCM-V0-021`
  bound at the aggregate while every scope passes on its own.
  - `too-many-obligations`: two intents of 129 requirements.
  - `too-many-claims`: two scopes of 260 linked claims.
  - `map-too-large`: five scopes of 470 claims, 210654 bytes each, 1053270 in total. Bytes are
    checked before claims.
  - In each case the stdout `dogfood-ocm-status` row carries the code and the at most 512-byte
    detail naming the total, the bound and the per-scope shares. stderr is the bare code.
