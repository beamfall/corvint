# 2026-10-15 V1-1420 and V1-1421: post-run authority and repository-probe bounds under host load

Lane V1-1420 and V1-1421. Base `6457b86bcd4b9048cfc93645b0250c4372115d72` (origin/main). The lane
adds one requirement, `GLTP-V0-053` (`docs/specs/go-live-test-provider-v0.md` §11). It is accepted
under the owner's 2026-10-11 standing auto-accept of lane requirements and amends no accepted
clause. No product bound changes.

## Observed

The host is a darwin machine with 12 cores. Load averages are as `uptime` reported them at the
start and end of each run.

1. V1-1420, `cmd/corvint-go-test-provider`. At BASE the whole package ran once at load
   58.6-78.3: 23 tests passed and 2 failed. `TestExecuteNormalCompletionHasNoRecordedSurvivors`
   failed its precondition with `Execute=execution authority changed: post-run revalidation`,
   `execution=INCOMPLETE` and `containment=true`.
   `TestProviderCommandUsesPinnedLiveParentAuthorityE2E` failed because the CLI path exited 1.
   Separate runs at load 44-46 failed `TestExecuteNormalCompletionHasNoRecordedSurvivors` and
   `TestProductionParentBindsNonASCIIRepositoryPath` with the same error.
2. V1-1421, `internal/mcp/bridge`. At BASE both tests ran with `-count=5` at load 63.0-60.6:
   3 of 10 failed. One failure was in `TestMCPFlowsCoverageRefusesAMissingPromisorObjectWithoutFetching`
   and two were in `TestMCPCEMReportRefusesAMissingCitedBlobWithAValidMapWithoutFetching`. Every failure was
   in the complete-clone control variant (`drops guard true`), which returned
   `&bridge.Error{Code:"repository-unavailable", ReasonClass:""}`.

## Diagnosis

1. V1-1420 is confirmed as the timeout. `provider.Execute` runs three post-run calls: revalidation,
   identity observation and lease release. Each runs under a fresh 15-second
   `postAuthorityTimeout`, and any failure becomes `ErrAuthorityDrift` with suffix
   `: post-run revalidation`. With the production parent verifier, each call re-hashes the
   GOROOT single-threaded: 270 MB in 15,588 files. Scratch instrumentation at BASE (not committed)
   recorded the following under load:
   - At load 49-65 the GOROOT tree walk took 7.7-21.1 s per call, and whole observations took
     10.6-25.4 s.
   - At load 37-44 revalidation, observation and release each reached the 15-second deadline.

   The provider comment says the bound is "large enough" on a cold filesystem. Under this load it
   is not. That is a product finding; this lane does not change the bound (owner decision 1 below).
2. V1-1421 is confirmed as the probe deadline. Instrumentation at BASE recorded the normalized
   cause of all 3 failures at `-count=5` (load 53.0-66.7): `Git repository probe exceeded its
   10-second deadline`. That is the gokernel `repository-probe-timeout`. The bridge's
   `normalizeFailure` maps it to `repository-unavailable` with an empty `ReasonClass`, so the
   control looked like a missing repository. The fault is in the test, not the refusal logic.

## Change

1. V1-1420 adds the test-only seam `provider.WithPostAuthorityBound` (GLTP-V0-053).
   - Each post-run call keeps its own fresh deadline, independent of caller cancellation.
   - A non-positive value keeps the 15-second default.
   - No production path sets it. The command reaches it only through the test-set
     `commandPostAuthorityBound`.
   - Two fixtures test binding or receipt semantics, not post-run latency. They lift the bound to
     ten minutes: `TestProductionParentBindsNonASCIIRepositoryPath` (GLTP-V0-004), and both the
     in-process and CLI paths of `TestProviderCommandUsesPinnedLiveParentAuthorityE2E`.
   - The GLTP-V0-041 fixture keeps the production bound, because its budget text cites the
     15-second bound. Lifting it would amend GLTP-V0-041 (owner decision 2).
   - In that fixture, a documented post-run refusal after clean containment is a provider failure
     outside the GLTP-V0-041 antecedent. The fixture still checks every other precondition, the
     `INCOMPLETE` execution, the wire deletion, and the identity and control probes. It then aborts
     as INCONCLUSIVE instead of running the PASSED-receipt conformance check. Any survivor still
     fails the test.
   - Line citations in the spec still resolve: provider and command edits stay in place and new
     code is appended. Two `main_test.go` citations in the GLTP-V0-041 commentary were already
     stale at BASE: `:473` for the verifier executable, now `:483`, and `:544-600` for
     `runAuthorityHelper`, now `:554-636`. The lane's two-line insertion moved `:473` onto a blank
     line, so both now cite the code they name. The requirement text is unchanged.
2. V1-1421: the two promisor refusal tests call the bridge under
   `gokernel.WithProbeBound(ctx, 10m)`, the existing V1-1391 test seam (decision 0082). Production
   keeps the 10-second probe bound.

## Owner decisions

1. The 15-second `postAuthorityTimeout` is too tight for the production parent verifier at load
   40-65. Raising it, or making the GOROOT re-hash cheaper, would amend GLTP-V0-027 and
   GLTP-V0-041.
2. If the GLTP-V0-041 fixture should lift the bound, its budget text needs an amendment. That would
   turn its INCONCLUSIVE aborts under load into PASS results.
3. Post-run deadline expiry is reported as `ErrAuthorityDrift` (`execution authority changed`),
   although no authority changed. A distinct timeout or unavailable class would change a
   documented refusal.

## Residuals

1. The MCP bridge maps gokernel `repository-probe-timeout` to `repository-unavailable` with an
   empty `ReasonClass`, so MCP clients cannot tell a slow probe from a missing repository.
   Changing this alters the MCP wire contract.
