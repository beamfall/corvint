## Decisions and implementation

1. V1-2571: retain the existing split-safe parallel and read-ahead scanner. The
   reported single-scanner design is already replaced at BASE by DCR-V1-551/559.
   Its adversarial split, escape, nesting, corruption, digest-tail and refusal
   differential tests pass unchanged. DCR-V1-7800 records the tighter qualification
   target without inventing a second scanner.
2. V1-2588: move chunk storage allocation from dispatch to the bounded decode
   workers, and reuse a worker-local JSON encoder. Keep the closed decoder and
   exact canonical comparison. The encoder adds one framing newline; the comparer
   checks it separately and cannot forgive an extra, changed or missing input byte.
   A canonical mismatch still does not stop later closed decoding: an undecodable
   member retains precedence. No artifact bytes, schema or stored state change.
3. V1-4230: replace repeated decimal stamp assembly with preallocated binary stat
   records and ordered per-directory hashes. On Linux/amd64 use descriptor-relative
   `newfstatat` with `AT_SYMLINK_NOFOLLOW` and worker-local name/stat buffers,
   avoiding per-entry full paths and FileInfo allocations. Other platforms keep
   the ordinary lstat path. Close the directory descriptor before descent. Keep
   every metadata field, the entry/cancellation bounds, symlink behavior, and both
   racy-window and coarse/skewed-clock abstentions. No directory-mtime shortcut.
   Stamps are private call-local state, not a persisted format.
4. V1-2746: the linear reference/import scanners are already present at BASE.
   Extend their whole-checkout regex differential test through `sourceImports`'s
   prefilter, so an incorrect necessary-condition gate cannot silently omit an
   import. Do not shrink the whole-checkout self-documentation fixture.
5. V1-4199: evaluate the existing experimental pack, whose Sources and Symbols use
   a string table and fixed-width columns, against `/3` and default `/4`. Keep
   `/4` as the default: the pack reduces decode share but loses total context CPU
   and latency. Do not ship a new default format or promote this challenger.

Rollback: revert worker allocation/encoder reuse or the private stamp changes
independently. Disable the experimental pack by unsetting `CORVINT_SNAPSHOT_FORMAT`;
the existing gob writer/reader and separate engine namespaces remain intact.

## First clean-build CLI comparison and retained failure

Candidate `da0b6f44e364f55b00b42f7b52e0dee7a330eac6`, built with
`vcs.modified=false`, against BASE, twenty interleaved reads per operation on the
66,752,223-byte attested DCR-V1-418 fixture. Load 37.64..44.08; stdout identical.
Flow p50/p95: 381.09/492.41 ms base, 325.79/609.02 ms candidate. Gaps:
228.87/270.62 ms base, 238.56/280.86 ms candidate. Candidate peak RSS
232,536 KiB = 238.12 MB, above 3.5 times the artifact (233.63 MB); base flow
also exceeded the bound (242,188 KiB). Both latency and RSS qualification fail.

Decision after that observation: cap the worker pool and queued batches at
`min(GOMAXPROCS, 8)`. Both active and queued jobs pin streamed blocks; the former
GOMAXPROCS-sized pool retained too many blocks/encoders on this 32-thread host.
Keep the first result rather than replacing it with a later favorable sample.
The bound changes no decoded value or refusal order and needs no format migration.
