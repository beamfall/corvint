## V1-4380: uninstrumented child binaries already reject the record (ALREADY_MET; spec amended)

Finding: the collector overlay (`internal/linecov/audit.go`) observes every `os/exec` launch; a
launched Go executable without `-cover` build metadata, without the digest-bound proof of the
collector's module-wide `-coverpkg` and overlay build, or with another coverage destination
rejects the record as `uninstrumented-child`, and a child whose counters never complete as
`missing-child-counters` (`collect.go`, `LPCV-V0-7601`). `TestUninstrumentedChild` already runs the
fixture with the child built under `GOFLAGS=""` (`cleared`), a prebuilt child (`prebuilt`), a
narrower `-coverpkg` (`partial*`) and a killed second child (`missing-second`), and asserts no
record with the named reason; `covered` and `covered-delayed-wait` assert the record is produced.
`TestFaultInjection` ("body reached only through an executed binary") shows a covered child's
record narrows to `calc.TestDouble`, `calc.TestNeg`, `calc.TestZero` and `e2e.TestTool`. The
collected Corvint index above shows the rule on the real tree: every test that starts `git`,
`bash` or `go` is divergent and always kept.

Change: `LPCV-V0-954` now states the Go detection rule and its witnesses in its own text (commit
`d48d8e2a3`), so the requirement is traced to tests where the ticket asks, rather than only
through `LPCV-V0-7601`. No code change; the qualified sources are untouched.
