## V1-4501: one fixture environment helper

`testsupport.GoEnv` adds `-buildvcs=false` to a `go` subprocess's last `GOFLAGS` entry, or adds
the entry when it is missing. It keeps an explicit `-buildvcs` setting. The scope is the failure
class: a `go` subprocess whose module sits under `TMPDIR` with no repository of its own. A stray
empty `.git` above `TMPDIR` makes Go's VCS lookup fail with `exit status 128`.
`TestGoEnvBuildsUnderStrayGitDirectory_AFPV07920` reproduces that failure on the WSL lane host
(go1.27.3, linux/amd64), then builds with `GoEnv`.

A survey of the roughly 60 test call sites to `go build`, `go run` and `go test` found two in the
class:

- the linked test-binary builds of `TestADNV0663SymbolSelectionCoversLinkedTestBinaries`
- the offline archive rebuild of `TestCurrentTasksSourceArchiveBuildsOffline`

Both now route through `GoEnv`. The other sites fall into four groups, none of which hits the
failure:

- They build in the checkout, which resolves VCS against the repository's own `.git`.
- They build a `git init`-ed fixture.
- They run with `GO111MODULE=off`.
- They already pass `-buildvcs=false`.

Rejected: converting every site. That would touch about 60 files for no failure. Production builds
and release stamping are unchanged. The `.github/cishards` helpers stay out of scope, because a
`.github` change forces FULL shards and belongs in its own pull request.

## V1-5045: impact --path

`corvint impact` now takes `--path PATH` and `--path=PATH`, repeatable and mixed with positional
paths, as an alias of the positional form. `docs/CAPABILITIES.md` and `corvint repro`'s help
already used `impact --path README.md`. A `--path` with no value names the positional form in its
error.

## V1-5015: env-prefixed VERIFY lines and command substitution

`DCW-V0-804` already admitted leading quoted `NAME='value'` assignments. The blocker was the
leading `env` word. With a quoted assignment after it, the line is now recorded as the typed argv
`["env", "NAME=value", ...]`. Unquoted metacharacters, `env` options and `$` values stay refused.

A `$(...)` or backtick substitution stays refused. The finish-lane refusal now names the line and
the plain replacement:

- `make go-version`, for the AGENTS.md toolchain check
- a committed script, for any other substitution

## V1-5016: dogfood-change names its own fix

`make dogfood-change BASE= TASK= PATHS=` already records both prechange receipts (`DCW-V0-621`). A
lane that runs it without TASK and PATHS reaches the bind with both receipts NOT_OBSERVED. The
no-diff-yet report now ends the absent-receipt lines with one `fix:` line naming that exact
rerun. Rejected: recording the receipts without a task. The query receipt needs the change's
description, and inventing one would be fabricated evidence.
