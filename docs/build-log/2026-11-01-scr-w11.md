## Decisions

- V1-3847:
  - The four Work tests keep their explicit environments and add only `CORVINT_WORK_RUN_PARENT`.
    The production `workChildEnvironment` is not changed: its fixed-`/tmp` fallback is the
    script's contract when no parent is configured.
  - `TestWorkScriptRejectsCallerScratch/ambient-target` asserted that the build lands under
    `/tmp`. It now asserts the configured run parent, else `/tmp`. Its point, never the caller's
    `TMPDIR`, is unchanged.
- The gate reads literals only. Allowed lines carry `// fixed-tmp: REASON`, on the line or the
  line before it, so a gofmt-aligned comment is not needed on a two-line assertion. The four
  allowed sites are:
  - the Darwin socket in `authoritystore` (V1-0778 `sun_path`)
  - the `jstestprovider` socket kinds
  - the `behaviorfalsify` assertion, which writes nothing
  - the live-only npm environment

  The gate is a doc gate, not a `GATE_STEPS` step. CI and batch closeout run `DOC_GATE_TARGETS`.
- V1-3845: `-c` is recognised only as its own argument after `go test` and before `-args`, so
  `bash -c 'go test ./x'` is still refused. `-list` and `-run '^$'` are not exempt (non-goal).
- V1-3851: the resolution applies only when the given path is unreadable and starts with
  `.git/`, so a readable path is used as given. `--plan` uses the same resolution.
- V1-3846: the scope is a tool flag, not a Makefile variable, because the `ledger/go-test` recipe
  is pinned by `STR-V0-006` (`tools/test-commands-check`). A partition failure falls back to the
  scoped patterns, never `./...`.
- One commit carries both V1-3845 and V1-3851. They change the same `heavy.sh` functions and the
  same `lane-scripts_test.sh` group, so splitting the hunks would leave an untested middle commit.
- The `ASD-V0-720` spec text was amended in a second spec commit (marker on the line before),
  still before the implementing commit.

## Friction

1. The corvint MCP server fails to connect (`CONNECTION_CLOSED`) in this session, so Corvint context
   came from the CLI only. Repro: start a Claude Code session with the corvint plugin; the MCP
   tools are listed as failed.
2. The WSL clone does not have `claude/batch-1101b`, so `git log --all --grep V1-38xx` on the lane
   host misses tickets that branch already delivered. The triage needed the Mac checkout. Repro:
   on wsl-lanes, `git -C ~/projects/corvint branch -a | grep batch-1101b` prints nothing.
3. `script/heavy.sh` discarded the manifest's refusal reason (`2> /dev/null`), so a stale manifest
   looked like an unselected package (fixed here, V1-3851). Repro on base: a manifest of another
   HEAD gives only the generic `HEAVY_WHOLE_REASON` refusal.
4. The WSL umask 0002 makes a new lane cache `~/.cache/LANE` group-writable, and the Work tests
   refuse it ("ancestor writable by other users"). Repro: `umask 0002; mkdir ~/.cache/x;
   TMPDIR=~/.cache/x/tmp` then run `go test -run TestWorkScriptPinsGitPreflight ./cmd/corvint`.
   The lane-creation script should `chmod 700` it.
5. `/tmp` on the WSL host is a 16 GB tmpfs at 100%. Any tool that ignores `TMPDIR` fails there.
   Repro: `df -h /tmp`.
6. The lane tickets file is JSON lines, not one JSON document, so `jq .` on it fails. Repro:
   `jq . FILE` reports trailing data.
7. `batch-precheck_test.sh` stops at the first failing case. A base breakage (case 4b, V1-3818)
   hides every later case, so checking a new group needed a patched scratch copy. Repro: run it
   on base `63384e26`; it stops at line 486.
8. The `STR-V0-006` pin on the `ledger/go-test` recipe prevents a Makefile scope variable, so
   scoped ledger runs must call `tools/gate-ledger` directly.
9. The lane env exports `CORVINT_GOCACHE`, and on base that makes `lane-scripts_test` group 7 fail
   (V1-3843, fixed on batch-1101b). Lanes on base must `unset CORVINT_GOCACHE` for that test.
