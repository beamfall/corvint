## V1-1399: gateselect keeps the AFP-V0-023 rule (owner decision)

`gateselect.Select` still selects every declared package when `.corvint/test-read-scopes.json`
is dirty. That is what accepted AFP-V0-050 states: its non-goals name the fast-tier selector
(`tools/gate-affected-select`) and the `corvint test` Go selection that passes the plan through
`internal/gateselect`, and they keep the AFP-V0-023 rule. AFP-V0-023 also limits its own narrowing
to "for the planner". Narrowing `gateselect` would change the text of an accepted requirement.
The standing auto-accept does not cover that, so this lane makes no change and leaves the
decision to the owner.

Feasibility, for that decision:

- `gateselect` reads only the worktree declaration (`readScopes` in
  `internal/gateselect/readscopes.go`). It uses only the standard library, because
  `tools/gate-affected-select` is built apart from this module.
- Narrowing needs two things. The base commit must reach `Select`, for example from the
  receipt's range. The base declaration must be read from Git objects, for example with
  `git cat-file` on `BASE:.corvint/test-read-scopes.json`, together with the same
  package-existence and module-ownership checks as `CommittedReadScopes`.
- It also needs the same fail-closed fallback and a test through `corvint test`.

The amendment would replace the AFP-V0-050 non-goal sentence with a requirement for
`gateselect`, and would remove "for the planner" from AFP-V0-023.

## V1-1400 (a): with `ps` failing, build descendants survived

When `ps` failed, `script/gate-affected-corvint.sh` warned and killed only the build. A
`process_table` function now prints `pid ppid` from `ps`. Where `ps` is missing or fails, it
reads `/proc/<pid>/stat` instead. The command name may hold spaces, parentheses and newlines,
so each record is joined onto one line and the parent pid is read after the last `") "`. The
fallback uses the `read` builtin, so the walk does not fork once per process.

A host with neither `ps` nor `/proc` still kills only the build, with the same warning. This
residual is accepted. On macOS `ps` is part of the base system, so a failing `ps` there means a
sandbox has denied the process listing, and no other process table is available.

Process-group kill was rejected. `set -m` under dash, the Linux `/bin/sh`, turns job control
off when there is no tty ("can't access tty"), so the build stays in the wrapper's group. With a
tty, dash would take the terminal's foreground group, and it stops itself with `SIGTTIN` when it
runs in the background. Measured here: `/bin/sh` (bash) and bash gave the build its own group.
dash did not, and zsh refused `-m`.

Test: `script/gate-affected-corvint_test.sh` adds a `TERM` case with a `ps` that exits 1. The
fixture-only `CORVINT_TEST_PROC_ROOT` stands in for `/proc` (macOS has none). The fake build
writes stat records for itself and its sleeper, and the sleeper's command name is `sl` newline
`) eep`. The case also fails if the wrapper reports that it found no process table. Executing
the wrapper always uses its `#!/bin/sh`, which is bash on macOS, so `GATE_AFFECTED_TEST_SHELL`
runs it under another shell instead.

- BASE: `FAIL: TERM: a build descendant outlived the gate`, with
  `gate-affected: cannot list processes; killing the build only` on stderr.
- Fixed: the test passes through `#!/bin/sh` and with `GATE_AFFECTED_TEST_SHELL=dash`.
- Mutations:
  - Dropping the step past the state field fails with the same descendant line.
  - Reading only the first line of each record (the pre-review wrapper), run under dash, fails
    the same way.

## V1-1400 (b): the base package check ignored module ownership

`CommittedReadScopes` accepted a base declaration naming a directory that a nested `go.mod`
owns, if the directory held a `.go` file. The observer does not treat such a directory as a
package of an observed module. Each declared directory's owner is now resolved the way
`observeModules` and `enclosingModule` resolve it:

- the nearest directory listed by the base `go.work` (the root alone when there is none), or the
  nearest unlisted `go.mod`, at or above the directory;
- a `go.mod` below a listed module's testdata is fixture data and is skipped;
- a directory named `go.mod` is not a manifest, because the observer collects only files;
- a `go.mod` that cannot be checked, or is not a regular file, counts as an owner.

The directory must belong to a listed module, and it must lie outside that module's testdata. It
must also lie where the observer's walk descends: no component may be hidden or in
`affected.SkippedDirectories`, unless the Go plugin admits that name (`build`, `dist`, `target`).
The admitted list is now one variable that both the walk and this check read. An unreadable base
`go.work` makes the base unknown. The check reads the base `go.work`, and one `go.mod` per
directory on each declared path that has one.

The AFP-V0-050 parenthetical ("outside testdata, directly holding a regular `.go` file") is left
unchanged. This implements its "holding no Go package" in the AFP-V0-023 sense of an observed
package. The change only makes more bases unknown, which falls back to the AFP-V0-023 rule.
Whether the parenthetical should also say "owned by an observed module" is left to the owner.

Test: `TestCommittedReadScopesFollowModuleOwnership_AFPV0050` has ten cases. Each also checks
that observing the same tree on disk raises `go:test-read-scopes-invalid` exactly when the base
is unknown.

| Case | Expected base |
|---|---|
| A package below a nested module | unknown |
| A nested module's root | unknown |
| A testdata fixture module | unknown |
| A `go.work`-listed nested module | read |
| The root module beside the nested ones | read |
| A root module that `go.work` does not list | unknown |
| A package beside a directory named `go.mod` | read |
| A package under `vendor` | unknown |
| A package under a hidden directory | unknown |
| A package under an admitted `build` directory | read |

- BASE: 5 of 10 fail (below a nested module, a nested module's root, an unlisted root, `vendor`,
  hidden).
- Fixed: 10 of 10 pass.
- Mutations:
  - Treating every directory as owned by the root module fails the first 3.
  - Skipping the walk check fails `vendor` and hidden.
  - Counting a directory named `go.mod` as a manifest fails that case.

## V1-1401: frontier entries in a full source observation (no defect)

The reproduction observed the Go units of a commit from its Git objects, as the PR #916 lane
did. A scratch test, since removed, called `golang.New().UnitsSource(affected.FSSource(
repository.RevisionFS(...)))` with `gitrun.NewDefaultBudget()`, and observed the worktree for
comparison.

| Commit | Disk units | Disk frontier | Revision units | Revision frontier |
|---|---|---|---|---|
| `595359a1b` | 336 | `go:nested-module-frontier` | 6 | `go:nested-module-frontier`, `go:test-binary-execs-invalid`, `go:test-read-scopes-invalid`, `go:unparsed-source` |
| `d47b0f01e` (main) | 336 | `go:nested-module-frontier` | 6 | the same four |

At both commits the source reader reported `git-budget-exceeded: Git operation budget exhausted`,
and `affected.BuildFS` over a fresh default budget returned that error.

- `go:nested-module-frontier` is expected and also appears on disk.
  `tools/local-authority/go.mod` requires and replaces `github.com/Beamfall/corvint`, and there is
  no `go.work`, so the module stays open (AFP-V0-031, V1-0867). `corvint affected --full` at
  `595359a1b` reports it too.
- `go:unparsed-source`, `go:test-read-scopes-invalid` and `go:test-binary-execs-invalid` come
  from the harness. The frozen default budget is 1,024 Git operations. Once it is spent, every
  read fails, and 330 of 336 packages go unobserved. The declarations then name directories that
  hold no observed package. A product caller cannot get this result silently: `BuildFS` returns
  the reader's fatal error. `internal/delta` declares 801,024 operations and treats exhaustion as
  `immutable-graph-unavailable` with the full suite (immutable-delta-v0, Bounds and failures).
  `CommittedReadScopes` lists only the declared directories and their parents, which fits in the
  default budget here, and an exhausted budget makes the base unknown.

Two residuals, not filed here. `UnitsSource` keeps walking for about 1.5 to 2 minutes after the
budget is gone. An embedder that ignores `Source.Err` gets frontier entries rather than an error.
