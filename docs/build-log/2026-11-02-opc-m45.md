## V1-2929: "native UI witness missing: sidebar"

Root cause. OpenTUI 0.7 (shipped with OpenCode 2.1.3 and 2.2.x) requires a resource owner for
`SyntaxStyle.fromStyles`. The Corvint TUI plugin called it with no owner, so plugin setup threw,
and the host dropped every Corvint TUI slot: no sidebar, so the witness reported only
`native UI witness missing: sidebar`. The host log carried the real error
(`message="plugin operation failed" plugin=corvint... stage=... error="..."`), but the
qualification did not read it.

Decisions.

- `AHI-1960`: `integrations/opencode/src/tui.tsx` passes `ctx.renderer?.nativeScene` as the owner.
  On a host without a native scene the argument is `undefined`, which is the old behaviour.
- `AHI-1961`: the inspector's witness cause appends the host's own plugin failure, read bounded
  (16 MiB) from the isolated host log and limited to `corvint*` plugins, so the next host-side
  setup failure names its error instead of a bare missing slot.

Live evidence (OpenCode 2.2.5, scripted qualification provider, cost $0):

- before the fix: `qualify-opencode --inspector` failed with `native UI witness missing: sidebar`;
- after the fix: PASS, dark and light themes, 46 checks (`native-sidebar` through `light-theme`),
  profile `corvint-opencode-inspector-witness/0`, host `opencode v2.2.5`, no interruption
  survivors. The report states its own limit: UI witness only, no promotion of integration support.

`NOT_RUN`: OpenCode 2.1.3 and 2.2.0. 2.1.3 is no longer installed on any lane host (its Homebrew
Cellar directory was removed; a stale `opencode serve --service` from 2.1.3 still runs from the
deleted binary), and 2.2.0 is not installed. The same OpenTUI 0.7 contract applies to both, which is
an inference, not an observation.

## V1-2717: zero Corvint tool calls in the SWE-bench Pro paired trial

Root cause, in order of weight:

1. Since `AHI-212` (adapter 0.7.26) an idle session carries only `corvint_context`, and its
   description said what the tool returns ("Ranked, revision-pinned files for a task; abstains when
   unsure."), not when to call it. The bundled skill, which does say when ("first when the task
   names behaviour but not files"), is registered only after the first call. Nothing in the idle
   prompt asked for the call.
2. In 8 of 10 sessions of the 0.7.26 rerun the confident candidate frame (`AHI-211`) was injected
   and already supplied file paths, so the agent had no reason to call. The two sessions without a
   frame (p03, p09) also made no call, which points at cause 1.
3. SWE-bench Pro problem statements name identifiers, which makes `grep` the natural first tool.

Decision (`AHI-1962`, amending `AHI-212`): the idle description now names the trigger and the
order: "Call first for a code change, before grep or read: the files to read and edit for the task,
ranked and revision-pinned; abstains when unsure." One sentence, at most 160 characters (the
80-character bound is replaced). Nothing else in the idle surface, injection or unlock changes.
Adapter 0.7.36 -> 0.7.37.

Live evidence. OpenCode 2.2.5 (`/opt/homebrew/bin/opencode`), model `anthropic/claude-opus-5-5`,
`opencode run --standalone --auto --format json`, isolated config with bash, webfetch and
websearch denied, on a disposable Go fixture (one bug in a coupon module, two charters: a
natural-language task and a SWE-bench-style task that names identifiers). Cost is the sum of the
`step_finish` costs; first-step tokens are the first step's prompt tokens.
