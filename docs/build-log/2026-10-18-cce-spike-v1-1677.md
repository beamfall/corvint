Spec: `docs/specs/change-compiled-e2e-v0.md` (job 5 usefulness, Promotion and kill criteria).

  in `packages/desktop-client/e2e` with page models, and a React Router app.
- Dependencies were installed with the repository's pinned Yarn 4.17.1 (`enableScripts: false`).
- Commit rule, fixed before any run: `git log --since=2026-07-01 --no-merges -i
  --grep='^fix\|^\[fix\]\|bug' -- packages/desktop-client/src/components`, the first 10, excluding
  fork merge commits.
- Declarations were the same for every change and were added on top of each commit with
  plumbing-only overlay commits (temporary index, `read-tree`, `update-index`, `commit-tree`), so the
  clone was never checked out. The overlay had:
  - `corvint/appmap.json`, a `react-router/0` router at `src/components/FinancesApp.tsx`, with the

  - three flows written from hosted tests (budget month, settings heading, reports dashboard);
  - `.corvint/e2e-blocks.json`, with environment `serve: ["yarn","start"]`, base URL
    `http://127.0.0.1:3001` and ready path `/`.

## Oracle-review falsifiers

Both were run live on the fixture app (`internal/appmap/testdata/fixture` plus the changee2e
overlay) through `Compile` then `Prove`, from a scratch test file that was not committed.

- **F1, static overlay:** head drops the booking behaviour (the Book button loses `data-action`) and
  writes a static `Booked` into `slot-status`. The verdict reads **DISCRIMINATES**, with proof digest
  `sha256:d6e205fb6f64d7462c8074280f95081f0fa099f68307c9cd6f3cbd2c63aac028` (base `327f63be`, head
  `3c5bbfdb`). So the falsifier holds: an outcome-only oracle accepts a change that removes the
  behaviour it claims to check.
- **F2, no-op seed:** base already books, and head only adds an HTML comment. The verdict reads
  **PRESERVES**, with proof digest
  `sha256:5647a0922138821e3dc06eb6f71c83332927fdf57b89408c19a74ed1737bfa68` (base `10fc97a2`, head
  `625fce05`). So the falsifier holds: job 5 counts this vacuous result as useful when the outcome is
  ADMITTED_AT_BASE.

## Decision

Kill change-compiled V0 test generation as the route to replacing hosted suites. On a real app it
fails at three separate layers:

1. The map: the React dialect finds no screens.
2. The impact hop: every changed span exceeds the reference-graph bound or is unplaced.
3. The oracle form: at most 1 of the 10 fixes is expressible even with a perfect map.

Fixing any one layer still leaves the other two.

Pivot, if the owner agrees: build a discrimination prover that applies CCE-V0-009 and
CCE-V0-016..018 to the existing hosted tests, without compilation. The 4 of 10 fixes that shipped a
hosted e2e test are its direct population. That prover inherits the F1 and F2 holes, so it needs:

- a behaviour-removal control, beyond the BBF render controls;
- a usefulness rule that does not count a PRESERVES verdict on an unchanged outcome.

## Limits

- One repository and ten changes. The upper-bound column is one reviewer's judgement.
- `prove` was not run on the real app, so the 120 s dev-server start and the cost of the serve
  environment there are NOT_OBSERVED.
- The declarations were hand-written by the evaluator, not by the project's own maintainers.
