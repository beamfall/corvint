# 2026-10-21 rehome-1021: CAL-V0-073 and CAL-V0-106 re-homed to CTW-V0-012..013

Tickets: V1-2165, V1-0988, V1-0798. Base: origin/main `f284484ebc613c8b61995f7af3ac53d170973be1`.

## Problem

`CAL-V0-073` (V1-0751 `ticket create --template`) and `CAL-V0-106` (V1-0854 `ticket refine
--batch`) were defined in trailing amendment sections of
`docs/specs/corvint-tasks-agent-leases-v0.md`, after its `## Requirements` section. The OCM intent
reader enumerates only that section, so neither was an OCM obligation; both sat in the RDG-V0-021
outside-section baseline. Batch 1021c tried moving them into the leases section, which pushed it to
258 obligations; OCM refused the whole section (`maxObligations = 256` in
`internal/lrfrepo/ocm.go`) and the batch reverted the move.

## Decisions

- Owner rule (2026-10-17): do not raise the 256 bound; re-home moved requirements into the owning
  domain spec. Pattern followed: the batch-1021d re-home (CAL-V0-380..381 to JRT-V0-015..016,
  CAL-V0-350..353 to ATR-V0-180..183): same text, new ID, a re-homed note, test function names keep
  their old numbers.
- Target spec: `docs/specs/corvint-tasks-intent-worktree-v0.md` (CTW). No Tasks domain spec owns
  ticket authoring commands; the CREATE/REFINE command contract lives in the external TCP-00 and the
  leases spec. CTW is the nearest existing Tasks domain spec: it governs how an agent's intent
  writes (`ticket create` and the other intent mutations) reach the intent store, and its acceptance
  evidence already runs through `corvint-tasks ticket create`. A new spec for two requirements was
  rejected as unnecessary (charter: create one only when nothing fits).
- IDs: `CTW-V0-012` = former CAL-V0-073, `CTW-V0-013` = former CAL-V0-106. CTW-V0 ended at 011 on
  origin/main; `git log --all -S` found no CTW-V0-012/013 on any fetched branch.
- Alias: the leases spec keeps a short `## Re-homed CREATE template and batch refine requirements`
  pointer (no definition line), and each moved section states the old ID is a retired alias. Code
  comments, the `ticket refine --help` text that cites `(CAL-V0-106)` and `TestCALV0073_*` /
  `TestCALV0106_*` names are left unchanged, so no Go behaviour, help byte or receipt changes.
- Acceptance: the moved requirements are accepted under the owner's standing auto-accept
  (2026-10-11), recorded in each definition and the CTW intent status.
- The "check for outside definitions" criterion of V1-0988 and V1-0798 is already delivered by
  RDG-V0-021 (`script/check-requirement-definitions.sh` with the shrink-only
  `script/requirement-definitions-outside-section.txt`); this change removes the two baseline rows.

## Evidence

  spec enumerates CTW-V0-012 and CTW-V0-013, and the leases spec still parses under the bound
  without them. It fails on the base CTW spec (enumerates only CTW-V0-001..011) and passes after.
- `make spec-requirements` regenerated REQUIREMENTS.tsv, INDEX.json and README.md.
- Doc gates and focused tests: see the PR body.

Revert the commit: the definitions return to the leases spec's trailing sections and the two
baseline rows return. No code, wire or store state depends on the IDs.
