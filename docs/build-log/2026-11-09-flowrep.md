## V1-5255: tests that belong to no variation

What was wrong. `flows gaps` reported `no-test` (a variation with no test) and nothing reported an
E2E test that no variation links; such a test was invisible to flow-based selection and to the
flow documentation.

Fix. `flows gaps --flows DIR --provider FILE` reads the `application-flow-selection-provider/1`
document the e2e-safe selection already uses (`internal/appflows/unlinked.go`,
`ReadInventoryProvider`, through the same closed, bounded, secret-screened reader) and joins its
`inventory` against the evaluated links: a test is linked when a non-inferred `test` link from a
variation names its key, the rule `no-test` applies. The `application-flow-gaps/1` document gains
the additive members `inventory` (`state` one of `absent`, `complete`, `partial`, `stale`,
`unverified`; `source`, `tests`, `reason`, `bound_to`), `unlinked_tests` (code `unlinked-test`),
`unlinked_total` and `unlinked_truncated`; the bound is 1024 in test-key order. The inventory
state comes from the provider's declared Playwright discovery receipt through
`typescript.VerifyPlaywrightDiscovery` at HEAD; a provider with no receipt is `complete` as the
author's attestation, named as such. A provider that declares another `flows` directory, cannot be
read or is not a provider is refused whole (exit 2). Without `--provider` the inventory is
`absent` and nothing is claimed. The `corvint.flows.gaps` tool gains the optional `provider` input
and returns the same document.

Tests (`internal/command/flows/flows_report_test.go`): `TestV15255GapsListsUnlinkedInventoryTests`
(absent, complete by attestation with one unlinked and one inferred-only test, every test linked,
unverified for a missing receipt, stale for a receipt bound to commit B naming B, partial and then
complete for a receipt bound to HEAD's config and sources, three refusals),
`TestV15255GapsUnlinkedBound` (1030 unlinked tests give exactly 1024, truncated, total 1030, stable
order) and `TestV15255V15257FlowsToolsMatchCLIVerbs` (tool and command bytes agree with and without
a provider; a stale inventory is visible over MCP; path and directory refusals). The gaps golden
`testdata/flows/gaps.golden.json` gains the absent inventory members and nothing else.

## V1-5257: one report of flow, variation, attached tests and last result

What was wrong. Coverage, gaps, impact and test-evidence were separate answers; nothing showed each
flow, its variations, the tests attached to each and the last observed result in one view.

Fix. `flows status --flows DIR [--evidence FILE]... [--base SHA]` (`internal/appflows/status.go`,
`internal/command/flows/flows_status.go`) writes `application-flow-status/0`: per flow and
variation, the attached tests (non-inferred test links crossed with the variation's projects, as
`flows map` evidence pairs are) and the last recorded `test-run-evidence/0` result of each:
records bound to HEAD's commit and tree from a clean worktree are preferred, among them the last in
evidence order; with only records of another tree the last one is reported `stale` with its
`source_commit`; with none the result is `NOT_OBSERVED`; `STATIC` records never count. A variation
with no attached test carries `no-test`. `--base` runs the `flows impact` pipeline
(`FlowImpactAt`) and keeps exactly the flows it names, with `limited_by_base`, `base` and the
impact graph's `scope` and `unknown`. The bound is 8192 test rows with `truncated` and full
`totals`. `corvint.flows.status` (`flows`, `evidence`, optional `base`) returns the same document;
with a base it takes the flows-impact serialization lock as `corvint.flows.impact` does. The report
computes no `complete`/`incomplete` flow status, which needs the run registry and stays with
`flows gaps`.

Tests: `TestV15257StatusReportsAttachedTestsAndLastResults` (a current pass, a flaky run, a stale
pass on commit B, a STATIC-only test as NOT_OBSERVED, two `no-test` variations, totals,
no-evidence answer, byte-identical repeat, unchanged repository snapshot),
`TestV15257StatusLimitedToChangeAndRefusals` (the `--base` flow set equals the `flows impact` flow
set and carries its scope; unknown base is `unsupported-affected-revision`; unreadable evidence,
`--registry`, a positional, an absent directory and a malformed flow file exit 2 with no report),
`TestV15257StatusBound` (33 projects times 256 test links give 8192 rows, truncated, totals 8454)
and the MCP parity test above (status with and without evidence and base; short base and unknown
member are invalid-arguments; an unknown base is flows-refused).
