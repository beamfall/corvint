## V1-3647: lane hooks silently drop a compound Bash command

Disposition: BLOCKED (scope). Both refusals come from `script/lane-guard.sh`, deployed as
`~/.claude/hooks/lane-guard.sh`: the `&` background refusal and the raw `go test` refusal. This
lane's charter forbids editing either file. No product hook in `integrations/`, `cmd/` or
`internal/` refuses a Bash command. hook-w13's `pre-tool` never sets `permissionDecision`.

The deny is correct: a PreToolUse deny runs no part of the command. Only the message misleads.
Proposed change for an owner-scoped lane: in `deny()`, append one sentence to every reason, for
example `Nothing in this command ran, including any edit before the refused part; rerun the edits
as their own command.` Add a `script/lane-scripts_test.sh` case for both repros,
`python3 edit.py && cmd &` and `sed -i ... && go test ./x`. Then redeploy the hook copy.
The deployed copy already differs from `script/lane-guard.sh` (friction 2).

export carries terminal artifacts such as `corvint/local-outcome.json` (build log
2026-10-31-fric-a-sp1). `TestLCPV0960ImportRefusesGitDirPathOutsideCorvint` passes at BASE.

Residual, suspected and not built (friction 3): a `root`-anchored file that is absent and ignored
by Git is still written at any worktree path. For example, `.corvint/unplanned-reads.enabled` is
ignored in this repository (`.gitignore:25`), so a crafted bundle could set that operator marker.
In an adopter repository it could also plant an ignored executable, such as one under
`node_modules/.bin/`.
