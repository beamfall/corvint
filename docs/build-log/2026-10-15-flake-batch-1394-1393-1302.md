# 2026-10-15 V1-1394, V1-1393, V1-1302: load-sensitive cmd/corvint tests

One lane for three `cmd/corvint` test flakes, all of the same class: a fixed 10-second wall-clock bound
that a test verifying semantics, not latency, inherits from the product (decision 0082). Base
`32c57367d00bc2ee67401a90b8f101e07067dc78` (origin/main after PR #912, V1-1391). No product deadline,
budget, Git-command count or assertion was widened.

## Method

Runs used prebuilt test binaries: BASE (`32c57367d`), the fix, and a mutant (the fix with both test
lifts made no-ops). Contention runs added 64 `yes` burners on this 12-core darwin host (go1.27.1),
started and stopped inside each foreground command; another session kept 24 more burners running.
Paired runs ran BASE and the compared binary concurrently under the same load.

## V1-1394: lifecycle AHI-003 snapshot-stale fallback (refuted at BASE; fixed by V1-1391)

`TestClaudeNativeDogfoodLifecycle/AHI-003_AHI-012_AHI-047_IDX-SNAP-V0-012` failed at merge
`c76e3d790` with `corvint-event-rejected:dogfood-event-index-snapshot-stale`. That merge predates
PR #912. The fallback is the Git probe's fixed 10-second bound expiring over a snapshot miss and its
in-memory index build (`dogfoodExpiryCode(missed)`), the cause V1-1391 diagnosed; its build log already
counted AHI-003 at 5 BASE failures and 0 fixed. #912's `liftedProbeBound` in
`lifecycleDeadlineContext` covers this subtest. IDX-SNAP-V0-012 deliberately exercises the miss path,
so creating a matching snapshot would remove coverage; no new change was made.

## V1-1302: source-view refusals under load

`executeSourceView` runs every Git command under one 10-second context, and each `sourceGit` command
under a 10-second procgroup timeout (ESV-V0-003). The three scripted tests run Git through a shell
stand-in. On a loaded host the bound expired mid-view, and the asserted outcome became the refusal of
whichever earlier command was running. `blob-budget` was one of those: it is the cat-file step's
failure, not the Git-command count. Every failure recorded 1 to 6 Git commands, never more than the
12-command bound.

Fix: `sourceDeadline(ctx)` returns `sourceGitDeadline` (10 s) unless the unexported
`sourceDeadlineKey{}` context value replaces it. Only `_test.go` sets that value, through
`liftedSourceDeadline` (ten minutes, a hang detector). The three tests use it. The head re-verify, the
digest check and the 12-command count assertion are unchanged. `TestSourceDeadlineReplacesFrozenBound`
pins the frozen 10 s and the lift. The ESV-V0-003 traceability row names it.

| Binary | Load (1-min) | Iterations x tests | Failures |
|---|---|---|---|
| BASE | 52-79, ambient | 20 x 3 | 53: object-format 24, stale-commit 13, stale-tree 10, missing-path 5, blob-budget 1 |
| fixed | 51-72, ambient | 20 x 4 | 0 |
| fixed | 116-193, 64 burners | 4 x 4 (5th cut by the 9-minute hang detector) | 0 |
| BASE | 137-230, 64 burners | 4 x 3 | 12 |
| mutant: `liftedSourceDeadline` returns ctx | same, paired | 6 x 4 | 24: all three tests plus `TestSourceDeadlineReplacesFrozenBound` |

Under 64 burners each scripted test took 56 to 169 seconds. The lifted bound is what lets it finish.

The focused rerun before binding found the same class in source-view tests outside the ticket that

the `source_handoff.go` native digest was re-frozen in
`benchmarks/selfuse-batch/source-views-manifest.json` (ESV-V0-005), as in `e4b50dcbd`.

## Independent review

One Codex round (`codex exec -s read-only`, range `32c57367d..d31979bbc`) reported no P1, P2 or P3
finding. It confirmed the seam is unexported and set only from `_test.go`. It confirmed both
production bounds stay at 10 seconds. It confirmed the head re-verify, digest and 12-command
assertions are intact. Its review was static: it did not reproduce the load runs.
The three later commits (`f822ef5ec`, `8afdc930d` and this record) only extend the same test-only
lift to more callers and re-freeze the digest. They were not sent for a second Codex round, under the
one-round cap.

A first local `line-citations-check` failed because the seam had been inserted mid-file and shifted
three pinned citations to `source_handoff.go`. The declarations moved to the end of the file, the three
bound sites kept their line numbers, and the check passed.

## Residual

- The scripted source-view tests take one to three minutes each on a loaded host. That is test cost,
  not a failure.
- BASE also failed `localcompletion.Begin` with `git-timeout` in the ReadOnly setup (`:482`) at load
  about 190. That is the same class in a different seam (`localcompletion`), not covered here.

- `TestSourceViewCancellationTerminatesGitProcessGroup` failed 3 of 3 at both BASE and the fix
  under 64 burners. It asserts a cancelled view returns within 8 seconds, and it cancels after waiting
  up to 10 seconds for a pid file. Those are latency assertions, not the 10-second source bound, so
  they are not changed here.
- `TestClaudeSourceHandoffCLI` failed once in 3 runs at an intermediate fix, and passed 3 of 3 in the
  final paired run. The capture's nested `context` run keeps its own bounds.
- Full `go test -p 1 -count=1 -timeout 30m ./cmd/corvint` runs both hit the 30-minute package hang
  detector at ambient load 55 to 150.
  - The first run, at `b2540001d`, stopped in the sequential phase, so the parallel target tests
    never started.
  - The second run, at `45c3f5b03` with `-v`, passed all 15 `TestSourceView*` tests and
    `TestClaudeSourceHandoffCLI` inside the package run. The ReadOnly and lifecycle tests had not
    finished when the detector fired.
  - Failures outside this lane, all load-shaped:
    - `TestHostAdapterJavaScriptHosts/GOC-V0-008`, at node subtest `AHI-034 cockpit RPC`: `timeout`.
    - `TestContextExpandRefusesWithoutSubstitutingContent`: `git-failed`, not `invalid-handle`.
    - `TestQualifiedLifecycle*` (3 tests): `qualified-lifecycle-unavailable`.
    - `TestAffected*UnknownScope` (2 tests): `git-cancelled`.
  - `TestHostAdapterSourceHandoffPublicationRefusals` (`NOT_PRODUCED stale-commit`) is in this class,
    and `d32a94152` lifts it.
