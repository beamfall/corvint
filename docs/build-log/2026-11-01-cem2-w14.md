## The four 2026-10-31 audits

one-line summaries of each report's conclusion.

- Usage (`cem-audit-usage.md`): CONCERNS. Closeout cost sits in reruns, not in the format; nothing
  in a map is runner-verified; "supported" means "cited", not "shown adequate".

## Decisions

- The body is index-based: `paths` in first-use order, evidence rows `[path, start, end]` (derived)
  or `[path, start, end, blobOid, spanSha256]` (pinned), and hunk rows `[reason, [ev, rel]...]`
  bound to the patch hunk ordinal. Hunk IDs, ranges, display paths, evidence IDs, blob ids, span
  hashes and dispositions are recomputed by the consumer, which is what makes four format-audit
  tamper vectors unrepresentable (CEM2-V0-019).
- Paths are interned in first-use order (evidence order), not sorted, so the encoding is a
  deterministic function of the 1.0 map and needs no extra sort key.
- The encoder abstains with `cem2-unsupported` instead of approximating whenever the 1.0 map holds
  something the body cannot carry: a spec other than `cem/1.0`, another `excludedPath`, criteria,
  receipts, links or artifacts, an explicit `role: "change"` (projection would drop it), a repeated
  or non-derived evidence id, a coverage or discriminates witness, an unknown reason or relation,
  a disposition that is not its reason's, or a dangling basis (CEM2-V0-020).
- A body over any cem/1.0 bound (bytes, hunks, evidence, path bytes) is refused with
  `cem2-bound-exceeded` before any Git read (CEM2-V0-010). The codes are prototype-local, not
  registry entries.
- Hunk order is significant: reordering hunk rows permutes the claims across patch hunks, so the
  projected 1.0 map is different and shows as a byte mismatch, not as an equivalent encoding.
- `GitSource` opens one budgeted `gitauth` repository per map and reads each distinct blob once;
  evidence is resolved at the base tree with the same mode and span rules as the native verifier.
- `internal/cem2proto` is declared in `.corvint/unbounded-readers.json`, not in
  `.corvint/test-read-scopes.json`. Its corpus test resolves every committed map's base and target
  in the repository Git object store, and the unwired test runs `git grep` over every tracked Go
  file; `.git` is unreadable under the confine wrapper, so the reads cannot be declared narrowly
  and the package is selected on every change. `make selection-baseline-check` stays at its floor
  (narrow 12/19, misses 0).

## Tamper-vector analysis

- Made unrepresentable in derived mode (the consumer recomputes the value, so a forged value has
  nowhere to go): `fabricated-evidence-id`, `span-hash-mismatch`, `hunk-ranges-moved`,
  `hunk-id-forged`. Tests: `TestCEM2V0019DerivedVectorsAreUnrepresentable` (a moved range, forged
  hunk id and forged span hash project back to the original; a forged evidence id does not encode).
  In pinned mode a stale or forged blob id or span hash is refused with `cem2-pinned-mismatch`.
  Hunk ids and ranges are not carried in either mode, so pinned mode cannot refuse them from the
  2.0 bytes; a forged 1.0 input is refused only by `EncodeChecked`, which projects against Git
  (see Review fixes).
- Changed meaning: `hunk-reorder` now permutes claims across hunks instead of being refused by an
  ID check (`TestCEM2V0006HunkReorderPermutesClaims`).
- New vectors introduced by the index format, each refused and tested in `refusal_test.go`:
  hunk-count mismatch, index out of range, code out of range, unknown `critical[]` entry
  (`cem2-unsupported-critical`), and `bodySha256` mismatch. The lane also tests patch-sha mismatch,
  pinned mismatch, malformed body, unresolved evidence, non-empty `parents[]` and the bound refusal.
- Still admissible: `span-hash-recomputed` and `evidence-ids-swapped` yield a different but valid
  1.0 map (`TestCEM2V0019AdmissibleClaimEdits`). The format binds what was cited, not whether it
  supports the claim; that stays V1-3771 and is not closed by 2.0.

## Review fixes

An independent Codex review of 477ff9840 returned CONCERNS with four findings. Each was checked
against the code before it was fixed; none was rejected.

1. Fixture git commands inherited `GIT_DIR`, `GIT_WORK_TREE` and `GIT_INDEX_FILE` (confirmed:
   `git()` in `fixture_test.go` used `os.Environ()`). The fixture now drops every inherited `GIT_*`
   variable before adding its own. `TestFixtureIgnoresInheritedGitRepository` points `GIT_DIR`,
   `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_COMMON_DIR` and `GIT_NAMESPACE`
   at a decoy and requires it to stay empty and the fixture's git dir to be its own. It failed
   before the fix (`git add -A`: not a git repository: `<decoy>/git_dir`) and passes after.
   `GIT_ALTERNATE_OBJECT_DIRECTORIES` is left out of the decoy set because `gitauth.Open` already
   refuses it (`unsupported-object-alternates`), which is the native layer's own guard.
2. `DecodeHeader` had no byte bound (confirmed). Decision: a header is bounded at
   `MaxHeaderBytes` = 16384 bytes, checked before parsing, and at `MaxHeaderEntries` = 64 entries in
   each of `parents` and `critical`, checked before the strings are copied and before the
   unsupported-critical and parents abstentions; both refuse with `cem2-bound-exceeded` and no Git
   read. 16 KiB holds 64 parent digests with room to spare, and the committed headers are about
   278 B. `TestCEM2V0010HeaderBoundsRefusedBeforeGit` covers the entry and byte bounds for both
   arrays, and that 64 critical entries still abstain as unsupported. Spec: CEM2-V0-010.
3. Pinned mode did not refuse a forged hunk id or moved range (confirmed: `Encode` drops them and
   `Project` rebuilds them, so the 1.0 input changed silently). Decision: keep the tamper analysis
   honest by adding a refusal, not by weakening the claim to "unrepresentable" alone. Carrying hunk
   ids in pinned bodies would undo the size result, so the check sits in a new `EncodeChecked`,
   which encodes, projects against Git and refuses a hunk whose id, path or ranges differ from the
   rebuilt one (`cem2-hunk-identity-mismatch`) and any other byte difference
   (`cem2-projection-mismatch`), in both modes; pinned digests still refuse with
   `cem2-pinned-mismatch`. Plain `Encode` stays Git-free and is documented as unable to see these
   vectors. CEM2-V0-019 and the failure-mode table were corrected to say so.
   `TestCEM2V0019CheckedEncodeRefusesForgedInput` covers a faithful map in both modes, then a moved
   range and a forged hunk id in each mode, a forged span hash in each mode and a forged evidence
   id. `EncodeChecked` is still unwired (CEM2-V0-001).
4. The size table's "body" rows included the headers (confirmed: the measurement summed header
   and body bytes). The table is relabelled and a header and body-alone split added: bodies alone
   are 290,775 B derived (5.2%) and 870,035 B pinned (15.6%). The measurement test now logs the
   header total and both body-alone sizes; it asserts only that the 2.0 forms are smaller than 1.0,
   so no assertion changed.

## CEM 2.0 audit revision

The owner-requested CEM 2.0 audit of 2026-11-01 (V1-3978, V1-3979) found that the intent above was
rebuilt from a false premise and that the codec prototype had unbounded inputs. This section
records the revision; the text above stays as the record of the first draft.

### Decisions

- The "Lost source" section above is wrong: the owner's Mac Tasks store holds the plan in full as
  V1-2600 to V1-2609. Only the WSL lane store lacked those tickets. The intent now cites them as its
  source, restates the user job, north star, guardrails (cost no greater than 1.0, incremental equals
  full rebuild, zero invented certainty) and stop-loss, and keeps the loss record as a correction.
- Plan order: V1-3980 (content-keyed claims, incremental closeout) first, because reruns (V1-1629),
  seals (V1-3667) and reseals (V1-3475) are the measured cost; then the V1-2600 value replay as the
  kill gate before any 2.0 wire work; the compact codec only as an optional transport experiment.
- The codec is a transport over the unchanged 1.0 logical model. Attestation stays cem/v2 over the
  projected 1.0 bytes plus the exact target commit and tree, because `internal/attest/cem_v2.go`
  already signs exactly that; the 1.0 sidecar stays authoritative, because `interop/cem01-go`
  compares it; pinned mode leaves the default; `inherited` is orthogonal provenance, not a sixth
  trust class.
- Dispositions: KEEP CEM2-V0-001, 006, 008, 011, 012, 014, 016, 020; CHANGE 002 to 005, 007, 009,
  010, 013, 015, 017 to 019, 021, 022. Each requirement line opens with its disposition, after the
  colon, because the requirement generator reads a parenthesis after the ID as an acceptance note and
  dropped those rows when the disposition sat there.
- New requirements CEM2-V0-023 (span rule), 024 (bases per hunk, aggregate references, expanded
  output) and 025 (hostile and fuzzed input never panics).
- Size figures are labelled unsigned representation bytes. The delta "quarter" saving, "a CEM is
  about a tenth of its patch" and "keys are the majority of bytes" were not reproduced on this base
  and are marked NOT_OBSERVED or removed.
- V1-3978's premise that `[p,-5,3]` decodes is inaccurate: `wire.Parse` refuses negative integers
  ("negative numbers are outside the wire integer range"), so a negative start never reached the
  resolver from bytes. The slice panic was reachable only through an in-process `Body`. Both layers
  now refuse it: `DecodeBody` refuses a span outside `0 <= start < end` as malformed before Git, and
  `resolveEvidence` refuses a negative start.
- Aggregate reference bound: `wire.MaxMapBytes / 119`, where 119 bytes is the shortest canonical
  basis object a projection emits, so any body over it cannot project within the 1.0 byte bound; it
  is tighter than 2048 hunks times 32 bases. An over-bound projection maps the encoder's
  `cemcode.MapUnavailable` to `cem2-bound-exceeded`.
- `TestCEM2V0001PrototypeIsUnwired` walks named top-level trees instead of running `git grep` over
  the repository root, and the corpus test derives the repository from `.corvint/changes`, so the
  affected planner no longer classifies `internal/cem2proto` as an unbounded reader; its
  `.corvint/unbounded-readers.json` entry is removed.
