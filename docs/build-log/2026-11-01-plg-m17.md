## V1-3894: plugin "stale corvint-mcp" and CONNECTION_CLOSED

Disposition: root cause found; repo-owned part delivered (`AHI-860`, README); the server-side
widening is blocked by lane scope (`internal/mcp/cli/` is owned by an in-flight lane).

The ticket's diagnosis (plugin cache 0.3.6 launches a stale `corvint-mcp`) is refuted:
`~/.claude/plugins/installed_plugins.json` records `corvint@corvint` 0.3.8 (lastUpdated
2026-11-01T12:11:19Z), whose `.mcp.json` runs `corvint mcp`, and both `~/.local/bin/corvint` and
`corvint-mcp` were build 40. The 0.3.6 directory is an unused cache leftover.

Cause, from the host's own evidence:

- The Claude Code MCP log for this repository,
  `~/Library/Caches/claude-cli-nodejs/-Users-russelllewis-projects-corvint/mcp-logs-plugin-corvint-corvint/2026-10-31T20-56-54-551Z.jsonl`,
  records `version negotiation probe closed the stdio server (rmcp-class pre-init hard close);
  respawning pinned legacy`, then `Server stderr: corvint-mcp: repository unavailable`, then
  `Connection failed (CONNECTION_CLOSED)`. The same sequence appears in the oscillux (00:14Z) and
  beamfall-workspace (12:22Z) logs. Those sessions ran binaries built before `MCPV0-950`, which
  exit 2 on an unusable root.
- `ps` showed live servers started as `corvint mcp --root /Users/russelllewis/.claude/spares/spare-tXk8RZ ...`.
  For one of them, `lsof` gave cwd `/Users/russelllewis/projects/corvint`, its environment held
  `CLAUDE_PROJECT_DIR=/Users/russelllewis/projects/corvint`, and its parent was the Claude desktop
  process (`CLAUDE_CODE_ENTRYPOINT=claude-desktop`). So a Claude desktop spare session expands
  `${CLAUDE_PROJECT_DIR}` in `.mcp.json` argv to the spare directory while the server's cwd and
  environment name the real project. The spare directory exists at launch and is deleted later.
- `MCPV0-115` substitutes the launch worktree only for a root that does not exist. An existing spare
  directory outside Git therefore reached the unusable-root path.
- With build 40 (`MCPV0-950`), the 14:49:45Z log shows `--root is not inside a Git worktree; serving
  tools/list, and every repository tool call answers invalid-root` followed by `Successfully connected`.
  The connection no longer closes, but every repository tool answers `invalid-root` in such a session.

Live probes on this host: `claude mcp list` reports the plugin server Connected from a non-repository
directory and from this worktree. Stdin probes of `corvint mcp` and `corvint-mcp` with the repository,
a missing spare, an existing non-Git directory and a literal `${CLAUDE_PROJECT_DIR}` all answered
`initialize` and `tools/list` with exit 0. AC1 (a version-mismatch hint) is already met by `V1-3702`.
For example, `CORVINT_PLUGIN_VERSION=claude-code/0.3.6` with an undeclared tool makes
`corvint.status` `_meta` `io.corvint/pluginCompatibility` report `compatible: false` and list the
missing tool.

Delivered:

- `AHI-860` in `docs/specs/agent-harness-integration-v0.md`, with
  `TestAHI860ClaudePluginHandshakeAcrossProjectDirShapes` (`cmd/corvint`). The test runs the
  plugin's declared args in a helper process, with cwd set to the repository, for each observed
  substitution: the repository, a subdirectory, a deleted spare, an existing non-Git spare and the
  unexpanded variable. For every shape it asserts the 2025-11-25 handshake, `tools/list` equal to
  `CORVINT_PLUGIN_TOOLS`, and exit 0. For the first three shapes `corvint.status` must answer from
  the repository with the plugin compatible. For the last two it must answer `invalid-root` with the
  reason on stderr.
- `integrations/claude-code/README.md` MCP paragraph. The stale sentence "outside any worktree it
  still fails to start" is replaced with the `MCPV0-950` behaviour. The paragraph now also says where
  the host keeps the server's stderr behind `CONNECTION_CLOSED` and how to recover.

Blocked (lane scope, not external). The exact proposed change, for the `internal/mcp/cli` owner:

- In `internal/mcp/cli/missing_root.go` `missingRootFallback`, also accept an existing root when
  `rootbind.Resolve(roots[0].root)` returns `rootbind.ReasonNoWorktree`, provided the launch
  directory resolves to a worktree.
- Give that case its own notice code, `non-worktree-root-launch-worktree`, and its own stderr line:
  `corvint-mcp: --root is not inside a Git worktree; serving the Git worktree enclosing the launch
  directory instead`.
- Amend `MCPV0-115` to say so. Flip the "existing directory outside Git" case of
  `TestMCPV0115FallbackIsNarrow` and add a positive test.
- In `cmd/corvint`, change the `existing non-worktree spare` case of the AHI-860 test to expect a
  repository answer.
- An alternative (host-specific, not preferred): when `CLAUDE_PROJECT_DIR` names a worktree and the
  argv root does not, prefer the environment.
- A `/bin/sh` launcher like Codex's was rejected because it cannot run on Windows.

Owner and install-side steps:

1. Restart any Claude session started before the build-40 binaries were on `PATH`. Its server
   closed at start and is not retried.
2. `claude plugin marketplace update corvint`, then `claude plugin update corvint@corvint`, picks
   up 0.3.9 when it ships.
3. Until the proposal above lands, a Claude desktop spare session whose spare directory still
   exists gets `invalid-root` from every repository tool. Start the session from the repository.
4. Upstream: report to Claude Code that desktop spare sessions expand `${CLAUDE_PROJECT_DIR}` in
   `.mcp.json` argv to the spare directory, while the server's cwd and `CLAUDE_PROJECT_DIR`
   environment are the real project.

## Friction

   rejects the flags. Workaround: `/bin/ls`.
2. `git grep -n PATTERN -A20 -- path` fails with `unable to resolve revision: -A20`, because options
   must come before the pattern. Expected: the context lines. Actual: a fatal error.
3. Claude Code hides the server's reason behind a bare `CONNECTION_CLOSED`. Repro: start a session
   whose server exits with a stderr reason. Expected: the reason in `/mcp` or the session. Actual: it
   is only in `~/Library/Caches/claude-cli-nodejs/<project>/mcp-logs-*`. Documented in the README.
4. Claude desktop spare sessions expand `${CLAUDE_PROJECT_DIR}` in `.mcp.json` argv to the spare
   directory, while the server's cwd and environment are correct. Expected: the project directory.
   Actual: `~/.claude/spares/spare-*`. This is upstream; see owner step 4.

   logs. Actual: the installed plugin was 0.3.8 with build-40 binaries.

   is delivered, either on an unmerged lane branch or on main awaiting close. Every one had to be
   re-screened.
