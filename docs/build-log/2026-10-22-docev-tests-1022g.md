# Docs-evidence test sweep: baseline timeouts, adapter policy boundary, Tasks lease latency (lane docev-1022g)

Lane docev-1022g, base `f29ddc0db09c01c370cd3c9bcc5022a296ae3876`. New requirement `FPK-V0-143` in
`docs/specs/falsifiable-packet-v0.md` (revision 32), accepted under the owner's standing lane
auto-accept (2026-10-11). The V1-0468 change adds a test and a named limitation to `NTP-V0-001`; it adds
no new requirement ID.

## Problem

- **V1-2199.** The ticket asks for a live Go mutation run under host load at least 30, to show that
  loaded runs no longer end without a verdict. The run made here had no such rows. But 34 claims
  reported `baseline tests fail before mutation`, and those cited tests pass when run alone. The
  cause is go test's own `-timeout`. The runner passes `-timeout <per-run share>`. On a loaded host,
  go test's alarm ends the test binary first. go test -json then prints `panic: test timed out after
  T` as output of the running test, followed by only the package `FAIL`. The running test gets no
  `fail` event. The runner classified that run as a red baseline, which is a false claim about the
  tests.
- **V1-0468.** The fixture adapter accepts only the `taskman-policy/0` policy profile, but no test
  covered that boundary.
- **V1-2205.** The decision 0549 latency targets T1 and T2 need one B2 measurement on a quiet host.

## Decisions

- **Alarm means budget, not red.** `baselineFailure` reports a failed baseline whose output holds the
  alarm marker as `BUDGET_EXCEEDED`, with detail `per-run limit of T reached during the baseline run`.
  A failed baseline without the marker keeps the `UNSUPPORTED` red-baseline detail. In `baselineGroup`,
  a test that reports its own `fail` event stays red. A claim with no attributed outcome goes to
  `baselineAlone` and gets the new classification.
- **Alarm survives the output cut.** The detail buffer keeps only the first 64 KiB. The event sink
  saves the alarm line when it streams past (`eventSink.timeout`). `runGoTest` appends that line when
  the buffer cut it off.
- **Mutant runs unchanged.** When the alarm ends a mutant run, it still counts as a kill, as
  `runGrace` intends. Residual question: on a heavily loaded host, this can record a false kill.
- **V1-0468 test.** `TestNTPV0001AdapterPolicyProfileBoundary` refuses policy profiles `/1`, an
  unknown profile, and a non-string profile. It also covers an unknown `externalReviews` key.
