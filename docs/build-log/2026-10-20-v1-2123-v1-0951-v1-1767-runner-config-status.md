## Decisions

- **V1-2123.** After launch, `finish` now reports `UNCERTAIN_EFFECT` when `wire.CodeOf` would give
  `MALFORMED`. That covers an uncoded filesystem error and a receipt refused without a code (via
  `refusal`). The ticket left the code choice open.
  - `UNCERTAIN_EFFECT` is already in the closed set (§11) and is not retryable. The command ran, and
    whether its outcome is recorded is unproved, which is exactly what that code means.
  - No new code was added.
  - The exit status (127, or 2 under HOLD) and the run item are unchanged. Coded failures such as
    `LOCK_TIMEOUT` keep their code.
  - A test-only seam, `attemptOutcomeReportFault`, rewrites the outcome write's report so a test can
    inject an uncoded refusal.
- **V1-0951.** `DecodeConfig` first runs one `encoding/json/jsontext` token pass. It refuses a
  repeated member at any depth and names its JSON pointer.
  - jsontext matches names exactly after unescaping, so an escaped spelling of a member counts as a
    repeat.
  - Case-folded aliases stay the strict decoder's concern, as `CAL-V0-064` keeps them for the ledger.
  - Other syntax errors are left to the existing strict decoder, so its messages do not change.
- **V1-1767.** `dispatchStatusValueFor` treats a nil `*dispatch.Config` as
  `&dispatch.Config{StateDir: dir}`, the same fallback `dispatchAuxConfig` gives production callers.
  It chooses rendering over a typed refusal, because production never passes nil and the empty
  configuration is already the documented fallback.
