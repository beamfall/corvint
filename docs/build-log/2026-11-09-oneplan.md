## Decisions recorded before code

- Declaration: a new tracked file `.corvint/flows.json`, profile `corvint-flows/0`, members `flows`,
  optional `kinds` (path-prefix rules for `unit` and `integration`) and optional `playwright`
  (`config`, `discovery`). Not `.corvint/workspace.json` (machine checkouts, not evidence) and not
  `.corvint/e2e-flows.json` (requires a binary consumer, which a Playwright-only adopter lacks).
- Member names: `testKind`, not `kind`, because a selection's `kind` is already the AZU-V0-001 driver
  kind. E2E selections are the new `plan.e2e` member, keyed by (project, path), not entries of
  `plan.selected`, so a reader of `plan.selected` sees the same units (APK-V0-005).
- Wire: additive optional members under the unchanged `affected-plan/0` and `affected-plan/1` names.
- Invalid declaration: the E2E member is `UNKNOWN` with `FLOWS_DECLARATION_INVALID`, not exit 2, for
  the same reason AFU-V1-1654 chose an unknown in the one planning tail that `corvint affected`,
  `corvint test` and a review's plan share.
- Links are evaluated at the measured commit (the resolved `--base`, else HEAD), as the e2e-safe
  profile does: a change to a reviewed target is a reach, not a stale link. Found while running the
  first CLI test (the HEAD evaluation marked the changed `src/checkout.ts` link stale); the spec was
  changed first (`ee6d51d2f`), then the code.

## V1-5251: one answer for unit, integration and E2E, each selection with its kind

What was wrong. `corvint affected` returned static units; E2E selection needed
`--provider FILE --selection-profile e2e-safe` and arrived as `advice.test_selection` with reason
codes but no flow or variation; the flow join was `corvint flows impact`; no selection carried a
test kind.

Fix. `internal/appflows/flowplan.go`: `ReadFlowsDeclaration`, `KindOf` and `JoinFlowPlan`, called
from `planAffectedGraph` after `BindE2EFlows` for a plan over the repository worktree. The join
reads the intents at HEAD, evaluates links at the measured commit, selects the test files of every
variation a reached link selects (naming flow, variation, changed path and target), widens for a
stale or unreviewed link (per flow), a global path, an unbounded plan unknown or an exceeded bound,
and assigns `testKind` by longest-prefix rule, `UNKNOWN` when no rule or two kinds match. New plan
types in `internal/liveverify/affected/e2eplan.go`; `plan.e2e` and `testKind` carried by the compact
plan (`affected_compact.go`) and printed by `--format text` (`affected_text.go`); help text in
`help.go`; `docs/CAPABILITIES.md` row and `internal/capcatalog/catalog.json` regenerated.

Tests. `internal/appflows/flowplan_test.go`: `TestAPKV0001OnePlanForEveryKind_V15251` (declared, and
no-declaration plan `DeepEqual` to the plan before the join), `TestAPKV0002EverySelectionCarriesItsKind_V15251`,
`TestAPKV0003E2ESelectionsNameFlowAndVariation_V15251` (two variations, one file, both rows),
`TestAPKV0004FlowEvidenceFailsClosed_V15251` (stale link, reviewed target changed and measured at its
base, inferred link, global lockfile, five invalid declarations), `TestAPKV0006DeterministicAndReadOnly_V15251`,
`TestAPKV0007AgreesWithFlowsImpact_V15251`. `cmd/corvint/affected_flowplan_test.go`:
`TestAPKV0001OnePlanForEveryKindViaCLI_V15251` (plain `--base`, no other option) and

## V1-5252: derive the E2E inventory from Playwright discovery

What was wrong. The e2e-safe selection needed a hand-written provider file listing every E2E test;
a test missing from the list could never be selected.

Fix. With the `playwright` member, `JoinFlowPlan` checks the config is tracked at the measured
commit, reads the receipt as a file and binds it through `typescript.VerifyPlaywrightDiscovery`
(HEAD, config bytes, source digest); the inventory is the receipt's (project, test) units. A file no
flow links is selected as `unlinked` and listed under `inventory.unlinked` (AFU-V1-141). A missing,
malformed or mismatched receipt or an untracked config gives scope `FULL`, selects every file the
flows attach with `inventory-underivable` and the unknown `E2E_INVENTORY_UNDERIVABLE` whose hint names
`corvint affected discovery` (AFU-V1-142, AFU-V1-143). No process is started (AFU-V1-144). With
`--provider FILE --selection-profile e2e-safe`, `appflows.ReconcileProvider` records
`inventory.source: provider` and `providerOmits` (AFU-V1-145); `advice.test_selection` is unchanged.

Tests. `TestAFUV1140DerivedInventorySelectsUnlinkedTest_V15252` (inventory from the receipt, a new
test inventoried once the receipt is refreshed, flows-only inventory without the member),
`TestAFUV1142UnderivableInventoryFailsClosed_V15252` (missing, malformed, stale receipt, untracked
config), `TestAFUV1145ProviderPrecedenceIsRecorded_V15252` in `internal/appflows`;
`TestAFUV1144PlanReadRunsNoProjectCode_V15252` (a config that writes a marker file; the marker is
absent and the receipt still binds), `TestAFUV1142MissingReceiptViaCLI_V15252` and
`TestAFUV1145ProviderWinsViaCLI_V15252` in `cmd/corvint`.

## Limits

- The `affected-summary/1` verdict, and so the `corvint.affected` MCP tool, do not yet count E2E
  selections; the full and compact plans and `--format text` do.
- A plan over a materialized snapshot (review) carries no `e2e` member.
- Inventory granularity is the test file; per-test keys come from flow links only.
- A flow with an inferred or unreviewed link runs every test it attaches on every change, by
  design (no narrowing authority, AFU-V1-008); the hint names the review as the repair.
