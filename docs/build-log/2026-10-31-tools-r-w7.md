    provenance would misstate the table's source.
- **V1-1148 criterion 1** (owner decision).
  - Re-measured on this base, `tasks-scale gen --tickets 1000` took 376.6 s: 114 s for the first
    500 tickets, 262 s for the second, with 2,193 receipts.
  - One `ticket create` at 1,000 tickets takes 233-338 ms and allocates 144 MB. pprof shows its CPU
    in:
    - `transaction.loadTickets` decoding every ticket;
    - `intent.LoadExpecting`/`decodeTreeIndexed`;
    - `intent.WriteClosedIndex`;
    - `journal.Reader.AuditForWriter`.
  - So each write is O(tickets) and gen is O(tickets²). A sublinear write needs the cross-call
    stat-keyed intent cache that V1-0910 proposes. Decision 0549 F1 declined that cache, and
    V1-0910 carries the owner hold `owner-decision` ("building it reverses that decision").
  - A harness shortcut that writes ticket files directly would stop building the store through
    the product writers, which is the point of `gen`, so it was not taken.
