## Review round 2026-11-04b: shard GOFLAGS, seal-mode hints, receipt framing

One P1 and three P2 findings were repaired. Each regression failed before the repair and passes
after it.

- P1: `go-test-shard.sh` inherited GOFLAGS, so `GOFLAGS=-skip=TestA` (or `-list`,
  `-test.skip`) silently dropped tests from every slice. Both the inventory and execution calls
  now pass `-skip= -short=false -c=false -n=false -fuzz= -exec=` (execution also `-list=`);
  command-line flags override GOFLAGS. Any GOFLAGS word outside a build, output and test-control
  allowlist refuses `inherited-goflags-unsupported` before any test runs, and an unreadable
  `go env GOFLAGS` refuses `goflags-unreadable` (DTL-V0-007,
  `TestDTLV0007InheritedGoflagsKeepCoverage`).
- P2: rerun hints from `SEAL=0` or `--seal no` runs dropped the stop-before-seal mode, so a
  retry would seal. Make-entry hints now keep `SEAL=0`, direct finish-lane hints keep
  `--seal no`, and the never-sealing inputs-check entry carries neither. The Makefile passes SEAL
  to dogfood-inputs-check so a closeout retry keeps it (DTL-V0-004,
  `TestDTLV0004RetryKeepsStopBeforeSeal`, `TestDTLV0004FinishStopsAfterCheck`,
  script/dogfood-cache_test.sh).
- P2: heavy.sh's list-only admission honored only the `-list` spelling, so `-test.list=`,
  `-args -test.list=`, or an inherited GOFLAGS `-exec` could run tests unbudgeted. It now keeps
  the whole-package policy for any `-test.` argument, anything after `-args`, a non-empty
  `-exec`, or an inherited exec not cleared by `-exec=`. The same alias class applied to the
  `-run` selection, so a `-test.run` alias now also keeps the whole-package policy
  (DTL-V0-007, `TestDTLV0007ListAliasAndArgsRefused`).
- P2: `TestAHI803SiblingRepositoryEditIsAttributedToItsOwner` compared the attribution to the
  whole receipt, which now carries cause/fix diagnostics first. The test now checks the exact
  frame: receipt line, one diagnostic pair per named code, then the attribution (DTL-V0-002).

Choices recorded:

1. inputs-check accepts `--seal yes|no` only so its hints keep the mode; it binds nothing.
2. The static pre-check skips, rather than drops SEAL=0, when the installed binary lacks `--seal`.
3. The `-test.run` alias refusal extends the review's list-alias finding to the same class.
4. Fail closed over modelling: all `-test.` arguments and anything after `-args` keep the
   whole-package policy instead of parsing the test binary's flags.
5. An inherited exec is neutral only when the command line passes an empty `-exec=`.
6. The shard recipe uses neutralizers plus an allowlist; `-json` is excluded because it changes
   the output the recipe parses. GOFLAGS read from a remote host's go env file beyond the
   cleared flags are not checked (named limit).
7. The AHI803 repair is test-only; the receipt format is unchanged.

Rollback: revert the shard neutralizers and allowlist, the `list_only`/`run_aliased` additions,
the `--seal` hint paths, and the test change; the prior admissions and hints return.

## Review round 2026-11-04c: `--` selection, relative scratch root, PreCompact diagnostics

The independent review of `c97cbf0fe` returned three P2 findings, all fixed with a regression
test that failed before its fix:

- P2: `list_only` ignored `--`. go passes `--` to the test binary, which stops parsing flags
  there, so `go test ./p/ -- -list=TestA` ran the whole package while logged as list-only.
  `list_only` now refuses on `--`, and a new `flags_terminated` keeps a `-run` with a later `--`
  under the whole-package policy (DTL-V0-007, `TestDTLV0007ListAliasAndArgsRefused`; before the
  fix the first `--` case was admitted with rc=0).
- P2: a relative CORVINT_SCRATCH_ROOT that does not exist made `free_gb` loop forever, because
  `${d%/*}` of a slash-free name never changes. `tmpfs_defaults` resolves a relative root against
  `$PWD`, and `free_gb` resolves a relative path and stops at `/` or `.` (DTL-V0-014,
  `TestDTLV0014RelativeScratchRootTerminates`, bounded at 20 s; before the fix it timed out).
- P2: a malformed-JSON PreCompact fallback emitted plain text that starts with the pin-unavailable
  line, so the cause/fix check never saw the frame. `compactionPlainOutput` now applies the
  diagnostics before adding the prefix (DTL-V0-002,
  `TestDTLV0002PreCompactPlainFallbackDiagnostics` reads the final emitted stdout; before the
  fix the pre-compact text had no `cause:` line). `TestClaudeCompactionDegradationIsPlainText`
  pinned the undiagnosed text and now expects the diagnosed frame.

Choices recorded:

1. `--` anywhere after `go test` fails closed for both `-list` and `-run`; heavy.sh does not model
   which side of `--` a flag sits on.
2. The relative root is resolved in `tmpfs_defaults` so the disk check and the command use the same
   absolute path; `free_gb` also resolves and terminates on its own, for any caller.
3. The PreCompact repair diagnoses the whole output map before the prefix; a frame that already
   names its cause (the pin-notice remediation) keeps it unchanged.

A self-review of the round diff added two controls: an argv `TMPDIR` override that is a missing
bare name reached the same `free_gb` walk, so the bounded test also covers it; and the `-run`
refusal is checked to name its `--` cause. Mutating `free_gb` back, or disabling
`flags_terminated`, fails the tests (a 20 s timeout, and `go test ./p/ -- -run TestA` admitted).
The two heavy.sh tests also pass on Darwin (bash 3.2, BSD df) as well as Linux.

Rollback: revert the `--` checks, the relative-root and walk-termination lines, and the
diagnostics call in `compactionPlainOutput` with the updated test expectation.
