# 2026-10-16 V1-1513: executable evidence for STR-V0-004 and STR-V0-011

V1-1513 follows the V1-1257 promotion-evidence audit (PR #988). That audit left two session test
runner requirements without executable evidence. STR-V0-004 was partial because there was no
versioned LPCV-V0-021 capability manifest. STR-V0-011 held only by construction. This change adds
the evidence and updates only those two traceability rows in
`docs/specs/session-test-runner-v0.md`. No requirement text changed, so `REQUIREMENTS.tsv` is
unchanged. The spec status did not change either: promotion is a later step, after #988 merges.

Base: `origin/main` `d147d68f3`.

## Contracts and decisions

- STR-V0-004. Each registered adapter (`go`, `declared`) now carries an in-process
  `AdapterManifest`. It has profile `corvint-test-adapter/0` and states exactly `cancel`,
  `discover`, `execute` and `plan`. That set is the discover/plan/execute/cancel subset of the
  LPCV-V0-021 provider operations that STR-V0-004 names.
  - `Runner.Execute` checks each adapter of the shard before any version probe or `go list`. An
    adapter is refused when:
    - it has no manifest;
    - its manifest names another adapter or another profile;
    - its manifest lacks a required operation (absence is never read as support);
    - its manifest states an operation outside the set, or a duplicate.
  - A refused adapter's invocations are dropped and the reason goes into `incomplete`, so the run
    is `INCOMPLETE`. Adapters that pass the check still run.
- Wire decision: none was needed. The manifest is never serialized. It is not in the
  `corvint-test-run/0` receipt, whose fields STR-V0-010 fixes, and it is not in any command output.
  `corvint-test-adapter/0` is an internal version label. Emitting the manifest, for example in a
  discovery command or a receipt, would be a wire change and needs its own requirement.
- STR-V0-011. The rule is that receipts have no reader other than `corvint test verify-shards`:
  `runTestVerifyShards` over `sessiontest.ReadReceipt` and `Verify`. The test fixes the exact set
  of receipt sites in product code, meaning non-test Go plus scripts, workflows and Makefiles. In
  Go, a site is:
  - a use of `ReadReceipt`, `Receipt`, `ReceiptProfile` or `Verify` through the sessiontest import;
  - a package-local use of one of those names inside `internal/sessiontest`;
  - a dot-import;
  - a string literal holding the receipt profile or the `test-run.` / `test-run[` file name.

  Outside Go, a site is the same profile or file-name literal, in files with a script, workflow
  or make extension, in `Makefile`, or in an extensionless file that starts with `#!`. A new site fails the test until a
  reviewed requirement admits it. The test lives in `cmd/corvint` because `internal/sessiontest`
  is Landlock-confined by `.corvint/test-read-scopes.json` and cannot walk the repository.
  `cmd/corvint` is already an unbounded reader.

## Review

One Codex round (read-only) reported three P2 findings. All three are fixed in this change, and
each fix has its own mutation in the table above.

1. Extensionless scripts were not scanned, and the repository has some, for example
   `script/corvint-work-queue`. The walk now scans extensionless files that start with `#!`.
2. The Go prefilter matched only a double-quoted sessiontest import, so a raw-string import that
   reads a receipt escaped detection. The prefilter now matches the bare import path, and a spy
   covers the raw-string case.
3. No execution test refused a declared adapter. `TestSTRV0004RunnerRefusesAdapterWithoutManifest`
   now runs a declared unit without the declared manifest and checks that its command is neither
   probed nor run.

## Limits

- The STR-V0-011 scan is static. It misses a reader that builds the receipt path without the
  profile or file-name literal and never names a sessiontest receipt symbol, for example by
  decoding arbitrary JSON from a computed path. Review remains the control for that case.
- Untracked local files under scanned directories can fail the test locally. CI scans only the
  checkout.
- The manifest proves registration and version before launch. It does not prove at run time that
  each operation it states works. Cancellation is still covered by the existing process-group
  tests.
- The ticket's touch paths name `internal/testrunner/`, but the code is in
  `internal/sessiontest/` and `cmd/corvint/`.

Rollback: revert this change. Without it, STR-V0-004 and STR-V0-011 return to partial and by
construction.
