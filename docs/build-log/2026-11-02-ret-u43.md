## Diagnosis: where the 1,728 gold files go

| bucket | files | share |
|---|---|---|
| in no arm's top 20 (corvint, bm25:ident, bm25:all) | 940 | 0.544 |
| hit by the confident tier | 249 | 0.144 |
| missed, but in bm25:ident's top 20 | 140 | 0.081 |
| hit by a widening row | 131 | 0.076 |
| row abstained; gold in no top 20 | 119 | 0.069 |
| missed, in bm25:all's top 20 only | 114 | 0.066 |
| row abstained; gold in bm25:all or bm25:ident | 35 | 0.020 |

- **Vocabulary gap (dominant).** 54% of gold files appear in no lexical arm's top 20, so neither
  the query's anchor extraction nor any re-ranking of these lists can reach them. Closing that gap
  would need relations no lexical channel carries; embeddings are out of scope (invariant 7).
- **Answer length is limited by precision, not by budget.** Rows: 169 confident-only, 183 with
  widening rows, 41 abstained. Answer sizes 0-4: 185 rows; 5-9: 87; 10-14: 68; 15-19: 50; 20: 3.
  So the `--limit` is almost never what stops an answer. Packets on 120 rows show why:
  `withheld` names "rows name no task identifier" on all 120, the cap of 10 on 47 and the 50%
  floor on 35. Marginal precision falls with rank: confident rows 0.161, widening rows 0.117,
  answer positions 1-5 / 6-10 / 11-15 / 16-20 0.186 / 0.112 / 0.065 / 0.025, and bm25:ident
  positions 6-20 0.04-0.06. Any row added past the current cutoff is less precise than the
  answered mean (0.18).
- **Abstention.** 41 rows abstain, holding 154 gold files. Only 35 of those files are in a
  lexical top 20. An abstained row scores precision 1, so answering these rows costs the most
  precision per file recovered.
- **Test paths** are 8% of gold files (136), with recall 0.16 against 0.22 for source paths, so
  test withholding is not a dominant cause.
- **Anchor extraction defect (minor).** 20 dev rows, all SWE-Bench-Pro, arrive as one escaped
  string with literal `\n` and no raw line break. The lexical channel then searched for, and
  disclosed in `widening.lexical.identifiers`, names such as `nThe`, `nEmail`, `nConfiguration`,
  `nResult` and `nopenLedgerFile`.

## Measured negative results

- **Prose-term fallback, simulated offline over the base reports.** On rows that have a confident
  answer and no widening rows, I appended the next k rows of a lexical arm not already answered.
  With bm25:all: k=1 0.3492 / 0.2458, k=2 0.3549 / 0.2340, k=3 0.3597 / 0.2272. With bm25:ident:
  k=1 0.3431 / 0.2562, k=3 0.3494 / 0.2463, k=5 0.3521 / 0.2410 (coverage / precision; base
  0.3414 / 0.2687). Applying it to every row without widening, abstained rows included, drops
  precision to 0.1517 already at k=1. Decision: do not relax the identifier gate. Every reading
  costs more precision than it returns in recall, and most fall below 0.25.
- **Escape decoding for every ranker (lane1).** `taskScanText` was applied in
  `newTaskContextCompiler` and `evalRank`. One of the 20 signature rows changed, in the confident
  tier, and lost its only gold hit: coverage 0.067 to 0, answer 4 to 3 files. Dev 393: 0.3414 /
  0.2687 became 0.3412 / 0.2681. The 20 control rows were identical. Rejected, because it moves the
  confident tier and `context` for no gain.

## Decision: GPK-V0-1950, decoding for the lexical channel only (lane2)

`taskScanText` (`internal/contextindex/task_escapes.go`) decodes a task only on a fixed signature:
no raw line break and at least two `\n` escapes. It runs one pass over `\n \r \t \\ \" \/` and
keeps every other sequence verbatim. `TaskLexicalChannel` is its only caller. The confident tier,
`TaskContext`, the `context` verb, harness packets, `prove` and the request echo are unchanged.
Measured with lane2 on the same 40 rows: ranked answers identical to base on 40 of 40. So dev
coverage and precision are unchanged (0.3414 / 0.2687). What changes is the receipt:
`lexical.identifiers` no longer names identifiers the task never wrote (invariant 2). This is a
truthfulness fix, not a recall gain.

Frozen evaluations: no input carries the signature, so their bytes are unchanged by construction.
That covers 0 of the 376 task texts under `benchmarks/` and 0 of the frozen agent-retrieval-bench
queries (`v2_code2test` 106, `v2_comment2context` 80, `v2_edit2ripple` 58, `v2_trace2code` 101,
the host copy at `corvint-lanes/ctx-u15-data`). `TestGPKV0002ManifestReplay` and
`TestWideningDivergence*` pass, and so do the `cmd/corvint` widening tests.

## V1-2716 verdict

- AC1 (full ContextBench rerun: recall ≥ bm25:ident at precision ≥ 0.25, or a measured reason it
  cannot): **PARTIAL.** A full rerun would read the held-out split, which this charter forbids.
  On dev the criterion holds at BASE (0.3414 ≥ 0.3079 at 0.2687). The measured reason held-out
  fails is unchanged from the 2026-10-26 receipt: the confident tier alone is below 0.25 there.
  This lane adds the dev mechanism behind it. Most missing gold is outside every lexical top 20,
  and the rows that remain cost more precision than they return in recall. The full rerun stays
  open for a lane allowed to read held-out rows.
- AC2 (no-root-AGENTS.md rows answer with uncertainty): **already met** by `GPK-V0-091`.
  `TestProjectOperationsQueryDegradesWithoutRootAgentsFile` is on BASE. The 393 measured dev rows
  had 0 corvint errors.
- Charter goal "show a recall gain on the development rows": **not met.** No evaluated change
  raised dev recall without a precision cost larger than the gain. The one defect fixed is
  recall-neutral.
