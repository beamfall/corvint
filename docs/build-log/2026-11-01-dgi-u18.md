## Decisions

- V1-4058, the CI half: adding a CI job for `make shell-test` is a `.github` change outside lane
  scope. Instead, the recipe pin also runs in a Go package that CI already selects for either side
  of the drift. The test runs the shell test's extraction line verbatim, not a Go copy of it, so a
  drift that breaks the shell test (796520b19's `BATCH_PRECHECK_SKIP_DRIFT=1` prefix) breaks the Go
  test too. A CI shell job is still worth having; it is left to the orchestrator.
- V1-4058, main red: `script/dogfood-cache_test.sh` fails at BASE. Lane scr-w16 fixed it at
  `7d0305476` (in `claude/batch-1101c`). This lane carries the byte-identical hunk as its own
  commit, so the new Go pin passes on this branch and the two changes merge cleanly. The pin
  failed at BASE with the exact drift. It passed in a scratch tree that had BASE's Makefile and
  `7d0305476`'s shell test.
- V1-3632, `script/heavy.sh:1366` (`words`): heavy.sh is off-limits this wave, and the expansion
  cannot be empty, because `unwrap_shell` reaches it only after `"$3"` matched `go test` or
  `go vet`. It is the one exempt `PATH:NAME` pair in `nounset_exempt`, with that reason.
- V1-3632, the rule is a per-file heuristic: it flags only arrays initialized as `NAME=()`, and
  any earlier `${#NAME[@]}` counts as a guard. The idiom is safe in every case, so every hit was
  rewritten rather than individually judged. The edits in `batch-precheck.sh` and
  `dogfood-finish.sh`, which `claude/batch-1101c` also edits, are line-local; none of those lines
  is in a batch-1101c hunk.
