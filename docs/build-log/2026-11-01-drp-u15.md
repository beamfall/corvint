# 2026-11-01 drp-u15 CEM 2.0 discovery replay pre-registration (V1-2600)

Lane drp-u15 pre-registered the CEM 2.0 Phase 2 kill-or-continue replay at origin/main
`b7ffc233396da54e2ac5a094ec314dc3b067f6fb` on the Unraid lane host. Scope was the pre-registration
only: no replay step ran, no label was computed, and no replay output exists. Contract:
`docs/specs/cem2-discovery-replay-v0.md` (`VRP-V0-001..054`); artifacts:
`benchmarks/cem2-discovery-replay-v0/`.

## Decisions

- Unit = non-test Go source hunk of the canonical CEM patch; ground truth = the fix's touched old-side
  code lines blamed back to the change, stored as `[path, line]` so they map onto CEM's
  three-context-line hunks, which differ from the selector's `-U0` hunks.
- Linkage = blame plus a shared ticket/requirement ID between fix subject and change message.
  Comment-only lines and ID-renumbering hunks touch nothing (first draft admitted
  `DCW-V0-396`-style renumbering "fixes"; qualifying fell from 54 to 52, selected stayed 40).
- Both arms share one coverage run over the same-directory `_test.go` oracle. Typed arm = fold of
  existing `cem verify --hunk-revert`, `cem discriminate` and `cem cover` witnesses; no new mutation,
  equivalence or label code. `likely-equivalent` is NOT_PRODUCED (no equivalence screen exists:
  `equivalen` appears only in `_test.go` files under `internal/liveverify`, `internal/cemdiscriminate`
  and `internal/cem`).
- Maps stay repository-relative inside the disposable worktree (CEM-V1-647) and are copied out.
- Decision rule: paired sign-style comparison, `delta = (b - c) / paired >= X`, pooled typed
  false-alarm rate `<= Y`, `b > c`; validity floor 80% paired, one infrastructure-only rerun, second
  invalid run = KILL. X and Y are `OWNER-BLOCKER`; proposed 0.15 and 0.60 (reasoning in
  `PROTOCOL.md` section 6).

## Friction

1. No beamfall/core clone on the Unraid lane host; external-repository AC cannot be met there.
2. The 2026-10-29 history reset leaves only 39 first-parent merges on origin/main and the old lineage
   is absent from Unraid, so no post-merge escape exists to select.
3. `cem cite|mark|cover|discriminate` accept an out-of-tree `--map` only with a repository-relative
   `--output` (CEM-V1-647), so an external harness must write into the worktree and copy maps out.
4. The corvint MCP server failed to connect (`CONNECTION_CLOSED`) in the dispatching session.
5. `make spec-requirements` rejects an Agent digest Claim over 160 characters only at generation
   time; the spec template does not state the limit.
6. `corvint dogfood propose-citations BASE` drafted a `specification` row (`docs/specs/cem-stable-v1.md:655`)
   for the hunk of a companion spec this change adds; `make dogfood-inputs-check` then refused it as
   `bootstrap-intent-not-unknown` (DCW-V0-449). Expected: the draft reads DOGFOOD_INTENTS and keeps a
   bootstrap intent unknown. Actual: one manual repair and one extra inputs-check run.
