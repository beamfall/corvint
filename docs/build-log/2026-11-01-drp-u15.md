`b7ffc233396da54e2ac5a094ec314dc3b067f6fb` on the Unraid lane host. Scope was the pre-registration

## Decisions

- Unit = non-test Go source hunk of the canonical CEM patch; ground truth = the fix's touched old-side
  code lines blamed back to the change, stored as `[path, line]` so they map onto CEM's
  three-context-line hunks, which differ from the selector's `-U0` hunks.
- Linkage = blame plus a shared ticket/requirement ID between fix subject and change message.
  Comment-only lines and ID-renumbering hunks touch nothing (first draft admitted
  `DCW-V0-396`-style renumbering "fixes"; qualifying fell from 54 to 52, selected stayed 40).
- Both arms share one coverage run over the same-directory `_test.go` oracle. Typed arm = fold of
  existing `cem verify --hunk-revert`, `cem discriminate` and `cem cover` witnesses; no new mutation,
  equivalence or label code. `likely-equivalent` is NOT_PRODUCED (no equivalence screen exists:
  `equivalen` appears only in `_test.go` files under `internal/liveverify`, `internal/cemdiscriminate`
  and `internal/cem`).
- Maps stay repository-relative inside the disposable worktree (CEM-V1-647) and are copied out.
- Decision rule: paired sign-style comparison, `delta = (b - c) / paired >= X`, pooled typed
  false-alarm rate `<= Y`, `b > c`; validity floor 80% paired, one infrastructure-only rerun, second
  invalid run = KILL. X and Y are `OWNER-BLOCKER`; proposed 0.15 and 0.60 (reasoning in
  `PROTOCOL.md` section 6).

## Review repair (2026-11-01)

An independent review raised seven findings against head `76234fb1a`. Each one was checked against
the pre-repair code. Where practical, a synthetic probe was run on Unraid (`/home/agent/.cache/drp-u15-probe/`).
Thresholds, decision rule, units, labels and budgets are unchanged. Requirements: `VRP-V0-055..061`.

1. **P1, pre-registration checked against a moving HEAD: CONFIRMED** (by code). `committed()` only
   compared PROTOCOL.md, thresholds.json and the manifest with whatever HEAD `--repo` had. It did not
   cover `select.py` or `harness.py`, and it did not tie the executing harness to `--repo`.
   - Fix (`VRP-V0-055`): `registration.sha256` fixes the sha256 of all six registered files in a
     fixed order. `check`, `run` and `score` exit 5 when a file differs. `run` and `score` exit 4
     unless the executing harness is the one inside `--repo` and every registered file is tracked
     and unmodified there. Every `run.json` records the registration digest, and `score` refuses
     any other digest.
   - Evidence: a copy with one byte appended to `thresholds.json` gives `check` exit 5. `score` on
     the uncommitted tree gives exit 4 (`protocol-modified`).
2. **P1, cleanup ran before go.mod was read: CONFIRMED** (probe). The plan's cleanup step removed
   the worktree, and only then was `go.mod` read from it. The module came back `None`, and the
   baseline was `NOT_OBSERVED(not-instrumented)` instead of `0/1`.
   - Fix (`VRP-V0-061`): the module is read with `git cat-file blob P:go.mod` before any step, and
     cleanup runs only in `finally`.
   - Evidence: the selftest `capture` case (stub corvint and go, temporary repository) scores
     `OBSERVED` with baseline `0/1`. Reverting the fix fails it with "finding 2".
3. **P1, a failed worktree add removed a pre-existing worktree: CONFIRMED** (by code). The old
   code ran `worktree remove --force` on the path whenever it existed, so a failed add removed a
   worktree that was already there.
   - Fix (`VRP-V0-057`, `VRP-V0-061`): an existing path is recorded `refused: worktree-path-exists`
     and left untouched. Only a worktree this call created is removed, in `finally`. The worktree HEAD must equal the change. Work and output directories are resolved
     with realpath and refused (exit 4) when they overlap the repository, the Git common directory
     or each other.
   - Evidence: in the selftest, a pre-existing dirty worktree keeps `dirty.txt`. Three overlapping
     path pairs exit 4. Removing the `created` guard fails the selftest.
4. **P2, score accepted artifacts from another change or tree: CONFIRMED** (by code).
   `score_change` read files with no identity check.
   - Fix (`VRP-V0-059`): `verify_capture` binds the following, and any mismatch exits 6:
     - `run.json` change, commit, base and registration;
     - the artifact set and sha256 against `run.json`;
     - every map's `baseRevision` and `patchSha256`;
     - hunk ids equal across maps;
     - discrimination `treeRevision`;
     - coverage `profileSha256` and `testRun`;
     - hunk-revert `expectedBase`, `targetRevision` and `patchSha256`;
     - one Corvint build and Go version across all captures.
   - Evidence: tampered registration, map base and patch each raise `CaptureMismatch` in the
     selftest. Removing the check fails it with "finding 4".
5. **P2, select.py depended on ambient Git config: CONFIRMED** (probe). On VRP-C001 the code gave
   16 hunks with the default config and 8 under `diff.interHunkContext=1000000`.
   - Fix (`VRP-V0-056`):
     - no system or global config and no `GIT_*` environment are read;
     - `-c` pins quotePath, attributesFile, noprefix, mnemonicPrefix, relative, algorithm,
       showSignature and the blame ignore settings;
     - diff runs with `--inter-hunk-context=0 --no-textconv --no-ext-diff --text --no-indent-heuristic --no-renames --no-relative`
       and fixed prefixes;
     - blame runs with `--no-textconv --ignore-revs-file=`, and the line count comes from `cat-file blob`.
   - Evidence: the selftest `selector` case gives the same hunks under repo-local
     `diff.interHunkContext=1000000` and `diff.context=9`. Removing the flag fails it with "finding 5".
6. **P2, the ID-only filter compared sorted lines: CONFIRMED** (probe). A fix that swaps two calls
   and renumbers their IDs gave touched lines `{}`.
   - Fix (`VRP-V0-060`): the masked removed and added lines are compared in order.
   - Evidence: in the selftest, a swap gives `{"a.go": [4, 5]}` and an in-order renumber gives `{}`.
     Reverting to sorted fails it with "finding 6".
7. **P2, timeouts left descendant processes running: CONFIRMED** (probe). After the timeout, a
   backgrounded `sleep` survived in state S.
   - Fix (`VRP-V0-058`): every step runs in its own session and process group. On exit, timeout or
     interrupt, the group gets SIGKILL and the harness waits up to 10 s for it to empty, recording
     `groupRetired`. Output collection after the kill is bounded.
   - Evidence: in the selftest `timeout` case the background child is dead. With a kill-only retire,
     the selftest fails with "finding 7".
