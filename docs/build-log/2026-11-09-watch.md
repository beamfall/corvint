# Lane watch: first-class `corvint watch`, macOS save events, replan latency budget

Date: 2026-11-09. Branch `claude/watch-first-class` on the decision 0594 cut. Tickets V1-4372 and
V1-5253. Spec commit `3735bef27`; requirements `LPCV-V0-1085..1087` and `PRB-V0-1014`.

## V1-4372: the watch loop reruns impacted tests on save

What was wrong. The save-driven replan loop existed only in the `tools/linecov` executable
(`linecov watch`, `LPCV-V0-7607`), which is neither a bundled app nor in the capability catalog's
`corvint` tree, so the owner's "on save, know which tests must run" answer was unreachable from the
product command. The loop also returned nil when its notification channel closed, which the next
ticket turned into a defect.

Fix. The loop, its plan types and its event sources moved to `internal/linecov/watch`, a package in
the `tests` layer that both executables import (no forward from the core to a tool). `corvint
[--root PATH] watch --index FILE [--once | --events-stdin] [--dry-run] [--packages a,b]
[--go-wrapper PATH]` dispatches to it (`cmd/corvint/watch.go`), streams one JSON event per line
(`plan`, `result`, `error`; user-scoped, never gate-eligible) and exits 0/1/2. `--dry-run` answers
without running a test. `linecov watch` keeps its flags and its non-Go `-command` path through the
same package (`watchSaves` and `watchTestArgs` stay as wrappers, so its existing tests are unchanged).
The verb has its help topic, root-help line, catalog node (`make capability-catalog`) and
`docs/CAPABILITIES.md` rows.

Tests. `TestWatchHelpAndRefusals`, `TestWatchOnceDryRunCLI` (cmd/corvint: a dry run plans
`^(TestPass)$` for a body edit and records `ReplanMillis`; a failing `--once` run exits 1; a
stdin-driven run repairs and exits 0); `TestRunDryRunAnswersWithoutRunning`,
`TestRunStreamsFailureThenRepair`, `TestRunRefusesNonGoWithoutPlanner`, `TestOnceAndLinesSources`
(internal/linecov/watch); the verb-matrix tests `TestRootHelpLabelsEveryVerbWithMaturityAndOwner`,
`TestRequireCleanHonouredOrRefusedByEveryCommand`, `TestEveryVerbHelpFollowsTheHouseFormat` and
`make capability-catalog-check`.

## V1-5253: native save events on macOS and a recorded replan latency budget

What was wrong. `tools/linecov/watch_other.go` refused every non-Linux host; no perf budget scenario
measured the save-to-answer path; and a stopped event source (root removed, inotify watches not
restorable, editor pipe broken) ended the loop silently with status 0, leaving the last plan on screen
as if current.

Fix. `source_darwin.go`: a kqueue source through the standard library's `syscall` (no cgo, no
FSEvents daemon, no new module, no polling). Every directory except `.git` and every regular file
hold one `O_EVTONLY` descriptor registered for write, extend, delete, rename and revoke; a directory
event rescans that directory and rewatches an entry whose inode changed, so an atomic replacement is
observed even when its own delete event was coalesced; descriptor exhaustion refuses at start with the
remedy instead of watching a subset. `Source` carries `Err()`: the loop emits one terminal
`{"Kind":"error"}` event naming the cause and returns `ErrSourceStopped`; `corvint watch` exits 2.
Each plan event carries `ReplanMillis`. Two perf budget scenarios, `watch-replan` (fixture code
repository, one body line of a multi-line method edited, a line index collected over its first four
packages at fixture generation, generator `/3`) and `watch-replan-self` (Corvint's own repository as
it stands, records-free index built for HEAD, or `--self-index`), each `corvint watch --once
--dry-run`, with enforced ceilings and an advisory 1,000 ms p95 target.

Fixture note. The generated `Describe` method became multi-line because a one-line function makes
any edit structural (`edit crosses function boundaries`, `LPCV-V0-8207`) and the whole module keeps
whole; with the body-line edit the full-scale plan is `pkg/p0002` compile-only, the other three
recorded packages excluded, 1,496 unrecorded packages whole.

Tests. `TestNativeSaveNotification` (atomic rename then in-place write), `TestNativeNewDirectorySaves`,
`TestNativeSaveNotificationDirectoriesAndIgnored`, `TestNativeStopIsExplicit` (root removed ends
with an error; context end ends without one) build for `linux || darwin`;
`TestNativeLostDirectoryEvents` (inotify); `TestVnodeRescanReconcilesInodes`,
`TestVnodeDropDirectoryTakesSubtree`, `TestDescriptorHint` (darwin only);
`TestNativeRefusesExplicitly` (other systems); `TestRunReportsStoppedSourceExplicitly`;
`TestPRBV01014WatchScenarios`, `TestPRBV0057CodeScenarios`, `TestPRBV0031CommittedBudgets`,
`TestPRBV0053BaselineProvenance`, `TestPRBV0024HarnessSmokeRun` (all twelve scenarios at smoke scale).

Darwin limit. This lane ran on Linux. The darwin files were compile-checked with
`GOOS=darwin GOTOOLCHAIN=local go vet ./internal/linecov/watch ./tools/linecov ./cmd/corvint
./internal/perfbudget/...`; the darwin tests were NOT_RUN and the kqueue source is `NOT_OBSERVED`
live until a macOS host runs `go test ./internal/linecov/watch`.

## Measurements (PRB-V0-1014, uncontended 32-core Linux host, Go 1.27.3)

Full scale, five samples, one unmeasured run, executable built at `c0724a7fa` (clean):

| Scenario | p50 ms | p95 ms | peak RSS | ceilings committed |
|---|---|---|---|---|
| `watch-replan` (1,500-package fixture, 4 recorded) | 698 | 752 | 33 MiB | 2,500 ms (3x p95), 64 MiB |
| `watch-replan-self` (Corvint, about 9,900 tracked files) | 1,188 | 1,253 | 49 MiB | 6,500 ms (5x p95, host and checkout dependent), 128 MiB |

Smoke scale (12 packages): `watch-replan` p50 70 ms; `watch-replan-self` p50 1,098 ms. The in-process
`ReplanMillis` of the full-scale fixture answer was 604 ms; the cold process adds index load and
startup. The self answer is dominated by `go list ./...` and the head-test parse of the whole module,
so it exceeds the 1,000 ms advisory target on this host; that target is advisory and measured, not
enforced. The baseline entries carry their own run's provenance (PRB-V0-053); the next
`--record-baseline` run replaces them.

## Found on the way

- The perf budget harness (test helper and `perf-budget` command) built only `corvint`, so every
  fixture build failed with `not-installed` for `corvint docs` since decision 0594 split
  `corvint-docs` out; both now build `corvint-docs` beside it. `TestPRBV0024HarnessSmokeRun` and
  `TestPRBV0970RunMeasuresOnlySelected` were red on the base for that reason.
- `mergeBaseline` cannot record a scenario the baseline lacks, so a new scenario's first baseline
  entry is still a hand edit with `PRB-V0-053` provenance, as for `PRB-V0-059`.
- Repinning the use-case receipts invalidates the `conformance/use-cases-v0` record-entry read-scope
  binding (`.corvint/record-entry-read-scopes.json`); no tool recomputes the digest, so it was
  recomputed with a throwaway program over `affected.RecordEntrySourceDigest`.
