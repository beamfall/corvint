# Selection: joined record readers and the entry-namespace ratchet (review fix round 1)

Date: 2026-11-07
Lane: selgo (branch `claude/sel-go`, base `4052b8540`), review fix round 1 after
`2026-11-06-selgo`.
Ticket: V1-4933. Requirements: AFP-V0-2746 and AFP-V0-2747 in
`docs/specs/affected-plan-selection-v0.md`. AFP-V0-2743 and AFP-V0-2745 are amended.
Owner goal: never fewer tests than needed.

## Findings

The independent review returned CHANGES_REQUIRED with two findings.

- **P1.** The AFP-V0-2743 and AFP-V0-2744 ancestor narrowing dropped real readers. A test in
  `reader/` that calls `os.ReadFile(filepath.Join("../docs", "build-log", "entry.md"))` reads
  `docs/build-log/entry.md`, yet none of its literals resolves to the record directory alone. Rule
  (d) does not mark `"../docs"` unbounded either, because it resolves below the root. Both
  selectors could omit the test. The spec had listed this case as an accepted failure mode, and the
  review rejected that.
- **P2.** The AFP-V0-2745 ratchet probed one synthetic name
  (`0000-00-00-record-readers-probe.md`). A glob that constrains file names
  (`filepath.Glob("../docs/build-log/2026-*.md")`) reads every new 2026 entry, but it did not match
  the probe, so the ratchet passed.

## Decisions

- **AFP-V0-2746: join, do not reconstruct.** I did not keep every ancestor reader, for two reasons.
  First, I measured `gate-affected-select`'s index on the round-0 head (`41a64d2eb`). For a probe
  entry, 76 packages (149 package-token pairs) hold a token that resolves only to `docs` or
  `.corvint`: 55 for a build-log entry and 45 for a sealed CEM. Most are a production `..` beside a
  lone `docs` or `.corvint` word. Keeping all of them would make every record entry select dozens
  of packages again. Second, a parser for `filepath.Join` arguments in both lexers would miss a joined
  variable (`base := "../docs"`).
  The rule instead keeps a reader when its token resolves to the root or a proper ancestor of the
  record directory and every remaining component of the directory (`build-log`, `changes`) is a
  whole `/` component of one of the unit's own tokens. Order and expression do not matter. The
  planner applies it in `reachesRecord`. `gate-affected-select` applies it in one extra pass of
  `resolvingReaders`, which also feeds `-bounds`. Each selector reads its own lexicon, so the CI
  selector stays a superset.
- **AFP-V0-2747: match the namespace.** `Graph.RecordReaders` now takes the record directory.
  Besides one unnamed probe, it builds a probe from each literal fragment at the entry position
  (`docs/build-log/2026-` gives `2026-x.md`). It also builds one from each glob's last component.
  `globEntry` searches the product of the pattern's `path.Match` items with the longest suffix
  prefix seen, so it finds an entry name the glob admits, or proves none exists (`*.json` for
  `.md`). A literal or glob that names one entry is skipped: one with no wildcard, or a fragment
  already ending in the suffix.
- **Walkers cannot be recorded.** A package that names `docs` or `.corvint`, joins nothing that
  reaches the directory, and does not locate the root is a walker. A walk or a computed name could
  read every new entry, yet no selector selects the package for one. Listing it in the record would
  only hide a reader, which is the review's point about P1, so the ratchet now refuses it even when
  listed. The routes are a declared read scope or the fixture marker. The repository has no such
  package today: the check passes with the unchanged baseline record.
- **Ownership of the record.** The whole `internal/liveverify/affected` run failed
  `TestOwnershipAuditRatchet_AZU_V0_002` and `TestRepositoryOwnershipComplete_AZU_V0_8900`, because
  round 0 added `.corvint/record-readers.json` without claiming it. It is now declared in
  `.corvint/runtime-readers.json` beside `.corvint/unbounded-readers.json`.

Fault injection. Each test fails when its fix is removed:

- `TestRecordEntryReadersJoinSeparateLiterals_AFPV2746`, with the join removed from
  `reachesRecord`: `joined`, `deep` and `rooted` lose their witness for both entries.
- `TestRecordEntryJoinedReadersSelectedByBothSelectors_AFPV2746`, whose fixture test really reads
  each entry through `filepath.Join`. With the `joins` pass removed from `resolvingReaders`,
  `gate-affected-select` drops `reader` and `deep/dir`. With the join removed from the planner, the
  planner drops them.
- `TestRecordReadersMatchTheEntryNamespace_AFPV2747`, with `recordProbes` returning only its fixed
  probe: the constrained-glob and fragment readers are lost.
- `TestAFPV2747RecordRatchetMatchesTheEntryNamespace`. With the fixed probe alone, the
  `filepath.Glob("../docs/build-log/2026-*.md")` and `"../docs/build-log/2026-" + name` packages
  pass the ratchet. With walkers returned among readers, a listed walker passes.

The under-selection controls stay selected: the joined readers, a lister, an exact namer, a
root-locating unit and a declared read scope. The narrowing controls stay narrowed: a pure
ancestor, a join to another directory (`docs/build`, `.corvint/change`), a fixture-root token, and
a glob or literal that names a single entry.

## Limits

- A record directory component spelt only by concatenation (`"build" + kind`) is no whole
  component of any token. Such a unit is a walker, so the ratchet sends it to a declared read
  scope. The selectors do not select it.
- The planner still names a lone `docs` or `.corvint` as a file name only (V1-0290). Composition
  through a production `..` and lone words therefore happens only in `gate-affected-select`. That
  was round 0's friction 9, and it is unchanged.
