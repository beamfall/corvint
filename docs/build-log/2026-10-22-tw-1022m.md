# 2026-10-22 lane tw-1022m: import-map writer (V1-0398) and parallel JSG store tests (V1-0961)

## Problem

V1-0398 (moved into 1.0 by the owner on 2026-10-22): `corvint-tasks` refused every write to a
non-fixture queue whose `importMapSha256` was non-null, so a store imported under a map could only
be driven through a fixture session. CAL-V0-001 kept that refusal and both the CAL and CTS specs
listed the import-map writer as a non-goal.

V1-0961: the `internal/tasks/store` package runs its JSG segment tests serially; the JSG set alone
took 604 s at load about 11, so the package trips the 30 m hang detector under host load.

## Decisions

- The writer is specified as CTS-V0-014 to CTS-V0-017 in `docs/specs/corvint-tasks-store-init-v0.md`,
  accepted under the owner's standing auto-accept (2026-10-11). CAL-V0-001, the CAL non-goal and the
  1.0 spec carry dated amendments pointing at them; no new CAL-V0 IDs.
- The map is bound at genesis, not on every write: `init` of a mapped non-fixture queue reads
  `.taskman/import-map.json`, binds it into the INIT digest and posts it as `intent/import-map.json`.
  The journal audit then binds the bytes for every later read, so no later write needs the map in
  its inventory. A null-map or fixture genesis is byte-identical to before; the journal genesis
  count admits exactly one extra post and only when the map is posted.
- After genesis the map is immutable (CTS-V0-016). Updating it on import (`appliedSeq`, new
  entries) stays a non-goal and is a residual.
- Import honours the map's identity (CTS-V0-017): a source item mapped to another ticket, or a
  ticket mapped to another source item, refuses `DUPLICATE_ID` inside the transaction with nothing
  written. The importer planner does not pre-check the map; that is a residual.
- The store inventory now lists `intent/import-map.json` because the journal's intent tree digest
  already included it; without that, a lease write on a mapped store refused `SNAPSHOT_MOVED`
  ("inventory differs from audit").
- Fixture queues that name a map stay refused (CAL-V0-003). Store guards in `release.go` and
  `reconcile.go` now refuse a map only on fixture queues.
- JSG tests: the segment seal stop hook became a per-repository `sync.Map` keyed seam, so the seal,
  migrate, validation, liveness and writer-verify tests run under `t.Parallel()`.
  `lease_resume_sealed_test.go` and `TestJSGV0013_*` stay serial (shared state). No assertion was
  removed or weakened.

## Evidence

- Fail without the fix: with the base files restored, `TestCTSV0014_ImportMappedQueueTakesEveryWrite`
  and `TestCTSV0017_ImportRefusesMapIdentityConflicts` fail at init with `MALFORMED`
  "unsupported queue identity/state". `TestCTSV0015_ImportMapBindingRefusesInit` passes on the base
  by design (regression guard for the refusals). With the fix all pass, with
  `TestCTSV0014_ImportMappedQueueLeasesAndReleases`, `TestCALV0001_*` and
  `TestCALV0026_GuardedInventoryParity`.
- JSG durations (heavy.sh, `-p 4`): before, the 23 JSG tests ran serially in 604.1 s at load about
  11. After, the parallel set took 79.4 s and the serial set 224.7 s at load about 14, about 304 s in
  total. The critical path is `TestJSGV0012_CompactionOnASealedStore` (58 s serial, 166 s under
  parallel contention; about 644 heartbeats). The whole-package wall time against the 10 m target in
  V1-0961 was not measured in this lane: NOT_RUN.

## NOT_RUN

- Whole `internal/tasks/store` package wall time (exceeds the 600 s tool bound per command).
- `corvint affected` tier 2 units, left to batch CI.
- V1-0907 (fold-state design), V1-1193 and V1-1662 (20k/47k measurements): not started in this
  lane's budget.

## Rollback

Revert the V1-0398 commit: restore the `ImportMapSha256 != nil` refusals in
`internal/tasks/transaction/model.go`, `internal/tasks/snapshot/stage_observation.go`,
`internal/tasks/store/release.go` and `reconcile.go`; drop the map from the INIT digest, INIT posts,
`snapshot/stage.go`, the journal genesis count, the store scan and the import audit; delete
`internal/tasks/transaction/import_map.go`. A store initialized with a map must be re-initialized;
null-map and fixture stores need nothing. Revert the JSG commit to restore serial tests and the
global seal hook.
