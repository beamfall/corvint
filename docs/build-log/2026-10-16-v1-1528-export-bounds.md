# 2026-10-16 V1-1528: companion release export bounds raised to 50,000 entries and 512 MiB

Decision. `PUB-V0-012` in `docs/specs/public-release-v0.md` bounded the companion source export at
10,000 entries and 128 MiB of exported bytes. Corvint's own repository has outgrown the entry
bound. On main `d4b1e2039` the export holds 9,994 entries and 113.5 MiB. It held 5,776 entries on
2026-10-01, so growth is about 350 entries a day, and the 10,000 bound would refuse the next export.
The orchestrator raised the bounds under delegated in-task authority (2026-10-16):

- `maxExportEntries`: 10,000 to 50,000.
- `maxExportTotalBytes`: 128 MiB to 512 MiB.

Both bounds stay refusals; the export never truncates. The archive verifier's retained-entry bound
is now derived as twice the export entry bound, so an archive of a full-size export verifies. Its
512 MiB compressed-archive bound is unchanged. An incompressible export at the full 512 MiB byte
bound could produce an archive that the verifier refuses. That is a recorded limit, not observed:
real source compresses well below it.

At 50,000 entries, the pairwise case-fold collision check took 7.4 s on this host under load. It ran
before the entry-count refusal, so it was replaced by a linear check. Each path is mapped to a
fold key, where each rune becomes the smallest rune in its `unicode.SimpleFold` orbit. Two paths
collide when their fold keys are equal, and a path collides with a directory prefix of another path
when their fold keys are equal. `TestRefuseCaseFoldCollisionsMatchesPairwiseEqualFold` checks that
the linear check refuses exactly the pairs that pairwise `strings.EqualFold` refuses. Replacing the
fold with `unicode.ToLower` makes that test fail.

Tests keep the byte-bound refusal fast by lowering the bound to 4 MiB through the same code path.
A separate subtest pins the production values.

Rollback: revert the two constants in `internal/companionrelease/export.go` and the spec text.
The linear collision check is equivalent and can stay.
