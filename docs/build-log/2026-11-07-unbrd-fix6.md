## Greptile P1 1: a literal extensionless run target lost its edge (confirmed)

`constructed` in `internal/liveverify/affected/shell/computed.go` returned early for every
computed target whose file name is literal and has no shell suffix. The early return was added in
`0e7f59fce` so that the toolchain probe `"$sdk/go"` in `script/heavy.sh` does not make heavy.sh a
dynamic source when the value bound cuts its expansion. It also skipped the plugin's own
extensionless scripts (AFP-V0-2205): `for dir in script; do "$dir/check"; done` gave no edge to
`script/check`, so an edit of `script/check` missed the caller's tests.

The fix keeps the shortcut only when no shell unit's file has that file name
(`ownedExtensionless`). A value of the target can link only a known path, and that path's file name
is the target's literal one, so a name no known file has can link nothing. Dropped values then lose
nothing either. A name an owned script has is expanded as TSP-V0-960 requires: literal values
link, and a cut list is `shell:dynamic-source`. The check scans the known shell paths, not just the
`ExtensionlessRoots` directories, so it stays sound if ownership widens. The heavy.sh probe still
takes the shortcut, because no owned script is named `go`.

`TestComputedTargetKeepsOwnedExtensionlessScripts_AFPV03144` checks five cases:

- a loop over `script` links `script/check`;
- a file-relative `"$d/check"` in `script/run.sh` links it;
- an edit of `script/check` selects the test that runs it, and an edit of `script/other` does not;
- a cut list naming `check` is a dynamic source;
- non-test probes of `go` and `check.py` stay bounded.

Before the fix, the first four cases failed. With the shortcut deleted entirely, the two bounded
controls fail, so the shortcut is still exercised.

## Greptile P1 2: an argument `[[` swallowed the next command (confirmed)

`openTest` in `internal/liveverify/affected/shell/lex.go` took any `[[` word in the current
command as an open conditional, so `echo [[ marker && . "$ENVFILE"` kept `&&` inside the
expression and lost the source. The script then lost `shell:dynamic-source` (AFP-V0-2953).

`openTest` now skips the leading reserved words `if`, `while`, `until`, `!`, `time`, `then`, `do`,
`else` and `elif`, and opens a test only when the next word is `[[` with no `]]` after it. The
review's list did not include `time`. It is added because `time [[ a || b ]]` is a test in command
position, and the previous lexer kept it whole. A separator, `{`, `(`, a case arm and a command
substitution already start a new word list in the lexer, which was checked for function bodies,
subshells, substitutions and case arms.

`TestConditionalOpensOnlyInCommandPosition_AFPV03145` checks three things:

- an argument `[[` before `&&`, `||`, `|` or inside an `if` keeps the next environment-named source,
  and a literal source keeps its edge;
- a test whose operand would build a script name if split stays whole after every leader and
  container;
- the parsed command lists are exact.

Before the fix, the argument cases and the parse case failed. With the leaders removed, the
`if`/`while`/`until`/`then`/`elif`/`else`/`do`/`!` cases fail.
