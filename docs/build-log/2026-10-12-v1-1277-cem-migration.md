# 2026-10-12 Committed CEM maps migrated to cem/1.0 (V1-1277)

Branch `claude/v1-1277-migrate`, stacked on `claude/v1-1276-dogfood-producer` at 75bc22605
(since merged as beamfall/corvint#837). Decision 0525 §3 step 6; requirements `CEM-V1-200..202`
in `docs/specs/cem-stable-v1.md` and `DCW-V0-050` in
`docs/specs/daily-change-evidence-workflow-v0.md` (proposed).

## Intent and decisions

- One dedicated commit, `0b6f1bc245b44a8620c5e64f91e87f6d08da08d0` "migrate committed CEM maps
  to cem/1.0 (V1-1277)", rewrites every committed `.corvint/changes/<bind>.cem.json` map and
  touches nothing else. File names stay the bind SHA. `script/cem-migrate-maps.sh` runs
  `corvint cem convert --in-place --repository <root> --map <abs>` for each map. A map that is
  already `cem/1.0` refuses `convert-source-is-stable` and stays byte-identical. Any other
  refusal stops the run. No map was edited by hand.
- The migration check is reproducible from the tree and needs no retained scratch state. For
  every map with converter provenance, `TestCEMV1100ConvertCorpusIdempotent` reads the source
  blob named by `provenance.sourceBlobOid` and checks `bindCommit` against the file name. It
  then checks the blob's SHA-1 and SHA-256, reconverts the blob and requires byte equality with
  the committed file. The test runs in the ordinary `go test ./...` gate, so no Makefile or CI
  edit was needed. A source blob that is absent gives a skip (`NOT_RUN`), never a pass.
  Mutation check: appending one byte to a committed map makes the test fail with "committed
  bytes differ from the conversion of <oid>".
- `cem-convert-parity --migrated` repeats that check over a scratch clone. It then verifies the
  committed bytes at T' on both consumers (`CEM-V1-104`). It also verifies the one natively
  produced stable map (860f59ea, no provenance) at its bind commit, and writes `targets.txt`
  for the citation run.
- `cem-citation-baseline` now passes `--artifacts <absolute root>` for a `cem/1.0` map; without
  it, status refused `artifacts-required`, and a mutation test confirmed this. It reads
  `--targets`, and it classes a converted map (provenance present, no `role`) by its legacy
  paths, as it classes the 0.2 source (`CEM-V1-201`).
- Seal baseline (`DCW-V0-050`):
  - The rewrite modifies 614 sealed paths, which `sealed-cem-modified` would otherwise refuse
    on every later range that spans it.
  - `internal/dogfoodflow/migration.go` names the migration commit in one constant. It admits
    exactly the migration's preimage→rewrite blob pairs and counts the migration commit as
    bound. Any other edit still fails.
  - A constituent added before the migration commit within the same batch fails
    `constituent-migrated`, with a fix line telling the operator to split the batch. It is never
    passed, because its bind-commit sidecar still holds the 0.2 bytes.
- The receipt repin is a separate commit, `0a5155d20`. The three `corvint-dogfood.json` receipts
  (UC-TASK-ORIENTATION, UC-CHANGE-CONSEQUENCE and UC-EVIDENCE-CARRYING-COMPLETION) pin
  `.corvint/changes/8668f77b….cem.json`. They are repinned at `repositoryRevision` = the migration
  commit, and `go run ./conformance/use-cases-v0` is valid (exit 0).

## Limits and NOT_RUN

- A migrated map verified directly at its bind commit is `REJECT excluded-artifact-mismatch`.
  The bind sidecars are not rewritten, so every check runs at T'.
- A `cem/0.x` map that lands on main after the migration commit is not converted (decision
  0525 step 7).
- A rebase or squash of the migration commit invalidates the `DCW-V0-050` constant. The
  migrated paths then fail `sealed-cem-modified` closed. Land the branch with a merge commit.
- The migration commit itself cannot be dogfood-bound: the bind loop would run over 614
  rewritten sealed paths. Bind this lane's tooling with `BASE=0b6f1bc24`.
- NOT_RUN:
  - `make gate`;
  - the full `cmd/corvint` package (only the CEM-V1-10x, batch-check and DCW selections ran);
  - the other packages in the 97-unit `corvint affected` selection that do not read committed
    maps.

## Rollback

Revert the merge commit. The maps return to their 0.2 bytes, which the 0.x readers still verify
until V1-1278. The receipts and the `DCW-V0-050` constant revert with them.
