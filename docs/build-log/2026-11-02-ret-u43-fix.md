the newline-count heuristic corrupts ordinary paths/code, and preprocessing invalidates JSON
envelopes before field-name exclusion and Unicode decoding. Base:
`8e84e2e5ba7b321ec184edacce512dab0ab416e4`; reviewed HEAD:
`96b7eccfd1af0603cf442495a65dc0d0612f3b71`. The repair remains uncommitted as requested.

parse extracted values again. Ambiguous unquoted escaped text stays literal. No new encoding
syntax, shared compiler change or fusion tuning is introduced. Rollback is in GPK-V0-1950.

repair. After repair, focused `TestTaskScanTextDecodesOnlyAnEscapedTask_GPKV01950`,
`TestTaskLexicalChannel*` and `TestContextIdentifierTerms*` checks passed, as did package vet.
