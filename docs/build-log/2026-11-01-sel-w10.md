## Codex review fixes (three P2s, all confirmed against the source)

1. A manifest whose only dependencies were local specifiers had no name, runners or `packages`,
   so `UnitsSource` dropped its scope. With a copied `node_modules/alias`, `installedPackage` then
   accepted the import again. The scope is now kept when `localSpecifiers` is non-empty.
   `TestNamelessManifestLocalSpecifierKeepsFrontier_V12789` uses node:test and a copied install.
   A first fixture named the linked package `alias`, which made it a workspace package with a real
   edge (correctly selected), so the fixture now gives it another name.
2. Taking local specifiers out of `dependencies` also took them out of runner detection, so a
   locally specified jest no longer made a convention-only `__tests__/case.js` a test.
   `dependencyRunners` now reads both sets. `TestLocalSpecifierRunnerStillRecognised_V12789`
   covers a version range and a `file:` jest.
3. `declaration-compat-check` failed on the dogfood `change.cem.json` and `change.ocm.*.json`
   between bind and seal. Both are now no planner input (exact name, and prefix plus suffix), and a
   look-alike name still fails. `TestDogfoodMapsAreNoPlannerInput_V13600` covers both cases.

Each regression test fails with its fix removed.

Follow-up found by the post-seal `batch-precheck`: the seal also leaves the ignored
`.corvint/change.ocm-status.json`, which the name-based exemption missed. Decision: the check now
compares only the `.corvint/*.json` files Git tracks (what a pinned planner reads in CI), plus the
tracked-until-seal `change.cem.json` exemption, instead of extending a name list for every local
output.

## Friction

1. WSL `/tmp` is full (0 MB), and Claude Code keeps its own Bash output capture there, so every
   command's output had to go to a file under `~/.cache/sel-w10` and be read back. Repro: any
   command whose output exceeds the inline limit while `df /tmp` shows 100%.
2. `make spec-requirements` ignores a spec that is not staged and only warns
   (`... is not staged, so this run ignored it`). A trace-row-only edit committed with `git add -A`
   afterwards is therefore never regenerated. Repro: edit a trace row, run
   `make spec-requirements` before staging.
3. The `affected` help usage omitted `--format` on two forms that accept it, and nothing failed;
   capabilities-check checks catalog rows, not usage/option agreement. Repro: base
   `corvint affected --help` versus `corvint affected --path X --format text`.
4. `moduleBoundary`'s generic "undeclared or unavailable go.mod" sent a probing session looking for
   repository-root bugs. Fixed here (V1-3529), but similar bare unknowns remain in

5. V1-3348, V1-3571 and V1-3505 were already delivered on the base, yet were still dispatched as
   open tickets. Repro: `git log --oneline --grep V1-3505 origin/main`.
