## V1-1375: suspicion confirmed

The `go-test` native parser (`internal/testrunner/native` `parseGo`) refused every event without
`Package`. Go 1.27 `go test -json` emits BuildEvents (`ImportPath`, `Action`, `Output`; actions
`build-output` and `build-fail`) with no `Package`, as `GLTP-V0-014` records.

Capture: a temporary module `example.com/buildfailprobe` (one `probe.go` referencing an undefined name,
one passing `probe_test.go`) run with `GOTOOLCHAIN=local GOFLAGS= go test -json ./...` under go1.27.2
darwin/arm64, exit 1. The 910 stdout bytes (SHA-256 `abae550e…3b39`) are committed unedited as
`go-build-fail.json` in `internal/testrunner/native/testdata/native-report-fixtures.json`, the
package's existing lossless fixture packaging (inventory 68 -> 69). They hold three BuildEvents keyed
`example.com/buildfailprobe [example.com/buildfailprobe.test]`, then a TestEvent `start`, `output`
and a package `fail` carrying `FailedBuild`. The fixture is in the package's own subtree, so
`.corvint/test-read-scopes.json` needs no entry.

At base, `TestGoActualBuildFailureStream` failed with `actual build-fail stream refused: Go event
package missing`. That confirms the suspicion.

Contract applied (`GLTP-V0-014` shape, `TRE-V0-003`/`TRE-V0-007`): the action picks the shape. A
`build-output`/`build-fail` event must carry `ImportPath` and no `Package`, `Test` or `FailedBuild`.
It never enters package or test accounting. `build-fail` adds `BUILD_FAILURE` naming the import path.
An event after its import path's `build-fail` is refused, and so is a second `build-fail`. A TestEvent
must carry `Package` and no `ImportPath`, and its action set no longer includes the build actions.
Duplicate-field, unknown-action and post-terminal checks are unchanged. The old Package-keyed
`build-fail` input is now refused. The existing hand-written case in
`TestGoStructuredStreamAndBuildFailure` now uses the real shape. The captured stream decodes as
incomplete with exactly `BUILD_FAILURE` (import path), `BUILD_FAILURE` (package, from `FailedBuild`),
`GO_PACKAGE_FAILURE`, `NO_TESTS` and `EXIT_REPORT_CONTRADICTION`. It never counts as a pass or as a
test failure.

Mutation: deleting the ImportPath `BUILD_FAILURE` append fails `TestGoActualBuildFailureStream`
(problem set mismatch). The restored tree passes.

## V1-1334: suspicion confirmed

CI run 38800604725 (PR CI, green, FULL shards) shows, in `go-product-shard (7)`,
`corpus_test.go:85: NOT_RUN: no Git repository: exit status 128` and `--- SKIP:
TestCEMV1201CommittedCorpusBinding`. `internal/cem/wire` is declared in
`.corvint/test-read-scopes.json`. AFP-V0-023 and `.github/testconfine` refuse any `.git` entry, so a
declared package can never read Git in full CI. The test skipped on every run while the spec row
cited it as evidence.

The smaller of the two allowed changes moves the test, not the CI job. Adding `.git` to the scope is
forbidden by the grammar. Moving it to another job means editing `.github/`. The test,
`migrationCommits`, `migratedUnchanged` and `gitObject` now live in the new undeclared package
`internal/cem/corpusbinding` (a `doc.go` plus `binding_test.go`). Full CI runs undeclared packages
unconfined from the `fetch-depth: 0` shard checkout. The package uses no `runtime.Caller`/`os.Getwd`.
It names the corpus with one `../../../.corvint/changes` literal, so path selection applies and it is not an unbounded reader. A first draft that passed separate `".."` tokens to `filepath.Join` failed `unbounded-readers-check` under rule (d). With the single literal the check passes and the unit count stays 43.
Under `CI=true` (set by GitHub Actions), a missing repository, migration commit or object now fails
the test instead of skipping it. Outside CI it still reports `NOT_RUN`. The test also fails when it
reads no maps. No `.github/` file changed.

Evidence: locally `CI=true` run: `migrated=615 native=111`, PASS in 128 s (load 147 -> 50). With
`CI=true GIT_DIR=/nonexistent` it FAILs (`CI=true: no Git repository`). Without `CI` it SKIPs. Mutation:
disabling the `CI` check turns the `CI=true` no-Git run into a SKIP/ok, so the guard bites.

Spec row: the `CEM-V1-201` traceability row said 621 maps, 615 migrated and 6 native. The corpus at
base holds 726 maps (615 migrated, 111 native). The row now states those counts at `945867cf`,
names the new package, and notes that the native count grows with each seal. Only the evidence cell
and the test location changed. The requirement text is unchanged.

Residual: `TestCEMV1201CommittedCorpusBinding` adds about 2-4 minutes to one full-CI shard
(`.github/cishards/package-costs.json` has no entry for the new package). If the AFP-V0-013 PR

skips. That is intended, but the driver would need Git.
