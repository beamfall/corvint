# V1-1967: `flows appmap blocker`, cross-checking a blocker's cited 404 against the route table

Owner input: GitHub #1215 (V1-1967), a follow-up to #1174. Requirements AMAP-V0-140..146 in
`docs/specs/application-map-v0.md` are accepted under the owner's standing auto-accept of lane
requirements (2026-10-11). Delivery is experimental over inline fixtures.

Decisions:

- Corvint has no blocked or fixture-gap classification store, so the cross-check is a read-only
  verb that takes the classification or failure note text (`--note`) and returns a verdict and
  exit code (1 when a cited request is flagged). Wiring it into a caller's classification
  workflow is the caller's step; no record, trace or Tasks state is touched.
- Spec home: the check reuses the AMAP-V0-100 Rails route compilation and the AMAP-V0-102..105
  action resolution of `flows appmap actions`, so it lives in the application-map spec next to
  them and adds no error code, map member or manifest member.
- Only `METHOD /path` pairs on a note line holding a standalone `404` token are read; a note
  citing none reads `not-applicable`, so the verb never second-guesses unrelated blockers.
- Verdicts are fail-safe: a request is flagged only when the compiled table is complete for it.
  A mount, rack endpoint or redirect with a literal path covers the paths it serves; one whose
  path is not literal covers every path; any route the parser abstained on makes an unmatched
  request `route-table-incomplete`. All of these read `uncertain` with a reason, never flagged.
- To know mounted and rack paths, the route parser now records an `opaque` route (declaration,
  verb, literal path) alongside the existing skipped note; `flows appmap actions` output is
  unchanged.
- A matched route whose action is missing reuses `ROUTE-ACTION-MISSING` (Rails answers an
  unknown action with 404), and a matched route with a defined action is accepted unchanged.
- Nearest routes rank by method, then in-order segment matches (`:param` matches any), then
  shared literal segments, then segment-count difference, then compiled order; at most three.

Evidence: `internal/appmap/route_blocker_test.go` (issue acceptance: `404 POST
/api/v2/widgets/42/archive` with only `POST /api/widgets/:id/archive` is flagged naming
`config/routes.rb:5`; a matched path is accepted; mounted, rack, non-literal and incomplete-table
cases read uncertain; matching rules; bounds; determinism) and
`cmd/corvint/flows_appmap_blocker_test.go` (exit 1/0/2, no repository change).

Limits: Rails routes only; compiled order stands in for Rails' route precedence; routing
constraints and engine routes are not read.
