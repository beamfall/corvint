# GitHub #717 Playwright discovery and witness producers (V1-1082, V1-1083)

Decision: two `docs corpus` verbs produce the caller-run inputs the experimental behavior adapter
already checks, so adopters stop hand-writing them (`DCP-V1-046..052`, proposed pending owner
acceptance). Neither runs Playwright, a browser or the application.

- `discover-playwright` (V1-1082) converts an unfiltered `playwright test --list --reporter=json`
  report into `corvint-playwright-discovery/1` / `live-playwright-list`. It reuses the issue-709
  listing validation: `validatePlaywrightListing` was extracted from `PlaywrightDiscoveryFromList`
  (`internal/liveverify/affected/typescript/playwright_discovery_list.go`, the one issue-709 file
  changed; its refusals and outputs are unchanged) and a new `PlaywrightListedTests` keeps each
  test/project execution's Playwright ID, location and title path. Anchors are Git blobs at the
  schema-2 migration's source revision in the migration's E2E repository; the working-tree bytes
  the listing observed must equal them. With `--receipt`, a qualified Playwright receipt for the
  same config and test bytes supplies the execution identity, so the adapter's receipt check and
  the registered test IDs agree.
- `witness-playwright` (V1-1083) reads a behavior-adapter request, the ID of its retained qualified
  receipt input and a caller-run Playwright JSON report, and emits a
  `corvint-behavior-witness-import/1` bundle binding contract digest, source revision, receipt
  input/revision/digest and the report digest. Each registered test gets a witness
  (`corvint-behavior-run/1` document plus the adapter observation link) only for a first-attempt
  pass agreed by receipt and report with observed event, cleanup and fixture annotations; every
  other test keeps one named unwitnessed reason, and shared defects (unqualified, incomplete or
  stale receipt; config mismatch; foreign report config) leave all tests unwitnessed. The caller
  retains the witness bytes and wires them; `behavior-adapter` rechecks the join, which the test
  shows moving `runtime_witnessed_contracts` to 1/1 without changing the contract digest.

The new code lives in `internal/doccorpus/behavior_playwright_{discovery,witness}.go` and
`cmd/corvint/docs_corpus_playwright.go`; `cmd/corvint/main.go` is unchanged. `ReadPlaywrightFile`
admits listings and reports up to 64 MiB (`PlaywrightListMaxBytes`); emitted records keep
`MaxBytes`.

Evidence: `TestPlaywrightDiscoveryProducerRoundTrip`, `TestPlaywrightDiscoveryProducerRefusals`,
`TestPlaywrightWitnessImporter` (internal/doccorpus), `TestPlaywrightListedTestsMultiProject`
(typescript) and `TestDocsCorpusPlaywrightProducersCLI` (cmd/corvint). On the base 7a2f14ad all
fail to build (undefined `BuildPlaywrightDiscovery`, `ImportPlaywrightWitnesses`,
`PlaywrightListedTests`); after, they pass. The fixture under
`internal/doccorpus/testdata/playwright-behavior/` is a real Playwright 1.63.0 listing and report of
a generic two-project suite, rebased to `@ROOT@`; the qualified receipt is synthetic.

Limits: listing, report and receipt are caller-declared. No `--project` filter, because narrowing
the listing narrows the discovered denominator. The report digest is in the bundle only; the closed
`corvint-behavior-run/1` wire has no field for it, so the compiler does not re-verify the report.
Witnessing and receipt-compatible identities need a qualified receipt; only first-attempt passes
are credited. Event annotations are the test's own claims; no browser semantics are verified.
`corvint affected` sees the fixture config as a Playwright unit, as with jstestprovider testdata.
The sibling issue-717 lane owns `DCP-V1-044`/`045` and edits the same spec and `docs_corpus.go`, so
these IDs start at 046 and a textual merge is expected. Live qualification against an adopter
repository is `NOT_OBSERVED`; `make gate` is `NOT_RUN`.
