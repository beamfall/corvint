### V1-2583: delivered

The spec came first: `7722d5f02` adds TJAA-V0-725 with binding provenance, a monkeypatch guard,
non-goals, failure modes and rollback.

`57ef1d085` (`internal/liveverify/affected/typescript/playwright_test_body_defer.go`) defers the
tag-closure reflective rule inside proven Playwright test bodies.

A test body is proven when all of these hold:
- It is the function-literal block body of the last argument of `test(...)`, of a member call
  `test.only`, `test.skip`, `test.fixme` or `test.fail`, or of a hook (`beforeEach`, `afterEach`,
  `beforeAll`, `afterAll`).
- `test` is bound by a named value import from `@playwright/test`.

The guard drops the deferral in these cases:
- Any value import from `@playwright/test` (other than `expect`, `defineConfig` and `devices`) is
  used other than as a direct callee.
- The package is loaded by `require`, a default or namespace import, or an export-from.
- A guard break in another closure file stops the closure at that file and line.

Tests are in `playwright_test_body_defer_test.go`: 5 positive rows and 11 stop rows. They were
run fail-first at the pre-implementation head:
- The 5 positive rows failed, as did the 2 helper-file stop rows.
- The other 9 stop rows already passed.

### V1-2744: fork decided; AC1 is infeasible soundly at lexical granularity, floor recorded

**Question.** Can importers be narrowed below whole-package at lexical granularity? The changed
names are the exposed `How`, `HowDraft`, `Prefixes` and `ProjectEntries` of `appmap`, plus any
`changee2e` selector.

**Method.** A scratch tool computed lexical reach from every Test, Fuzz and Benchmark function to
those names. It also checked always-run code (TestMain, init and package-level var initializers).
- Host: wsl-lanes, go1.27.3 linux/amd64, load about 4-10, lane tree at `57ef1d085`.
- The tool is scratch only and was removed.

| Package | Always-run code reaches an exposed name | Tests reaching an exposed name | Narrowable only if always-run code is ignored (unsound) |
|---|---|---|---|
| cmd/corvint | yes (init, TestMain, flowSubcommands, corpusOperations, workAdoptionVerbs, requireCleanParseWitness, affectedProgramIdentity) | 1372/1463, all through `run()` | 91 (6.2%) |
| internal/changee2e | yes (TestMain) | 99/115 | 16 |
| cmd/corvint-corpus-mcp (not on the allow-list) | no | 24/28 | 4 |

**Decision.** In the allow-listed packages, every test runs code that reaches the exposed names,
either through always-run code or through `run()`. Selecting fewer tests would miss tests that
really reach the change. A sound cut would need a typed call graph that tells initializer
references from calls, plus proofs about cross-package state. That is design-size work and outside
this ticket.

**Outcome.**
- The floor stays as afs-w27 measured it: plan 84 to 75 (SYMBOL mode).
- AC2 is met: named whole-package reasons are in place (afs-w27).
- AC3 is met: recall 6/6 against the nm oracle, and 0/56 misses in V1-3282's live run.
- AC1 should be closed as infeasible at this granularity, with the measurement above as evidence.
  A typed-call-graph follow-up should be filed if wanted.

### V1-2685: delivered for every remaining binary that has subcommands; 38 rows remain by design

`3da738995` adds CAP-V0-726, which ships command trees for `corvint-update` and
`corvint-work-queue`. Each has real subcommands that the CAP-V0-041 scan misses:

  on it.

  `internal/worklistadapter`. That package is now named as a second dispatch source.

What the commit changes:

  `internal/capcatalog/trees/`.
- Adds the two binaries to `commandTreeRefs`, `catalog.json`, the Makefile, `llms.txt`, the
  `docs/CAPABILITIES.md` Command trees section and the `treeCompanions` member of
  `companion_cli_contract_test.go`.
- Lowers `ratchetCeiling` from 40 to 38.
- `corvint-update` keeps its authored usage as its root help.
- `corvint-work-queue` answers help before `runProducer` and acquires nothing, so WQO-V0-007 is
  unchanged.
- `c184930d7` declares both snapshot reads in `.corvint/test-read-scopes.json`.

Fork decision: AC1 requires trees only for binaries "that have subcommands", and
`clitreetest.CheckCompanion` requires at least one node. The 38 remaining ratchet rows are out of
tree scope by design:

| Rows | Kind | Where their surface is gated |
|---|---|---|
| 16 | analyzer processes | their own host protocol |
| 4 | folded shims | covered by the `corvint-test` tree |
| 4 | MCP servers | their tools are mcp-tools catalog rows |
| 14 | single-mode tools | not gated by a tree |

The 14 single-mode rows now say so: "single-mode tool: its dispatch matches no subcommand word,
so it has no command tree (CAP-V0-726)". The flags of single-mode tools stay ungated by a tree.
That gap is named in CAP-V0-974 and CAP-V0-726. Closing it needs a flag-only tree form, a design
change to `clitree`, and is a candidate follow-up.
