## V1-5200: E2E suites that spawn the corvint binary were undeclared consumers

What was wrong. Only the two `tools/web-flows` scripts were declared binary consumers. On this
branch the suites that exec Corvint binaries are the installed-host proofs,
`extensions/vscode/test/installed/run.mjs` (with `worker.mjs`, `mcp-client.cjs`,
`overflow-regression.mjs`) and `conformance/interactive-alpha/core-provider-proof.mjs`: they exec
`corvint-go-test-provider`, `corvint-js-test-provider` and `corvint-test-validity-mcp` from an
extracted release on the pinned macOS host, and nothing in CI or the Makefile ran or named them.
The VS Code unit tests under `extensions/vscode/test` spawn node fakes, not Corvint.
`conformance/interactive-alpha/core-process.test.mjs` is a node:test suite of the process harness
with no runner. `core-planning-proof.mjs` and `roadmap-proof.mjs` exec the Tasks binary (extracted)
and the console (cut) and are dead. `cce-live` is a retired target (decision 0593).

Fix. `.corvint/test-binary-consumers.json` declares both proofs as consumers of the three provider
commands, without `run` (no Linux runner can execute them), so a change reaching any of those builds
names them as `UNSELECTED_BINARY_CONSUMER`, which CI retains as a check still required (STR-V0-750)
without widening the Go shards (CIN-V0-860). `make interactive-alpha-test` runs
`core-process.test.mjs`; `typescript-test` (the declared TypeScript family, `make host-adapter-test`)
depends on it, so the `host-adapters` job runs it. `cmd/corvint` is left undeclared for the same
reason AFP-V0-762 gives for web-flows. The dead proofs are left in place and documented.

Tests. `TestRepositoryDeclaresWebFlowsConsumers_AFPV0762` now also pins the two installed-host
entries. Probe (dirty `internal/jstestprovider/application_attestation.go`, a transitive dependency
of the js provider): the plan names `conformance/interactive-alpha/core-provider-proof.mjs` and
`extensions/vscode/test/installed/run.mjs` as `UNSELECTED_BINARY_CONSUMER` with the hint naming
`cmd/corvint-js-test-provider`, and selects both web-flows consumers (`DECLARED_CONSUMER`). Before
the change the same probe named nothing for the proofs.

Not observed. No node binary exists on this host, so `make interactive-alpha-test` was not run
here; it needs `/usr/bin/python3` and `ps -axo lstart=` (both present on `ubuntu-24.04` runners).

## V1-5195: flows as the join between code and Corvint's E2E suites

Design. `.corvint/e2e-flows.json` (`corvint-e2e-flows/0`) binds consumer files of
`.corvint/test-binary-consumers.json` to flow IDs of an intent directory. `appflows.BindE2EFlows`
runs in `planAffectedGraph`, the one planning tail of `corvint affected`, `corvint test` and
review, after the AFP-V0-762 and AZU-V0-007 rules: a reached bound consumer is kept when any link
of a bound flow has a target the change reaches (the selection carries `flows`; an unknown's hint
names them), left out when a `reviewed` link of some flow explains every changed path reaching its
commands (`e2eOmitted` records the mapping), and otherwise kept with `E2E_UNMAPPED_CHANGE` naming
the path. Global paths forbid omission; an invalid declaration adds `E2E_FLOWS_INVALID` and narrows
nothing; snapshot plans and plans over 4096 dirty paths are unchanged. The CI driver
(`gateselect.E2EFlowUnknown`) and `corvint test` admit the two entries without widening, because
the consumer they concern is already selected or a check. A separate file was chosen over a
`flows` member of the consumer entries because a planner pinned to an older commit refuses unknown
members and would drop every consumer. The intent directory is `flows/`, owned by
`internal/liveverify/affected/liverepo/e2eflows_repo_test.go` (moved there on 2026-11-10, because
a confined test cannot read `.git`) through an owner row; the declaration is claimed through
`.corvint/runtime-readers.json` like the other planner declarations.

Granularity finding. The Go graph reaches a link target through its owning package, so a flow that
anchors a command's `main.go` is reached by every change that rebuilds the command. Corvint's four
intents (`installed-go-live-tests`, `installed-js-live-tests`, `installed-test-validity-mcp`,
`web-flows-browser-gate`) anchor each command's `main.go` and one file per internal package the
suite exercises; measured on this repository the binding omits nothing today, and its effect is the
`flows` annotation, the reviewed anchors (`reviewed_at` = `5cb958a65`, the declaring commit) and
the fail-closed unknowns. Narrowing between consumers of one command arises only through flows
whose targets lie in packages the change does not reach, as the fixture test shows (`web/run-b.mjs`
omitted for a `lib/lib.go` change with a reviewed `tool-run` link). File- and line-level reach stays
with the `e2e-safe` profile. Item (2) of the ticket (anchor subcommand handlers so handlers
distinguish) is not achievable at package granularity; the spec states this.
