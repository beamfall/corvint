# Driver frontier claims bounded to evaluated make alternatives (selfloor)

Lane selfloor takes the `FRONTIER_SITE` part of V1-5000. That ticket measured 1,487 driver units
over the last 20 merges that the new `.corvint/changes/<sha>.cem.json` of each PR selected by a
`FRONTIER_SITE` witness. The lane adds AFP-V0-3120 to AFP-V0-3124 to
`docs/specs/affected-zero-unknown-v0.md`, and review round 1 adds AFP-V0-3125 to AFP-V0-3128. Fix round 2 amends AFP-V0-3127 and makes the root `Makefile` run nothing at read time. Path-literal, record, unbounded and broad-scope readers
belong to other lanes and are unchanged here.

## Why a new CEM reached these sites

The cause is in `internal/liveverify/affected`, at base `538e823f4`:

1. **Every computed site claims every dirty path.** `driverSites` (`driver.go`) seeds each unit
   whose `Frontier` holds `driver:computed-invocation`, on any plan with a dirty path. Its witness
   is `FRONTIER_SITE` on `dirty[0]`, and it walks the unit's dependents. A CEM path sorts before
   `docs/` and source paths, so it became the witness.
2. **The expander turned ambiguity into computed sites.** `driverExpander.lookup` (`driver_make.go`)
   set `ambiguous` for any variable with more than one assignment. `function` did the same for
   `if`, `or`, `and`, `filter`, `filter-out`, `findstring`, `word`, `wordlist`, `firstword`,
   `lastword` and `join`.
3. **One ambiguous value marked the whole file.** `makeUnits` (`driver.go`) expanded every
   variable value and remainder line with one file-level expander, used or not. It then set
   `shared.computed = shared.computed || fileExpander.ambiguous` on every target of the file.

The repository's `Makefile` defines
`CORVINT_GOCACHE ?= $(patsubst %/,%,$(or $(TMPDIR),/tmp))/corvint-go-build-cache`. That one
`$(or ...)` made 188 of its targets computed sites, out of 196 computed driver units in the
repository; the other 8 are CI jobs. All 123 `FRONTIER_SITE` selections of merge `36e2da4e8`
are these sites at chain length 1. `shell:foreign-invocation-unmodelled` is not a seed. It is an
inbound unknown entry that `frontierUnknowns` names under `plan.unknown` and `frontierBearers`,
and it selects no unit.

## Design

- **Evaluation (AFP-V0-3121).** Recipe lines, prerequisites and includes expand into every
  complete alternative, walking at most 256 expansions per text:
  - a variable's values come from its assignments: every conditional branch, `?=` and `+=` in
    file order, and target-specific values;
  - the expansion in progress takes one value per variable;
  - an `if`, `or` or `and` that only the environment decides takes both outcomes;
  - word functions are exact over definite values.

  The repository's worst recipe line needs 112 distinct expansions, and the whole Makefile
  expands in about 6 ms.
- **File scope (AFP-V0-3120).** Only an ambiguous `$(shell ...)`, an ambiguous remainder recipe,
  or a bare statement that can expand to make text marks every target of a file.
- **Certified read set (AFP-V0-3122).** Bounding a site's argv does not bound what it reads.
  Before this rule was added, a draft dropped the claim for every evaluated target, and the
  replay showed it would drop 116 Makefile targets for the CEM of `36e2da4e8`. Among them were
  `eol-policy-check`, `binary-blobs-check`, `stray-backups-check` and `tracked-ignored-check`.
  Their scripts list every tracked file with `git ls-files`, so a new CEM really is their input.
  The graph had selected them only through the old file-wide claim. A probe also showed that a
  literal target running a `git ls-files` script, or `go run` of a program that reads a
  root-relative path, is not selected for a new CEM. That gap predates this lane.

  An evaluated target, one the old rule claimed, therefore drops its claim only when every
  command it runs is certified:
  - operand-bounded commands with no recursive option;
  - go package commands other than `go run`, `generate` or `tool`;
  - make calls;
  - shell test scripts, which the shell plugin selects for itself.

  Anything else keeps claiming every dirty path. A literal make file is unchanged. Review
  round 1 narrowed this list to operand-bounded modes (AFP-V0-3128) and added the commands make
  runs while reading the file (AFP-V0-3127).
- **Parity (AFP-V0-3124).** `internal/gateselect` attributes Go packages only and has no driver
  logic, so the requirement is pinned by a parity test, not shared code.
  `TestDriverFrontierBoundParity_AFP_V0_3124` plans the same fixture with and without the driver
  claimant. Go selections, selected tests and `SelectStructural` lines are identical.

## Review round 1: five soundness findings

The independent review of the first lane head (`4e265137c`) returned CHANGES_REQUIRED with five
P1 findings. Each one is confirmed in that head's code:

1. **Immediate assignments lost their captured values.** `variableAlternatives` recorded `:=`
   as plain `=`. Every value was then re-expanded lazily against the final assignments. With
   `PKG = ci`, `RUN := go test ./tools/$(PKG)` and `PKG = local`, the claimant expanded RUN with
   `local`, while make runs `ci`. Prerequisites, includes and statements had the same defect,
   since make also expands them where it reads them.
2. **A later global assignment erased a target-specific value.** A scoped value was unioned into
   the running set, and the next global `=` replaced the whole set.
3. **Unknown operands were certified.** `cat $(INPUT)` with `INPUT = $(or $(FILE),known.txt)`
   passed certification, while `pathWord` discarded the unknown operand.
4. **The whitelist did not bound reads.** `sha256sum -c` reads the files its manifest lists, and
   `awk` and `sed` programs can read files or run commands.
5. **Parse-time shell uncertainty was discarded.** `shared.merge` set `uncertified` for a
   `$(shell ...)` scan, and the next statement overwrote it with the remainder-recipe flag.

The repairs:
- **AFP-V0-3125.** Each event of a make file records its position. `variableAlternatives(name,
  limit)` walks only the first `limit` events:
  - an immediate value is the escaped expansion of its text against the earlier events;
  - `+=` onto a simple value appends a captured expansion;
  - prerequisites, includes, statements and conditional lines expand at their own position.
- **AFP-V0-3126.** Target-specific events are kept apart. They are applied over the final global
  values and every earlier scoped value, and are never replaced.
- **AFP-V0-3127.** `parseTime` collects every `$(shell ...)` and `!=` command reached by
  read-time text, used or not, and scans it for every target. A SHELL or `.SHELLFLAGS` naming
  anything but a plain shell with `-c` also counts. A `$(shell ...)` in a recursive value still
  counts only where a recipe expands it.
- **AFP-V0-3128.** Certification is per command:
  - literal operands, a known directory, no unknown input redirection and no `xargs`;
  - no checksum `--check`, `--files0-from`, jq module or library path, and no recursive `grep`,
    `cp` or `diff`;
  - `awk` and `sed` are gone from the list;
  - a go command may leave unknown only an output or selection value, because any other unknown
    word can split into `-exec`.

Each finding has a table-driven regression. I ran every new test against the first head's
sources: every positive case failed, and every control passed. `TestDriverMakeFunctionsComputed_AZU_V0_9850`
now expects a computed site for `go test ./$(firstword $(PKGS))_test`, since PKGS can split into
flags.

The round considered, and left out, one more change: keeping the environment alternative for a
`?=` variable. That would make every `GO ?= go` recipe a computed site, including literal targets
the base never claimed. It belongs to the existing non-goal on command-line and environment
overrides, which the spec now states in AFP-V0-3125 as the default-invocation boundary.

How to read the replay:
- **Round 1 selects exactly the base's units on every merge.** No unit was added or dropped, and
  every unknown entry and scope is identical. Each plan also reports the same 195
  `driver:computed-invocation` sites as the base; the first head reported 120.
- `FRONTIER_SITE` fell only from 1,573 to 1,550. For about 22 units a real edge is now found
  first, such as `requirement-ids-free` by `DEPENDENCY_PATH`, or `conflict-markers-check` by
  `UNBOUNDED_READER` through `script/heavy.sh`. Every one of them is still a site.
- Test files are unchanged throughout, because driver units carry none.

**Why the first head's 716 dropped units all came back.** The root Makefile defines
`WINDOWS_VET_GOCACHE := $(if ...,$(if $(filter tmpfs ramfs,$(shell stat -f -c %T $(patsubst
%/,%,$(or $(TMPDIR),/tmp)) 2> /dev/null)),...))`. Make runs that `stat` while it reads the file,
for every target. Its operand can come from the environment, so AFP-V0-3128 does not certify it,
and AFP-V0-3127 leaves every evaluated target of the file uncertified. A throwaway
in-package probe built the driver graph of the `36e2da4e8` Makefile alone:
- as committed, 187 of its 187 targets are computed sites;
- with only that assignment made recursive (`=`), 115 are.

The same holds at the lane head (188 and 115). The `$(shell script/dogfood-merge-base.sh)` beside
`DOGFOOD_MERGE_FORWARD_BASE` is not reached in the default invocation, since `BASE ?= origin/main`
filters it out.

**What would recover the precision soundly.** Either of these would let the 73 targets drop their
claims again, without a model change that could miss a test:
- make `WINDOWS_VET_GOCACHE` recursive, so its `stat` runs only inside `windows-vet` (fix round 2
  did this; see below);
- add a rule that a read-only `$(shell ...)` with no consumer outside its own variable affects
  only that variable's readers.

The remaining claims also need a reader rule for repository scripts and `go run` tools, as
before.

## Fix round 2: a recursive WINDOWS_VET_GOCACHE

The orchestrator made three decisions under the owner delegation of 2026-11-02:
1. **The shared `.git/info/attributes` blocker is gone.** The merge drivers now load per command
   (`git -c core.attributesFile=...`), so `cem-prepare` binds in the lane worktree again.
2. **`WINDOWS_VET_GOCACHE` becomes a recursive assignment (`=`, was `:=`).** Its `stat` then runs
   only where `windows-vet` expands it. AFP-V0-3127 now states that the root `Makefile` runs no
   uncertified command while make reads it.
3. **The default-invocation boundary is accepted as written in AFP-V0-3125.** Command-line and
   environment overrides of a variable the file sets stay outside the model, and this lane models
   none of them.

**windows-vet still holds (AFP-V0-054, ASD-V0-061).** The recipe text is unchanged, so the
`TestAFPV0054` parity with the CI vet step is unaffected. `make -n windows-vet` names the same
`GOCACHE` before and after the change. The three `script/lane-scripts_test.sh` cases also give the
same results:
- a fake `stat` answering `tmpfs` gives the XDG cache;
- one answering `ext2/ext3` gives the `TMPDIR` default;
- a caller's `CORVINT_GOCACHE` is kept.

`CORVINT_GOCACHE` is a `?=` that no later line reassigns, so evaluating `$(origin ...)` lazily gives
the same answer. Only `WINDOWS_VET_ENV` reads the variable, and nothing exports it.

**Regression.** `TestFrontierSiteRootMakefileRunsNoReadTimeCommand_AFP_V0_3127` builds the driver
graph of this repository's root `Makefile`:

It reads the real `Makefile`, so a change to that file selects it.

  claiming every path. Narrowing them further needs a reader rule for those programs, not a

the base, each dropped unit is a frontier claim on a path its bounded command set cannot read.
