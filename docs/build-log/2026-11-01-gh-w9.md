Decisions (made by the lane; the owner was asleep):

- Placement. The check runs inside the narrowing gate (`id: narrow`, `continue-on-error: true`),
  so a lagging pin makes every shard run FULL, never red. A required red job or doc-gate would
  block every PR and lane after any selection merge until someone repinned. A PR also cannot pin
  its own merge commit, so a red check could never pass on the PR that changes selection code.
- Source of the script. The gate reads `pin-lag.sh` from the compared main commit: the tested
  merge's first parent on the PR path, and `$scripts` on the merge-queue path. It never reads it
  from the tested tree. A PR that edits the script is a `.github` change, which already forces FULL.
- Semantics. Lag means a tree diff on the declared selection paths between the pin and main, plus
  the pin being an ancestor of main. A revert therefore counts as no lag. The commit count and the
  first 10 hashes are informational only.
- Path list. It is declared in the script, not derived from the import graph: `internal/gateselect`,
  `internal/liveverify/affected`, `internal/sessiontest`, `tools/corvint-pr-tests`,
  `tools/gate-affected-select`, `.github/cishards`, `cmd/corvint/affected*.go`,
  `cmd/corvint/test*.go`, `narrow.sh` and `narrow.jq`. It excludes `*_test.go`, `testdata/` and
  `.github/cishards/package-costs.json`, which only moves shard costs.
- Requirement ID. The lane block was 1010-1014, but `script/gen-spec-requirements.sh` parses only
  3-digit suffixes, so CIN-V0-1010 was silently left out of `REQUIREMENTS.tsv`. I used CIN-V0-010
  instead. It is unused on every ref, and CIN-V0 keeps 001-049 for itself.
- Consequence. In-flight lanes that change a selection path make CI run FULL until the next repin.
  tools-r is one, since it touches `internal/liveverify/affected`. Repin both pins after such a
  merge lands.
