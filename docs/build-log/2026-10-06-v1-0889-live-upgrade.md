# V1-0889 in-place corvint-tasks upgrade with live attempts (issue 644)

Date: 2026-10-06. Ticket V1-0889, GitHub #644. Requirements CAL-V0-130..134 in
`docs/specs/corvint-tasks-agent-leases-v0.md`, all proposed; acceptance is human-owned.

## Why operators drained

- No documented upgrade procedure or compatibility rule: `docs/TASKS-EXTERNAL-AGENTS.md` and the
  specs had none, so drains were precautionary.
- The external lease path has no build binding. Attempt records carry policy, config and capability
  digests but no binary identity (`internal/tasks/snapshot/attempt.go`). Heartbeat, renew and plain
  release are fenced only by generation, terminal phase and expiry (`leaseContext.fenced` and
  `planRenew`, `planRelease`, `planHeartbeat` in `internal/tasks/transaction/lease.go`). The store
  version is the fixed `taskman-state/0` (`internal/tasks/snapshot/probe.go`).
- The dispatcher ledger refused another profile version and members from a newer build with
  uncoded errors that surfaced as MALFORMED (`LoadLedger` in `internal/tasks/dispatch/ledger.go`).
  Adoption across restart already worked (`Open` in `internal/tasks/dispatch/loop.go`).
- Under the user service, a changed executable holds new launches until `service install --replace`
  (`internal/tasks/service/run.go`, `lifecycle.go`); workers are preserved, so this stalls rather
  than requiring a drain.
- Mixed-build window: detached attempt runners re-execute `os.Executable()` as a supervisor
  (`internal/tasks/cli/attempt_detach.go`) and supervised owners record their PID
  (`internal/tasks/store/program_run.go`); both keep running build N after a swap. Nothing stated
  that N+1 writes only records N can read.
- The HANDOFF policy-digest fence (`internal/tasks/transaction/lease_handoff.go`) is a separate cause
  owned by V1-0888 and is not changed here.

## Change

`version` reports `formats` (`cli.LiveFormats`). Equal sets mean adjacent-compatible builds; a
build that changes a listed format must bump its version. `LoadLedger` now refuses another
dispatch-state version or an unknown top-level member with UNSUPPORTED_VERSION before decoding.
The operator procedure is in `docs/TASKS-EXTERNAL-AGENTS.md`.

The supervised-host pin is kept unchanged: it pins the host runtime, not corvint-tasks, so it never
blocked a corvint-tasks swap. The boundary is that a live supervised owner must not be killed.

## Evidence

`TestCALV0130_AttemptClaimedUnderBuildNContinuesUnderNPlus1` builds corvint-tasks twice with
`-X main.build=41` and `42`, claims under 41, installs 42 by rename, then heartbeats, renews and
releases under 42. Between those, it heartbeats with the retained build 41 binary, and it runs
`receipt audit` under both builds. `TestCALV0131_*` covers the store VERSION refusal, the
formats set and the newer-build attempt and run record refusals. `TestCALV0132_*` covers the ledger refusals and adoption. A live fleet upgrade is
NOT_RUN.

## Review repair (Codex P2 findings on b6932acb)

- The first `formats` set listed 13 records and missed consumed formats such as
  `taskman-programs/0`, `taskman-stage/0` and `taskman-pool-state/0`. It now lists the store
  VERSION and all 53 profiles the tasks packages persist and decode again; 15 profiles written only
  to stdout are listed separately in the test. `TestCALV0131_LiveFormatsCoverEveryDecodedProfile`
  scans every non-test Go file under `internal/tasks` for `taskman-*/N` literals and fails when one
  is in neither list, or when a listed entry is named by no source. Removing `taskman-stage/0` from
  the set was checked to fail it.
- Decoders checked closed keys before the profile, so a record from a newer build with a new member
  was MALFORMED, and the run record compared its profile without a code. `wire.ProfileVersion`,
  `wire.RawProfileVersion` and `(*wire.Reader).Profile` now refuse the decoder's own profile at
  another version with UNSUPPORTED_VERSION before any other check. They are applied in every
  decoder of a listed profile, nested ones included (retry accounting, direct-pool admission,
  lane-untouched attestation, release attestation, criterion binding, supervision policy). The
  run record uses `CheckProfile` (ATR-V0-010 amended in text by CAL-V0-131). The dispatcher event
  log stays a skip-on-mismatch tail read, which the spec now states.
- The survivor case ran build N only as separate short CLI calls. The test now starts a build N
  `run` from the installed path before the rename, keeps it running across the swap and the build
  N+1 heartbeat, renew and read, then lets its command end: it heartbeats again, records its run
  outcome and exits 0.

Not covered end to end: callers that wrap a decoder's error lose its code (`wire.CodeOf` does not
unwrap). The attempt, run record, store VERSION and dispatcher ledger paths were checked at the CLI;
the other decoders are covered at the decoder only.

## Inference

On macOS, rewriting a signed running binary in place can terminate the process. This is inferred,
not measured here, and it is why the procedure installs by rename.
