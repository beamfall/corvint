# Nightly #1116: no-Python external-conformance exemption, real-probe helper fd, MCPV0-038 check

Issue [#1116](https://github.com/beamfall/corvint/issues/1116): the scheduled release-gates full gate
on `714393264` (run 39258757168) failed on macos-15 and ubuntu-24.04.

## V1-1970: `no-python-runtime-dependency-test` (both hosts, deterministic)

`script/spec-toolchain-conformance.sh` (`STA-V0-011`, V1-1697) creates a venv and runs `pip` to
install third-party Spec Kit, so the `GOC-V0-008` scan flagged 15 of its lines. That script measures
upstream's own view and is not a gate step; the path-filtered conformance workflow runs it.

Decision: a named exemption by exact repository path (`GOC-V0-011`), not an env opt-in. An opt-in
would have to guard each of the 15 lines, and the script needs Python unconditionally. The scan
now reads `grep -Hn` lines and drops only those whose path field is exactly the script. It also
fails when the exemption becomes reachable: `GATE_STEPS` lists the target, another target depends
on it, another recipe runs the script, or another scanned script invokes it outside a comment.

Evidence: the script's new self-tests allow the exempt line. They fail the same line under
`script/build.sh`, `script/spec-toolchain-conformance.sh.bak`, a prefixed path and a Makefile
recipe, and they detect all three Makefile reachability shapes. Four mutants (substring exemption,
no `GATE_STEPS` rule, no prerequisite rule, no recipe rule) each fail a self-test in an isolated
copy of the tree. The check passes on macOS (`/bin/sh`, BSD awk) and in `golang:1.27.2` (dash, mawk).

## V1-1780: `TestTQDV0021_RealProbes` silent miss (ubuntu, intermittent)

Root cause: a test bug, not a probe bug. `TestDoctorLockHelperProcess` opened the lock file and
never used `f` after `Flock`. A garbage collection in the helper could finalize the `*os.File`,
closing the descriptor. On Linux that releases the flock and removes the process as an opener while
it keeps running. The doctor then correctly saw nothing to report. That explains both shapes:

- nightly: both helpers lost their descriptors, so there were no findings and no warnings;
- merge-queue run 39133588433: only the holder lost its descriptor, so SLOW was reported but not HELD.

Proof: forcing `runtime.GC()` in the helper before `ready` without a keep-alive failed 3 of 3 runs
with the nightly's exact signature (`"findings":[]`, warnings `[]`).

Fix (test only): the helper keeps `f` alive until exit (`runtime.KeepAlive`). It also forces two
collections and waits 100 ms before `ready`, so a lost keep-alive fails every run instead of
intermittently. The doctor's probe output was accurate, so `TQD-V0-021` needs no amendment and no
requirement ID was added.

Evidence: `-count=20` passed on darwin and in a linux/arm64 `golang:1.27.2` container (kernel 6.8,
procps-ng 4.0.4).
