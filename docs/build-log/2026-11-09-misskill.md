## V1-5216: a fail-closed FULL fallback tripped the global kill switch

What was wrong: PR #163's main-built shadow refused its `.corvint/runtime-readers.json` entry
(`no plan: unsupported-affected-graph`), so `corvint test --dry-run` printed a document with scope
`FULL`, a reason, a manifest digest, no plan or partition digest and no Go unit. `row.jq` required
both digests in the `corvint-pr-selection/0` shape, so all sixteen documents failed it, the row was
`INCOMPLETE` ("selection documents cover shards  of 16"), and four `ci-control-plane` runs over three
tested merges wrote three distinct `INCOMPLETE` names into the AFP-V0-030 window: `accept.sh` printed
FULL (killSwitch TRIPPED, incomplete=3) for every pull request.

Fix (CIN-V0-7921): a `FULL` document with a non-empty reason is a fallback document and passes the
shape without the digests. A row whose every selection document is `FULL` is the new class `FULL`,
named `ci-forward-FULL-pr<N>-<sha>-e<E>-f<f>-r<skew|abstain|plan>`; `bar.jq` counts FULL rows on their
own (`full` in JSON, one markdown line) and they are neither complete nor `INCOMPLETE`, take no
window place and never replace a counted row. The per-(pull request, commit) deduplication of the
window already existed; the four #163 names counted three, which is what tripped.

Tests (`tools/ci-forward-row/fullrow_test.go`): `TestCINV07921FallbackSelectionIsATypedFullRow_CINV07921`,
`TestCINV07921CollectorNamesTheFullRowWithItsType_CINV07921`,
`TestCINV07921FullRowsAreNotNarrowingEvidence_CINV07921` (the four-names-over-three-merges window),
`TestCINV07921FallbackRerunsKeepTheVerdictMet_CINV07921` (`accept.sh` over the #163 listing shape:
MET with FULL names; the old INCOMPLETE names reproduce the 2026-11-09 verdict FULL with a tripped
switch).

Not delivered: the owner-listed `infra-reclassified.txt` keys for the three already-uploaded
`ci-forward-INCOMPLETE-pr163-<sha>-e2-f0` artifacts. Their tested-merge SHAs are GitHub-synthesised
commits that exist nowhere in this clone (`872458ac…` is the only prefix the ticket gives), and this
lane runs no `gh`. The owner appends one `pr163-<40-hex sha> artifact=<id>` line per artifact under
a dated comment; until then the three rows age out of the latest-20 window on their own.

## V1-5218: all-abstained FULL rows counted as narrowing evidence

What was wrong: with the shape fixed, an all-FULL run would have been `CLEAN` (S empty, nothing
failed outside it) and counted toward the 8 complete rows of AFP-V0-029 although the shadow
measured no narrowing; a planned whole-universe FULL run already did.

Fix: the `FULL` class above, excluded from the complete count. Evidence:
`TestCINV07921FullRowsAreNotNarrowingEvidence_CINV07921` (twenty abstained FULL rows: NOT MET, 0
complete, switch clear; beside eight complete rows the count is unchanged). Fault injection in
`TestCINV07921FallbackSelectionIsATypedFullRow_CINV07921`: with the `elif $fullRun then "FULL"`
branch of `row.jq` removed, the all-abstained #163 run classifies `CLEAN`, and `MISS` once a package
fails; and the bar test shows the pre-change `CLEAN` names meeting the bar.

## V1-5219: tool skew on a PR that changes affected-graph inputs

What was wrong: the shadow is built from `main` (trusted), so a pull request that changes
affected-graph inputs the pinned tool cannot read has no measurement, and the row did not say why.

Fix: the typed abstention. `selection.full.type` is `skew` when every shard planned nothing with a
reason starting `no plan: unsupported-affected-graph`, `abstain` for any other no-plan reason, `plan`
for a planned whole-universe run; the name carries the type and `bar.jq` reports the counts per type
and the pull requests. Building the shadow from the pull-request head was rejected: it would run
pull-request code in the trusted shadow (AFP-V0-047). A fixture pull request changing
`.corvint/runtime-readers.json` yields `ci-forward-FULL-pr163-<tested merge>-e1-f0-rskew`
(`TestCINV07921CollectorNamesTheFullRowWithItsType_CINV07921`).

## V1-5198: main full-run misses were advisory and never confirmed

What was wrong: `mainmiss.sh` linked a failed full run of main to the narrowed pull requests that
skipped the failing package, but `bar.jq` labelled the count advisory, nothing reran anything, and
the two observed rows (#104 at `dba1f4d6c`, run 42194527842; #109 at `654df5053`, run 42235669659;
both `internal/tasks/store`) stayed unconfirmed.

Fix (CIN-V0-7922): the new `.github/workflows/main-miss.yml` runs `mainmiss.sh` (moved out of
`ci-control-plane.yml`, which has no Go toolchain) and then `mainmiss-confirm.sh`, the
package-level analogue of `linecov-miss.yml`: each skipped package runs once at the merge commit's
first parent and twice at the merge commit under the shards' `-race` build, `test-confine` wrapper
and 50m deadline. Pass, fail, fail is `confirmed` and is uploaded as `ci-forward-MISS-pr<N>-<merge>-e<E>-f1`,
which the bar and the AFP-V0-030 kill switch count like any MISS (one: NOT MET and `accept.sh`
FULL; two in the window: TRIPPED); a merge pass is `flake`, a base failure `preexisting`, anything
unrunnable `unconfirmed`. The check is retained as
`ci-forward-MAINCHECK-r<run>-<sha>-e<E>-c<confirmed>-k<flake>-u<unconfirmed>-pr<N>…`, reported as
`mainMiss.checks`; a confirmed miss files one GitHub issue (the filed ticket) and fails the job.
`mainmiss.sh`/`mainmiss.jq` record each miss's `merge_commit_sha`. `main-miss.yml` is not added to
`github-guard.sh`'s inputs: like `linecov-miss.yml` it runs from the default branch only and can only
widen to FULL.

Tests (`tools/ci-forward-row/mainmiss_confirm_test.go`):
`TestCINV07922ConfirmationRerunsClassifyEachSuspectedPullRequest_CINV07922` (a real Git repository
and a `go` stand-in: confirmed, absent-at-base confirmed, flake, preexisting, off-main and
no-merge-commit unconfirmed; rerun order and flags; MAX_PACKAGES and BUDGET_SECONDS; an unusable base
capture; no worktree left), `TestCINV07922ConfirmedMainMissIsAMissRow_CINV07922`,
`TestCINV07922MainMissWorkflowBinding_CINV07922`; `TestAFPV0983MainFailureNamesTheNarrowedPullRequest`
now checks `merge`; `TestAFPV0047WorkflowBindings` and `TestCINV0960WorkflowsAgreeOnTheForwardEpoch`
read the epoch from `main-miss.yml`.

### Classification of the #104 and #109 rows (local replay, 2026-11-10)

The confirmation protocol was replayed on this host for both rows with `go1.27.3 linux/amd64`.
`mainmiss-confirm.sh` itself could not finish here: `internal/tasks/store` holds 722 top-level tests
and one `-race` run of it exceeded 15 minutes (907 subtests started, 477 passed when the run was
stopped), past this lane's single-command budget. The same `go test -json -count=1 ./internal/tasks/store`
was therefore run without `-race` and without the `test-confine` wrapper, as eight test-name slices
whose union is the package's full test list at each commit (`go test -list`), four slices at a time,
and each capture classified with the script's `rerun` filter (package-level `pass`/`fail` event and
exit status). One base slice of #104 timed out under load at 9m with ten tests unfinished; those
ten were rerun alone and passed. Every other slice passed first time.

| Row | Base (merge^1) | Merge commit | Base result | Merge result | Verdict |
|---|---|---|---|---|---|
| #104, run 42194527842 | `9208cc7e25bb82503ef9d61b0ce6a5f02039e649` | `dba1f4d6c9a33098470ccf57794fb66f989f03c8` | 694 passed, 28 skipped, 0 failed | 694 passed, 28 skipped, 0 failed | FLAKE |
| #109, run 42235669659 | `7fd70eab2f6475074dd1c85c62a43cb5a6a7ff0e` | `654df5053cc3a5f36aa4ecb48af36c5eaea0a86c` | 694 passed, 28 skipped, 0 failed | 694 passed, 28 skipped, 0 failed | FLAKE |

Both rows are classified FLAKE under CIN-V0-7922's rule (a pass at the merge commit ends the
protocol): the package the narrowed selections skipped passes at both merge commits, so the main
failures were not caused by those pull requests, consistent with the flakes V1-4798 and V1-1405 the
ticket suspected. Limits: the replay ran without the race detector and the confine wrapper, so a
race-only or confinement-only failure would not reproduce here; a hosted rerun under the workflow
remains `NOT_OBSERVED`. No MISS row results from a FLAKE verdict.
