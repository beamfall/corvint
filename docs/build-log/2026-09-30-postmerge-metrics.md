# Experimental per-content-class post-merge evidence

Issue #396 (native V1-0543) supplies human-owned intent: stage/follow-up timing, net edits after a
bot commit, later corrections/reverts/invalid findings/containment, policy classes and reproducible
recommendations. The optional Darwin/Linux companion grants no merge authority. The proposed
[contract](../specs/postmerge-metrics-v0.md) is technical scope, not owner policy promotion.

## Design and independent findings

A bounded independent Gate A found two HIGH gaps in the initial plan: sorting a late revert by its
target's old run time could consume demotion prematurely, and a retained array cannot prove complete
history. Revision review passed after separating immutable run/event chronology and requiring
contiguous class sequences plus independent explicit run/event completeness watermarks. Both remain
caller assertions. Equal-time events precede runs; a revert resets the next-N cooldown at event time.
The cohort and knowledge cutoff are half-open. Future rows are validated and must fit inventory
watermarks, but do not affect historical recommendations.

Independent source review found one MED gap: an in-window reverted run could regain an eligible
class recommendation after cooldown reached zero. The first repair adds an explicit reverted-cohort
review reason and zero/exhausted cooldown regressions. No HIGH authority-boundary finding was raised.

Counts use a distinct corrected generated-run numerator and generated-run denominator. Minimum
samples and integer basis-point comparisons are explicit. No-change, failed, unknown, historical
demotion, remaining cooldown and event kinds remain separate. The report does not infer authorship
or complete external capture. Stages/follow-up/edits with missing evidence force review.

Immutable Git reads disable rename recognition, so a rename is two changed paths and delete-plus-add
lines. Binary totals stay unknown. Committed attributes are pinned to the approved revision;
mutable local info/attributes and named diff drivers refuse. Git version is retained. The existing
bounded owned-process runner is reused, with descendant observation and tested cancellation; this
is not complete containment of every fast detach. Inputs, process streams and elapsed execution are
bounded. Standalone CLI registration leaves Core's optional boundary intact.

## Evidence and qualification

Pre-change Corvint query and impact receipts were retained. Query returned seven results with no
critical omission; history/learned links remained advisory. Impact on the reused process runner
omitted 71 ranked rows and is not a claim to change that package. Other analyzer/browser/live
integration routes are inapplicable: this slice is a local Go companion and reducer, with no external
service action. Initial `make dogfood-change` before edits retained missing CEM/intent/outcome
NOT_PRODUCED rows. A new intent bootstrap was committed before enrollment against the original base;
it does not retroactively supply an accepted base spec. Affected advice is retained, including broad
mandatory-gate suggestions; the owner's scoped-work preference selects focused checks here. No
repository-wide gate or token savings is claimed.

Focused fixtures exercise event chronology, incomplete inventories, exact rate thresholds, canonical
bytes, real Git additions/deletions/modifications/renames/binary/odd paths/zero delta, configuration
isolation, nonancestor refusal, output overflow, cancellation of owned descendants and actual CLI
reporting. Darwin observations do not qualify a Linux runtime cell. Independent source review,
shared spec registration, final frozen checks/CEM/OCM, publication, integration and native completion
remain required; passing source fixtures alone is not delivery.
