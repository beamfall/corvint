# Lane affected-w3 (wave 3): affected, liveverify and impact tickets

Lane `affected-w3` on the WSL host, branch `claude/lane-affected-w3-1031` from `origin/main`
`dbc1713779fc17ce0386fe95d3e0f6347f5f9aee`. Requirement IDs come from the lane block 760-779 in
each governing prefix; `AFP-V0-760` was already taken on the base, so the AFP ones start at 761.
V1-2259 and V1-0633 were built by two sub-lanes in their own worktrees, on
`claude/lane-affected-w3-ancestry-1031` and `claude/lane-affected-w3-confine-1031`. Both were merged
into the lane branch with merge commits. Their spec sections did not overlap; `REQUIREMENTS.tsv` was
regenerated after each merge.

## Decisions

- V1-2051 (AFP-V0-761): affected keeps planning one repository root and does not follow a `go.work`
  `use` outside it. A plugin may now name the route past a frontier (`affected.FrontierRoute`).
  The route is appended to the entry's `hint`, so `detail`, scope and selection are unchanged. For
  `go:workspace-module-outside-root` the route is: plan the sibling's change in its own checkout,
  and declare the cross-module Go API relations for `corvint breakage`.
- V1-2054 (KAT-V0-761/762):
  - `gradle/libs.versions.toml` is a Kotlin config unit, and every Kotlin unit under its build
    root imports it. That is the "all modules with a stated reason" option: alias-level
    resolution is not modelled.
  - A root catalog also reaches the tests of a nested build. This over-selects, which is safe.
  - In a `com.android.test` module (plugin id, or a catalog plugin alias), a test in `src/main`
    is the typed unit `kotlin:android-test:<module>:unknown:...`, with the frontier
    `kotlin:android-test-module`. The task stays `unknown` because the build's variants
    define it.
- V1-1017 (AFP-V0-762):
  - `.corvint/test-binary-execs.json` gains an optional `consumers` member, `FILE -> [COMMAND]`.
    It becomes TSP-V0-005 `callers` on the command unit.
  - When a plan reaches the command's build, every consumer file that no selection runs as a
    test is named `UNSELECTED_BINARY_CONSUMER`. A command reached only for its own test files
    names none.
  - Measured on this repository:
    - A `cmd/corvint-web-flows/main.go` change now *selects* `tools/web-flows/test/navigation-e2e.mjs`
      (a node-test unit reached through the new edge). It names `tools/web-flows/test/e2e.mjs` as
      the explicit unknown.
    - A `main_test.go`-only change names nothing.
  - The e2e scripts also run `cmd/corvint`, but they are declared only against
    `cmd/corvint-web-flows`. A first draft that also declared `cmd/corvint` named e2e.mjs on
    almost every plan, because nearly every change reaches that build. The batch replay
    `TestBatchReplayDeclaredRuntimeReaders_V12941` caught this.
- V1-1831 (RUBY-AFFECTED-V0-761): the Ruby plugin owns the root `app/views/**`.
  - Each template is a `ruby:view:` source unit.
  - Every route-dispatched test carries every view unit as a route-dispatch edge. A view change
    therefore selects request, system, feature and controller specs with `ROUTE_DISPATCH_BOOT`,
    and the plan stays `BOUNDED`.
  - A template outside the root `app/views` stays unowned. A view with no route-dispatched test
    abstains as `NO_SELECTABLE_TEST`.
- V1-1851 (NGI-V0-761): for `app/controllers/<x>_controller.rb`, impact lists the tracked
  `spec/requests/<x>_spec.rb` as an advisory, low-confidence convention row scored 440.
  - An unmatched controller abstains, and so does `application`.
  - `config/routes.rb` is not read.
  - The `request-spec` and `controller-spec` rows of `conformance/ruby-profile-v0/rows.json` now
    list `spec/requests/users_spec.rb`.
- V1-2077 (AFP-V0-763): instruction files get **no** built-in class.
  - Reason: only the project knows whether a build, a test or a tool reads `AGENTS.md`.
    Corvint's own `affected` advice reads the Verify block. A built-in class would be a Corvint
    guess outranking project authority.
  - An undeclared instruction file keeps `UNOWNED_DIRTY_PATH`, now with a hint that names the
    AFP-V0-160 declaration route.
  - This repository now declares its own `AGENTS.md` and `CLAUDE.md` in
    `.corvint/documentation-paths.json`.
- V1-2082 (AFP-V0-764): every profile keeps a refusal; none plans a `--path` list, because each one
  plans its own change set. The refusals are now typed, `unsupported-affected-path-profile`, and
  each names its reason and recovery:
  - snapshot: a frozen tree;
  - provider: the protocol carries no path list;
  - Playwright: its discovery comes from the worktree;
  - AppMap: the report is bound to the `--base` range.

  `--base` stays `invalid-arguments`.
- V1-1450 (TCQ-V0-761): when a hunk's own directory has no candidate test, the guarding-test
  search falls back to its direct importers.
  - The importers are the root module's directories that import the package, at most 16, in
    directory order.
  - In an importer, a candidate is a test that reaches an exported name of the hunk's closure.
  - Hunks that already have an own-directory candidate are unchanged, so cost and goldens are
    unchanged too.
  - Proven by a real `go test` revert-and-run fixture.
- V1-2206 (AFP-V0-765): the two Go lexers' token streams are not equal, so neither lexer is
  shared, and the 3.90 s median was not re-measured (the sharing step is conditional on
  equality). The four differences are:
  1. Lexed region: after an imports-only parse in one, an import recognizer over the whole file
     in the other.
  2. Comment mode: `ScanComments` in one, mode 0 in the other. Measured over all 6146 tracked Go
     files, the streams are equal once comments are dropped, and no comment splits a qualifier,
     so this has no selection impact today.
  3. Root-locator table shape: the contents are equal.
  4. Literal lexicon: the fast tier lacks the AFP-V0-505/506/840 and V1-1818 rules. This is a
     designed selection difference between the two lexicons, not something sharing a lexer could
     remove.

  Test placement: the repository measurement lives in `internal/liveverify/affected`, because
  `internal/gateselect` declares an empty test read scope.
- V1-2055 (KAT-V0-763, SATS-V0-761): no route resolves these dependencies, because breakage
  covers Go only. Each is a named cross-repository frontier that carries the dependency path:
  - a Gradle `includeBuild` outside the root becomes `kotlin:cross-repository-build:<path>`;
  - a SwiftPM `.package(path:)` outside the root becomes `swift:cross-repository-package:<path>`;
  - a `revision:` pin becomes `swift:cross-repository-package:<url>@<revision>`.

  Version and branch requirements are not flagged, so ordinary Swift plans do not widen.
- V1-2060 (TJAA-V0-761..763):
  - A multi-binding `export const` is keyed per bound name, by declarator text.
  - A sited non-dynamic frontier now taints only the tests whose static closure reaches its
    site, with the witness `FRONTIER_SITE_REACH`. An unsited frontier, or one sited outside the
    graph, still refuses.
  - Further profiles and runners are deferred, each with its reason, and runtime loading stays
    unmodelled.
- V1-2259 (EEP-V0-770..773, sub-lane):
  - Every listed ancestry read is either guarded by `gitancestry.Rewritten`/`RewrittenAt` with a
    typed unavailable state, or recorded as safe with its reason.
  - Dogfood decision: dogfoodflow entry points refuse grafted and shallow checkouts outright. No
    CI job runs a dogfood flow on a shallow checkout: the fetch-depth 2 jobs run only shell
    rev-parse, the gate-reuse finder or the CCE live tests. `ResolveSealBinding` and the
    `script/dogfood-*.sh` wrappers already refused shallow.
  - The contextindex range read is guarded at its three callers, because any byte change to
    contextindex sources forces an analyzer-schema bump.
- V1-0633 (AFP-V0-766..769, sub-lane):
  - The AFP-V0-013 driver gains `--confine WRAPPER`. Its digest and the
    `testconfine.ConfinedEnv` environment are part of the frozen identity. Both selected and
    shadow runs use `-exec WRAPPER` in a clone that has `.git`.
  - Freeze and shadow refuse to start when a covered target declares read scopes and no wrapper
    is given.
  - Landlock is available on this WSL kernel, so the confinement tests ran rather than skipped.
  - Wiring the wrapper into `.github/workflows/pr-tests-qualification.yml` is an owner-protected
    `.github` change and stays a non-goal (AFP-V0-769).

## Friction

1. The lane block collided with an ID already on the base: `AFP-V0-760` is taken (V1-3084).
   Repro: `git grep -n 'AFP-V0-760' dbc1713779fc -- docs/specs/affected-plan-v0.md`.
2. `script/heavy.sh` refuses a whole-package run without `HEAVY_WHOLE_REASON`, even for a small
   plugin package whose `Owns` rule changed, where every test is relevant. Repro:
   `~/lanes/heavy.sh go test -count=1 ./internal/liveverify/affected/kotlin/`.
3. `make spec-requirements` refuses any edit to a spec's `Intent status` or digest `Status` line
   (SRG-V0-980). The lane charter and older specs still suggest recording acceptance there. Repro:
   append "; AFP-V0-761 experimental" to line 6 of `docs/specs/affected-plan-v0.md`, then run
   `make spec-requirements`.
4. `affected.Source.Files` passes the base name, not the path, to its accept callback. A plugin
   that owns a file by directory (`gradle/libs.versions.toml`, `app/views/**`) silently lists
   nothing until it post-filters. Repro: `root.Files(isVersionCatalog)` returns no catalog.
5. A stray `go build ./cmd/corvint` binary, which is gitignored, fails
   `TestRepositoryShellForeignCallersComplete_TSP_V0_005`, because the source walk includes
   ignored files. Fixed in the test, but the walk itself still reads ignored build products. Repro:
   `go build ./cmd/corvint && go test -run TSP_V0_005 ./internal/liveverify/affected/`, at the base.
6. Declaring a Node consumer of `cmd/corvint` would widen almost every plan in this repository to
   `UNKNOWN`, because nearly every change reaches that build. Binary-consumer declarations
   against hub commands therefore cost precision. Repro: declare `tools/web-flows/test/e2e.mjs`
   against `cmd/corvint` and run `TestBatchReplayDeclaredRuntimeReaders_V12941`.
7. `internal/gateselect` declares an empty test read scope. A repository-measurement test can only
   live in a package with a broader scope, which is not obvious until the confined CI run fails.
   Repro: see `.corvint/test-read-scopes.json` `"internal/gateselect": []`.
8. From the V1-0633 sub-lane:
   - `make traceability-tests-check` fails on a spec-only commit that names a test not yet
     written, which conflicts with the spec-before-implementation commit order. Repro: commit a
     spec citing a new `TestX`, stash the code, then run `make traceability-tests-check`.
   - `corvint affected` selects about 82 units for any `REQUIREMENTS.tsv` regeneration, through
     generic unbounded readers. Repro: `corvint affected --base dbc1713779fc` on a spec-only
     branch reports `selected=82`.
9. From the V1-2259 sub-lane:
   - Any byte change to contextindex production source fails `TestAnalyzerSchemaInputs` and forces
     an analyzer-schema bump. Repro: add a comment to
     `internal/contextindex/range_bound_precheck.go`, then run
     `go test -run TestAnalyzerSchemaInputs ./internal/contextindex`.
   - `GIT_GRAFT_FILE=/dev/null` makes Git print the deprecated-grafts hint on stderr, which
     corrupts `CombinedOutput`. Repro: `GIT_GRAFT_FILE=/dev/null git rev-parse HEAD`.
   - `corvint affected` selected 198 units on that branch. Repro:
     `corvint affected --base dbc1713779fc` on `claude/lane-affected-w3-ancestry-1031`.
   - A test lowers the dogfood flow's Git output bound below a path length, so a new `f.git` read
     on an entry path fails with `git-output-over-bound`. Repro: route `requireTrustedAncestry`
     through `f.git` and run
     `TestProposeCitationsDCWV0802NamesWhyThePatchIsUnavailable/over-read-bound`.
   - The first heavy.sh jstestprovider run went past the 120 s default Bash timeout because of
     compile time.
