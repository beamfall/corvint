## Kernel captures and native process joins

No role/node assertion exists in a capture. The raw PID comes from the parsed stat, never a free-standing claimed key. Namespace/stat/executable reads use the fixed pinned observer recipe and the exact same live birth bracket; paths are constructed from parsed positive PID, not arbitrary JSON path instructions.

Parse Linux stat using decimal PID before comm and the final `) ` delimiter; check required field count/state/PPID/starttime field22 without trimming raw bytes. Before/after must agree on PID, PPID and starttime, boot/namespace, cmdline bytes, executable link and full executable artifact identity; changed/read-incomplete bracket fails. A birth key is (exact boot_id bytes, namespace device+inode, PID, kernel starttime ticks). Native lstart joins additionally require the retained native tool output from that same bracket and its pinned formatting; lstart alone is insufficient and its second-granularity limitation remains. Runtime executable content must match exact independently pinned rule bytes. ## Qualification constructor precondition (no circular token)

The concrete qualification validator rechecks the frozen case invariants: actual owned launch/joins and independent absence, two distinct fresh workload birth sets with equal mapped topology, safe retirement of an interrupted real grandchild, plus exact negative controls for legacy samples, ambiguity, graph substitution and PID reuse, native schedule ordering and witness-order invariance. Actual independently supervised harness execution/protected retention under the pinned implementation is mandatory; synthetic schema/link fixtures or unbound stdout cannot qualify this profile. Admitted parent must pin the report only after that exact campaign evidence and required independent review exist. Existing qualification from another profile is not transferable.

These qualification preimages/campaign are NOT_PRODUCED today.
